【墨西哥重点】更深的事件旅程 ≠ 可以上传更深的信用风险字段

Mexico 现金贷建议使用两层数据：Marketing-safe Journey Layer 保存经审核的 Register/KYC/Valid Apply/业务阶段事件；Risk Truth Layer 保留内部 Approve、Fraud、FPD、Vintage、LTV 及敏感风险判断。信用分、负债、逾期、催收、拒绝原因等用户级风险字段不要因为希望广告算法“学得更深”而直接上传平台。

2）海外投放知识学习

Primary / Secondary / Biddable / Non-biddable：深层事件不是越多越好

Primary Conversion Action 在 Campaign 使用对应 Goal 时可用于出价并进入 Conversions；Secondary Conversion Action 通常只用于观察并进入 All conversions。特别注意：Secondary 一旦加入 Custom Goal，而 Campaign 使用这个 Custom Goal，仍会参与出价。

Google 官方原文：Primary and secondary conversion actions
Lead/Register → KYC → Valid Apply → Approve → Disburse → First-loan CAC → FPD/Vintage → Risk-adjusted LTV

判断一个事件是否适合直接用于出价，至少同时看 Signal Volume、P50/P90 Conversion Lag、Journey Signal Coverage、事件定义稳定性、数据边界与 Primary→Disburse Yield。

3）实操训练

Mexico Google Search｜Event Goal Architecture Audit

  1. 导出最近 28 天每个 Search/Web-to-App Campaign 的 Conversion Goal、Primary/Secondary、tCPA、Conversions、All conversions。
  2. 建立事件阶梯，并为每个事件填写 business_definition、source_system、primary_secondary、biddable、median_lag、p90_lag、dedup_key、owner。
  3. 打通 gclid/utm → session_id → user_id → application_id → loan_id，计算 Journey Signal Coverage 与 Primary→Disburse Yield。
  4. 建立 Allowlist/Blocklist：信用分、负债、逾期/催收、拒绝原因等敏感风险字段不进入广告平台 schema。
  5. 账户若实际开放 Journey-aware Bidding/相关 beta，再做受控测试；未开放时先用 Secondary Observation 验证旅程，不假设功能可用。

内部起点（非官方 Benchmark）：Journey Signal Coverage ≥95%；关键事件 Dedup Coverage ≥99%；最终扩量仍要求 First-loan CAC 不恶化超过 10%、成熟 FPD7 不恶化超过 1.5pct。

4）业务分析

Apply CPA 贵 25%，首贷 CAC 可能反而便宜约 27%

示例：两组均花 100,000 MXN。只优化 Raw Apply 得到 1,000 Apply，CPA=100；Approve=25%，Disburse=70%，最终 175 个首贷，First-loan CAC≈571 MXN。更完整的 Journey 信号只有 800 Apply，CPA=125，但 Approve=40%、Disburse=75%，最终 240 个首贷，First-loan CAC≈417 MXN。

Platform CPA → Primary→Disburse Yield → First-loan CAC → FPD/Vintage → Risk-adjusted LTV → Payback / ROI

因此现金贷不能用浅层 CPA 单独决定预算；真正要比较的是更深事件是否稳定带来更多健康首贷。
