2）知识学习

AdAttributionKit / SKAN：数据可见性下降 ≠ 用户质量下降

AdAttributionKit 是 Apple 的隐私保护广告归因框架，基于 SKAdNetwork 能力向广告网络和开发者提供安装、再互动和转化 Postback，而不依赖跨 App 个体追踪。Apple 会根据 crowd anonymity / privacy threshold 决定 Postback 可包含的数据粒度，因此 Fine Conversion Value 缺失、只出现 Coarse Value 或部分字段为 null，不应直接判定为 Fraud 或埋点故障。

Apple 官方原文：AdAttributionKit ｜ Ad Attribution overview
Ad → Install/Reengagement → Update Conversion Value → Apple Privacy Tier → Postback → MMP / Developer → Backend Cohort

现金贷建议只把早期、非敏感业务阶段编码为归因信号，例如 First Launch / Register / KYC / Submit Application；信用评分、收入、审批额度、逾期/催收标签等敏感金融数据留在内部数仓。

3）实操训练

iOS Postback × Backend 对账

  1. 取最近 28 天 iOS Campaign 的 Apple/MMP Postback、Install、Register、Apply、Approve、Disburse、Spend、Campaign、Creative、App Version。
  2. 只统计 Apple 签名验证通过、`postback-identifier` 去重后的有效 Postback。
  3. 分别统计 Fine Conversion Value、Coarse Conversion Value、无细粒度值的 Postback。
  4. 按 Campaign/Day/Cohort 对比 Valid Postback → MMP Install → Backend First Launch → Apply → Disburse，不强求用户级一一映射。
  5. Fine Value Availability 下滑但 Backend 稳定时先查 privacy tier / volume mix；Postback 验签率与 Backend 同时下降再查 SDK、endpoint、版本和网络。
Apple 官方原文：Verifying a postback ｜ Receiving attributions & postbacks

内部可先以 28 天自身基线监控，Fine Value Availability 或 Verified Postback Rate 较基线下降超过 10pct 时触发排查；10pct 是内部监控起点，不是 Apple 官方阈值。

4）业务分析

iOS“可见转化”下降 26.7%，首贷 CAC 可能完全没变

示例：同样 Spend=100,000 MXN、有效 Apple Postback=4,000，上周 3,000 个带 Fine Value，本周只有 2,200 个；只按 Fine Value 会认为“可见转化”明显恶化。但如果 Backend 两周都产生 200 个首贷：

Backend First-loan CAC = 100,000 ÷ 200 = 500 MXN

真实 CAC 并没有变化。因此 iOS 的预算判断顺序应是：Postback Data Quality → MMP Aggregate Attribution → Backend First-loan CAC → FPD/Vintage → LTV。Fine/Coarse 信号首先是“可见性层”，不是经营真相层。

研发
