2）海外投放知识学习

Blended CAC ≠ Incremental CAC：扩量时必须看边际获客成本

Base：100,000 MXN → 200 首贷 → CAC = 500 MXN
Expansion：40,000 MXN → 60 首贷 → Incremental CAC ≈ 667 MXN
Blended：140,000 MXN → 260 首贷 → CAC ≈ 538 MXN

Blended First-loan CAC 回答“整个 Campaign 平均一名首贷多少钱”；Incremental First-loan CAC 回答“新增这一段预算，每多一名首贷究竟花多少钱”。示例中 Blended CAC 只恶化约 7.6%，但增量预算本身比 Base 贵约 33%。

现金贷还要继续看 Expansion Cohort 的 Approve、FPD/Vintage 和 Risk-adjusted LTV。扩量常见误区包括：平台建议加预算就直接加、用 D0/D1 未成熟数据评价 Expansion、把 Bid Protection 广告金当盈利保障、以及只看 Campaign 平均值掩盖边际恶化。

3）实操训练

Mexico TikTok Safe Budget Increase 扩量实验

  1. 选择过去 14–28 天表现已经稳定的 Mexico Smart+ App Promotion / Lead Generation Campaign，固定 Base Budget、Optimization Event 和当前成熟首贷 CAC。
  2. 确认账户是否真实开放 Safe Budget Increase；先关闭与其冲突的 Scheduled Budget Increase、自动预算规则等。
  3. 设置 Extra Daily Budget；如果优化 Apply，用 Allowable First-loan CAC × Mature Apply→Disburse Rate 反推 Target Cost，而不是直接把首贷 CAC 当平台 Apply Target。
  4. 建立 Base / Expansion 分层，记录 Spend、Apply、Approve、Disburse、First-loan CAC、FPD7/Vintage、LTV。
  5. 次日先看 Delivery、Extra Budget Utilization、Platform Cost 和深层漏斗；风险指标等待 Cohort 成熟后再决定长期扩量。

内部起点（非 TikTok 官方标准）：Expansion Incremental CAC ≤ Base Mature CAC 的 120%；Approve Rate 不低于 Base 5pct 以上；成熟 FPD7 不高于 Base 1.5pct 以上；Expansion Risk-adjusted LTV/CAC 不低于 Base 的 90%。

4）业务分析

Blended CAC 只恶化 8%，新增预算的风险调整回报可能已经接近失效

假设 Base Spend 100,000 MXN，200 个首贷，CAC = 500 MXN；FPD7 = 18%，Risk-adjusted LTV = 900 MXN，则 LTV/CAC = 1.80。开启增量预算后，多花 40,000 MXN只新增 60 个首贷，Incremental CAC ≈ 667 MXN；如果 Expansion Cohort FPD7 升到 24%、Risk-adjusted LTV 只有 700 MXN，则 Expansion LTV/CAC ≈ 1.05。

总体 Blended CAC 仍只有约 538 MXN，看起来“账户平均仍健康”，但新增预算已经几乎没有利润缓冲。扩量因此必须依次回答：能不能花出去 → 有没有新增申请 → 有没有新增健康首贷 → 新增首贷的风险调整价值是否高于新增获客成本。

5）产品相关

Budget Expansion Registry + Scale Cohort Ledger

产品
定义可扩量产品版本、额度/期限/定价、Landing/App 承接能力、disclosure_version。
投放
维护 base_budget、extra_budget、bid strategy、target cost、启停时间、Campaign/Ad Group 和 Bid Protection 状态。
数据
产出 Base vs Expansion：Spend、Apply、Approve、Disburse、Incremental CAC、FPD/Vintage、LTV。
风控
判断边际风险是否恶化，给出 Allowable Incremental CAC 与风险止损线。
研发
保证 campaign_id/adgroup_id、event_id、application_id、loan_id、budget_version 可串联，并支持回滚。

Budget Expansion Registry 建议保存 market / platform / campaign_id / budget_version / base_budget / extra_budget / target_cost / enabled_at / product_version / disclosure_version / owner；Scale Cohort Ledger 则保存 base_or_expansion / spend / apply / approve / disburse / CAC / FPD/Vintage / LTV / decision。
