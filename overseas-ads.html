1）今日最新资讯

2026-09-10｜TikTok LPV：把“广告点击”拆成“页面真正成功加载”

今天官方核查没有发现过去24小时会改变 Mexico 现金贷核心准入边界的新禁投规则。当前最值得直接落地的是 Landing Page View（LPV）：TikTok 当前将其定义为 Traffic Objective 下的优化目标，只有用户点击广告且目标 Landing Page 成功加载才计一次。它与广告主通过 Pixel / Events API 分享的 Default Page View / View Content 不是同一事件。

TikTok 官方原文：Landing Page View

为什么重要：Web-to-App 的 CTR/CPC 好但申请差，可能不是用户意愿问题，而是弱网、页面过重、重定向、WebView、第三方脚本、Deep Link/Fallback 等造成点击后损失。LPV 可以把“点击但没到页”单独量出来。

投放影响：当前 LPV 可用于全球 Auction Ads、iOS/Android、第三方 Landing Page/TikTok Instant Page，并支持 TikTok/TikTok Pangle、Lowest Cost/Cost Cap；Traffic 默认仍是 Click，需要主动改成 LPV；TikTok 当前明确 LPV 与原生 Split Test 不兼容。

TikTok 官方原文：LPV availability / setup / reporting

TikTok 当前 Smart+ Traffic 指南同时建议：主要目标是 Click/LPV 时可使用 Smart+ Traffic；若已有 Pixel/Events API 且要推动具体网站 Conversion，则考虑 Smart+ Web。

TikTok 官方原文：About Smart+ Traffic Campaigns

【墨西哥重点】页面要更快，但不能为了 LPV 删除贷款披露

Mexico Web-to-App 的 Landing Page 同时是转化资产 + 合规资产。LPV 只解决“有没有成功到页”，不会让不可投贷款产品变成可投。建议保留主体、期限、费用/年化口径、代表性成本等必要信息，同时优化首屏资源、重定向与 CTA。

2）海外投放知识学习

Click、LPV、Page View、Session、Conversion 怎么区分

Click只说明用户点了广告；LPV要求页面成功加载；Default Page View / View Content 是站点通过 Pixel/Events API 上报的事件；Session 按分析工具自己的会话规则计算；Conversion 是 Register、Apply、Disburse 等业务目标。TikTok明确说明 LPV、GA Page View 与 Session 因定义和触发逻辑不同，出现差异是正常的。

TikTok 官方原文：LPV definitions and reporting differences
Landing Page Load Rate = LPV ÷ Ad Clicks
Click-to-LPV Loss Rate = 1 − LPV ÷ Ad Clicks
Cost per LPV = Spend ÷ LPV
LPV→Apply Rate = Backend Valid Apply ÷ Matched LPV
LPV→First-loan Rate = First Disbursed Borrowers ÷ Matched LPV

常见误区：Click=有效访问；LPV高=首贷质量高；LPV与GA不一致=埋点故障；为了提速删除贷款披露；深层事件量已足够仍只优化LPV。

3）实操训练

Mexico Web-to-App「Click → LPV → Apply」漏斗体检

  1. 拉14天 Campaign / Ad Group / Placement / Creative / OS / Landing Page Version 的 Spend、Clicks、LPV，并接 Backend Register/KYC/Apply/Approve/Disburse。
  2. 新增 Cost/LPV、Load Rate、Click→LPV Loss、LPV→Apply、LPV→First-loan。
  3. 按 OS、Network、WebView、LP Version、Placement/Publisher 拆分。
  4. 检查首屏资源、Redirect、DNS/TLS、JS、第三方SDK、Deep Link fallback、404/Timeout和披露模块。
  5. LPV 当前不支持 TikTok 原生 Split Test，可用 matched-cell：尽量可比的两个 Ad Group，一组 Click、一组 LPV，只改变核心目标，并明确非随机实验。
  6. D1看 Delivery/LPV/Load Rate/Cost per LPV；首贷和FPD按成熟 Cohort 再判断。

内部排查起点：Click→LPV Loss 相对同OS/同LP版本28天基线恶化≥5pct进入P1；绝对Loss≥20%进入P0。均为内部起点，不是平台官方阈值。

4）业务分析

CPC 更便宜，First-loan CAC 仍可能更贵

A：100,000 MXN → 5,000 Click → CPC 20 → 3,000 LPV → 600 Apply → 147 首贷 → CAC≈680

B：100,000 MXN → 3,750 Click → CPC≈26.7 → 3,375 LPV → 743 Apply → 182 首贷 → CAC≈549

A 的 CPC 更低，但大量点击没有形成成功到页；B 的 CPC 更高，却因为真实到达和后续漏斗更好而获得更低首贷 CAC。若 LPV→Apply 高但 Approve 低，应查流量意图、产品条件、预筛与风控；若 CAC 好但 FPD/Vintage 恶化，仍不能扩量。

5）产品相关

Landing Page Performance Contract

产品
维护 LP Version、信息结构、贷款披露、CTA、Web-to-App 与 disclosure_version。
投放
看 Click→LPV 与 Cost/LPV，根据深层事件量选择 Traffic/LPV 或 Web Conversion。
数据
打通 click_id → lp_version → user_id → application_id → loan_id，统一 LPV/GA/Backend 口径。
风控
按页面/素材 Cohort 看 Approve、Fraud、FPD、Vintage。
研发
负责首屏性能、Redirect、Deep Link/Fallback、WebView、Pixel/Events API、错误码与版本监控。

建议状态：Draft → Compliance Approved → Performance QA → Active → Degraded → Rollback / Superseded。
