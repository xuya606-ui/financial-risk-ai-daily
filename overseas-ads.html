政策纠偏｜TikTok Mexico Financial Services

2026-08-29 重新核对当前 TikTok 官方原文后，对 8 月 28 日知识库口径再次修正：

  1. Mexico 所在市场组对普通金融服务/贷款的核心要求是当地/区域许可、必要 disclosure/disclaimer、18+。该市场段落中的 Sales Representative application permission 明确用于 cryptocurrency / crypto trading / NFT 等特定类别，不应扩大成“所有普通贷款都必须 Sales Rep permission”。
  2. Mexico 当前禁止清单确实包含 High APR Loan（APR ≥50%）、Payday Loan、Short-term Loan（还款周期 ≤90 天），因此这三项仍属于当前 TikTok Mexico 明确限制。
  3. 官方 may-be-allowed 示例中包含 mortgage、consumer finance、P2P、BNPL loans，因此不能把 P2P 一概标为 Mexico 禁止类别。
官方原文：TikTok Financial Services Policy（EN） ｜ TikTok Financial Services Policy（ES-LATAM）

Android 归因反作弊升级：Protect360 Advanced Security

过去24小时未发现足以改变现金贷核心投放策略的重大平台新规，因此今日扩展到最近两周。AppsFlyer 近期更新的 Advanced Security Protect360 模块用于在 Android 首次启动后、正式归因前识别 SDK/Attribution Spoofing 和被操纵流量，尤其适合高量 App 与 Affiliate/Publisher 流量。

官方原文：AppsFlyer Advanced Security ｜ Validation Rules

现金贷意义：媒体/MMP 的便宜 Install 或 Apply 必须用 backend first_launch、Register、Apply、Disburse 再验证，否则假安装、伪造事件、Device Farm 或归因劫持会同时污染 CPA 和算法学习。

【墨西哥重点】TikTok 当前贷款广告执行口径

当地/区域许可 + 必要披露 + 18+ + 不属于禁止类别

当前明确禁止：APR ≥50% High APR Loan、Payday Loan、还款周期 ≤90 天 Short-term Loan 等。Crypto/NFT 等特定类别另有 Sales Rep permission 要求。

2）知识学习

四类移动归因欺诈

SDK Spoofing：伪造 SDK 请求；Install Hijacking：真实安装被抢归因；Device Farm：真机/模拟器批量制造转化；Post-attribution Fraud：归因后才识别的欺诈。

MMP = 归因真相层
Backend = 业务真相层
两者必须持续对账
3）实操训练

MMP × Backend 反作弊体检

  1. 按 Media Source / Publisher / Campaign / Geo / App Version 对比 MMP Install、backend first_launch、Register、Apply、Disburse。
  2. 计算 MMP-to-Backend Install Gap、Backend Verified Conversion Rate、Fraud Block Rate、Post-attribution Fraud Rate。
  3. 排查 Click→Install、Install→Apply 的异常时间分布、设备/IP/数据中心聚集和模拟器信号。
  4. 把异常继续接到 Approve、Disburse、FPD7、Vintage。

内部试验可先以 MMP Install 与 backend first_launch 差异 >5% 预警、>10% 专项排查；这是内部起点，不是 MMP 官方阈值。

4）业务分析

为什么 CPI/Apply CPA 变好，首贷 CAC 与 FPD 反而恶化？

假流量或低质流量会夸大 Install/Apply，让媒体指标变漂亮，却不会同步产生真实首贷。更危险的是，平台可能继续用这些伪造/低质事件学习，进一步扩大错误人群。

Spend → MMP Valid Install → Backend Verified Apply → Approve → Disburse → FPD/Vintage → Risk-adjusted LTV
5）产品相关

Attribution Trust Layer

产品负责事件可信度规则；投放维护 Publisher 白名单/观察名单；数据维护 install/click → user → application → loan 映射；风控联动设备/团伙/FPD；研发负责 SDK、事件签名、event_id、幂等和关键事件 backend confirmation。
