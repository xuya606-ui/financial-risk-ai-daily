2）海外投放知识学习

Referred、Assisted、Incremental：三个“转化”不是一回事

Referred = TikTok 是转化前最后触点
Assisted = TikTok 更早参与，但最后触点是其他渠道
Incremental = 如果没有这次广告，本不会发生的新增转化

Referred Conversion回答“最后是谁接住了转化”；Assisted Conversion回答“旅程里 TikTok 有没有参与”；Incremental Conversion才回答“广告是否真正创造了额外业务”。三者不能相加当成“新增首贷”。

现金贷例子：用户在 TikTok 看到贷款教育视频，第二天 Google 搜品牌，第三天打开 App 完成申请并放款。TikTok 可能是 Assisted，Google 可能拿 Last Click；但到底没有 TikTok 时用户会不会仍然借款，需要增量实验才能回答。

常见误区：Assisted 高就直接加预算；把 Referred + Assisted 与 MMP Last-click Loan 相加；用更长 Attribution Window 得到更多平台转化后误认为真实首贷增加；MMP 与 TikTok 使用不同窗口却直接比较 CPA。

判断方法：媒体归因解释“谁参与”，Backend 确认“真实业务发生”，Incrementality 回答“是否真正新增”。现金贷预算最终仍按 Mature First-loan CAC → FPD/Vintage → Risk-adjusted LTV/Payback 判断。

3）实操训练

Mexico Attribution Window × Backend 对账

  1. 盘点配置：按 TikTok Campaign / Ad Group 导出 CTA、EVTA、VTA 设置，同时记录 MMP 对应 Attribution Window；先不改设置。
  2. 统一事件：明确 Install、Register、Apply、Approve、Disburse 各自来自 TikTok、MMP 还是 Backend，建立 source_of_truth。
  3. 拉 28 天数据：Spend、TikTok Attributed Apply、MMP Attributed Apply、Backend Valid Apply、Approve、Disburse，以及 P50/P90 Conversion Lag。
  4. 做窗口比较：用 Attribution Analytics/报表比较不同窗口下的 Conversion/CPA；把“报表变化”与 Backend 实际首贷变化分开。
  5. 拆 Placement：若 Mexico Smart+ 实际有 PineDrama，单独拆 Spend、Apply、Approve、Disburse、First-loan CAC；不要和 For You / Search 混成一个结论。

内部预警起点：若 TikTok Ads Manager vs MMP 的同事件差异相对自身 28 天基线恶化超过 10pct，进入排查；该 10pct 是内部运营起点，不是 TikTok 官方阈值。排查顺序：Attribution Window → Event Mapping → UTM/Deep Link → Event Dedup/S2S → Conversion Lag → Fraud。

次日复盘：先判断差异是否来自窗口和数据链，再看 Campaign 真实质量；不因为单日报表 CPA 变化立即大幅调预算。

4）业务分析

归因窗口把 CPA 降低 27%，真实首贷 CAC 可以完全不变

假设 Mexico TikTok App Campaign 一周 Spend = 100,000 MXN。

1-day click 口径：220 个 Apply → Apply CPA ≈ 455 MXN
7-day click 口径：300 个 Apply → Apply CPA ≈ 333 MXN
Backend 成熟首贷：100 人 → First-loan CAC = 1,000 MXN

把窗口从短口径切到长口径，平台报告里的 Apply CPA 下降约 27%，但真实首贷人数没有增加，First-loan CAC 仍是 1,000 MXN。这里发生的是Attribution Coverage 变化，不是业务提升。

同理，Assisted Share 上升说明 TikTok 可能在更上游发挥作用，但不能据此直接计算新增利润。正确经营链应是：Attribution Window / Assisted → Backend Mature First-loan CAC → FPD/Vintage → Risk-adjusted LTV → Incrementality Test → Budget。

5）产品相关

建立 Attribution Governance Registry + Measurement Contract

产品经理
定义 Web/App/Web-to-App 漏斗、KYC/Apply/Disburse 事件和 Deep Link fallback；确认哪些数据可用于营销归因。
投放
维护每个 Ad Group 的 CTA/EVTA/VTA、Placement/PineDrama 状态、Campaign 变更日志；不把 Assisted 当 Incremental。
数据
统一 TTAM/MMP/Backend 事件字典，输出 Window-normalized CPA、TTAM-MMP Gap、P50/P90 Conversion Lag 与成熟首贷。
风控
按 Campaign/Placement Cohort 继续看 Approve、Fraud、FPD/Vintage；风险标签留在内部分析层。
研发
保证 UTM、Deep Link、event_id、S2S、MMP/SAN mapping、去重和 schema_version 稳定。

Registry 推荐字段：platform / campaign_id / adgroup_id / acquisition_mode / placement / attribution_window / mmp_window / event_name / event_source / source_of_truth / p50_lag / p90_lag / schema_version / effective_from / owner。
