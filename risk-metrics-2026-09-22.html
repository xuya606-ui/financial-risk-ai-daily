支付与还款链路风险指标

今日完整学习：Disbursement Success Rate、First Attempt Repayment Success Rate、Retry Recovery Rate、Repayment Success Rate@N。以下业务数字为模拟案例，用于训练分析逻辑，不代表行业统一标准或墨西哥监管阈值。

1. Disbursement Success Rate｜放款成功率｜DSR

1）指标是什么：已经进入放款执行的贷款里，有多少最终把资金成功结算到“正确、已验证”的收款账户。大白话：审批通过不等于钱真正安全到账。

2）为什么重要：这是审批后、资金发放阶段的同步运营+欺诈控制指标。它解决放款通道稳定性、账户错误、账户变更、银行卡/CLABE不匹配和错误入账问题，也是放款件数、激活、FPD和Fraud Loss的上游。

3）精确定义与公式：

DSR(count) = 固定结算窗口内成功结算到预期已验证账户的唯一放款订单 ÷ 已实际提交支付网络的Eligible唯一放款订单DSR(amount) = 成功结算金额 ÷ 已实际提交支付网络的Eligible放款金额

必须固定Settlement Window、订单/账户/用户去重、是否包含Pending/Return/Reversal；Gateway Accepted不等于最终Settled。未实际提交支付网络、在放款前已撤销的订单不进入分母。

4）如何看高低：通常越高越好，但“高DSR”不代表没有欺诈：如果账户校验很弱，钱可能高比例成功打到错误或被接管账户。低DSR可能是支付网络、银行、账户信息、风控拦截或欺诈攻击造成。

5）墨西哥现金贷七步案例

背景：30天首贷切换新Payment Router，同时Channel C上线银行卡/CLABE变更。
数据：放款指令12,000笔、MXN18m；DSR从97.5%降至95.8%；Account Mismatch 2.1%→4.6%；Channel C×Recent Bank Change DSR约91%；其中Recent Device Change占比14%；投诉0.5%→0.9%。
现象：整体放款成功率下降，账户不匹配和账户变更场景明显增加。
拆解：按Payment Rail×Bank×Account Change×Device Change×Channel×Limit拆分，异常主要集中Channel C的近期换卡/换CLABE用户。
根因：能确认Router切换、账户变更与异常同步出现，但仍需支付返回码、账户归属验证和ATO标签验证，不能把所有失败直接归因为欺诈。
决策：Technical Fail重试/切换通道；Account Mismatch要求重新验证；Bank Change+Device Change+High Value做Step-up；Confirmed Wrong Account硬停。
结果：观察7—14天DSR件数/金额、Return、Fraud Loss、投诉、到账时延和重复放款；技术恢复且欺诈不升才认为策略有效。

6）诊断逻辑：①Settled/Return/Reversal状态 → ②Error/Bank/Payment Rail → ③Account Match → ④Bank Change/Device Change → ⑤Fraud/Complaint。

7）策略动作：技术失败切通道或Retry；账户格式问题修正；账户归属不一致重新验证；高风险换卡组合Step-up；确认ATO/错误账户停止放款并冻结后续资金动作。

8）常见误区：Gateway Accepted当成功；Pending算成功；重复Retry重复计件；件数DSR与金额DSR混用；把客户主动撤销混进失败分母；高DSR就认为账户安全。

9）推荐拆分维度：Bank、Payment Rail、Channel、Score、Limit、New/Repeat、Account Change、Device Change、Region、Strategy Version。

10）预警方式：同结算窗口、同支付渠道建立自身历史基线并设置最低样本量。DSR下降+Technical Error上升可作为技术黄灯；Account Mismatch上升+ATO/Fraud上升可作为风险红灯候选。任何具体数值阈值均应是内部阈值。

11）与其他指标关系：Approval → Verified Account → DSR → Disbursement/Activation → FPD/Fraud Loss → EL/Margin。

12）小练习与答案

5,000笔已实际提交支付网络的放款，其中4,850笔在规定窗口内成功结算到正确账户。DSR是多少？

答案：4,850÷5,000=97.0%。

2. First Attempt Repayment Success Rate｜首次还款尝试成功率｜FASR

1）指标是什么：到期或进入合格还款窗口后，第一次真正发起的扣款/支付尝试就成功的比例。大白话：不用Retry，第一次就把钱收回来多少。

2）为什么重要：贷中/贷后同步指标，连接支付体验、客户现金流、银行通道和早期逾期。它能快速发现支付链路故障，但不能单独代表信用风险。

3）精确定义与公式：

FASR(count) = 第一次合格还款尝试最终Settled成功的唯一账户 ÷ 已发起第一次合格还款尝试的唯一Eligible账户FASR(amount) = 首次尝试成功结算金额 ÷ 首次尝试应收金额

必须固定Due/Eligible、Attempt定义、Settled状态、观察窗口和账户去重；处理中、授权成功但未清算、冲正不能直接算成功。

4）如何看高低：通常高更好，但下降可能来自Technical Failure、付款时间点、银行系统、余额不足或账户失效。FASR下降而最终PSR@7提高，说明首扣链路变差但Retry/恢复机制可能有效。

5）墨西哥现金贷七步案例

背景：新Payment Router上线自动Retry。
数据：Due账户12,000；FASR 72%→63%；PSR@7 82%→86%；Retry Recovery约36%→62%；Technical Fail占首扣失败的22%；FPD7 17.6%→15.8%。
现象：首扣成功下降9pp，但最终7日收款反而提升。
拆解：Bank A/B技术超时贡献首扣下降；Insufficient Balance在工资到账后重试恢复较好；Invalid Account基本无法靠Retry恢复。
根因：首扣下降与Router/银行返回结构高度相关，不能直接写成借款人信用恶化。
决策：技术类失败优化通道/时段；Soft Fail允许有限Retry；Hard Invalid停止盲重试并引导更新账户。
结果：看FASR、PSR@7、FPD7、Roll、Payment Cost、Complaint、Duplicate Debit是否同步改善。

6）诊断逻辑：①Due/Attempt口径 → ②Settled/Return → ③Failure Type → ④Bank/Time/Channel → ⑤PSR@N/FPD。

7）策略动作：Technical Fail切换通道；Soft Fail按工资日/时段Retry；余额不足做合规提醒；Hard Fail停止重试；账户/身份异常Step-up。

8）常见误区：授权成功=清算成功；未发起尝试的用户混进分母；把所有失败当余额不足；件数和金额混用；首扣低就直接认定信用变差。

9）推荐拆分维度：Bank、Payment Channel、Failure Type、Due Day、Payroll Timing、Score、Limit、New/Repeat、Device/Account Change。

10）预警方式：小时/日技术监控和成熟信用监控分开。FASR突然下跌且Technical Fail同步上升是技术黄灯；FASR下降且Soft Cash-flow Fail、FPD、Roll同步上升才更像信用风险。

11）与其他指标关系：Due → FASR → Retry Recovery → PSR@N → FPD/Roll → Bad/EL。

12）小练习与答案

10,000个账户都已发起首扣，6,300个首次成功。FASR是多少？

答案：63%。

3. Retry Recovery Rate｜重试挽回率｜RRR

1）指标是什么：第一次支付失败的账户中，有多少通过后续Retry最终成功。大白话：首扣失败后还能救回来多少。

2）为什么重要：同步运营/贷后指标，用来衡量Smart Retry的真实价值；帮助区分“可恢复失败”和“不可恢复失败”，避免无效重试增加费用、投诉和重复扣款。

3）精确定义与公式：

Retry Recovery Rate@N = 首次失败后在N日内至少一次Retry成功并Settled的唯一账户 ÷ 首次失败且Eligible for Retry的唯一账户

金额版本用被Retry成功挽回金额除以首次失败Eligible金额。必须固定N日窗口、Eligible条件、最大Retry次数和Settled状态。

4）如何看高低：高通常说明Retry有效，但并非越高越好：若首扣本身设计很差，可能“FASR很低、RRR很高”，最终成本反而更高。需要联合PSR@N和Cost/Complaint看。

5）墨西哥现金贷七步案例

背景：自动Retry从固定次日改为按错误类型/工资到账时段。
数据：首扣失败3,700笔；N日Retry成功2,300笔；RRR≈62.2%；Soft Insufficient Balance约74%；Technical Fail约81%；Hard Invalid Account约4%；Payment Cost/Loan增加MXN3.2。
现象：总体挽回明显提升，但Hard Fail反复Retry几乎没有收益。
拆解：按Failure Type×Bank×Retry Attempt×Time of Day×Payroll拆分，收益集中Soft/Technical。
根因：错误类型与可恢复性高度相关；但不同银行清算延迟可能造成“延迟成功”误算为Retry效果，需要排除。
决策：Soft/Technical差异化Retry；Hard Invalid停Retry；账户变更/身份异常改为验证而非持续扣款。
结果：观察RRR、PSR@7、Retry次数、成本、投诉、重复扣款、FPD/Roll；只在净回收价值为正时保留策略。

6）诊断逻辑：①首次失败真实性 → ②Failure Type → ③Attempt序号/时段 → ④Settled Lag → ⑤成本/投诉/PSR@N。

7）策略动作：按错误类型设置最大Retry次数与退避；工资型客户在更合适时段Retry；技术故障切备用通道；Hard Fail转账户更新；风险异常转Step-up。

8）常见误区：把延迟清算当Retry成功；所有首扣失败都做同样Retry；只看RRR不看成本；一个账户多次成功重复计数；高RRR就认为支付链路优秀。

9）推荐拆分维度：Failure Type、Bank、Payment Rail、Attempt No.、Time、Payroll、Score、Limit、New/Repeat、Strategy Version。

10）预警方式：RRR下降需先看Failure Mix；Retry次数上升但RRR/PSR@N不升属于效率黄灯；RRR提升但投诉/重复扣款上升则需要体验/合规红灯候选。

11）与其他指标关系：FASR↓ → Eligible Failures → RRR → PSR@N → Cure/Roll → Collection Cost/Margin。

12）小练习与答案

3,700个首次失败账户中，2,300个在7天内Retry成功。RRR是多少？

答案：2,300÷3,700≈62.2%。

4. Repayment Success Rate@N｜N日最终还款成功率｜PSR@N

1）指标是什么：到期Eligible账户在固定N日窗口内，经过首次支付、Retry、人工还款等合格路径后，最终成功结算的比例。大白话：不管中间失败几次，N天内最终真正收回多少。

2）为什么重要：这是比FASR更接近真实现金结果的同步/短周期结果指标，连接支付治理、早催和FPD；同时能衡量Retry是否只是“过程更复杂”还是确实增加回收。

3）精确定义与公式：

PSR@N(count) = Due后N日内至少一次Settled成功的唯一Eligible账户 ÷ 同一Due Cohort的Eligible账户PSR@N(amount) = N日内累计合格Settled金额 ÷ 同一Due Cohort应收金额

必须固定Due Cohort、N、退款/冲正/部分支付、件数/金额和提前还款处理。若部分支付可计金额PSR，但件数PSR需定义“全额/满足Cure条件”。

4）如何看高低：通常越高越好，但高PSR可能依赖大量Retry、较高费用或过度触达；因此必须联合Payment Cost、Complaint、Cure/Roll和重复扣款看。

5）墨西哥现金贷七步案例

背景：新Router+Smart Retry上线。
数据：FASR 72%→63%；RRR约36%→62%；PSR@7 82%→86%；FPD7 17.6%→15.8%；Payment Cost/Loan +MXN2.7；Complaint基本稳定。
现象：首次支付更差，但最终7日现金结果更好。
拆解：Soft/Technical Fail是PSR提升主来源；Hard Invalid和Bank Mismatch贡献有限。
根因：Smart Retry与PSR改善高度相关，但需要排除清算延迟、渠道Mix和到期日结构变化。
决策：保留高净收益Retry路径；淘汰无效Hard Retry；银行变更高风险场景先验证再支付。
结果：至少观察两个Due Cohort的PSR@1/@3/@7、FPD7、Roll30、Cost、Complaint、Duplicate Debit和Contribution Margin。

6）诊断逻辑：①Due Cohort/成熟窗口 → ②FASR → ③RRR/Payment Channel → ④Partial/Settlement/Reversal → ⑤FPD/Roll/Cost。

7）策略动作：PSR低由技术驱动则修通道；余额不足驱动则优化Retry/提醒；身份账户异常做Step-up；高成本低增益路径下线。

8）常见误区：把授权/处理中算成功；不同N日窗口横比；件数与金额PSR混用；未成熟Due Cohort进入分母；忽略退款/冲正；PSR高就忽略投诉成本。

9）推荐拆分维度：Due Date、Channel、Bank、Failure Type、Score、Limit、Term、New/Repeat、Payment Method、Strategy Version。

10）预警方式：同Due Cohort、同N窗口、最低样本量；PSR@N下降并且FPD/Roll上升更值得信用红灯；PSR稳定但成本/投诉升高属于经营黄灯。

11）与其他指标关系：FASR + Retry Recovery → PSR@N → Cure / FPD / Roll → Bad / EL → Contribution Margin。

12）小练习与答案

10,000个Due账户中，首扣6,300成功，之后Retry又成功2,300。假设无冲正且均在7天内，PSR@7是多少？

答案：(6,300+2,300)÷10,000=86%。

指标口径必须以内部数据字典、产品合同、支付清算规则和风险偏好为准；这里的数值只用于学习和演练。
