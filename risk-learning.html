今日知识：Thin-file（薄信用档案）

一句话：Thin-file不是“坏征信”，而是“可用于判断信用风险的历史信息太少”。No-file则可能连有效信用记录都没有，两者需要分开管理。

为什么重要：传统信用评分依赖历史账户和还款行为。Thin-file真正的问题是模型不确定性高；一刀切拒绝会损失好客，把缺失值当低风险又会放大欺诈和信用风险。

推荐组合：信用历史长度 + 活跃账户数 + 7/30天查询密度 + 当前负债 + 收入/现金流可信度 + 设备/身份风险

墨西哥现金贷模拟案例

背景：首贷申请12,000人，其中2,400人为Thin-file。
数据：Thin-file全量FPD7=18%，成熟信用档案客群=14%；Thin-file中“收入验证通过+设备稳定+30天查询≤1”的FPD7仅11%；“新设备+30天查询≥3+无稳定收入证据”FPD7达31%。
现象：Thin-file整体风险偏高，但内部差异远大于“Thin-file标签”本身。
拆解：查询密度×设备×收入验证×Limit后，风险集中在短期多头和身份/设备不稳定组。
根因：Thin-file只是信息不足状态；信息不足与其他负面信号共现才是更强风险候选原因。因果仍需实验验证。
决策：低风险Thin-file小额首贷+短额度有效期；中风险做收入/银行卡/身份二验；高风险组合拒绝或冷静期。
观察：FPD3/7、MOB1 DPD30+、提款率、复借率、EL和Contribution Margin。

判断方法：先区分No-file/Thin-file → 看短期查询密度 → 看收入/现金流真实性 → 看设备/身份风险 → 再决定准入与额度。

常见误区：“没有逾期记录=信用好”；只用账户数量定义Thin-file；所有Thin-file统一低额度；把征信缺失与接口失败混为一谈。

小练习与参考答案

A只有1个账户但稳定12个月且近期无查询；B有3个账户但都在近20天新开并查询5次。谁优先二验？

答案：B。短期新增多头比单纯账户少更提示现金流压力或借新还旧风险。

今日指标升级：DPD30+ / Cure / Recovery / Collection

DPD30+：总体下降不代表真实改善；高速扩量可能用未成熟资产稀释存量逾期，必须同Vintage同MOB比较。

Cure Rate：必须把真实现金回正与展期/重组“技术回正”拆开，否则催收KPI会被抬高。

Recovery Rate：建议Gross与Net同时看；供应商比较必须把催收成本和投诉/合规纳入。

Collection Rate：分母口径决定意义；回款率上升但Cure/Roll不改善，可能只是更多小额部分还款。

今日实操：DPD30+“真假改善”诊断

字段：loan_id、disbursement_date、snapshot_date、MOB、DPD、outstanding_principal、channel、score、limit、term、strategy_version、extension_flag、payment_amount。

步骤：总体DPD30+ → 新放款余额占比 → Vintage×MOB → Channel×Score×Limit → Roll/Cure/Extension。

SELECT vintage_month,mob,SUM(CASE WHEN dpd>=30 THEN outstanding_principal ELSE 0 END)*1.0/NULLIF(SUM(outstanding_principal),0) dpd30_amt FROM monthly_snapshot GROUP BY vintage_month,mob;

复盘：次日先看D1/D3、支付失败和流量结构；未成熟DPD30+不提前下结论。

今日业务：总体逾期下降，为什么利润还会恶化？

扩量会用大量尚未成熟的新资产稀释总体逾期；如果同时件均、边缘Score和EAD上升，未来EL可能变坏。经营判断应该使用同Vintage同MOB风险 + EAD + CAC + 资金成本 + Contribution Margin。

今日产品：Thin-file低额度起步 + 动态升级

低风险Thin-file不建议直接拒绝，可展示“初始可借额度”，后续根据按时还款、信息完善、多头变化和设备风险动态升级；中风险先做收入/银行卡/身份二验，高风险组合拒绝或冷静期。

职责：产品负责额度解释/二验；风控负责分层与升级规则；数据监控Thin-file→FPD→Vintage→复借→LTV；研发支持额度版本和复评；运营不得绕过风险分层。
