今日知识｜Delinquency Flow & Net Flow Forecasting｜逾期迁徙与净流量预测

概念：单看 DPD30+ 存量，只知道“现在有多少逾期”；Flow / Roll / Cure 则回答“资产正在向哪个方向移动”。建议统一建立 Bucket：

Current → 1-7 → 8-29 → 30-59 → 60-89 → 90+ / Write-off

每个 Bucket 同时记录进入（Inflow）、向更差桶迁徙（Roll）、治愈/回流（Cure）和净流量（Net Flow）。

为什么重要：Current DPD30+ 可以暂时稳定，但如果 1-29→30+ Roll 上升、30+ Cure 同时下降，未来 DPD30+/Bad 很可能恶化；反之，存量高但 Cure 改善，风险可能正在修复。

墨西哥现金贷七步案例

背景：30天复借产品，Channel B扩量，同时Collection Strategy C下调人工触达比例。
数据：观察12,000个到期账户；1-29→30+ Roll 28%→39%；30+ Cure 31%→22%；期初30+余额MXN8.0m；本期新流入30+ MXN3.6m；Cure/回收/结清流出MXN1.7m；Net Flow +MXN1.9m；MOB1 DPD30+ 12.5%→16.8%。
现象：月底30+余额快速积累，风险流入速度超过治愈/回收速度。
拆解：Channel B × Low Score × Limit≥MXN2,000 的 1-29→30+ Roll 达52%；同渠道低Limit约34%，其他渠道约27%-31%。
根因：可确认 Roll/Cure 共同恶化且集中于特定Segment；但渠道扩量、额度和触达策略同时变化，不能把单一因素未经验证就写成因果。
决策：高Roll Segment降额/降量；恢复高风险早期人工触达；低风险稳定客保留Digital First；用Champion/Challenger验证Collection Strategy C。
结果：观察2-4周的Roll、Cure、Net Flow、MOB1 DPD30+、Bad/Charge-off和Collection Cost；净流入下降且成本可控才认为策略有效。

判断方法：统一Bucket与Snapshot → Roll/Cure → Net Flow → Channel×Score×Limit×Term×Strategy拆解 → MOB/Bad/Charge-off成熟验证。

常见误区：不同月龄资产直接比较Current DPD；部分还款当完全Cure；只看件数不看余额；核销导致DPD下降就误判改善；用期末存量反推因果。

小练习与答案

期初30+余额8.0m，本期流入30+ 3.6m，Cure/回收/结清流出1.7m。若不考虑核销和其他调整，净流入多少？

答案：+1.9m；理论期末约9.9m，说明风险池在扩张，需要继续拆Roll与Cure来源。

今日指标学习

Ever 30+ Rate：固定Cohort在同MOB内“曾经跨过30天逾期线”的比例，比Current快照更少被后续Cure掩盖。

Early-to-30 Roll Rate：期初1-29 DPD中滚入30+的比例，适合在Bad成熟前发现早期风险恶化。

Net Flow to 30+：30+流入减去真实Cure/Recovery/Settlement流出，判断风险池净扩张还是收缩。

Charge-off / Write-off Rate：达到核销政策条件的损失确认比例，必须与Recovery-after-write-off和LGD联合看。

字段：loan_id、snapshot_date、dpd、bucket、opening_balance、outstanding_balance、payment_amount、cure_flag、writeoff_amount、recovery_after_writeoff、channel、score_band、limit_band、term、strategy_version、collection_vendor、rpc、ptp。

步骤：固定Snapshot/Bucket → 构建t→t+1迁徙 → 件数/金额Roll → Cure/Recovery → 30+ Net Flow → Channel×Score×Limit×Strategy → 用MOB1 DPD30+、Bad/Charge-off成熟验证。

Roll In − Cure Out → Net Flow → DPD30+ Stock → Bad / Charge-off → Recovery / LGD

第二天复盘：先查Snapshot完整性、支付入账延迟、展期/重组/核销口径，再判断业务风险；避免数据口径变化被误判为信用恶化。

今日业务｜经营周报从“DPD30+存量”升级到“风险流量”

固定链路：FPD → 1-29 Roll → 30+ Inflow → 30+ Cure/Recovery → Net Flow → DPD30+ Stock → Bad/Charge-off → Recovery/LGD → Margin。这样才能区分“新风险正在恶化”与“历史坏账仍高但新流入已改善”。

今日产品｜还款页与催收触达按风险迁徙阶段设计

1-7 DPD优先处理支付失败恢复与轻提醒；8-29 DPD强化提醒与分层渠道；即将30+的高风险用户增加人工触达和明确可执行还款路径；30+再按RPC/PTP、余额、历史行为和合规要求分层。产品负责还款路径，风控负责Bucket/Treatment，数据监控Roll/Cure，研发保证支付幂等/入账及时，运营不得通过人工操作改变DPD口径。
