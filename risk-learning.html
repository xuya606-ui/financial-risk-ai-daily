今日知识｜Agentic AML/KYC Governance

概念：当AI Agent参与KYC、AML、Fraud Case或支付流程时，风控对象从“模型”扩展为Model、Prompt、Tool、Permission、Identity、Network、Data和External Write的组合。

Use Case → Risk Tier → Agent Identity → Tool Scope → Human Review → Monitoring → Incident → Rollback

为什么重要：Agent的错误可能直接影响客户身份、账户、支付、拒绝和可疑报告，不同于只生成文本。必须让每一个高影响动作都能追溯到Agent身份、版本、工具、授权和人工责任人。

七步案例：背景：墨西哥现金贷平台用Agent处理KYC/AML；数据：月度100,000个Case，自动处理率68%→79%，人工复核32%→21%，高风险False Negative 1.1%→1.8%；现象：效率提升但高风险漏检增加；拆解：New Device+Bank Change+Shared Payer组合最差；根因：自动化扩展与漏检同步，需Holdout和人工抽样验证，不能直接写成单一因果；决策：低风险继续自动化，高风险保留人工Review，所有Agent动作留痕；结果：观察Automation、False Negative、Override、Case SLA、Complaint和Net Loss。

指标/公式：Automation Rate=Auto-completed mature cases÷Eligible cases；False Negative Rate=事后确认高风险但未拦截Case÷成熟高风险Case；Scope Violation Rate=越权Tool Call÷Total Tool Call。

常见误区：自动化率越高越好；模型有理由就等于可审计；Agent权限与用户权限混用；只看平均指标不看高风险组合。

判断方法：先校验数据成熟和标签，再看Risk Tier、Tool Scope、人工Override、Case结果，最后决定放量、收紧或回滚。

小练习：100,000个Case中自动处理79,000个，自动化率是多少？高风险误漏检1,800个，成熟高风险Case 100,000个，FN Rate是多少？答案：79%；1.8%。

实操与产品

实操：Agent登记→固定风险等级→工具白名单→区分只读/写入→高风险强制人工Review→记录Tool Call→每日监控Automation/False Negative/Override/Scope Violation。

业务：把AI Agent纳入获客、KYC、授信、放款、还款、催收全生命周期，至少同时看Automation、Fraud Loss、FPD、Case SLA和Cost。

产品：改银行卡/CLABE、放款、支付、身份结论、AML结案等高风险动作必须二次确认、撤销入口和审计记录；运营不得绕过强验证。
