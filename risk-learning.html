今日知识：多头借贷（Multiple Borrowing / Loan Stacking）

一句话：同一借款人在较短时间内向多家机构申请或持有多笔未结清信贷。它既可能是正常信用需求，也可能代表流动性恶化、过度负债、套现或“以贷养贷”。

为什么重要：对短期现金贷，多头常是FPD和深度逾期的领先信号；但不能把“征信查询多”直接等同于“已经借了很多钱”。查询、实际授信、未偿余额和还款压力必须分开。

多头率 = 观察窗内命中≥N家信贷机构/产品的有效申请用户 ÷ 有效申请用户
申请密度 = 最近7/30天新增信贷查询次数
债务负担率示例 = 月度债务偿付额 ÷ 可验证月收入

墨西哥现金贷模拟案例：5,000名首贷申请人中，900人最近30天有≥3家信贷查询，该组FPD7为27%，其余用户为12%。继续拆解后，高风险主要集中在“≥3家查询 + 最近7天新增2家以上 + 额度使用率>80%”人群。结论不是“所有多头都拒绝”，而是将短期新增多头与额度、Score、收入、设备/身份风险组合使用。

判断方法：先区分存量多头与短期新增多头 → 再看是否真正有活跃贷款/未偿余额 → 再叠加收入与月供压力 → 最后结合设备/银行卡/身份一致性和还款历史。

常见误区：征信查询次数当借款笔数；不同征信源覆盖差异不处理；首贷和复借使用同一阈值；未做对照就把渠道坏账全部归因于多头。

今日小练习与参考答案

若A组最近30天≥3家查询，FPD7=24%；B组无多头，FPD7=13%，但A组平均额度比B组高60%。下一步先做什么？

答案：先按Score×Limit×查询密度拆解，并同时看金额FPD；确认是多头本身、额度暴露还是两者叠加，而不是直接全拒A组。

今日指标：FPD1 / FPD3 / FPD30 / Ever DPD30+ / Current Rate

学习主线：FPD1更敏感于支付/提醒/欺诈，FPD3可以过滤一部分短暂失败，FPD30更接近实质信用风险；Ever DPD30+保留“曾经坏过”的历史，而Current Rate只看“现在是否正常”。

诊断要点：如果FPD1大幅上升但FPD3快速回落，先查自动扣款与提醒；如果FPD1/3/7同步恶化，则更像客群或策略风险。

今日实操：多头借贷 × FPD早期预警矩阵

必备字段：user_id、application_time、channel、campaign、score_band、approved_limit、disbursed_amount、bureau_inquiries_7d/30d、active_loans、monthly_debt_payment、verified_income、dpd1/dpd3/dpd7、payment_fail_flag、device_risk、strategy_version。

操作步骤：多头分层（0-1/2/3+） → 加最近7天查询密度 → 算FPD1/3/7件数与金额 → 拆Score×Limit → 单列支付失败 → 输出渠道×多头×额度矩阵。

判断：FPD1高但FPD3/7回落，先查支付；3+多头人群FPD1/3/7持续同步高且高额度更差，再考虑收紧准入或额度。

复盘：第二天先看多头结构、支付失败和FPD1；更强结论等待FPD3/7成熟。

今日业务：为什么某渠道放款高，但FPD更差？

不要直接把结论写成“渠道差”。建议按流量结构 → 多头/欺诈 → Score → Limit/Term四层拆。低CAC、高放款可能同时伴随短期新增多头、高额度边缘客增加，最终表现为金额FPD恶化。

经营判断：渠道评价回到风险调整后贡献利润：收入 − 资金成本 − CAC − Expected Loss − 支付/运营/催收成本。

今日产品：提款/放款前实时轻量复核

对于“审批通过后并非立即放款”的产品，用户点击确认借款时增加一次轻量复核：近期多头、设备/手机号/银行卡变化、账户状态、黑名单、额度有效期。

交互规则：风险不变→正常放款；轻度上升→可降额或缩短额度有效期；重大身份/设备异常→触发二次验证。前端应给清晰状态，不把后台复核表现为随机失败。

职责：产品负责状态/解释；风控定义规则；数据监控命中→提款→FPD→EL；研发负责额度版本、幂等和回退；运营只触达当前仍有有效额度的人。
