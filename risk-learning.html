今日知识｜Thin-file & Bureau Coverage Governance｜薄征信与征信覆盖治理

概念：Thin-file 是“有征信但历史太薄”；Bureau No-hit 是“查询成功但没有可用档案”；Technical Fail 是“查询本身没有成功”。三者必须在日志、策略、页面和指标上分开。

Query Success → Bureau Hit → File Depth → Inquiry Velocity → Alternative-data Coverage → Decision → FPD/Vintage → EL/Margin

为什么重要：把No-hit当低风险会放松准入，把Technical Fail当高风险会误杀。年轻客、新到信、自由职业者与现金经济用户更容易出现Thin-file；合理做法是用经过验证且合规的数据补充，而不是自动拒绝或自动提额。

墨西哥现金贷七步案例

背景：30天首贷扩大年轻用户/自由职业者Channel C，同时切换部分SIC查询链路。
数据：月申请60,000；Query Success 98%→94%；Bureau Hit 82%→69%；Thin-file 18%→31%；30日Inquiry中位数1.4→2.6；Alternative-data Coverage 76%→91%；Approval 30%→34%；FPD7 14.5%→18.2%。
现象：审批增加，但征信覆盖下降、Inquiry上升、早期坏账恶化。
拆解：Channel C×Thin-file×Limit≥MXN2,000 FPD7约25%；稳定工资、低Inquiry Thin-file约13%；Technical Fail重试成功后的风险并未明显更高。
根因：客群结构、Inquiry和Limit变化与风险恶化高度相关；但不能把Thin-file直接写成唯一因果，也不能把查询失败当成信用风险。
决策：Technical Fail走Retry/Fallback；真实Thin-file使用经过验证的收入、设备、账户与历史行为分层；High Inquiry×High Limit先降额；稳定低Inquiry Thin-file保留Challenger。
结果：等待两个成熟FPD7 Cohort，再看MOB1 DPD30+、Amount FPD、EL/Loan、Approval、投诉与Contribution Margin。

指标/公式：Query Success = 技术成功查询÷发起查询；Bureau Hit = 有有效档案÷技术成功查询；Thin-file = 符合内部薄档案定义的Hit客户÷Hit客户；Inquiry Velocity = 决策时点前7/30天合格信贷查询数。

判断方法：先拆技术状态与业务状态 → 再看Channel×File Depth×Inquiry×Limit → 最后用成熟FPD/Vintage/EL验证。

常见误区：No-hit=好客；No-hit=坏客；Technical Fail算Thin-file；Inquiry越多一定越坏；替代数据覆盖越高就越好；决策后查询数据穿越。

小练习与答案

10,000笔查询中9,500笔技术成功，7,125笔有有效征信档案。Query Success和Bureau Hit分别是多少？

答案：95% 和 75%。Bureau Hit分母应使用9,500，不应把500笔技术失败混进去。

今日指标学习

Bureau Query Success Rate：区分“系统没查成”和“客户没档案”的第一道质量指标。

Bureau Hit Rate：技术成功样本中可获得有效信用档案的比例。

Thin-file Rate：有档案但信用历史较薄的客户占比，定义必须版本化。

Inquiry Velocity：7/30天内信贷查询速度，用于识别多头与短期资金压力。

今日实操｜Bureau Coverage × Thin-file Risk Matrix

字段：application_id、user_id、channel、bureau_vendor、query_status、bureau_hit、tradeline_count、oldest_tradeline_months、inquiries_7d、inquiries_30d、score_band、verified_income、alternative_data_coverage、approved_limit、approval_flag、fpd7、dpd30、maturity、strategy_version。

步骤：拆Technical Success/Fail → 仅在成功样本计算Hit → 版本化Thin-file规则 → Channel×Thin-file×Inquiry×Limit → FPD/EL/Margin → Technical Fail和真实Thin-file采用不同动作。

Query Success ↓ + Hit稳定 + Outcome稳定 = 技术问题优先；Hit ↓ + Thin-file ↑ + Inquiry ↑ + FPD/EL ↑ = 风险黄灯

第二天复盘：先查Vendor SLA、授权、超时、Retry和重复查询，再查Channel Mix、Inquiry与额度。深度坏账未成熟前不因一天No-hit上升就全量收紧。

今日业务｜不要把“有征信/没征信”做成二元审批

固定链路：Query Success → File Depth → Inquiry → Income/Device/Account → Approval → Limit/EAD → FPD/Vintage → EL/LTV。年轻或新进入正式金融体系的用户可能Thin-file但并非高风险；反过来，有完整征信但Inquiry突然升高的用户也可能正在多头借贷。

今日产品｜征信技术失败应有Retry/授权/Fallback路径

产品对授权缺失、网络超时、Vendor失败给重试或明确提示，不把技术失败页面写成信用拒绝；风控负责Thin-file/Inquiry Guardrail；数据维护Query→Outcome；研发记录Vendor/Error/Consent/Retry和幂等；运营不得人工绕过高风险Inquiry或征信授权要求。
