今日知识：Champion / Challenger 策略测试

一句话：Champion是当前线上生产策略，Challenger是在受控样本中测试的新策略/模型。核心目的不是证明“新模型离线分数更漂亮”，而是验证它是否真正改善风险调整后经营结果。

为什么重要：线上现金贷经常出现“Approval更高但坏账更差”或“AUC更高但利润更低”。Champion/Challenger把这些争论变成可验证实验。

策略增量价值 ≈ Challenger风险调整后贡献利润 - Champion风险调整后贡献利润

墨西哥现金贷模拟案例

背景：首贷产品准备放宽Score cutoff，10%用户随机进入Challenger。
数据：Champion 9,000人：Approval 32%、FPD7金额15.0%、CAC MXN305、单客Contribution Margin MXN182；Challenger 1,000人：Approval 36%、FPD7金额16.4%、CAC MXN302、单客Contribution Margin MXN190。
现象：Challenger风险略升，但利润更高。
拆解：利润增益主要来自中等Score、低额度段；最低Score+高Limit组利润为负。
根因：策略放宽不是统一好/坏，增益集中在特定客群组合；实验提供了比离线指标更强的因果证据。
决策：扩大中Score低额度Challenger流量；最低Score高额度继续Champion。
观察：等FPD7成熟后继续追MOB1/2 Vintage、EL和Contribution Margin，再决定是否全量。

判断方法：冻结实验目标和主指标 → 随机分流 → 检查样本平衡 → 等关键指标成熟 → 做客群异质性拆解 → 扩量/回滚。

常见误区：实验组不是随机；样本未成熟就全量；同时修改渠道/额度/模型导致无法归因；只看AUC或Approval。

今日小练习与参考答案

Challenger AUC更高、Approval更高，但FPD7和EL恶化且Contribution Margin下降，是否应该因为AUC更高而上线？

答案：不应该。AUC只反映排序能力之一，线上决策最终应看成熟后的风险调整利润和业务目标。

今日指标：Flow Rate / PTP Kept / Precision / Recall

Flow Rate：观察期内有多少资产新流入目标逾期桶；用于看“新增逾期压力”。

PTP Kept：承诺还款的人里，真正按承诺兑现的比例；比单独PTP Rate更能反映催收质量。

Precision：模型抓出来的人里，有多少真的坏/欺诈，重点控制误杀和人工审核成本。

Recall：所有真正坏/欺诈里，模型抓到了多少，重点控制漏放/漏欺诈。

关键：Precision和Recall必须在固定标签、成熟期和阈值下比较，并与Approval、Bad Capture、EL、审核成本一起看。

今日实操：Champion / Challenger线上策略实验

必备字段：user_id、experiment_group、assign_time、channel、score、limit、term、approval_flag、disbursement_flag、CAC、dpd1/3/7、bad_flag、revenue、funding_cost、collection_cost、strategy_version。

操作步骤：随机分流并冻结实验组 → 检查渠道/Score/Limit基线平衡 → 同时报Approval/放款/FPD/EL/Contribution Margin → 做Score×Limit×Channel拆解 → 等成熟后扩量或回滚。

SELECT experiment_group, COUNT(*) n, AVG(approval_flag) approval_rate, AVG(dpd7_flag) fpd7, AVG(contribution_margin) cm FROM exp_matured GROUP BY experiment_group;

复盘：第二天先看分流是否被运营干预、支付/FPD1是否异常；更强结论等待FPD3/7及Vintage成熟。

今日业务：为什么Recall提高，利润反而可能下降？

Recall提高代表抓到了更多真正坏客户，但如果通过大幅降低阈值实现，False Positive也可能暴增。坏账减少的收益，可能小于审批下降、收入减少和人工审核增加带来的损失。

业务判断：新增拦截损失节省 − 新增误杀利润损失 − 二次验证/人工审核成本。Recall必须和Precision、Approval、Bad Capture、EL、Contribution Margin一起看。

今日产品：灰度风险用户的三路分流

对于模型不确定区间或Challenger新增客群，不建议全部“直接拒绝”。可以设计：低风险→直接通过；中风险→二次KYC/收入/银行卡验证；高风险→拒绝或冷静期。

职责：产品负责状态与解释；风控定义灰度区和二验触发；数据监控二验通过→放款→FPD/EL；研发保证策略版本、实验组和回滚；运营不得绕过实验规则定向放量。
