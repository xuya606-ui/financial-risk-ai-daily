今日知识｜KYC Decision Waterfall & Identity Assurance

概念：KYC 不应只有一个“通过/拒绝”结果，而应拆成 Start → Document Capture → OCR/Document Validation → Face/Liveness → Identity Match → Step-up/Manual Review → Pass/Fail。只有把每一步拆开，才能判断是风险恶化、用户流失还是技术故障。

KYC Final Pass = Completed Identity Evidence × Valid Document × Liveness/Face Match × Policy/Step-up Outcome

为什么重要：如果 Completion 下降，可能是 SDK、网络、设备兼容或页面摩擦；如果 Identity Pass 下降，可能是真实客群变差，也可能是 Vendor 阈值或证件拍摄质量变化。把所有失败都写成 Fraud 会造成好客误杀和 Approval 下滑。

墨西哥现金贷七步案例

背景：首贷APP更换人脸/活体SDK，并扩大Channel B。
数据：申请50,000；KYC Completion 78%→70%；Identity Pass 91%→87%；Liveness Failure 5%→11%；Step-up Conversion 68%→44%；Approval 32%→27%；Confirmed Identity Fraud 2.8%→3.0%。
现象：审批明显下降，但确认身份欺诈只小幅上升。
拆解：Android旧版本×Channel B×新SDK的活体技术失败最高；高风险Device+证件冲突群体的Fraud捕获才真正增加。
根因：技术问题与渠道结构同时变化；不能把全部KYC下降直接写成“欺诈增加”。
决策：技术失败提供重试/Fallback；文档冲突或强Device异常进入Step-up；明确身份冲突才Hard Fail。
结果：48-72小时看SDK Error/Completion；两个成熟Fraud Cohort后看Fraud Capture、FPR、Approval、Complaint与Margin。

判断方法：Eligible分母 → Completion → Technical Error → Document/Identity Reason → Liveness/Face → Step-up → Fraud Outcome → Approval/Margin。

常见误区：活体失败=欺诈；KYC没完成=信用拒绝；SDK超时进入Fraud标签；只看Pass率不看Completion；不同Vendor/阈值版本横比。

小练习与答案

KYC Completion 从80%降到68%，Liveness Failure 从4%升到13%，但成熟Fraud只从3.0%升到3.2%。第一动作是什么？

答案：优先排查SDK/设备/网络技术链，不应直接全量收紧KYC。

今日指标学习

KYC Completion Rate：进入KYC的Eligible用户中有多少真正走完全流程。

Identity Verification Pass Rate：完成且可判定的身份申请中有多少通过身份一致性验证。

Liveness Failure Rate：有效活体结果中的Fail比例，不等于Fraud Rate。

KYC Step-up Conversion Rate：被要求追加验证的成熟用户中有多少最终完成并通过。

字段：application_id、channel、app_version、os_version、device_model、kyc_vendor、document_type、ocr_result、liveness_result、face_match_score、stepup_flag/result、technical_error_code、final_kyc_result、fraud_label、approval、complaint、strategy_version。

步骤：固定Eligible分母 → Start/Completion → OCR/Document → Liveness/Face → Step-up → Final Pass → Vendor×Device×Version → Fraud Outcome → Approval/Margin。

KYC Start → Completion → Identity Pass → Step-up → Final Pass → Approval → Fraud/FPR

第二天复盘：先看错误码、设备版本、Vendor SLA和流量结构；Fraud标签未成熟前，不因单日Pass下降直接长期收紧。

今日业务｜KYC下降先判断“风险变差”还是“系统变差”

经营看板固定展示 KYC Completion、Identity Pass、Liveness Failure、Step-up Conversion、Final KYC Pass、Approval、Confirmed Fraud、FPR 和 Contribution Margin。技术指标和风险指标必须分轨。

今日产品｜可恢复失败必须给用户明确恢复路径

OCR模糊、网络超时、SDK异常、光线不足等提供重拍/重试/Fallback/人工复核；证件不一致、强团伙或设备冲突等高风险失败不暴露Rule ID和阈值。产品负责恢复路径，风控负责Reason Taxonomy，数据负责漏斗与Outcome，研发负责SDK/Fallback/日志，运营不得绕过强身份规则。
