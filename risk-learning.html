今日知识｜Collection Funnel & Promise-to-Pay Governance｜催收漏斗与承诺还款治理

概念：催收不是“打更多电话、拿更多承诺”，而是把可触达账户转化成真实、合规、可持续的现金回收。完整漏斗为：

Deliverability → RPC → PTP → PTP Kept → Cash Collected → Cure / Roll → Recovery / Net Loss

为什么重要：如果团队只奖励Raw PTP，催收员可能制造不现实的承诺；PTP表面提升，Kept、Cash、Cure却下降，甚至投诉上升。真正的经营目标应是“风险调整后的净回收”，而不是通话或承诺数量。

墨西哥现金贷七步案例

背景：30天复借产品，Collection Strategy V4增加WhatsApp自动触达，并把部分Agent激励从现金回收切换成PTP数量。
数据：逾期账户10,000；Due MXN15m；RPC 36%→52%；PTP 40%→57%；PTP Kept 68%→41%；7日Collection 31%→28%；30+ Roll 34%→39%；投诉0.8%→1.6%；后段Recovery 18%→16%。
现象：联系和承诺显著增多，但兑现、现金和迁徙结果恶化。
拆解：Vendor B×Low Score×High Balance RPC=61%、PTP=66%，但Kept仅28%、Complaint=2.4%；Vendor A同类RPC≈45%、Kept≈63%。
根因：激励、客群、Vendor话术与低质量承诺高度相关，但仍需Challenger/质检确认，不能把未验证关联直接写成唯一因果。
决策：Agent/Vendor KPI切换为Kept + Cash + Cure - Complaint；High Balance/High Roll人工优先；低风险用户Digital-first；Vendor B做话术审计和Challenger。
结果：连续2-4周看RPC、PTP、Kept、Collection、Cure、Roll、Recovery、Cost/Collected、投诉；下游现金与风险同时改善才算成功。

指标/公式：RPC=Right-party Contact÷Eligible；PTP=Valid Promise÷RPC；PTP Kept=按规则兑现的成熟PTP÷成熟PTP；Collection@N=N日现金÷固定应收基准；Recovery@MOB=累计净回收÷Default EAD。

业务场景：早期催收、30+催收、外包Vendor管理、数字催收、人工作业、承诺还款、支付失败恢复、后段Recovery。

常见误区：RPC越高越好；PTP越多越好；承诺金额当现金；不同DPD/MOB直接比较；未成熟PTP进分母；忽略件数/金额差异和投诉成本。

判断方法：先查可达性和身份确认 → 再看PTP质量 → 再看兑现/现金 → 最后看Cure/Roll/Recovery/投诉和成本。

小练习与答案

1,000个Eligible逾期账户中500个RPC，300个形成PTP，120个按规则兑现。RPC、PTP、PTP Kept是多少？

答案：RPC=50%；PTP=60%；PTP Kept=40%。如果Kept和Cash恶化，不能因PTP上升而认定催收有效。

今日指标学习

RPC Rate：真正联系到正确借款人的比例。

PTP Rate：RPC后形成有效还款承诺的比例。

PTP Kept Rate：成熟承诺中按规则兑现的比例，是承诺质量核心。

Collection Rate：固定应收基准下实际现金回收率。

Recovery Rate：Default/Write-off风险池中按固定MOB回收的净现金比例。

今日实操｜Collection Funnel × Vendor / Treatment Matrix

字段：loan_id、dpd_bucket、due_amount、balance、score_band、vendor、treatment、deliverability、rpc、ptp、ptp_amount、ptp_due_time、ptp_kept、cash_collected、cure、roll30、recovery_cash、collection_cost、complaint、strategy_version。

步骤：固定Bucket/观察窗 → Deliverability/RPC → PTP → Kept → Cash → Cure/Roll → Recovery/Cost/Complaint → Vendor×Score×Balance×Treatment。

RPC ↑ + PTP ↑ + Kept ↓ + Collection/Cure ↓ = 低质量承诺黄灯；Collection ↓ + Roll ↑ + Complaint ↑ = 红灯候选

第二天复盘：先查支付入账、承诺窗口、重复联系和数据延迟；再抽样听录音/看聊天记录，确认高PTP低Kept是否来自不现实承诺；最后调整激励与Treatment。

今日业务｜优化净现金与风险迁徙，不优化Raw Call/Raw PTP

经营看板固定为 Deliverability → RPC → PTP → Kept → Cash Collection → Cure/Roll → Recovery → Net Loss → Cost/Complaint。Vendor和Agent绩效至少同时包含Kept、Cash、Cure、Roll、Cost/Collected和投诉。

今日产品｜PTP之后的还款体验决定兑现率

承诺后页面清楚展示承诺金额、日期、可用支付方式、失败重试和提醒；自动还款/保存支付方式必须符合授权与合规要求，不使用默认勾选或Dark Pattern。产品负责支付与恢复，风控/催收负责Treatment，数据负责漏斗，研发负责入账幂等，运营/Vendor不得人为篡改PTP兑现口径。
