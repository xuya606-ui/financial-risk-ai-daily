今日知识：模型监控与漂移 Model Monitoring & Drift

一句话：模型上线不是结束；真正要持续回答的是“当前客群、当前数据和当前业务策略下，这个模型还是否有效”。

为什么重要：海外现金贷的渠道、设备供应商、反欺诈SDK、新老客结构、额度、宏观环境都会变化。即使模型代码完全没变，输入分布和标签关系也会变化。

四类漂移：数据漂移（变量分布变）、客群漂移（渠道/用户结构变）、表现漂移（AUC/KS/Gini变）、校准漂移（预测PD与实际Bad偏离）。

监控链：数据完整性 → Channel/Population → PSI/缺失率 → AUC/KS/Gini → Calibration → Approval/Bad Capture → EL/Contribution Margin

墨西哥现金贷模拟案例

背景：模型V5上线3个月，整体AUC从0.76降到0.73。
数据：全量PSI=0.12；渠道C PSI=0.31；渠道C占比18%→37%；低Score占比+11pp；全量FPD7 15%→17%；渠道C FPD7=24%。
现象：像是模型衰退，但风险高度集中在单一渠道。
拆解：Channel×Score×Device后发现渠道C新设备和低端机占比明显上升；其他渠道AUC基本稳定。
根因：更强候选原因是客群/渠道结构变化；是否需要全量重训仍需变量级漂移和OOT表现验证。
决策：先对渠道C降量或单独Challenger，排查高漂移变量和Vendor Version，再决定是否重训。
观察：未来2-4周继续看PSI、AUC/KS、FPD7、Approval、EL和Contribution Margin。

常见误区：PSI高就直接重训；只看AUC不看Calibration；用未成熟标签评估表现；阈值/规则变化后把经营结果全部归因于模型。

判断方法：数据完整性 → 供应商/版本 → 客群漂移 → 变量漂移 → 模型表现 → 校准 → 策略/利润。

小练习与参考答案

AUC稳定，但Approval下降8pp、FPD只改善1pp。应该先查模型还是策略？

答案：先查策略阈值、规则重叠和流量结构。AUC稳定说明排序能力没有明显恶化。

今日指标：KYC Pass / Take-up / Bad Capture / Risk-adjusted Return

KYC Pass Rate：不仅是转化指标，也是KYC技术质量和身份风险的上游信号；必须拆OCR、证件、人脸、活体、银行卡同名和Vendor Version。

Drawdown / Take-up Rate：授信用户中真正提款的比例；高风险用户更积极提款时，Take-up升高可能同时推高EAD和EL。

Bad Capture Rate：全部成熟Bad中被策略捕获多少；不能和Rule Hit混用，并需要与FPR、Approval、EL Saved和好客利润损失一起看。

Risk-adjusted Return：把收入、CAC、资金成本、EL和可变成本放到同一个收益框架，避免“CAC最低”或“APR最高”就被误判为最好。

今日实操：模型漂移监控看板

字段：application_id、apply_date、channel、model_score、score_band、核心变量、approval_flag、limit、dpd7、bad_flag、maturity_flag、strategy_version、vendor_version。

步骤：数据完整性/版本 → Channel PSI → 变量PSI/缺失率 → 成熟AUC/KS/Gini → Calibration → Approval/Bad Capture/EL/Contribution Margin。

SELECT channel,score_band,COUNT(*) n,AVG(approval_flag) approval,AVG(CASE WHEN maturity_flag=1 THEN bad_flag END) bad_rate FROM applications GROUP BY channel,score_band;

复盘：标签未成熟前，不依据短期Bad Rate直接做全量重训；先确认流量、数据和Vendor变化。

今日业务：AUC稳定，为什么利润还会下降？

AUC只衡量排序能力，不代表策略阈值、额度、渠道、资金成本或利润。经营复盘应按：Data/Channel → Model → Rule/Cutoff → Approval/Limit → Take-up/EAD → FPD/Vintage → EL → Contribution Margin逐层拆解。

今日产品：模型漂移触发“降级模式”

当关键数据供应商故障、变量缺失异常或模型漂移超过内部阈值时，产品不要表现成随机失败。低风险稳定客群继续；中风险进入二次KYC/人工审核；高风险或关键数据缺失暂缓提款。

职责：产品负责降级状态和解释；风控定义触发条件/fallback；数据监控PSI/缺失率/表现；研发支持模型版本、供应商切换和Kill Switch；运营不得绕过降级控制。
