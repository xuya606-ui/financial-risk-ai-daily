今日知识｜Payment Failure Taxonomy & Retry Strategy｜支付失败分类与重试治理

概念：支付失败不等于信用失败。至少拆成Hard Failure、Soft Failure、Technical Failure、Account/Identity Mismatch和Customer Cash-flow Failure，再决定Retry、Reroute、Step-up、账户更新或催收。

First Attempt Success → Failure Taxonomy → Retry → Final Payment Success@N → Cure / Roll / FPD

为什么重要：如果把技术超时、银行清算异常和余额不足混成一个“还款失败”，会把支付系统问题误判成信用恶化；反过来，对Hard Invalid持续自动重试也会增加支付费用、投诉和重复扣款风险。

墨西哥现金贷七步案例

背景：30天现金贷切换新Payment Router并上线自动Retry；Channel C同时增加银行卡/CLABE变更。
数据：Due账户12,000、Due Amount MXN18m；First Attempt Success 72%→63%；7日Payment Success 82%→86%；Retry Recovery约36%→62%；Bank/Account Mismatch 2.1%→4.6%；FPD7 17.6%→15.8%。
现象：首扣成功显著下降，但最终7日收款反而提升，说明“首扣失败”和“真实信用坏账”发生分离。
拆解：Temporary Bank Error / Insufficient Balance的Retry效果较好；Channel C×Recent Bank Change的Account Mismatch更高；Hard Invalid Account反复Retry基本无增益。
根因：新Router、Bank Change和失败结构变化与指标同步变化，但在完成错误码映射、清算延迟和对照验证前，不能把全部改善直接归因于Retry。
决策：Soft/Technical Fail做有限次数、分时段Retry；Hard Invalid停止重试并引导更新账户；Bank Change+Device Change做Step-up；技术支付失败不直接写成信用拒绝或欺诈。
结果：观察7—14天First Attempt、Retry Recovery、PSR@7、FPD7、Roll30、Payment Cost、Complaint和Duplicate Debit。

业务场景：放款到账、自动扣款、银行卡/CLABE变更、还款路由、催收支付链接、复借还款资格。

常见误区：Gateway Accepted当最终成功；把所有失败归因于余额不足；重复Retry重复计数；Payment Success用全申请作分母；把技术失败直接当信用坏账；只看件数不看金额。

判断方法：先看清算/错误码 → 再看账户匹配/设备 → 再看余额/现金流 → 最后才判断信用风险。

小练习与答案

10,000个Due账户，首扣6,300成功；3,700个首扣失败中2,300个在7天内Retry成功。求FASR、Retry Recovery、PSR@7。

答案：63%；约62.2%；86%。

今日指标学习

Disbursement Success Rate：资金是否真正结算到正确、已验证账户。

First Attempt Repayment Success Rate：第一次合格还款尝试就成功的比例。

Retry Recovery Rate：首扣失败后通过Retry最终挽回多少。

Repayment Success Rate@N：固定N日窗口内最终成功收回的账户/金额比例。

今日实操｜Payment Failure Matrix × Smart Retry

字段：loan_id、user_id、due_date、due_amount、payment_attempt_id、attempt_no、payment_channel、bank_id、account_change_flag、device_change_flag、error_code、failure_type、settled_flag、reversal_flag、fpd7、roll30、complaint、strategy_version。

步骤：固定Due/Eligible → 首次尝试 → Error Code标准化 → Hard/Soft/Technical/Mismatch → Retry → Settled Success@N → FPD/Roll → 成本/投诉。

First Attempt↓ + Final PSR↑ = Retry有效但首扣链路需修；Technical Fail↑ = 技术黄灯；Mismatch↑ + ATO/Fraud↑ = 风险红灯候选

第二天复盘：先查清算延迟、Error Mapping、幂等与重复扣款，再看余额不足和信用风险；Pending状态不提前判失败。

今日业务｜Payment Failure 不等于 Credit Failure

经营链固定为 Due → First Attempt → Failure Type → Retry → Payment Success@N → Cure/Roll → FPD/Vintage → EL/Margin。首扣失败上升时，必须先回答“技术、账户、支付能力还是信用风险”，再决定是否调整准入、额度或催收。

今日产品｜银行卡/CLABE变更同时管理恢复体验与ATO风险

Technical Fail提供Retry/Fallback；余额不足提供合规提醒和明确重试时间；Invalid Account引导更新；New Device + Bank Change + High-value资金动作触发Step-up。产品展示“处理中/失败/成功”必须与真实清算状态一致，避免重复支付。

职责：产品负责状态与恢复路径；风控定义Hard/Soft/Mismatch和Step-up；数据维护Payment Funnel；研发保证幂等、清算回调和错误码；运营不得绕过账户变更强验证。
