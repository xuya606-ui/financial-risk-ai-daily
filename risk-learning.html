今日知识｜FPD Waterfall & Maturity：FPD1→FPD3→FPD7

概念：FPD不是单一数字，而是首期逾期从到期后D+1、D+3、D+7逐步“沉淀”的早期风险曲线。

Payment/KYC/Fraud → FPD1 → Early Cure → FPD3 → FPD7 → Roll → DPD30+ → Bad/EL

为什么重要：FPD1对支付技术、银行处理、节假日和自动扣款重试非常敏感；FPD3过滤部分短暂延迟；FPD7更接近真实早期信用质量。只看一个点，容易把支付事故误判成信用恶化，或把件数改善误判成金额风险改善。

核心公式：FPDn = 首期到期后D+n仍逾期的成熟账户/余额 ÷ 首期到期且成熟到D+n的账户/应还余额。必须固定Grace Period、Partial Payment、Extension、技术挂账和账户/订单口径。

墨西哥现金贷七步案例

背景：14天首贷产品上线新支付SDK，同时渠道B扩量。
数据：成熟20,000单；FPD1 20%→29%；FPD3 17%→19%；FPD7 14.8%→15.6%；Payment Failure 5%→14%；Auto-debit Success 84%→70%；金额FPD7 16%→16.9%。
现象：FPD1跳升很大，但FPD3/7变化有限。
拆解：Provider×Error Code×App Version发现Timeout/Bank Routing Error集中在新SDK；Score/Limit结构变化有限。
根因：支付技术异常是强候选原因，但需要回滚/备用路由实验确认，不能直接写成唯一因果。
决策：先修支付、Technical FPD与Credit FPD分离；不立即全量降低Approval。
结果：24-72小时看支付恢复；D+3/D+7成熟后再决定是否调Cutoff/Limit，并继续看MOB1 DPD30+与EL。

判断方法：成熟度/到期结构 → Payment Error → FPD1到FPD3治愈 → Channel×Score×Limit → FPD7件数/金额 → DPD30+/EL。

常见误区：FPD1直接等同信用风险；件数FPD下降就判断风险变好；未成熟Cohort与完整历史横比；展期后抹掉原始逾期。

小练习与答案

FPD1从19%升28%，FPD7只升0.5pp，Payment Timeout从3%升12%。先改准入还是先修支付？

答案：先修支付，并等待FPD3/7确认深度信用风险。

今日指标学习

FPD1：最敏感的首期到期信号，必须与支付/技术指标联动。

FPD3：过滤一部分D+1临时噪声，适合看早期持续未还。

FPD7：更接近真实早期信用质量，但必须同时看金额、EAD和后续Vintage。

DPD30+：更滞后的深逾指标，总体Current口径可能被新资产分母稀释，优先同Vintage同MOB比较。

字段：due_date、maturity_d1/d3/d7、fpd1/3/7、amount_due/overdue_amount、provider/error_code/retry、channel、score、limit、device_risk、strategy_version。

步骤：成熟期 → 件数/金额 → FPD1与Payment Error → FPD1→3→7留存 → Channel×Score×Limit → Fraud/Device → DPD30+/EL。

Segment → Payment Failure → FPD1 → FPD3 → FPD7 → Amount Risk/EAD → MOB1 DPD30+ → EL

今日业务｜不要因为FPD1跳升就自动收紧信用

FPD1↑且Payment Failure↑、FPD7稳定，更像支付事故；FPD1/3/7同步↑且低Score高Limit占比、金额FPD和EL同步恶化，才更支持信用策略问题。经营看板固定显示Payment Failure、FPD1/3/7、Amount FPD7、Avg EAD、MOB1 DPD30+和EL。

今日产品｜还款失败页需要恢复路径

区分银行处理中、Provider Timeout、余额不足、Bank/CLABE需重新验证、重复扣款保护；技术失败不能直接进入高压催收。产品负责状态/重试，风控负责Technical vs Credit标签，数据维护FPD Waterfall，研发做幂等和备用路由。
