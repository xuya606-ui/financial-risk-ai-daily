今日知识：Credit Bureau × Multiple Borrowing｜征信与多头借贷策略

一句话：征信查不到不等于低风险，查询多也不等于必须拒绝。真正需要判断的是近期融资需求、当前活跃债务、偿付能力和额度暴露的组合。

Bureau Hit → Recent Inquiry → Active Lenders / Balance → DTI/PTI → Score → Limit → FPD / Vintage → EL

墨西哥现金贷模拟案例

背景：12,000名Bureau-hit首贷申请，渠道C扩量。
数据：30天查询0-1次FPD7=11%；2-3次=17%；4+次=27%；3+活跃Lender整体FPD7=24%；“4+查询 + 低Score + Limit≥MXN1,800”FPD7=34%。
现象：Approval基本不变，但风险结构恶化。
拆解：Inquiry × Active Lenders × DTI × Score × Limit，并先排除Vendor超时与重复查询。
根因：风险更集中于近期资金需求快速增加与高额度组合，不能把所有历史多头用户视为同一风险。
决策：高查询+高DTI+边缘Score降额/二验；稳定收入低额度组用Challenger验证。
观察：FPD3/7、金额FPD、MOB1 DPD30+、EL和Contribution Margin。

常见误区：技术No-hit当No-file、历史关闭账户算当前多头、Hard/Soft Inquiry混用、重复查询不去重、把相关性当因果。

小练习与答案

用户A历史4个账户但仅1个活跃、30天无新查询；用户B有2个活跃账户、7天5次查询且刚换设备。谁优先二验？

答案：B。近期查询密度和实时账户风险更能反映当前风险。

今日指标：Bureau Hit / Recent Inquiry / Multi-Borrowing / Application Velocity

Bureau Hit Rate：征信查询中获得可用结果的比例；Vendor Timeout、No-file、Identity Mismatch必须分开。

Recent Inquiry Rate：7/30天近期信用查询密度；Hard/Soft和重复查询规则必须统一。

Multi-Borrowing Rate：当前同时持有多家活跃贷款的用户比例；Active和Historical不能混。

Application Velocity：User/Device/Phone/IP在30分钟/24小时/7天窗口内的申请速度；需排除技术重复和运营商NAT。

今日业务：Approval没变，为什么FPD还能变差？

因为通过比例不等于通过结构不变。高查询、多头、高额度客群占比上升时，Approval可以完全不变，但金额FPD和EL明显恶化。

经营链：Channel → Inquiry/Multi-Borrowing → Score → Limit/EAD → FPD → EL → Contribution Margin。

今日产品：征信不可用时设计Fallback

新客技术No-hit优先重试/备用Vendor，仍不可用时进入低额度、补充验证或暂缓；稳定复借客可以在明确边界内使用内部还款与账户安全历史做Fallback；真实No-file采用低额度起步并通过真实还款逐步升级。技术错误不得直接写成信用拒绝。

职责：产品负责状态解释和恢复路径；风控负责Fallback与额度边界；数据拆Vendor Failure/No-file/Identity Mismatch；研发负责重试和备用Provider；运营不得绕过高风险No-file规则。
