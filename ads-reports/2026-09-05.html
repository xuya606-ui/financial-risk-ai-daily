现金贷 APP 海外投放学习日报｜2026-09-05

今日主题：Google Search Text Disclaimer × AI Max 合规自动化｜Mexico 现金贷重点

1）今日最新资讯

Google Search 的 Text Disclaimer 已可全球使用：AI Max / FUE 自动化下，合规文案终于有“强制展示位”

Google 当前官方帮助文档显示，Text Disclaimer 已面向全球广告主提供。批准后的 Disclaimer Asset 会出现在 Responsive Search Ads（RSA）的描述区域，并且与 AI Max、包括 Final URL Expansion（FUE）在内的功能兼容。单条免责声明最长 90 个字符；它只能在 Campaign 创建并已有 RSA 后再添加。

Google 官方原文：About text disclaimers for Search ads

对现金贷尤其重要的是，Google 明确说明：批准后的 Text Disclaimer 会覆盖原先固定在 Description Line 1 的资产；但如果 Disclaimer Asset 审核不通过，RSA 本身仍可能继续投放，只是改用其他描述行。因此，Text Disclaimer 是一个强合规资产，但不能被当成“配置一次就永远安全”的开关。

Google 官方原文：Disclaimer display / disapproval considerations

更关键的是：Text Disclaimer 不能替代 Personal Loans 落地页/App 的强制披露。Google 当前 Personal Loans 政策仍要求：只允许需要 61 天或以上才能全部偿还的个人贷款，并要求 Landing Page/App 显著展示最短/最长期限、最高 APR 或当地一致口径，以及包含全部费用的代表性总成本示例。

Google 官方原文：Personal loans policy

AI Max 迁移时间口径校正

当前 Google Help Center 的执行口径需要特别区分：使用 Text Customization（原 ACA） 的 Search Campaign 与使用 Campaign-level Broad Match Setting 的 Campaign 从 2026 年 9 月开始自动升级到 AI Max；而当前 DSA Help Center 明确写的是 2027 年 2 月开始自动升级。此前将 DSA 也归入 2026 年 9 月自动升级的口径，不再作为当前执行依据。

Google 当前官方口径：Text Customization：September 2026 ｜ Campaign-level Broad Match：September 2026 ｜ DSA：February 2027

对投放的影响：9 月 Mexico Search 迁移时，应重点审计 ACA/Text Customization 和 Campaign-level Broad；同时把 Disclaimer Asset、FUE、Landing Page Disclosure 作为一个整体治理，不要因为 AI Max 自动化而让贷款合规文案失控。

今天建议动作：优先在稳定的 Mexico Personal Loan Search Campaign 上建立“Approved Disclaimer + FUE URL 白名单/排除 + LP Disclosure Version”三层合规链，再做 AI Max 扩量。

【墨西哥重点】TikTok / Google 贷款准入边界今天没有发现新的 24 小时级变化

TikTok 当前 Mexico 所在市场组仍要求金融广告具备当地/区域许可、满足 disclosure/disclaimer、只面向 18+；may-be-allowed 示例包括 consumer finance、P2P、BNPL 等贷款，明确禁止示例仍包括 APR ≥50% High APR Loan、Payday Loan、以及还款周期 ≤90 天的 Short-term Loan。

TikTok 官方原文：Financial Services Policy

Google Personal Loans 的 61 天和落地页/App 披露要求仍保持不变。对 Mexico 团队来说，平台广告里的 Disclaimer 只解决“广告展示层”，产品页仍必须独立满足 Google 的 Personal Loans 披露要求和你们当地适用的法律/合规要求。

Google 官方原文：Google Personal Loans
2）海外投放知识学习

Compliance Asset Stack：RSA、Text Disclaimer、Text Customization、FUE、LP Disclosure 分别管什么？

Search Term → RSA
　　　　　├─ Advertiser Assets
　　　　　├─ Text Customization / Google AI Assets
　　　　　└─ Text Disclaimer（批准后强制进入描述区）
→ Final URL / FUE Selected URL
→ Landing Page / App Disclosure
→ Apply → Approve → Disburse

RSA 是最终参与竞价并组合标题/描述的搜索广告；Text Customization 会基于 Domain、Landing Page、已有 Ads 和 Keyword 生成额外标题/描述；Text Disclaimer 用于必须在 Search Ad 中展示的条款/披露；FUE 可以把流量送到同域名更相关页面；而 Landing Page Disclosure 才是贷款产品信息披露的业务/政策承接层。

一个最容易犯的错误是：“我已经在广告里加了免责声明，所以 LP 不需要再写期限/APR/代表性成本。”这不成立。Google Personal Loans 政策明确要求这些信息在 Landing Page 或 App 中显著披露。

另一个误区是只靠 Pinning。Google 当前说明，FUE 开启时 pinned RSA assets 可能不会被使用；而 Text Disclaimer 设计的价值恰恰是可以与 FUE 兼容。对于受监管行业，这比单纯依赖固定 Description 更适合做强制合规文字。

Google 官方原文：Text Disclaimer ｜ AI Max / FUE
3）实操训练

今天做一次 Mexico Search「Disclaimer × FUE × LP」合规体检

  1. 建范围：导出所有 Mexico Personal Loan Search Campaign，标记 AI Max、Text Customization、FUE、当前 RSA、当前 Final URL。
  2. 加 Disclaimer：对需要广告层强制披露的 Campaign 使用法务/合规批准过的 90 字符以内文案；不要临时由投手自行编写法律口径。Google 要求 RSA 先存在，再添加 Text Disclaimer。
  3. 查审核状态：记录 Disclaimer Asset 的 Approved / Disapproved / Pending。若 Disapproved，不要误以为 Campaign 会自动停止；Google 明确说明 RSA 仍可能继续投放。
  4. 查 FUE URL：导出 Landing Pages Report / Selected by AI Max，检查所有实际被 FUE 选中的 URL 是否属于允许承接新客贷款广告的页面。
  5. 查 LP 披露：每个 Eligible URL 检查最短/最长期限、最高 APR/当地等效口径、代表性总成本是否完整，并记录 disclosure_version。
  6. 次日复盘：看 Disclaimer 状态、Asset Impressions、CTR/CPC、Apply CVR；业务成熟后继续看 Approve、Disburse、首贷 CAC、FPD/Vintage。

内部第一版可以把 Compliance Asset Coverage Rate < 100% 或 FUE Disclosure Pass Rate < 100% 直接设为“禁止新增预算”的红线。这是内部治理规则，不是 Google 官方阈值。

4）业务分析

为什么更“合规”的广告 CTR 可能下降，但首贷 CAC 反而改善？

下面是一个纯示例，用来说明不要把 Disclaimer 的价值只看成 CTR。

方案 A：Spend 100,000 MXN → 1,000 Click → 200 Apply → 80 Approve → 56 首贷
First-loan CAC = 100,000 ÷ 56 ≈ 1,786 MXN

方案 B：加清晰 Disclaimer 后 CTR 略降 → 900 Click → 190 Apply → 90 Approve → 68 首贷
First-loan CAC = 100,000 ÷ 68 ≈ 1,471 MXN

方案 B 的点击更少，但可能因为广告承诺更透明、低意向/误解用户减少，Approve 和 Disburse 反而更好。是否真的发生这种改善，需要你们自己的 Experiment 和成熟 Cohort 验证。

反过来，如果 Disclaimer 占据描述空间后 CTR/CVR 明显下降，而 Approve/FPD 没改善，也不能因为“合规资产”就忽视经营损失。正确判断顺序是：

Disclaimer Status → CTR/CPC → Apply → Approve → Disburse → First-loan CAC → FPD/Vintage → LTV/ROI
5）产品相关

建立 Disclosure Version Registry + Compliance Asset Contract

建议把“广告文案合规”和“落地页披露”正式做成一套可版本化产品能力，而不是靠投手截图。

产品经理
维护产品期限、费率/费用口径、代表性成本示例、适用用户、页面与 disclosure_version；页面过期时自动失去广告承接资格。
投放
维护 Campaign → Disclaimer Asset → RSA → FUE / Final URL 的映射；任何 AI Max / Budget 扩量先通过合规 Guardrail。
数据
保存 campaign_id、asset_id、final_url、disclosure_version，并输出 Disclaimer Coverage、FUE Disclosure Pass、首贷 CAC。
风控/合规
审核强制文案、产品可投范围和目标市场规则；风险结果继续按 Campaign / Query / URL Cohort 观察。
研发
提供 Disclosure Component、版本追踪、URL Eligibility、404/Redirect 监控和 Kill Switch。

推荐状态机：Draft → Legal Approved → Ads Approved → Active → Superseded / Blocked。这样任何一个贷款参数变化，都能知道哪些 Ads / URL / Disclaimer 需要同步更新。
