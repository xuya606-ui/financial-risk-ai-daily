1）今日最新资讯

Google App Connect 可做 Deep Linking A/B Test：把“Web 还是 App 承接更好”变成可量化实验

发生了什么：Google Ads 当前提供 App Connect 的 Deep Linking A/B Test。它可以在 Search Campaign 中把一部分流量通过有效 Deep Link 导入 App，另一部分继续走移动网页，从而比较 CVR、Conversion Value 与 Deep-link uplift。官方建议选择最近 30 天约有 10,000+ impressions、至少有一个有效 Deep Link、同时具备可出价 Web/App primary conversion 且使用 Smart Bidding 的 Search Campaign。

为什么重要：现金贷常见链路是“Search → Web LP → App/申请”。团队过去很容易靠经验争论“直接进 App 是否更好”，现在可以用同一 Campaign 的实验框架验证。对于已安装 App 的用户，直接进入对应的注册、KYC、申请或提款页面，理论上能减少页面跳转和重复登录摩擦；但最终仍要用首贷 CAC、FPD/Vintage 和 LTV 验证，而不是只看平台 CVR。

怎么做：Google Ads → Experiments → Campaign features and settings → App Connect，选择符合条件的 Search Campaign，设置流量比例与实验周期。Google 官方建议至少运行 14 天再做最终优化判断，并重点查看 Deep-link uplift、Users who have app（UHA）uplift 和 CVR。

2）海外投放知识学习

Deep Link、UHA 与 Conversion Lag：为什么实验不能只看当天 CVR

Deep Link 是把用户从广告直接带到 App 内指定页面的链接能力；UHA（Users Who Have App）是“已安装 App 的用户”子集；Conversion Lag 是从点击到最终转化被记录之间的时间延迟。

Deep-link uplift = 深链路径相对非深链路径的转化提升
首贷真实判断 = CVR uplift → Approve → Disburse → CAC → FPD/Vintage → LTV

现金贷场景：Search 用户点击“申请贷款”广告，如果已安装 App，Deep Link 可以直接进入 Apply 页面；没有安装 App 的用户仍可能落到 Web。因为两类用户基础质量和历史关系不同，整体 uplift 可能被“未安装 App 用户”稀释，因此 Google 特别提供 UHA uplift 作为更准确的深链效果观察维度。

常见误区：① 实验跑 1–3 天就下结论；② 只看 Apply CVR，不看 Approve/Disburse；③ Deep Link 跳到错误业务状态，比如未 KYC 用户被直接送到提款页；④ 使用中间 redirect URL，导致实验不可用或归因异常。

判断方法：至少等一个完整的业务转化周期，再把 Google 的 CVR/UHA uplift 和自有数仓的首贷 CAC、FPD7、D30 Contribution 对齐。

3）实操训练

今天做一版“Search → App”深链实验方案

  1. 筛 Campaign：优先选择最近 30 天约 10,000+ impressions 的 Mexico Search Campaign，并确认 Smart Bidding 已开启。
  2. 检查技术条件：至少有 1 个有效 Deep Link；Web 和 App 各有至少一个可出价 Primary Conversion；避免使用 redirect URL。
  3. 确定实验入口：建议优先测试高意图页面，例如 Register、KYC Start、Apply，而不是一上来跳到过深的审批/提款步骤。
  4. 分流：内部首轮可用 50/50 作为便于解释的测试比例（这是实验设计建议，不是 Google 强制要求），并固定出价、素材和核心落地内容。
  5. 平台指标：CVR、Conversion Value、Deep-link uplift、UHA uplift、Cost。
  6. 业务指标：Apply Rate、Approve Rate、Disburse Rate、首贷 CAC、件均、FPD7、D30 Contribution。
  7. 周期：至少运行 14 天，再结合转化延迟和风险成熟度做结论。

次日复盘：先只检查流量分配、Deep Link 是否命中正确页面、事件是否漏传；不要因为第 1 天 CVR 波动就停实验。

4）业务分析

为什么 Deep Link CVR 明显提升，首贷 CAC 仍可能更差？

因为前端转化提升只是减少摩擦，不代表带来的用户更能授信或更愿意提款。举例：相同 CPC = 20 MXN，Web Apply CVR = 8%、Approve = 35%、Approve→Disburse = 70%，理论首贷 CAC 约 1,020 MXN；App Deep Link Apply CVR 提升到 12%，但如果 Approve 降到 25%、Approve→Disburse 降到 60%，理论首贷 CAC 反而约 1,111 MXN。

所以要把 Deep Link 评价拆成两层：第一层是体验 uplift（CVR、登录/表单减少）；第二层是经营 uplift（首贷 CAC、风险调整 LTV、Payback）。只有两层都变好，才值得把更多 Search 流量导入 App。

进一步排查：如果 App CVR 高但 Approve 低，可能是 App 承接把更多边缘用户推进了申请；如果 Disburse 低，可能是额度/定价展示、银行卡绑定或提款确认摩擦；如果 FPD 变差，则要看是否不同的 UHA 客群结构导致风险画像变化。

5）产品相关

建立“用户状态 × Deep Link 目标页”路由表

未安装 App
落到合规 Web LP / 应用商店，不强制失效跳转。
已安装、未登录
Deep Link 保存目标页参数；登录后恢复到原目标步骤。
已登录、未 KYC
跳 KYC Start，不应直接进入 Apply/Disburse。
KYC 完成、未申请
跳 Apply 页面，带回来源 Campaign/Keyword。
审批通过、未提款
仅对合规召回链路跳到提款确认，仍需保留金额/费用/期限披露。

产品经理：定义路由状态机和 fallback；投放：维护 Campaign→Deep Link 映射；数据：打通 gclid/click ID → user_id → application_id → loan_id；风控：验证不同路径客群质量；研发：处理 Universal/App Links、登录态恢复、event_id 去重、redirect 监控和异常 fallback。

产品原则：Deep Link 的目标不是“跳得越深越好”，而是“把用户送到当前最合理、最合规、最少摩擦的下一步”。
