现金贷 APP 海外投放学习日报｜2026-09-10

今日主题：TikTok Landing Page View（LPV）× Web-to-App 页面到达质量。今天官方核查未发现过去24小时改变 Mexico 现金贷核心准入边界的新规，因此重点转向一个当前可直接落地、但经常被忽视的流量质量问题：点击之后，页面到底有没有真正打开。

1）今日最新资讯

今日平台核查：TikTok LPV 可直接优化“点击后成功加载页面”，适合排查 Web-to-App 点击浪费

TikTok 当前官方文档将 Landing Page View（LPV）定义为 Traffic Objective 下的优化目标：只有用户点击广告，并且第三方 Landing Page 或 TikTok Instant Page 成功加载，才计为一次 LPV。LPV 由 TikTok 根据页面加载计算，与广告主通过 Pixel / Events API 回传的 View Content、Default Page View 不是同一个事件。

TikTok 官方原文：Landing Page View

为什么重要：现金贷 Web-to-App 经常出现“CTR/CPC 看起来很好，但注册和申请很差”。其中一部分并非用户没意愿，而是页面过重、重定向、WebView兼容、弱网、第三方脚本或 Deep Link/Fallback 导致点击没有转成真实页面到达。LPV 能把这个问题单独量出来。

对投放的影响：当前 LPV 面向全球 Auction Ads，可用于 iOS/Android、第三方网页与 TikTok Instant Page，并支持 TikTok/TikTok Pangle Placement、Lowest Cost/Cost Cap。Traffic Campaign 默认仍是 Click，需要广告主主动选择 LPV；TikTok 还明确说明 LPV 与原生 Split Test 目前不兼容。

TikTok 官方原文：LPV availability / setup / reporting

TikTok 当前 Smart+ Traffic 文档也建议：如果主要目标是 Click 或 LPV，可用 Smart+ Traffic；如果已接入 Pixel / Events API，且真正希望推动更深的网站事件，则应考虑 Smart+ Web 去优化 Conversion，而不是长期停留在浅层流量目标。

TikTok 官方原文：About Smart+ Traffic Campaigns

建议动作：今天把 Mexico 漏斗拆成 Impression → Click → LPV → Register/KYC → Apply → Approve → Disburse。Click→LPV 差，先修页面/跳转；LPV→Apply 差，再修产品承接；Apply正常但Approve/FPD差，再看流量质量与风控匹配。

【墨西哥重点】LPV 是转化工具，不会改变金融广告准入边界

TikTok 当前对 Mexico 所在市场组的金融服务广告仍要求当地/区域许可、必要 disclosure/disclaimer，并限制为 18+；允许示例包含 consumer finance、P2P、BNPL 等贷款，明确禁止示例仍包括 APR≥50% High APR Loan、Payday Loan、还款周期≤90天的 Short-term Loan。

TikTok 官方原文：Financial Services Policy — Mexico

Google Personal Loans 当前仍只允许需要 61 天或以上才能全部偿还的个人贷款，并要求 Landing Page/App 显著披露最短与最长期限、最高 APR 或当地一致的等效年化口径，以及包含全部适用费用的代表性总成本。

Google 官方原文：Financial products and services: Personal loans

Mexico 产品原则：不要为了提高 LPV 而把页面“减重”到删除必要贷款披露。应同时做到加载更快、产品事实更清楚、披露仍完整、CTA 更明确。

2）海外投放知识学习

Click、LPV、Page View、Session、Conversion：五个概念不要混

Click只证明用户点了广告；LPV进一步要求页面成功加载；Default Page View/View Content是广告主通过 Pixel/Events API 分享的网站事件；Session 由 GA/分析系统按自己的会话规则计算；Conversion 则是 Register、Apply、Disburse 等业务目标。TikTok明确提示 LPV、Google Analytics Page View 与 Session 因定义和触发逻辑不同，出现差异是正常的。

TikTok 官方原文：LPV definitions and reporting differences
Landing Page Load Rate = LPV ÷ Ad Clicks
Click-to-LPV Loss Rate = 1 − LPV ÷ Ad Clicks
Cost per LPV = Spend ÷ LPV
LPV→Apply Rate = Backend Valid Apply ÷ Matched LPV
LPV→First-loan Rate = First Disbursed Borrowers ÷ Matched LPV

适用场景：Web-to-App、H5贷款预审页、TikTok Instant Page、Search/Social Landing Page。常见误区：Click=有效访问；LPV高=首贷质量高；TikTok LPV与GA不一致就判断埋点坏；为了提速删除APR/期限/费用披露；深层事件量已足够仍长期只优化LPV。

3）实操训练

  1. 拉最近14天：Campaign / Ad Group / Placement / Creative / OS / Landing Page Version 的 Spend、Clicks、LPV；Backend同步拉 Register、KYC、Valid Apply、Approve、Disburse。
  2. 新增 Cost/LPV、Landing Page Load Rate、Click→LPV Loss Rate、LPV→Apply Rate、LPV→First-loan Rate。
  3. 按 Android/iOS、4G/5G/Wi-Fi、浏览器/内嵌WebView、Landing Page Version、Placement/Publisher拆分。
  4. 检查首屏关键资源、重定向次数、第三方SDK、DNS/TLS、JS阻塞、图片/视频、Deep Link fallback、404/Timeout、表单首屏与披露模块。
  5. 由于当前 LPV 与 TikTok 原生 Split Test 不兼容，可先用 matched-cell 方法：两个尽量可比的 Ad Group，一组优化 Click、一组优化 LPV，只改变核心目标，明确这不是随机实验。
  6. D1先看 Delivery、LPV、Load Rate、Cost/LPV；Apply/Approve/首贷继续等待数据成熟，FPD/Vintage不做过早结论。

4）业务分析

CPC 更便宜，首贷 CAC 仍可能更贵

A：Spend 100,000 MXN → 5,000 Clicks → CPC 20 → 3,000 LPV → Load Rate 60% → 600 Apply → 147首贷 → First-loan CAC≈680

B：Spend 100,000 MXN → 3,750 Clicks → CPC≈26.7 → 3,375 LPV → Load Rate 90% → 743 Apply → 182首贷 → First-loan CAC≈549

A 的 CPC 更低，但点击后损失更多；B 的 CPC 更高，却因为页面真实到达和后续申请更好，首贷 CAC 更低。这个示例不是证明 LPV 一定优于 Click，而是说明媒体浅层指标必须沿业务漏斗验证。如果 LPV→Apply高但Approve突然下降，应查流量意图、产品条件、预筛与风控；如果首贷CAC好但FPD/Vintage恶化，仍不能扩量。

5）产品相关

Landing Page Performance Contract：把加载、披露、埋点和经营结果做成跨团队契约

产品经理
维护 Landing Page Version、信息结构、期限/费用/资格说明、CTA、Web-to-App 跳转、disclosure_version。
投放
按 Campaign/Ad Group/Creative/Placement 看 Click→LPV 和 Cost/LPV；根据深层事件量选择 Traffic/LPV 还是 Web Conversion。
数据
打通 click_id/campaign_id/adgroup_id/lp_version/session_id/user_id/application_id/loan_id，统一LPV、GA Session、Backend Visit口径。
风控
按 Landing Page/Creative Cohort 看 Approve、Fraud、FPD、Vintage，避免页面优化只放大低质量用户。
研发
负责首屏性能、Redirect、Deep Link/Fallback、WebView、Pixel/Events API、event_id、错误码和页面版本监控。

建议状态：Draft → Compliance Approved → Performance QA → Active → Degraded → Rollback / Superseded。页面发布后若 Load Rate、LPV→Apply 或 Redirect/Timeout 异常，应按 lp_version 快速定位并回滚。
