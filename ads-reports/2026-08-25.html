1）今日最新资讯

Google 明确：8·17 目标出价变化是“全球渐进式 rollout”，不同账户今天可能仍看不到同样行为

发生了什么：Google 当前 FAQ 明确写明：自 2026-08-17 起，针对 Limited by budget + Target CPA / Target ROAS 的新出价行为开始全球 rollout，但这是渐进式部署，所以截至今天 8 月 25 日，不同账户、不同 Campaign 可能还没有同时出现完全一致的新表现；Bid Target Adjustment Tool 如果暂时不可见，也会随着部署继续自动开放。

为什么重要：这解释了为什么同一个团队里，某些 Search/PMax/Demand Gen Campaign 已经明显开始向 tCPA/tROAS 目标靠拢，而另一些仍接近历史表现。现在不应把“还没变化”误判成“此次机制对我账户无效”。

对现金贷投放的影响：如果过去某个 Campaign 的实际申请 CPA 长期优于设置的 tCPA，随着 rollout 覆盖扩大，实际 CPA 可能逐步靠近目标值。现金贷要同步看 Apply CPA → Approve Rate → Disburse Rate → 首贷 CAC → FPD/Vintage，而不是只看平台是否贴近 tCPA。

建议动作：今天给所有受影响 Campaign 增加一个“rollout 观察标签”，记录过去 14 天 actual CPA/ROAS、target、预算状态、首贷 CAC 和风险表现；目标/预算调整后继续遵守 Google 建议，至少观察 1–2 个 conversion cycles。

第二个重点：App 获客正在从“买转化”升级到“买价值”

Google App Campaign 当前支持安装、应用内行为，以及 Maximize conversion value / Target ROAS 等价值型出价。Google 官方说明，App Campaign 的 tROAS 需要 Firebase，并要求用于优化的 first-party in-app event 传递动态 value。TikTok 的 App VBO 也提供 Highest Value 与 Target ROAS 路径。

为什么现金贷值得关注：传统 tCPA 只会问“能不能便宜买到 Apply/Disburse”；价值型优化则可以进一步问“哪些转化对业务更值钱”。但贷款业务最大的风险是把放款金额当 value：金额越大的高风险贷款可能被算法误认为“越优质”。

官方原文：Google：About bidding in App campaigns ｜ Google：Maximize conversions for App campaigns ｜ TikTok：App Value-Based Optimization

【墨西哥重点】今天没有发现过去 24 小时改变核心贷款广告边界的新规，但“价值优化”受 Credit Policy 约束

TikTok 对 Mexico 所在市场组当前仍要求金融服务广告具备当地/区域许可、符合披露要求并限制 18+；禁止 APR ≥50% 的高 APR Loan、Payday Loan 以及还款周期 ≤90 天的短期贷款。

Google 的 Conversion Value Rules 官方页面还特别提示：对于 Housing、Employment 或 Credit 相关广告，部分 value rule 条件可能不可用。所以现金贷不能简单按某些受众属性去人为提高/降低广告价值，更不能把敏感信用属性变成投放定向信号。

建议：墨西哥价值优化优先从“事件层级价值”与“允许回传的商业价值”入手，例如 Apply、Approve、Disburse 的相对价值；涉及信用评分、逾期、收入、审批额度等敏感字段时，默认留在内部数仓，是否外发必须经过合规与数据政策审查。

2）海外投放知识学习

VBO：Conversion-based Bidding 和 Value-based Bidding 到底差在哪？

Conversion-based Bidding 的核心是“多拿转化”：例如 Maximize Conversions 或 tCPA。只要用户完成 Apply，系统通常会把这次 Apply 当作同等的一次转化。

Value-based Bidding 的核心是“多拿价值”：例如 Maximize Conversion Value、tROAS、TikTok VBO。不同转化可以有不同 value，算法会尝试把预算给到更有价值的转化。

Conversion-based：最大化 Conversion Count / 控制 CPA
Value-based：最大化 Conversion Value / 控制 ROAS

现金贷关键：价值不能直接等于放款金额。更合理的内部经营口径是：

Risk-adjusted Value ≈ 预期收入 − 预期信用损失 − 资金成本 − 服务/催收等变动成本

但这条公式首先是内部经营定义。真正发送到广告平台的 value 应只包含平台允许、经过隐私/合规审查的数据，并避免把敏感信用属性直接作为广告定向或价值规则条件。

常见误区：① 把 loan amount 当 conversion value；② 事件量不足就直接切 tROAS；③ Value 定义每周大改，导致算法重新学习；④ 平台 ROAS 好看，但风险调整 LTV 反而变差。

3）实操训练

今天做一张“Value Mapping 表”，先不要急着上线 tROAS

  1. 列出事件：Register、KYC Complete、Apply、Approve、Disburse、Good First Payment。
  2. 定义内部业务价值：分别计算每个事件向后最终转成优质首贷/利润的概率和期望贡献，不要只看事件本身数量。
  3. 做成熟度校准：Approve/Disburse 的 value 用至少 30–60 天成熟 Cohort 回看；最近未成熟数据不直接用于重新定价。
  4. 建立双版本：内部 Risk-adjusted Value 用于经营判断；平台可回传 Value 只保留政策允许、隐私合规的字段。
  5. 小流量实验：先选 1 个稳定 Campaign 做 Value-based Challenger，对照原 tCPA Champion，保持素材、地区、产品版本基本一致。

观察指标：Spend、Conversion Count、Conversion Value、平台 ROAS、Approve Rate、Disburse Rate、首贷 CAC、FPD7、D30/D60 Contribution。

判断逻辑：只有“平台 value/ROAS 改善 + 风险调整首贷价值改善”同时成立，才扩大预算。

第二天怎么复盘：先检查事件/value 是否漏传、异常放大或默认值污染；不要在第一天只因 ROAS 波动就判实验失败。

4）业务分析

为什么 CAC 更高的 Campaign，反而可能更值得投？

假设两个墨西哥 Campaign 都花费 100,000 MXN：

Campaign A
500 笔首贷
首贷 CAC = 200 MXN
每笔平均风险调整价值 = 260 MXN
总价值 = 130,000 MXN
Value/Cost = 1.30
Campaign B
350 笔首贷
首贷 CAC ≈ 286 MXN
每笔平均风险调整价值 = 430 MXN
总价值 = 150,500 MXN
Value/Cost ≈ 1.51

如果只看 CAC，A 更漂亮；但从风险调整价值看，B 反而创造更多利润空间。这个例子说明：当现金贷已经能稳定追踪 FPD/Vintage/LTV 后，预算决策应该从“最低 CAC”逐步升级成“最高 Risk-adjusted Value / Cost”。

但要注意：这不意味着忽略现金流。B 的 Payback 可能更长，因此还要同时看资金成本和回收周期。

5）产品相关

建立 Value Event Contract：把投放价值定义变成产品能力

产品经理
定义 Register/Apply/Approve/Disburse/Good Payment 的事件口径、value 版本和产品版本映射。
投放
明确哪些 Campaign 用 tCPA，哪些进入 VBO/tROAS Challenger；不自行修改 value 口径。
数据
计算成熟 Cohort 的 expected contribution，维护 value_version，并对平台 Value 与内部 Risk-adjusted Value 做对账。
风控
提供内部风险调整结果，但敏感信用属性默认留在内部，不直接作为广告平台定向/规则条件。
研发
保证 event_id、event_time、currency、value、value_version、重试/去重和异常监控完整。

产品设计建议：在内部投放后台新增“Value Mapping”页面，展示事件 → 当前 value → 生效日期 → 样本期 → 成熟度 → 负责人 → 平台同步状态；所有 value 修改必须留版本，避免口径静默变化。
