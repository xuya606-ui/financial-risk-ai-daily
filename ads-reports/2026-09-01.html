现金贷 APP 海外投放学习日报｜2026-09-01

今日重点：Google AI Max 自动升级进入 9 月执行窗口；重点不是“AI Max 开没开”，而是升级后的 Keyword Prioritization / Query Routing 是否改变了品牌词、高意图词与现金贷用户质量。

1）今日最新资讯

Google AI Max 自动升级进入 9 月窗口：Broad Match 的“类 Exact 优先级”会消失

发生了什么：Google 已明确，从 2026 年 9 月开始，仍在使用 Campaign-level Broad Match Setting 或 Automatically Created Assets / Text Customization 的符合条件 Search Campaign，会开始自动升级到 AI Max for Search；Google 预计符合条件的升级在 9 月底前完成。DSA 的自动升级已被延后到 2027 年 2 月，因此今天不要把 DSA 和这次 9 月迁移混为一谈。

配置映射：ACA / Text Customization 用户升级后，Google 默认开启 Search Term Matching + Text Customization；Campaign-level Broad Match Setting 用户升级后，默认开启 Search Term Matching。这不等于本次 ACA/Broad 自动升级会自动打开 Final URL Expansion。DSA 在 2027 年 2 月迁移时才是三项 AI Max 能力一起映射并保留旧 URL controls。

Google 官方原文：AI Max automatic upgrade / feature mapping ｜ Campaign-level Broad Match Setting

今天最需要关注的隐藏变化：Keyword Prioritization

旧的 Campaign-level Broad Match Setting 有一个特殊规则：其中的 Broad Keyword 在“与用户 Search Term 完全相同”时，会在账户内被按同时具有 Exact + Broad 的优先级参与路由。Google 当前帮助文档明确说明：迁移到 AI Max 后，Broad Keyword 不再被当成 Exact Match Keyword 参与优先级判断。

标准 AI Max / Search 的优先级逻辑大致是：① 与 Search Term 完全相同的 Exact Match Keyword；② 与 Search Term 完全相同的 Phrase/Broad Keyword 或 PMax Search Theme；③ AI relevance；④ 同优先级候选再看 Ad Rank。也就是说，如果你过去依靠 Campaign-level Broad Setting 保持品牌词、核心产品词的流量路由，9 月迁移后账户内的 Campaign / Ad Group 流量分配可能变化。

Google 官方原文：Keyword prioritization & AI Max behavior

建议动作：今天先做迁移前 Snapshot，不要等成本变化后才追原因。对必须保持固定路由的品牌词、高意图产品词和合规敏感词，建立 Exact Match 覆盖；Google 的建议是新增 Exact 副本来维持优先级，而不是把现有 Broad 直接改成 Exact，因为直接转换可能损失该 Keyword 的历史统计连续性。

2）海外投放知识学习

Keyword Prioritization：Match Type、Relevance、Ad Rank 到底谁决定“这次搜索由哪个 Campaign 吃到”？

Keyword Prioritization不是简单的“Exact 永远赢、Broad 永远输”。Google 会先判断候选 Keyword/Search Theme 的优先级，再在同级候选中结合 Ad Rank。

优先级 1：Identical Exact Match Keyword
优先级 2：Identical Phrase / Broad Keyword 或 PMax Search Theme
优先级 3：AI relevance 选最相关 Ad Group / Keyword
优先级 4：同优先级候选再看 Ad Rank

历史特殊规则：Campaign-level Broad Match Setting 曾让其中的 Broad Keyword 在 identical query 场景里被当作“Exact + Broad”优先。迁移 AI Max 后这一特殊待遇取消，回到标准优先级。

现金贷例子：你有 `Mexico_Brand_Broad` 和 `Mexico_Brand_Exact` 两个 Campaign。过去 Broad Setting 可能让 Broad Campaign 在品牌完全一致搜索上继续获得大量流量；迁移后 Exact Match Brand Keyword 的优先级会更明确。于是 Brand / Non-brand 的 Spend、CPA、Approve Rate 可能突然变化，即使市场需求本身没变。

常见误区：① Campaign CPA 变了就认为算法变差；② 只看 Keyword Match Type，不看 Search Term 实际路由；③ 为了“恢复原状”把所有 Broad 直接改 Exact；④ 忽略 PMax Search Themes 也参与账户级优先级。

判断方法：先看账户级总 Spend、总首贷 CAC 是否变化，再拆 `Search Term → Campaign → Ad Group → Keyword → Final URL`。如果账户总结果稳定但 Campaign 指标大幅互换，优先判断是 Query Routing 变化，而不是业务真实恶化。

3）实操训练

今天执行：AI Max Migration Query Routing Audit

  1. 建立迁移清单：导出所有 Mexico Search Campaign，标记 `legacy_broad_setting / ACA_text_customization / ai_max_status / migration_notice`。
  2. 保存基线：固定 8 月 18–31 日 14 天基线，至少保留 Search Term、Campaign、Ad Group、Keyword、Search Terms Match Type、Spend、Clicks、Apply、Approve、Disburse、First-loan CAC。
  3. 定义关键 Query：分为 Brand、Core Product、High Intent、Compliance Sensitive 四类；每一类维护 intended_campaign 和 intended_match_type。
  4. 补 Exact Coverage：对必须保持固定优先级的关键 Query，按 Google 建议新增 Exact Match 副本；不要为了迁移一次性把所有 Broad 改成 Exact。
  5. 检查 3 个新指标：AI Max Migration Coverage、Intended Query Routing Rate、Exact Query Capture Rate。
  6. 次日复盘：先看 Spend/Clicks 是否从一个 Campaign 搬到另一个 Campaign，以及 Search Term Match Mix 是否变化；如果关键 Query 的 Intended Routing 比 14 天基线下降 >5pct，先排查优先级/Ad Rank/Exact Coverage，而不是直接改预算。5pct 是内部预警起点，不是 Google 官方阈值。

不要做：迁移第一天同时修改 Bid、Budget、Negative Keyword、Landing Page、Optimization Goal。否则无法区分“迁移路由变化”和“人为改动”。

4）业务分析

Campaign CAC 突然恶化，不一定是渠道变差：先排除“流量被重新路由”

假设迁移前 Brand Broad 和 Brand Exact 两个 Campaign 合计花费 100,000 MXN、带来 500 个首贷，账户级 CAC = 200 MXN。迁移前 Broad Campaign 承接 60,000 MXN / 300 首贷，Exact 承接 40,000 / 200 首贷，两者 CAC 都是 200。

AI Max 迁移后，由于 Exact 优先级重新明确，假设流量重分配为：Broad 30,000 / 120 首贷，CAC = 250；Exact 70,000 / 380 首贷，CAC ≈ 184。此时账户仍然是 100,000 / 500 = 200 MXN，真实经营结果没有变，但 Campaign A 看起来“恶化 25%”，Campaign B 看起来“改善 8%”。

Account CAC = Total Spend ÷ Total First Loans
Campaign CAC Change = Routing Mix Effect + Within-Campaign Performance Effect

如果团队只看 Campaign 级日报，很容易错误地砍掉 Broad Campaign 或把大量预算追到 Exact Campaign。正确顺序是：先确认 Routing Mix → 再看 Approve/Disburse → 再看 FPD/Vintage → 最后判断是否需要预算动作。

更进一步，如果 Exact/Brand Query 的用户本来就有更高授信率、更低 FPD，那么迁移会同时改变渠道风险 Mix。所以 9 月这轮 Search 迁移最好把 Query Routing 和风险 Cohort 一起看，而不是只做媒体报表。

5）产品相关

建立 Search Governance Contract：把“哪些 Query 应该去哪”产品化

建议新增一份 Search Governance Contract，核心字段：`query_class / normalized_query / intended_campaign / intended_adgroup / intended_match_type / brand_flag / product_type / allowed_final_url / disclosure_version / owner / migration_status`。

产品经理
定义 Brand/Core Product/High Intent 的业务意图，维护每类 Query 对应的产品页、用户状态和 disclosure_version。
投放
维护 Exact Coverage、Brand Inclusions/Exclusions、Negative Keywords、Campaign/Ad Group 结构和 AI Max migration status。
数据
打通 `search_term → campaign_id → adgroup_id → keyword → final_url → user_id → application_id → loan_id`，输出 Query Routing 与业务质量。
风控
按 Query Class 看 Approve、Fraud、FPD/Vintage，识别“高意图但高风险”的搜索需求。
研发
保证 Tracking Template、URL 参数、Deep Link、event_id 与 disclosure_version 可追踪，并对异常 Landing Page 路由告警。

最终目标：AI Max 可以自动扩展，但公司仍能回答：这条搜索为什么进入这个 Campaign、看到了什么表达、落到了哪个页面、最终带来了什么质量的贷款用户。
