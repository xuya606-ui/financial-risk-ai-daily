1）今日最新资讯

距离 9 月只剩几天：Google Search 的 AI Max 自动升级进入最后准备窗口

今日判断：本轮对 Google、TikTok、Meta 官方渠道的检索，没有发现过去 24 小时内会立即改变墨西哥现金贷核心广告准入边界的新政策。今天最值得执行的动作不是追一条新公告，而是处理一个已经非常接近生效窗口的 Google Search 结构变化。

发生了什么：Google 官方帮助页明确写明：从 2026 年 9 月开始，使用 campaign-level broad match setting 的 Search Campaign，以及使用 Text customization（原 Automatically Created Assets / ACA） 的 Search Campaign，将自动升级进入 AI Max for Search 的管理体系。需要特别区分：Dynamic Search Ads（DSA）的自动升级已延后到 2027 年 2 月，并不是所有 DSA 都会在今年 9 月一起迁移。

Google 官方原文：Broad match campaign setting：September 2026 auto-upgrade ｜ Text customization：September 2026 auto-upgrade ｜ DSA：February 2027 auto-upgrade

为什么重要：AI Max 不只是一个名称变化。它把 Search Term Matching、Text Customization 和 Final URL Expansion（FUE）放到同一套 Search 自动化体系里。FUE 开启后，Google 可以根据搜索意图把用户送到同域名内更相关的 URL；Text Customization 会结合 Landing Page、已有广告和关键词生成新的标题/描述。

现金贷的特殊风险：如果网站里存在产品介绍页、优惠活动页、FAQ、登录页、还款页、催收/帮助页等多个 URL，FUE 可能把广告流量导向与你原先 Final URL 不同的页面。Google 同时说明：当 FUE 生效并选择了不同 URL 时，RSA 的 pinned assets 可能不会按原方式使用；Tracking Template 配置不兼容时，也可能出现扩展后的落地页 404。对金融广告来说，这意味着文案、落地页、贷款期限/APR/总成本披露和归因参数必须一起治理。

Google 官方原文：How AI Max for Search works ｜ Final URL expansion in Search ｜ Set up AI Max

建议动作：今天不要等到 9 月自动升级后再排查。先把所有启用了 campaign-level broad match 或 ACA/Text Customization 的墨西哥 Search Campaign 拉出来，建立 URL Allow/Exclude 清单、贷款披露检查和 Tracking Template 验证；如果准备主动使用 AI Max，优先用官方 AI Max Experiment 做受控测试，而不是直接全量打开。

Google 官方原文：AI Max Experiments ｜ AI Max Reporting

【墨西哥重点】AI Max 扩流量之前，先锁死“可投产品 + 可投页面”

TikTok 当前墨西哥所在市场组仍要求金融服务广告具备当地/区域许可、满足必要披露并限制 18+；同时禁止 APR ≥50% 的高 APR Loan、Payday Loan，以及还款周期 ≤90 天的短期贷款。Google Personal Loans 当前仍只允许需要 61 天或以上才能全额还清的个人贷款，并要求 Landing Page/App 显著披露最短/最长期限、最高 APR 与代表性总成本。

官方原文：TikTok Financial Services Policy ｜ Google Personal Loans

产品结论：Google 的 FUE 能“选更相关页面”，但不能替你判断那个页面是否满足现金贷广告披露。墨西哥站点应明确标记哪些 URL 可以承接贷款广告，哪些 URL 必须永久排除。

2）海外投放知识学习

AI Max for Search 到底是什么？不是 PMax，也不等于“全部交给 AI”

AI Max for Search仍然属于 Search Campaign。它的核心可以拆成三层：

Search Term Matching：扩大/优化“哪些搜索词可以触发你”
Text Customization：扩大/优化“广告具体怎么说”
Final URL Expansion：扩大/优化“用户最后被送到哪个页面”

Search Term Matching会结合 broad match、素材和 Landing Page 信号扩大可匹配的搜索机会；Text Customization会根据域名、Landing Page、现有广告和关键词生成更贴近具体搜索意图的标题和描述；FUE则在同域名中挑选更可能匹配意图和转化的页面。

现金贷例子：你原来的 Keyword 是 `préstamo personal`，Final URL 固定到 `/prestamo-personal`。开启 AI Max 后，系统可能找到新的相关 Query、生成更贴合 Query 的文案，并在符合设置时把用户送到另一个更相关 URL。对普通电商，这可能只是“更合适的商品页”；对现金贷，则要确认另一个 URL 是否展示了正确贷款期限、APR、费用、主体和申请条件。

常见误区：① 把 AI Max 当成 PMax；② 认为开启 AI Max 后 Keyword/Ad Group 管理全部消失；③ 认为 FUE 只会换 URL、不影响创意；④ 认为 pinned RSA 一定会原样展示；⑤ 认为页面只要同域名就都可以承接贷款广告。

判断方法：对现金贷，评价 AI Max 必须同时看三个对象：Search Term、Generated/Customized Asset、Landing Page URL。任何一个扩张，都要继续穿透到 Apply、Approve、Disburse、FPD 和 LTV。

3）实操训练

48 小时 AI Max 合规体检：先控制 URL 和文案，再谈扩量

  1. 筛 Campaign：导出墨西哥 Search Campaign，标记 campaign-level broad match、Text Customization/ACA、当前 Final URL、是否已启用 AI Max。
  2. 建 Landing Page Registry：列出同域名所有可能被广告命中的 URL，至少记录 product、term、APR/费用口径、主体、语言、页面状态、是否允许 FUE。
  3. 建 URL Exclusion：优先审查登录页、还款页、催收/帮助页、隐私页、过期活动页、仅老客页、无完整贷款披露页。确认不应该承接新客广告的页面，直接加入 URL Exclusions。
  4. 检查文案生成：审查 Landing Page 与已有广告中是否存在容易被 AI 组合成误导性承诺的表达。若账户支持 Text Guidelines，用 restricted terms / messaging restrictions 控制生成范围。
  5. 验证 Tracking：检查 Tracking Template、UTM、click_id、Deep Link/redirect。Google 明确提醒 AI Max 动态 URL 与不兼容模板组合时可能造成 404。
  6. 先 Experiment：使用 AI Max Experiment 做 Control vs Treatment，保持 Budget、Bid、产品版本基本一致；Treatment 再决定是否同时开 Search Term Matching、Text Customization、FUE。

次日先看：Search Term、Final URL 分布、404/跳转异常、CTR/CPC、Apply CVR；成熟后再看 Approve、Disburse、首贷 CAC、FPD7 和 Risk-adjusted LTV。

4）业务分析

为什么 AI Max 把首贷 CAC 降低了，ROI 仍可能变差？

假设两个方案都花费 100,000 MXN。

指标原 SearchAI Max Treatment
首贷数400500
首贷 CAC250 MXN200 MXN
FPD718%27%
每笔平均风险调整价值360 MXN240 MXN
风险调整总价值144,000 MXN120,000 MXN
Risk-adjusted Value / Cost1.441.20

AI Max 看起来把首贷 CAC 从 250 降到 200，但如果扩出来的 Query/页面带来更弱的用户质量，FPD 上升、风险调整贡献下降，最终经营结果反而变差。

所以 AI Max 的正确业务链不是：

More Search Terms → More Conversions → Lower CPA = 成功

而应该是：

Expanded Search Terms / URLs → Apply → Approve → Disburse → Mature CAC → FPD/Vintage → Risk-adjusted LTV → ROI

关键点：自动化扩量真正要追求的是“新增的高质量可盈利用户”，不是“新增的便宜转化”。

5）产品相关

建立 Landing Page Eligibility Registry：把“哪些页面允许广告落地”产品化

建议新增一个内部 Landing Page Eligibility Registry，每个 URL 至少维护：

url / country / product / new_or_repeat_user / min_term / max_term / max_apr_or_local_rate / representative_cost_example / entity / disclosure_version / page_owner / ad_eligible / fue_allowed / last_reviewed
产品经理
定义页面状态、用户场景、贷款披露和是否允许承接新客广告；过期页面自动下线 ad_eligible。
投放
维护 AI Max URL Inclusions / Exclusions、Search Term 和 Ad Group；不允许使用未经 Registry 审核的 Landing Page。
数据
把 search_term / adgroup_id / final_url / creative_id 串到 user_id → application_id → loan_id，输出 URL 级 CAC、FPD、LTV。
风控
比较不同 Query/URL 带来的 Approve、Fraud、FPD/Vintage，识别“低 CPA 但高风险”的自动扩流量。
研发
保证 Disclosure 组件版本化、Tracking Template 兼容、404 监控、redirect/Deep Link 正常；Registry 变更可即时同步 FUE 控制。

可落地页面指标：Landing Page Apply CVR、Landing Page First-loan CAC、Landing Page Risk-adjusted Value / Cost。
