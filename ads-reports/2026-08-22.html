为什么重要：投放团队以后可以更快做 Campaign 诊断、素材复盘和日报整理，但对现金贷而言，平台 AI 能看到的主要仍是媒体侧信号；它并不会天然理解你的授信率、放款率、FPD、Vintage、LTV、资金成本和合规边界。若直接按照“最低 CPA”建议扩量，仍可能买到更差的风险用户。

对投放的影响：建议把 Meta AI 定位成“媒体运营助手”，而不是“现金贷经营决策器”。可用于解释 CPM/CTR/CPC/CPA 变化、找异常 Campaign、整理素材与报表；最终预算迁移必须回到首贷 CAC + FPD/Vintage + LTV/ROI。

建议动作：如果账户已经开放该能力，只连接经过公司批准的业务资产；Google Workspace 中不要放可被模型直接读取的借款人明细、银行账户、收入、信用评分、审批结果、逾期/催收标签等敏感金融数据。所有 AI 建议先经过后端经营数据复核。

2）海外投放知识学习

Pixel + Events API / Conversions API + Event Deduplication：服务器回传到底解决什么？

Pixel 是浏览器/网页侧事件采集；Events API / Conversions API 是服务器直接把营销事件发送给广告平台。两者结合的价值不是“多报一遍”，而是提高事件覆盖、减少浏览器拦截/网络丢失带来的漏数，并让平台拥有更稳定的优化信号。

用户行为 → Browser Pixel / SDK
同一行为 → Server Events API / CAPI
两条链路使用同一 event_id → 平台 Deduplication → 只计 1 次有效事件

Event Deduplication（事件去重）就是避免 Pixel 和 Server 同时回传同一个 Apply 后，被平台算成两次转化。TikTok 明确要求重叠事件使用同一个 event_id；同名同 ID 的重复事件会被合并/去重。TikTok 也推荐 Pixel + Events API 联合部署。

EMQ / Event Match Quality是“平台能否把你的事件有效匹配到广告触达”的诊断信号。它是数据连接健康指标，不是业务质量指标：EMQ 很高，也不代表用户授信率或还款质量好。

Standard Event 与 Custom Event：TikTok 的 Standard Event 有平台预定义名称，例如 CompleteRegistration、SubmitApplication。Custom Event 适合补充业务观察，但 TikTok 当前明确说明 Custom Events 不能直接用于 Campaign 优化，因此现金贷不要随意用“Approve/FPD7”等自定义事件替代平台支持的优化事件，更不要在事件名或参数里泄露敏感信用信息。

3）实操训练

今天做一张“营销事件白名单 + 数据防火墙”

  1. 列事件：按 Visit/ViewContent → Register → KYC Start/Complete → SubmitApplication → 后续业务状态列出所有事件，并标记哪些要发给 Meta/TikTok/Google，哪些只留内部。
  2. 列参数：为每个外发事件建立参数白名单。建议允许 event_id、event_time、source、campaign/ad/creative id、app/web version、粗粒度页面/产品版本等；涉及借款人级金融/信用内容必须单独审核。
  3. 检查双链路：如果 Browser Pixel + Server API 都发同一事件，确认 event_id 一致、时区一致、事件名一致。
  4. 做对账：每天比较“内部 eligible event 数”与“平台收到的 unique event 数”，形成 Event Coverage Rate；同时抽样检查重复事件是否正确合并。
  5. 建立 Kill Switch：一旦发现敏感字段误传、event_id 冲突或转化暴涨异常，研发能立即关闭某一事件/参数，而不是等待下一次 App 发版。

次日复盘：先看事件覆盖率、平台 Diagnostics/EMQ、重复/漏传；再看平台 CPA 是否变化。不要在数据链路刚改完的 24 小时内直接用 FPD 评价。

4）业务分析

为什么 AI 告诉你“Apply CPA 降了 20%”，首贷 CAC 反而可能恶化 17.6%？

假设优化前 Apply CPA = 160 MXN，Approve Rate = 40%，Approve→Disburse = 70%，理论首贷 CAC ≈ 571 MXN。

平台/AI 优化后 Apply CPA 降到 128 MXN（-20%），但新流量的 Approve Rate 降到 28%、Approve→Disburse 降到 68%，理论首贷 CAC 反而升到约 672 MXN，比原来恶化约 17.6%。

首贷 CAC ≈ Apply CPA ÷ (Approve Rate × Approved→Disburse Rate)

如果 FPD7 同时从 20% 升到 26%，则业务价值进一步恶化。结论是：媒体 AI 很擅长优化“你给它的目标”，但你必须确认这个目标与公司真正的利润函数一致。

5）产品相关

把“Marketing Event Contract”做成正式产品能力

产品经理
维护事件字典、触发时点、字段白名单、用户授权/同意状态与版本；把“哪些事件允许外发”写成产品规则。
投放
只向研发申请真正需要用于优化/归因的事件和参数；不能因为想“让算法更聪明”就无限加字段。
数据
维护 event_id、平台事件、内部 user_id/application_id/loan_id 的映射；输出 Event Coverage、延迟和对账差异。
风控
审批、额度、风险等级、FPD/Vintage 等敏感质量数据优先留内部；对外只提供经审批的聚合/脱敏经营标签。
研发
实现 Pixel/SDK + Server API、event_id 去重、重试、延迟监控、字段过滤、Kill Switch 与版本追踪。

目标：让“媒体需要什么数据”和“公司允许什么数据出域”成为两套明确边界，而不是每次临时讨论。
