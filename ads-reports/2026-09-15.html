1）今日最新资讯

TikTok Safe Budget Increase：把“扩预算”拆成基础预算 + 增量预算，而不是一次性把全盘放大

TikTok 当前官方帮助页在 2026 年 9 月更新了 Safe Budget Increase：它面向使用 Maximum Results 的 App Promotion、Lead Generation、Sales 等支持场景，让广告主保留原有 base daily budget，同时额外设置一笔 extra daily budget，并为这部分增量预算设置 Target cost per result。系统只有在看到足够稳定的表现信号时才会使用额外预算；官方同时明确，这个 Target 只是算法指导目标，不是成本上限保证，额外预算也是可用上限，不保证每天花满。

TikTok 官方原文：About Safe Budget Increase ｜ Set up Safe Budget Increase

这对现金贷最重要的变化不是“可以自动加预算”，而是可以把扩量正式拆成 Base Cohort 与 Expansion Cohort。基础预算继续观察稳定 CAC / FPD / Vintage；额外预算必须单独计算 Incremental First-loan CAC、Approve、FPD/Vintage 和 Risk-adjusted LTV，不能只看 Campaign Blended CPA。

TikTok 同时提供限时的 Smart+ Bid Protection 激励。符合条件的日期里，如果 Safe Budget Increase 实际使用了增量预算、成本超过 1.2× bid，并满足转化量等要求且没有发生负面操作，系统可能发放广告金；资格按自然日评估。手动关闭 Safe Budget Increase、降低 base/extra budget、暂停/删除 Campaign、素材全部拒审、余额不足、风险控制问题等，都可能使当天失去补偿资格。广告金不能提取或跨账户转移，TikTok 也保留撤回激励的权利。

TikTok 官方原文：Smart+ Bid Protection for Safe Budget Increase

投放影响：以后扩量不能再用“整体 CPA 还行”批准。应该新增“增量预算使用率、增量首贷 CAC、扩量 Cohort FPD/Vintage、增量 Risk-adjusted ROAS”四层校验。Bid Protection 只能看作平台激励，不能替代业务成本和风险 Guardrail。

2）海外投放知识学习

今天核心：Blended CAC ≠ Incremental CAC——扩量时要看“边际获客成本”

Blended First-loan CAC = 总 Spend ÷ 总 First Disbursed Borrowers。它适合回答“整个 Campaign 目前平均一名首贷多少钱”。

Incremental First-loan CAC = Expansion Spend ÷ Expansion-attributed First Disbursed Borrowers。它回答“新增这一段预算，每新增一个首贷实际上花了多少钱”。

Base：100,000 MXN → 200 首贷 → CAC = 500 MXN
Expansion：40,000 MXN → 60 首贷 → Incremental CAC ≈ 667 MXN
Blended：140,000 MXN → 260 首贷 → CAC ≈ 538 MXN

如果只看 Blended CAC，从 500 变成 538 MXN，似乎只恶化 7.6%；但增量预算本身的 CAC 已经是 667 MXN，比 Base 贵约 33%。所以扩量决策不能只看平均值。

对现金贷还需要继续加一层：Incremental Risk-adjusted CAC。如果 Expansion Cohort 的 Approve Rate 更低、FPD/Vintage 更差，那么真实经济成本会比 667 MXN 更差。

适用场景：自动加预算、节假日扩量、新 Placement/Publisher 拓量、Broad 扩人群、提高 Campaign Budget、提高 bid/target、Smart+ 自动扩量。

常见误区：认为“平台建议加预算=应该加”；认为 Bid Protection 可以抵消业务风险；用 D0/D1 未成熟首贷判断 Expansion Cohort；把广告金抵扣后的媒体账单当作真实获客经济性。

判断方法：先验证 Base 稳定，再单独记录 Expansion Spend、Expansion First-loan、Approve、FPD/Vintage、LTV；只有边际经济性满足 Guardrail 才持续扩量。

3）实操训练

Mexico TikTok Safe Budget Increase 扩量实验

  1. 选择一个过去 14–28 天已经稳定的 Mexico Smart+ App Promotion 或 Lead Generation Campaign，记录 Base Daily Budget、Optimization Event、Maximum Results、当前首贷 CAC 与风险成熟度。
  2. 确认账户是否实际开放 Safe Budget Increase；关闭会冲突的 Scheduled Budget Increase、自动规则或其他自动加预算工具。
  3. 设置 Extra Daily Budget，同时把 Target cost per result 映射到业务容忍度：如果平台优化 Apply，就用 Allowable First-loan CAC × Mature Apply→Disburse Rate 反推，而不是直接把 First-loan CAC 填成平台 tCPA。
  4. 建立 Base / Expansion 分层：至少记录 Spend、Apply、Approve、Disburse、First-loan CAC、FPD7/Vintage、LTV；若平台无法直接区分扩量用户，至少按启用时间、Campaign/Ad Group、小时/日期 Cohort 做近似分层。
  5. 次日先看 Delivery、Extra Budget Utilization、Platform Cost；业务上先看 Apply/Approve/Disburse，FPD/Vintage 等待 Cohort 成熟后再决策是否长期保留。

内部第一版 Guardrail（非 TikTok 官方标准）：Expansion Incremental CAC ≤ Base Mature CAC 的 120%；Expansion Approve Rate 不低于 Base 5pct 以上；成熟 FPD7 不高于 Base 1.5pct 以上；Expansion Risk-adjusted LTV/CAC 不低于 Base 的 90%。

常见错误：同一天同时修改 Creative、Audience、Optimization Event 和 Extra Budget；为了维持 Bid Protection 资格而不敢暂停已经明显恶化的 Campaign；把广告金补偿算成风险质量改善。

4）业务分析

Blended CAC 只恶化 8%，增量 Cohort 的风险调整回报可能已经腰斩

假设 Mexico TikTok Base 每日 Spend 100,000 MXN，产生 200 个首贷，CAC = 500 MXN；FPD7 = 18%，每名首贷的 Risk-adjusted LTV = 900 MXN，因此 Base LTV/CAC = 1.80。

启用 Safe Budget Increase 后，多花 40,000 MXN，只新增 60 个首贷：Incremental CAC ≈ 667 MXN。如果 Expansion Cohort 的 FPD7 上升到 24%，风险调整后 LTV 只有 700 MXN，那么 Expansion LTV/CAC ≈ 1.05。

总体 Blended CAC 仍只有约 538 MXN，看上去“账户整体还健康”；但新增预算的 LTV/CAC 已从 1.80 降到约 1.05，新增预算几乎没有足够利润缓冲。

所以现金贷扩量必须把四个问题分开：能不能花出去 → 能不能带来更多申请 → 能不能带来更多健康首贷 → 这些新增首贷的风险调整价值是否高于新增获客成本。
