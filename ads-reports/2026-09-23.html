1）【今日最新资讯】Smart+ 模块化控制与 Brand Safety 测量继续前移

TikTok 当前 Smart+ 继续强调“模块化自动化”：Targeting、Budget、Placement、Creative 等模块可分别开启或保留人工控制，且 Automatic Placement 在部分账户中已允许手动选择 TikTok、Pangle、Lemon8 或 Global App Bundle。对现金贷投放的直接影响是：今后不能只记录“是否使用 Smart+”，而要记录每个自动化面的配置版本。

官方原文：TikTok Smart+ ｜ Smart+ Targeting

TikTok 近期还扩大了第三方 Brand Safety 与 Viewability Measurement 的适用场景，覆盖 Search、升级后的 Smart+ 等更多投放面，但可用性仍取决于市场、Objective 与合作方。对金融广告而言，这意味着“投了哪里”与“用户质量如何”可以获得更细的外部验证，但不能替代内部 FPD/Vintage 和欺诈识别。

官方原文：TikTok Brand Safety & Suitability

2）【海外投放知识学习】Automation Surface 与 Guardrail

Automation Surface 指一个 Campaign 中可以单独自动化的控制面：Audience、Budget、Placement、Bid/Optimization、Creative、Destination。真正成熟的 Smart+ 管理，不是追求“自动化最多”，而是明确哪些可以探索、哪些必须锁死。

Automation Efficiency = 成本效率提升 + 业务质量稳定 + 合规 Guardrail 通过

现金贷建议：Audience、Budget、Creative 可以做渐进式自动化；贷款期限、费用、APR、主体、Landing Page、Disclosure、年龄和地区边界必须由产品/合规控制。每次开关变化生成 automation_version，并按版本比较 Apply、Approve、Disburse、First-loan CAC、FPD/Vintage。

常见误区：Smart+ CPA 下降就认为用户质量变好；实际上可能只是 Placement Mix、表单摩擦或浅层事件定义变化。

3）【实操训练】Mexico Smart+ 模块化自动化单变量实验

  1. 选择一个过去28天稳定的 Mexico App Promotion/Lead Generation Campaign，冻结 Product、Disclosure、Optimization Event 和素材池。
  2. Control 保留当前设置；Treatment 只开放一个模块，例如 Audience 自动化或 Automatic Placement，不同时修改 Budget、Bid 和 Creative。
  3. 保存 automation_version / audience_mode / budget_mode / placement_mode / bid_mode / creative_mode / destination_lock。
  4. D1-D3 看 Spend、Delivery、Placement Mix、Creative Mix；D7 看 Valid Apply、Approve、Disburse、First-loan CAC；成熟后看 FPD/Vintage。
  5. 内部起点：First-loan CAC 改善≥10%、Approve Rate 不恶化超过3pct、成熟 FPD7 不恶化超过1.5pct，才进入下一层自动化。

以上为内部实验 Guardrail，不是平台官方 Benchmark。

4）【业务分析】低 CPA 不一定是低 CAC

示例：两组都花 120,000 MXN。Control 产生 1,500 Apply、428 首贷，First-loan CAC≈280 MXN；Treatment 产生 1,900 Apply，但只产生397首贷，First-loan CAC≈302 MXN。Treatment 的 Apply CPA 更低，但由于 Approve Rate/Disburse Rate 下降，真实首贷成本更高。

Platform CPA → Valid Apply → Approve → Disburse → First-loan CAC → FPD/Vintage → Risk-adjusted LTV

预算决策应按边际首贷和风险调整后 LTV，而不是只看平台浅层 CPA。若自动化扩量后件均下降、Approve 下降、FPD 上升，即使 ROAS 表面变好，也应限制扩量。

5）【产品相关】Automation Control Registry

建立跨团队 Registry：platform / market / campaign_id / automation_version / audience_mode / budget_mode / placement_mode / bid_mode / creative_mode / destination_lock / product_version / disclosure_version / enabled_at / owner。

  • 产品：锁定产品事实、额度/期限/费用与可投 Landing/App Destination。
  • 投放：记录每次自动化开关、Bid、Budget、Placement 和 Creative 变化。
  • 数据：按 automation_version 输出 Apply→Approve→Disburse→CAC→FPD/Vintage。
  • 风控：比较自动化 Cohort 的 Fraud、Approve、FPD、Vintage，避免把算法探索当成信用判断。
  • 研发：保证 campaign/adgroup/creative/destination/version → user → application → loan 可追溯并支持回滚。
