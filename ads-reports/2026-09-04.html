1）今日最新资讯

TikTok Pangle 正式以 TikTok Ad Network 继续扩张，Mexico 现金贷要把“版位扩量”升级成“Publisher 风险治理”

TikTok 当前官方文档已经统一使用 TikTok Ad Network（formerly TikTok Pangle）命名，并在 2026 年 9 月更新了 Placement、可投地区、Block List 和互动素材说明。官方称该网络覆盖全球接近 40 万个 App / Publisher，通过 App 流量触达的日活用户规模超过 10 亿；同时提供 Publisher 透明度、实时反作弊以及 DoubleVerify / Integral Ad Science 等第三方 post-bid brand safety measurement。

TikTok 官方原文：About TikTok Ad Network (formerly TikTok Pangle)｜Last updated: September 2026

对现金贷 APP 的真正影响不是“多了一个便宜流量池”，而是 Ad Group 的 Placement 会把用户来源从 TikTok Feed 扩到大量第三方 App / Publisher。这些流量可以使用 CPC、CPM、oCPM；oCPM 下还支持 Cost Cap、Maximum Delivery、Hybrid Bidding 和 Target ROAS。TikTok 明确说明：TikTok Ad Network 的 Placement 在创建 Ad Group 时选择，创建后不能修改，因此测试时需要把 Placement 当成独立实验变量治理，而不是上线后再随手切换。

TikTok 官方原文：Placement、Bidding 与 Delivery 说明 ｜ Split Testing Variables（Placement 可作为单一测试变量）

平台还提供 Block List，用于阻止广告出现在不希望的媒体 App / Publisher 上；TikTok 同时提醒，使用 Block List 会减少可用流量，因此可能降低 Impression 和 Performance。对现金贷来说，Block List 的正确用法不是“看到低 CTR 就拉黑”，而是结合 Fraud、Backend Verified Install、Approve、Disburse、FPD/Vintage 做 Publisher 级治理。

此外，TikTok Ad Network 会自动使用 Endcard、Recommended Card、Animation Effects 等互动样式；Endcard 可读取 App Store 的 App icon、名称、评分、描述和 CTA，并可能使用 TikTok 内部 AI 生成动画。现金贷 APP 因此还要检查应用商店页面中的贷款描述、品牌主体、费用/期限表达是否和广告及实际产品保持一致。

今天建议：如果墨西哥账户已开放 TikTok Ad Network，不要直接和 TikTok Feed 混在同一经营结论里。先建立 Placement → Publisher → Valid Install → Apply → Approve → Disburse → FPD → LTV 的单独看板，再决定是否扩量。

2）海外投放知识学习

Publisher / Placement Quality：为什么“TikTok 流量”不能只看成一个渠道

Placement 是广告展示的位置或流量环境；Publisher 是实际承载广告的网站或 App。TikTok Feed 与 TikTok Ad Network 属于不同 Placement 生态，而 TikTok Ad Network 内部又包含大量不同 Publisher。

TikTok Channel
├─ TikTok Feed / Search / Other TikTok placements
└─ TikTok Ad Network
   ├─ Publisher A
   ├─ Publisher B
   └─ Publisher C ...

现金贷例子：Publisher A 的 CPI 可能只有 18 MXN，但 Backend Verified First Launch 只有 70%，Approve Rate 14%，FPD7 30%；Publisher B 的 CPI 为 25 MXN，但 Verified First Launch 95%，Approve 36%，FPD7 18%。如果只看 CPI，A 会被扩量；如果看首贷和风险，B 可能更值得投。

适用场景：App Network、联盟、程序化、Audience Network、Pangle/TikTok Ad Network、第三方 SDK 流量。

常见误区：① 把 TikTok Feed 和 Ad Network 合并看 CPA；② 只按 CTR/CPI 拉黑 Publisher；③ Fraud 只看 MMP，不和 Backend First Launch/KYC/Approve 对账；④ 用 Block List 后只看 CPA，不检查因流量收缩导致的量级影响；⑤ Publisher 质量还没成熟就永久拉黑。

判断方法：Publisher 至少同时看 Spend、Valid Install、Apply、Approve、Disburse、First-loan CAC、Fraud、FPD/Vintage、Risk-adjusted LTV。低前端成本 + 低后端质量，应归类为“便宜但不可扩”，而不是“高效渠道”。

3）实操训练

今天搭一个 TikTok Feed vs Ad Network 的 Placement Split Test

  1. 先确认可用：在 Mexico Ads Manager 的 Ad Group Placement 中检查 TikTok Ad Network 是否可选；不可见则记录为 Not Available，不做推断。
  2. 控制变量：优先使用 TikTok Split Test，把 Placement作为唯一变量；保持 Campaign Objective、Optimization Event、Creative、Bid、Budget、OS、产品版本一致。
  3. 测试组：Control = TikTok placement；Treatment = Automatic Placement 或包含 TikTok Ad Network 的 Placement。若账户支持更细的独立 Placement，再做第二轮。
  4. 媒体层：看 Spend、Impression、CTR、CPC、CPI/CPA、Budget Utilization、Learning。
  5. 业务层：强制接 Backend Verified First Launch、Apply、Approve、Disburse、First-loan CAC；Publisher 维度再看 Fraud/异常设备。
  6. 风险层：等 Cohort 成熟后比较 FPD7、Vintage、D30 Contribution 和 Risk-adjusted LTV。
  7. Block List：只有当某 Publisher 同时在 Fraud / Backend Gap / Approve / FPD 中持续显著劣于基线时才进入 Observe → Limit → Block，不因单日 CTR 差直接封禁。

内部第一版预警：某 Publisher 的 Backend Verified Install Rate 比账户中位数低 >10pct，或 Publisher First-loan CAC 高于账户基线 30% 且样本已成熟，可进入 Review。该阈值为内部实验起点，不是 TikTok 官方标准。

次日复盘：先看 Delivery 是否成功分流、Publisher 数据是否可获得、Backend Gap 是否异常；不要在 FPD 未成熟时就下“Ad Network 用户更差/更好”的最终结论。

4）业务分析

Ad Network CPI 便宜 40%，首贷 CAC 仍可能贵 57%

假设同样花费 100,000 MXN：

TikTok Feed：CPI = 25 MXN → 4,000 installs
Backend Valid First Launch = 95% → 3,800
Apply = 30% → 1,140
Approve = 35% → 399
Approve→Disburse = 70% → 279 首贷
First-loan CAC ≈ 100,000 ÷ 279 = 358 MXN

TikTok Ad Network：CPI = 15 MXN → 6,667 installs（表面便宜 40%）
Backend Valid First Launch = 75% → 5,000
Apply = 24% → 1,200
Approve = 22% → 264
Approve→Disburse = 67% → 177 首贷
First-loan CAC ≈ 100,000 ÷ 177 = 565 MXN

结果是：Ad Network CPI 低 40%，但 First-loan CAC 反而高约 57%。如果 FPD7 还比 Feed 高，真实 ROI 会进一步恶化。

所以“网络扩量”的正确经营逻辑应改为：

Placement / Publisher → Valid Install → Apply → Approve → Disburse → First-loan CAC → FPD/Vintage → Risk-adjusted LTV → Incremental ROI

真正值得扩的是风险调整后仍可盈利的新增 Publisher 流量，不是最便宜的 Install。

5）产品相关

建立 Publisher Quality Registry + Placement Guardrail

建议在内部投放后台新增 Publisher Quality Registry，把第三方 App / Publisher 从“平台黑盒”变成可追踪对象。

产品经理
定义 Placement / Publisher 状态、Block 流程、审核理由和恢复机制；确保 App Store / Landing Page 的品牌与贷款披露可被第三方 Endcard 正确引用。
投放
维护 Placement 测试、Publisher Allow/Observe/Block 状态、Block List 和 Creative 版本。
数据
打通 `placement → publisher → campaign/adgroup → MMP install → user_id → application_id → loan_id`；按 Publisher 输出 CAC、Fraud、FPD、LTV。
风控
建立 Publisher 级设备/IP/ASN、欺诈、Approve、FPD/Vintage 质量分层，避免只按前端 CPA 拉黑。
研发
保证 MMP Publisher/Sub-publisher 参数、Deep Link、event_id、Server-side event 与 App version 可追踪；监控异常 Publisher ID 缺失率。

推荐状态机：`New → Observe → Eligible → Limited → Blocked → Re-test`。其中 Blocked 不应永久不可逆；当平台流量结构或 Publisher 改善后，可以小流量 Re-test。

另外，由于 TikTok Ad Network 的 Endcard 可能自动引用 App Store 信息，产品侧应把商店页贷款主体、描述、评分展示、CTA、隐私政策和产品版本纳入广告合规发布流程。
