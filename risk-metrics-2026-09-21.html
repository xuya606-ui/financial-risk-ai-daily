2026-09-21E.模型与策略F.经营/利润

Champion / Challenger 实验指标学习卡

今天完整升级 Approval Lift、Bad/FPD Lift、Contribution Margin Lift、Sample Ratio Mismatch（SRM）。所有数值阈值均应由内部历史与实验设计确定，不冒充行业统一标准。

1. Approval Lift｜审批增量

1）指标是什么：Champion/Challenger实验中，新策略相对主策略多批准了多少申请。大白话：新策略到底“多放了多少人”。

2）为什么重要：它解决增长效果量化问题，是贷前同步指标；适用于准入、额度、定价、KYC、Fraud Threshold等策略实验。但它只是业务收益的一部分，不是最终风险结论。

3）精确定义与公式：

Approval Lift(pp) = Approval Rate_Challenger − Approval Rate_Champion

Approval Rate分母必须是同一Eligibility规则下、完成随机化并进入决策的唯一申请；固定观察时点、申请/用户口径、策略版本。百分点差与相对百分比增长必须分开。

4）如何看高低：Lift为正说明放款覆盖增加；为负说明更保守。高Lift不一定更好，因为可能伴随EAD、FPD、Fraud或Funding成本上升。

5）案例—背景：墨西哥30天首贷，中低Score测试提额策略。
数据：Champion N=20,000，Approval=30%，Avg EAD=1,500，FPD7=14%，CM/Approved=115；Challenger N=5,000，Approval=34%，Avg EAD=1,700，FPD7=15%，CM=122。
现象：Approval Lift=+4pp，同时风险与额度上升。
拆解：Medium Score×Limit≤1,800增长质量较好；Low Score×Limit≥2,000 FPD7升至23%。
根因：策略与差异高度相关，但先确认随机分流、样本平衡和版本一致，不能直接把全部差异写成因果。
决策：局部放量Medium Score；Low Score恢复Champion额度。
结果：至少看两个成熟FPD7 Cohort，再联合MOB1 DPD30+、EL和CM。

6）诊断逻辑：Eligibility/随机化 → SRM → Channel/Score Mix → Approval Reason → Limit/EAD → FPD/EL/CM。

7）策略动作：高Lift且风险稳定可逐步放量；高Lift但EL上升则降额、缩窄Segment；技术拒绝减少造成Lift先修技术，不归因于信用策略。

8）常见误区：把30%→34%写成“+4%”而不是+4pp；实验组与对照组分母不同；随机化后又改变Eligibility；只看审批不看放款。

9）推荐拆分：Channel、Campaign、Score、Limit、Term、新老客、Region、Device、Strategy Version。

10）预警方式：建议同时设置最低样本量、分流质量和成熟风险Guardrail。示例：Approval Lift明显为正但FPD/EL连续两个成熟Cohort超出自身历史稳定区间，进入黄/红灯；具体阈值为内部标准。

11）与其他指标关系：Eligibility → Approval Lift → Disbursement/EAD → FPD/Bad → EL → Contribution Margin。

12）小练习：Champion 30%，Challenger 34%，Approval Lift是多少？答案：+4个百分点。

2. Bad / FPD Lift｜坏账/首逾增量

1）指标是什么：新策略相对旧策略带来的成熟风险差值。大白话：多放的量到底多坏了多少。

2）为什么重要：贷后滞后结果指标，是Champion/Challenger是否安全的核心验证。

3）精确定义与公式：

FPD7 Lift(pp) = Mature FPD7_Challenger − Mature FPD7_Champion

必须同Vintage、同成熟期、同Bad/FPD定义，并区分件数和金额口径；未成熟样本不进分母。

4）如何看高低：正值一般意味着风险恶化，但如果新增利润明显高于新增损失，策略仍可能有经济价值；因此要与EL、CM、LTV一起看。

5）案例—背景：同一提额实验。
数据：Champion FPD7=14%；Challenger=15%；Avg EAD 1,500→1,700；Low Score×High Limit FPD7=23%。
现象：整体只恶化1pp，但局部Segment严重恶化。
拆解：Channel×Score×Limit×Term×Strategy Version。
根因：额度和风险同时变化，需排除渠道Mix与SRM后再做因果判断。
决策：局部回滚高风险段，不全量回滚。
结果：观察MOB1 DPD30+、Amount FPD、EL和CM是否同步改善。

6）诊断逻辑：Maturity → SRM/Mix → Score/Limit/EAD → Fraud/Payment → DPD30+/EL → CM。

7）策略动作：局部风险集中做Segment Guardrail；全Segment持续恶化则停实验；金额风险恶化优先降EAD。

8）常见误区：未成熟Bad；件数/金额混淆；不同Vintage直接比；看到相关关系就宣称因果。

9）推荐拆分：Vintage、Score、Limit、Term、Channel、Device、Region、Strategy Version。

10）预警方式：同成熟Cohort与最低Bad事件数；连续两个成熟Cohort超内部稳定区间可升级红灯。

11）关系：Approval/Limit → FPD Lift → Roll/DPD30+ → Bad/EL → Margin。

12）小练习：14%→15%的FPD7 Lift是多少？答案：+1pp。

3. Contribution Margin Lift｜风险调整贡献利润增量

1）指标是什么：Challenger相对Champion带来的风险调整贡献利润变化。大白话：新增增长扣完资金、损失和可变成本后，真的多赚钱吗？

2）为什么重要：经营/利润结果指标，连接准入、额度、资金、损失、Fraud、催收与增长。

3）精确定义与公式：

CM = Revenue − Funding Cost − Expected/Actual Credit Loss − Fraud Loss − Variable/Servicing/Collection Cost − Incremental IncentiveCM Lift = CM_Challenger − CM_Champion

必须固定口径：每Eligible、每Approved、每Disbursed或总额；损失成熟度、CAC是否扣除、Recovery如何计入都要版本化。

4）如何看高低：正值通常越好，但若坏账尚未成熟，早期CM可能虚高；总CM为正也可能掩盖某些Segment为负。

5）案例—背景：首贷提额实验。
数据：CM/Approved 115→122，+7；Approval 30%→34%；FPD7 14%→15%；Low Score×High Limit段CM转负。
现象：整体经济性改善，但高风险局部段亏损。
拆解：Score×Limit×Funding Source×Channel。
根因：新增Revenue覆盖了部分新增EL，但高EAD低Score段损失放大。
决策：保留盈利Segment、回滚负CM Segment。
结果：继续看成熟Actual Loss、Recovery、LTV。

6）诊断逻辑：Revenue → Funding → EL/Actual Loss → Fraud/Collection → Variable Cost → Segment → Maturity。

7）策略动作：EAD驱动亏损就降额；Funding驱动则优化资金结构；低ROI渠道降量；高CAC但高LTV客群需看生命周期。

8）常见误区：只看Revenue；忽略未成熟损失；CAC重复扣；每单利润和总利润混用。

9）推荐拆分：Channel、Score、Limit、Term、Funding Source、Cycle、新老客、Strategy Version。

10）预警方式：同成熟窗口比较；总CM为正但边缘Segment长期为负时局部红灯；具体阈值为内部标准。

11）关系：Approval×EAD → Revenue/Funding/EL → CM → LTV/CAC。

12）小练习：CM 115→122，Lift是多少？答案：MXN7/approved。

4. SRM｜Sample Ratio Mismatch｜样本比例异常

1）指标是什么：实验实际分流比例与计划分流比例是否异常偏离。大白话：实验是不是从入口就分错人了。

2）为什么重要：模型/策略实验的前置质量指标。SRM存在时，任何Approval、Bad、Margin Lift都可能被分流Bug或Eligibility污染。

3）精确定义与公式：比较Observed Group Counts与Expected Allocation，可用卡方检验或等价方法。分母应是完成Eligibility并进入随机化的样本。统计阈值属于实验平台/内部规范，不是信贷行业统一标准。

4）如何看高低：SRM不是“策略表现差”，而是“实验结论可能不可信”；应先修实验，再谈业务。

5）案例—背景：计划80% Champion / 20% Challenger。
数据：25,000 eligible，预期20,000/5,000；实际若20,000/5,000则正常；若22,500/2,500则明显偏离。
现象：严重偏离可能来自Feature Flag、App版本、渠道分流或曝光日志错误。
拆解：Channel×App Version×OS×Region×Time。
根因：必须技术排查，不得把结果差异归因于策略。
决策：暂停发布结论，修复分流后重新定义有效实验窗口。
结果：新窗口SRM正常后再计算Lift。

6）诊断逻辑：Randomization ID → Eligibility → Assignment → Exposure → App Version → Channel → Outcome。

7）策略动作：修复Feature Flag、埋点与分流；严重SRM重启实验；保留异常窗口作为技术事件。

8）常见误区：所有申请都进分母；随机化后人工改组；看到业务显著差异就忽略SRM；跨版本曝光污染。

9）推荐拆分：Channel、App Version、OS、Region、Time、Experiment ID、Strategy Version。

10）预警方式：实验平台统一设置统计门槛与最低样本量；出现持续或大幅比例偏离即技术黄/红灯。不要把某个p值写成行业统一风险阈值。

11）关系：Eligibility/Randomization → SRM → Valid Experiment → Lift → Rollout。

12）小练习：80/20计划、25,000样本，观察22,500/2,500时第一动作？答案：先查SRM和分流，不解释策略效果。

这些指标学习卡用于内部风险管理和实验设计学习；生产阈值需结合公司风险偏好、样本量和统计规范。
