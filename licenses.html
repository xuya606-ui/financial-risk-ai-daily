二、业务穿透：六个问题决定真实许可边界

分析推断：与一家持牌金融机构合作，不意味着APP自动继承其全部许可。每次上线新资金方、产品、钱包、还款或催收方案，都必须回答：谁审批？谁定价？谁出资？谁持有债权？谁向用户收费？谁催收？

长期维护：Developer → APP Brand → Legal Entity → SOFOM/License Status → SIPRES → RECA → RECO → Actual Lender → Funding Party → Creditor → Collector/REDECO。

三、PLD/FT 与 AML

SOFOM E.N.R.适用的PLD/FT义务应持续纳入CNBV监督视角。现金贷建议把KYC、PEP/制裁、第三方代还、Shared Bank/Wallet、Counterparty Graph、异常资金路径与Case Outcome连成闭环。

CNBV处罚与监督公开说明

四、征信、还款能力与贷后迁徙

贷前征信查询、放款后报送、用户争议和Affordability应分开管理：Application Bureau Query → Loan Disbursed → Bureau Report → Correction/Dispute；同时将Bureau Debt + Verified Income转成DTI/PTI/Residual。贷后进一步固定 Early Roll → Cure → Net Flow → DPD30+ → Charge-off → Recovery/LGD，避免只看单一DPD快照。

五、数据隐私与第三方 AI/SDK

身份证/OCR、人脸/活体、设备指纹、征信、CLABE/银行卡、支付和行为数据建议采用字段级治理：

Field → Purpose → Privacy Notice/Consent → Vendor/Subprocessor → Storage Region → Cross-border Access → Retention → AI Training Use → Delete/ARCO

潜在风险：超目的处理、授权不足、第三方共享不透明、数据泄露、训练用途不清，以及由此产生的监管、诉讼和应用商店风险。

六、Brand Fraud / 假贷款 / Malware / ATO

当前重点风险链：Fake Offer / Link / APK → Malware / Credential Theft → Device Compromise → ATO → Bank Change → Drawdown → Fraud Loss。

CONDUSEF 9月警示已覆盖假贷款、恶意链接与Malware。客服“非本人申请/非本人提款”样本应回流设备、身份和ATO策略；New Device + Password Reset + Bank Change/Drawdown应提高Step-up。短信OTP不能作为设备已被控制场景下的唯一防线。

七、Google Play 贷款 APP Gate

Target API：自2026-08-31起，新APP和更新需Target Android16/API36或以上；现有手机APP至少Target Android15/API35，符合条件者可申请延期到11月1日。

Financial Features Declaration：覆盖Personal loan direct lender、Loan facilitator、Payday loans、Banking、Line of credit、EWA、Microfinance等。个人贷款相关功能还需提供进一步材料并保持Actual Lender关系可核验。

Financial Services Policy：个人贷款需披露期限、最高APR、代表性总成本和隐私政策；不得推广要求60天或更短时间内全额偿还的个人贷款；对联系人、精确定位、电话号码、照片/视频、完整APP列表等敏感权限存在限制。

Google Target API · Financial Features Declaration · Financial Services Policy

八、Apple App Store 贷款 APP Gate

Apple App Review Guidelines 3.2.2(ix)要求个人贷款APP清楚披露贷款条款、最高等效APR和到期日；最高APR不得超过36%（含成本与费用），且不得要求60天或更短期限内全额偿还。

判断原则：Apple平台Gate与墨西哥本地法律许可独立判断；一个通过不能替代另一个。
