二、业务穿透：六个问题决定真实许可边界

分析推断：与持牌机构合作，不意味着 APP 自动继承其全部许可。每次上线新资金方、产品、钱包、还款或催收方案，都必须回答：谁审批？谁定价？谁出资？谁持有债权？谁向用户收费？谁催收？

长期维护：Developer → APP Brand → Legal Entity → SOFOM/License Status → SIPRES → RECA → RECO → Actual Lender → Funding Party → Creditor → Collector/REDECO。

三、征信/SIC 与 Thin-file

法律/监管背景：CNBV说明，SIC收集、管理和提供个人/企业信用历史；SOFOM应成为至少一家SIC用户并定期向其提供所发放信用信息。SIC向用户提供信用信息通常需要客户明确授权。

风控实践：决策日志建议至少记录 `bureau_query_status / bureau_hit / file_depth / inquiries_7d / inquiries_30d / tradeline_count / oldest_tradeline_months / consent_version`。

关键区分：Technical Fail ≠ Bureau No-hit ≠ Thin-file。技术失败走Retry/Fallback；真实No-hit/Thin-file再进入替代数据与额度策略。

潜在风险：授权不足、重复查询、数据穿越、把No-hit误判低风险/高风险、使用未经验证替代数据导致误杀或偏差。

七、数据隐私与第三方 AI/SDK

身份证/OCR、人脸/活体、设备指纹、征信、CLABE/银行卡、支付与行为数据建议采用字段级治理：

Field → Purpose → Privacy Notice/Consent → Vendor/Subprocessor → Storage Region → Cross-border Access → Retention → AI Training Use → Delete/ARCO

八、Brand Fraud / 假贷款 / Malware / ATO

持续风险链：Fake Offer / Domain / Link / APK → Credential Theft / Malware → Device Compromise → ATO → Bank Change → Drawdown → Fraud Loss。监控品牌词、域名、APK/Package、WhatsApp/SMS、社媒广告、收款账户和“非本人申请/提款”投诉。

高优先级组合：New Device + Password Reset + Bank Change / Drawdown，叠加Root/Hook、Overlay、Accessibility Abuse、Remote-control Tool和异常Session。

九、Google Play / Apple App Store Gate

Google：自2026-08-31起，新APP和更新需Target Android 16/API36或以上；现有手机APP至少API35，符合条件可延期至2026-11-01。Financial Features Declaration覆盖Personal loan direct lender、Loan facilitator、Payday loans、Banking、Line of credit、EWA、Microfinance等。

Apple：App Review Guidelines 3.2.2(ix)继续要求个人贷款APP清楚披露贷款条款、最高等效APR和到期日；最高APR不得超过36%（含成本费用），且不得要求60天或更短时间内全额偿还。

监管实践：墨西哥法律许可与商店分发政策是两个独立Gate。Developer、Legal Entity、APP Brand、Actual Lender、Financial Declaration、隐私与权限必须一致。
