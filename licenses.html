二、业务穿透：六个问题决定真实许可边界

分析推断：与一家持牌金融机构合作，不意味着 APP 自动继承其全部许可。每次上线新资金方、产品、钱包、还款或催收方案，都必须回答：谁审批？谁定价？谁出资？谁持有债权？谁向用户收费？谁催收？

长期维护：Developer → APP Brand → Legal Entity → SOFOM/License Status → SIPRES → RECA → RECO → Actual Lender → Funding Party → Creditor → Collector/REDECO。

三、RECA / SIPRES / 合同一致性

监管实践：RECA 是合同登记与查询的重要工具，但“已登记”不应被宣传为“已获监管批准”。线上现金贷上线前应做三方核对：SIPRES主体状态 × RECA合同 × APP/隐私政策/借款页面展示主体，再对 Actual Lender、Funding Party、Creditor 和 Collection Party 做穿透。

风险：主体与合同不一致可能引发消费者争议、监管整改、资金方审查，以及 Google Play / App Store 对 Developer/Actual Lender 关系的补件或拒审。

六、数据隐私与第三方 AI/SDK

现行 LFPDPPP 中主管“Secretaría”为 Secretaría Anticorrupción y Buen Gobierno。身份证/OCR、人脸/活体、设备指纹、征信、CLABE/银行卡、支付与行为数据建议采用字段级治理：

Field → Purpose → Privacy Notice/Consent → Vendor/Subprocessor → Storage Region → Cross-border Access → Retention → AI Training Use → Delete/ARCO

潜在风险：超目的处理、授权不足、第三方共享不透明、跨境处理不清、数据泄露、AI训练用途不明，以及监管/诉讼/应用商店风险。

七、Brand Fraud / 假贷款 / Malware / ATO

持续基线风险链：Fake Offer / Domain / Link / APK → Credential Theft / Malware → Device Compromise → ATO → Bank Change → Drawdown → Fraud Loss。即使当天无新警示，也应持续监控品牌词、域名、APK/Package、WhatsApp/SMS、社媒广告、收款账户和客服“非本人申请/非本人提款”样本。

New Device + Password Reset + Bank/Beneficiary Change + Drawdown 属于高优先级 Step-up 组合；短信 OTP 不应成为设备已被控制场景下的唯一防线。

八、Google Play 贷款 APP Gate

Target API：自 2026-08-31 起，新APP和更新需 Target Android16/API36 或以上；现有手机APP至少 Target Android15/API35，符合条件者可申请延期到 2026-11-01。

Financial Features Declaration：覆盖 Personal loan direct lender、Loan facilitator、Payday loans、Banking、Line of credit、EWA、Microfinance banking 等。个人贷款相关功能还需提供进一步材料，并保持 Actual Lender 与 Developer 关系可核验。

Financial Services Policy：个人贷款需披露期限、最高APR、代表性总成本和隐私政策；不得推广要求60天或更短时间内全额偿还的个人贷款；联系人、精确定位、电话号码、照片/视频、完整APP列表等敏感权限存在限制。

Google Target API · Financial Features Declaration · Financial Services Policy

九、Apple App Store 贷款 APP Gate

Apple App Review Guidelines 3.2.2(ix) 要求个人贷款 APP 清楚披露贷款条款、最高等效 APR 和到期日；最高 APR 不得超过 36%（含成本与费用），且不得要求 60天或更短期限内全额偿还。

判断原则：Apple 平台 Gate 与墨西哥本地法律许可独立判断；一个通过不能替代另一个。

十、Paquete Económico 2027：宏观情景如何转风控

政府预算情景继续用于压力测试，而不是直接作为业务结果。建议保持三条传导：

GDP / Employment → Employer Risk → Payroll Stability → DTI/PTI → Inquiry → FPD/Vintage

Rate / TIIE → Funding Cost → Price/Limit → Contribution Margin

USD/MXN → Cloud/AI/KYC Cost + Employer Cash Flow → Operating/Borrower Risk
