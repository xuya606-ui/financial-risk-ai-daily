一、主体与牌照矩阵

主体/模式法律要求监管实践常见用途主要风险
SOFOM E.N.R.不是银行牌照；仍需满足适用的PLD/FT等义务，并保持CONDUSEF/SIPRES状态等要求。CNBV明确SOFOM E.N.R.在PLD/FT事项上仍受其监督，直至SIPRES法律状态发生相应变化。自有/机构资金消费贷、现金贷、应收融资等，具体结构需结合公司章程、合同与监管登记。把“E.N.R.”误解为完全无监管；主体/品牌/合同/催收不一致；PLD/FT、征信报送、消费者保护。

二、业务穿透：六个问题决定真实牌照边界

分析推断：合作一家持牌金融机构，不意味着APP自动继承其全部许可。上线任何新资金方/产品前至少回答：谁审批？谁定价？谁出资？谁持有债权？谁向用户收费？谁催收？

长期维护：Developer → APP Brand → Legal Entity → SOFOM/License Status → SIPRES → RECA → RECO → Actual Lender → Funding Party → Creditor → Collector/REDECO。

三、PLD/FT 与 AML

法律/监管实践：SOFOM E.N.R.适用的PLD/FT义务通过CNBV相关体系接受监督；SITI PLD/FT是履行部分信息报送义务的重要电子渠道。

业务动作：KYC/Beneficial Owner、制裁/PEP、交易/还款异常、Shared Bank/Wallet、异常第三方代还、Counterparty Graph、Case Outcome和可疑活动调查应形成闭环。

CNBV SITI PLD/FT · FATF专业洗钱报告

四、征信：贷前查询与放款后报送是两条责任链

贷款主体应把“贷前征信查询”和“放款后征信报送/更正”当作不同责任链管理。推荐：Loan Disbursed → Bureau Report Due → Report Sent → Accepted/Rejected → Correction → User Dispute Closed。

建议指标：报送完整率、Timeliness、Rejected Record Rate、Correction SLA、Identity Match Rate。

原文：CNBV SOFOM FAQ

五、数据隐私：当前私人数据保护主管安排已变化

法律要求：2025-03-20发布的现行《Ley Federal de Protección de Datos Personales en Posesión de los Particulares》将“Secretaría”定义为Secretaría Anticorrupción y Buen Gobierno，并由其承担私人数据保护相关监督、核查和处罚职责。法律对金融/财产数据、敏感数据、隐私告知、ARCO、安全和部分具有法律/重大影响的自动化处理规定了相应要求。

监管实践：机构改革后，仍把INAI写成当前私人数据保护主管机构的隐私政策、合同、客服话术和ARCO流程应逐步清理。贷款APP尤其应核验身份证/OCR、人脸/活体、设备、征信、CLABE/银行卡、支付、行为数据及第三方AI/SDK数据链。

建议数据台账：Field → Purpose → Notice/Consent → Vendor/Subprocessor → Storage Region → Cross-border Access → Retention → Training Use → Delete/ARCO。

潜在风险：用途超范围、同意不足、敏感/金融数据治理不当、第三方共享不透明和安全事件处置不足可能形成行政处罚、投诉和平台审核风险。

原文：现行私人数据保护法 · 原文：Buen Gobierno主管安排

六、Google Play 贷款 APP Gate

Target API：自2026-08-31起，新APP和更新需Target Android 16/API36或更高；现有手机APP至少Target Android15/API35以继续正常面向运行更高Android版本的新用户；符合条件的开发者可申请延期至11月1日。

金融声明：含金融功能APP需完成Financial Features Declaration，包括Personal loan direct lender、Loan facilitator、Payday loans、Line of credit、Banking等类别。Developer Account、Legal Entity、Actual Lender、牌照/登记与声明需形成可验证关系。

平台风险：Target API不满足会影响提交/可发现性；金融功能、主体材料或敏感权限不一致会造成审核、补件或下架风险。

Google Target API · Financial Features Declaration · Google Financial Services Policy

七、Apple App Store 贷款产品 Gate

Apple App Review Guidelines 3.2.2(ix)要求个人贷款APP清晰披露贷款条款、等效最高APR和到期日；最高APR不得超过36%（包括成本和费用），不得要求在60天或更短时间内全额还款。

必须独立判断：“墨西哥法律允许经营”与“Apple允许App Store分发”是两个Gate，不能互相替代。

Apple App Review Guidelines
