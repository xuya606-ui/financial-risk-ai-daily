墨西哥贷款牌照、资质与 APP 合规专题

面向线上现金贷、消费信贷、数字信贷APP。以下内容严格区分法律要求、监管实践、市场惯例与分析推断；具体主体上线前仍应由墨西哥律师/合规团队核验最新法律、许可和合同结构。

一、主体与牌照矩阵

主体/模式法律要求监管实践常见用途主要风险
SOFOM E.N.R.不是银行牌照；仍需满足适用的PLD/FT等义务，并保持CONDUSEF/SIPRES状态等要求。CNBV明确SOFOM E.N.R.在PLD/FT事项上仍受其监督，直至SIPRES法律状态发生相应变化。自有/机构资金消费贷、现金贷、应收融资等，具体结构需结合公司章程、合同与监管登记。把“E.N.R.”误解为完全无监管；主体/品牌/合同/催收不一致；PLD/FT、征信报送、消费者保护。
SOFOM E.R.属于受监管SOFOM，适用更完整的金融监管框架，具体取决于其关联/融资结构及法律状态。上线需核验CNBV/CONDUSEF状态、合同、资本/治理与适用规则。受监管金融集团/特定融资结构下的信贷。把E.R.和E.N.R.混用；未核验具体监管范围。
IFPELey Fintech框架下电子支付资金机构，需正式授权。如果APP涉及钱包、储值、用户资金留存或电子支付资金，必须重新评估是否进入IFPE边界。电子钱包/支付账户等。把贷款功能与资金留存/支付功能混在同一主体却未重新评估许可。
IFCLey Fintech下集体融资机构，需正式授权。涉及公众/投资人资金撮合、众筹式融资时需穿透真实资金来源与投资人关系。众筹/公众投资人融资撮合。把“合作放款”误当成可以直接面向公众吸收/撮合资金。
银行银行业务需相应银行许可与审慎监管。APP、合同、实际贷款人、资金方和债权人需要一致可验证。存款、支付、授信等综合银行业务。合作银行不等于科技APP自动获得银行牌照权限。
助贷/导流/合作放款是否需要自身金融许可取决于业务实质、收费、资金/债权、审批/定价控制等。监管/平台审核往往穿透实际Lender、Developer、合同和数据处理关系。流量、技术、风控服务、联合营销、资金合作。主体穿透不清、收费边界、数据共享、消费者误导、品牌/合同不一致。

二、业务穿透：六个问题决定真实牌照边界

分析推断框架：合作一家持牌金融机构，并不意味着APP自动继承其全部许可。上线任何新资金方/产品前，至少回答：谁审批？谁定价？谁出资？谁持有债权？谁向用户收费？谁催收？

还应维护：Developer → APP Brand → Legal Entity → SOFOM/License Status → SIPRES → RECA → RECO → Actual Lender → Funding Party → Creditor → Collector/REDECO。

三、PLD/FT 与 AML

法律/监管实践：SOFOM E.N.R.适用的PLD/FT义务通过CNBV相关体系接受监督；SITI PLD/FT是履行部分信息报送义务的重要电子渠道。

业务动作：KYC/Beneficial Owner、制裁/PEP、交易/还款异常、Shared Bank/Wallet、异常第三方代还、Case Outcome与可疑活动调查需要形成闭环。

近7天国际风险参考：FATF 2026-09-03报告指出，地下银行/Hawala和专业洗钱网络越来越多地使用银行账户、Fintech、支付服务商、虚拟IBAN、预付卡与虚拟资产钱包作为正式金融体系的入口/出口。

CNBV SITI PLD/FT · FATF 2026报告

四、征信与数据责任

贷款主体应把“贷前征信查询”和“放款后征信报送/更正”当作不同责任链管理。推荐数据链：

Loan Disbursed → Bureau Report Due → Report Sent → Accepted/Rejected → Correction → User Dispute Closed。

建议指标：报送完整率、Timeliness、Rejected Record Rate、Correction SLA、Identity Match Rate。

五、Google Play 贷款 APP Gate

Target API：自2026-08-31起，新APP和更新需Target Android 16/API36或更高；现有手机APP至少Target Android15/API35以继续正常面向运行更高Android版本的新用户。

金融声明：含金融功能APP需完成Financial Features Declaration；包括Personal loan direct lender、Loan facilitator、Payday loans、Line of credit、Banking等类别。个人贷款相关功能还可能要求进一步材料。

产品/平台风险：Developer Account、Legal Entity、Actual Lender、牌照/登记与声明需形成可验证关系；贷款产品还需遵守Google金融服务政策及受限制敏感权限要求。

Google Target API · Financial Features Declaration · Google Financial Services Policy

六、Apple App Store 贷款产品 Gate

Apple App Review Guidelines 3.2.2(ix)要求：个人贷款APP清晰披露贷款条款、等效最高APR和到期日；最高APR不得超过36%（包括成本和费用），不得要求在60天或更短时间内全额还款。

必须独立判断：“墨西哥法律允许经营”与“Apple允许App Store分发”是两个Gate，不能互相替代。
