主体/牌照判断四层

层级怎么理解APP需要核验
法律要求SOFOM E.N.R.不是银行牌照，也不是“无监管”；适用PLD/FT、消费者保护、合同、征信等义务仍需履行。IFPE/IFC属于Ley Fintech下正式授权类型。Legal Entity、许可/注册状态、业务模式、合同、消费者披露、PLD/FT。
监管实践主管机关和平台审核会穿透主体、合同、实际贷款人和业务流程的一致性。Developer → APP Brand → Legal Entity → SOFOM/License Status → SIPRES → RECA → RECO → Actual Lender → Funding Party → Creditor → Collector/REDECO。
市场惯例技术、获客、风控、资金、运营可拆给不同合作方。每个合作方的职责、合同、数据权限和收费链路。
分析推断合作一家持牌机构不等于APP自动继承全部许可。谁审批、谁定价、谁出资、谁持债权、谁收费、谁催收。

SIPRES / RECA / RECO / REDECO 核验

SIPRES：用于核验金融机构的公司、行政与状态信息，不是产品收益/费率查询工具。

RECA：CONDUSEF页面明确提示，合同登记本身并不当然意味着合同已完成监管实质审查/评价，除非适用透明度规则要求登记前审查授权。

RECO / REDECO：应与实际收费、催收主体和APP披露保持一致。

官方：CONDUSEF｜SIPRES说明 · CONDUSEF｜RECA · CONDUSEF｜官方注册体系入口

PLD/FT：SOFOM E.N.R.仍属于明确监督对象

CNBV官方FAQ继续将SOFOM E.N.R.列为PLD/FT相关主体。APP产品设计不能把“E.N.R.”理解为“无需反洗钱治理”。

官方：CNBV｜SOFOM E.N.R. PLD/FT FAQ · CNBV｜SITI PLD/FT

支付账户变更与ATO：今日运营风控建议

分析建议，不是新增监管规则：银行卡/CLABE变更要区分可恢复支付问题与ATO风险。建议把 New Device + Bank Change + High-value Drawdown / Repayment Anomaly 作为高优先级Step-up组合；Technical Fail可Retry/Fallback，Account/Identity Mismatch应重新核验，Confirmed Wrong Account应停止资金动作。

产品、风控和研发需要共同保证Payment Status与真实清算状态一致，并用幂等控制重复放款/重复扣款。

Google Play：墨西哥信贷APP当前P0 Gate

Target API：自2026-08-31起，新APP和更新需Target Android16/API36+；现有手机APP至少API35以维持对更高Android版本新用户的正常分发；符合条件者可申请延期至2026-11-01。

Financial Features：准确申报Personal loan direct lender、Loan facilitator、Payday loans、Banking、Line of credit、EWA、Microfinance banking等；个人贷款相关功能需补充材料。

贷款政策：需披露期限、最高APR/当地一致费率、代表性总成本、隐私政策；60天或更短全额偿还规则和敏感权限限制继续重点核验。

重要纠正：Google的36% APR硬上限当前是美国特定要求，不应误写成墨西哥统一Google Play上限。

官方：Target API · Financial Features Declaration · Financial Services Policy

Apple App Store：36% APR + 60天规则

Apple App Review Guidelines 3.2.2(ix)继续要求个人贷款APP清楚披露所有贷款条款、最高等效APR和到期日；最大APR不得超过36%，包括成本与费用；不得要求在60天或更短时间内全额还款。

结论：本地法律合规与App Store分发合规是两个独立Gate。

官方：Apple｜App Review Guidelines

上线前统一核验清单

  1. Developer Account主体是否与APP品牌/法务主体可解释。
  2. Actual Lender是谁，资金方与债权持有人是谁。
  3. 审批、定价、收费、催收分别由谁执行。
  4. SIPRES / RECA / RECO / REDECO状态与APP文案是否一致。
  5. PLD/FT、征信授权、隐私Notice、跨境数据与Vendor链是否完整。
  6. Google Financial Features、API level、敏感权限和贷款披露是否通过。
  7. Apple 36% APR / 60天规则是否独立通过。
  8. 支付账户变更、清算状态和ATO Step-up是否可审计。
  9. 所有“已获批准/已持牌”表述是否有可点击官方证据，无法确认则标记“原文待核验”。
