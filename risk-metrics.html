今日联合判断框架

Deliverability → RPC → PTP → PTP Kept → Cash Collection → Cure / Roll → Recovery → Net Loss

RPC和PTP属于过程指标；Kept、现金、Cure/Roll与Recovery才逐步接近真实结果。今天重点升级历史高频催收指标，避免用“触达多/承诺多”替代真实回款。

RPC Rate｜Right Party Contact Rate

1）是什么：Eligible逾期账户中，真正联系到正确借款人的比例。

2）重要性：贷后同步/领先指标，是PTP、Collection和Cure的上游。

3）公式：至少1次Right-party Contact唯一账户 ÷ Eligible Collection Accounts固定DPD、窗口并按账户去重，金额口径另报。

4）高低：通常高更有利，但高RPC若伴随过度联系、低Kept或高投诉，并非好结果。

5）七步案例：V4上线后N=10k、Due=15m；RPC 36%→52%、PTP 40%→57%，但Kept 68%→41%、Collection 31%→28%、Complaint 0.8%→1.6%。Vendor B高余额客RPC 61%但Kept 28%。相关性明确但需Challenger验证因果；决策改KPI与频率；观察2-4周Cash/Cure/Complaint。

6）诊断：Deliverability → Vendor/时段 → PTP/Kept → Cash/Cure/Complaint。

7）动作：号码问题修数据；时段问题调触达；高RPC低Kept调话术/激励；高投诉降频。

8）误区：接通率=RPC；重复联系重复计数；跨Bucket比较；RPC高=催收强。

9）拆分：DPD、Vendor、Treatment、Score、Balance、Region、时段、号码来源。

10）预警：RPC突降+Deliverability跌是技术黄灯；RPC升+Kept/Cash跌+Complaint升是质量红灯候选。

11）关系：Deliverability → RPC → PTP → Kept → Collection/Cure → Roll/Bad。

12）练习

1,000个Eligible中500个RPC，RPC=50%。

PTP Rate｜Promise-to-Pay Rate

1）是什么：RPC后形成明确金额和日期的有效还款承诺比例。

2）重要性：同步指标，衡量协商结果但不代表实际现金。

3）公式：有效PTP唯一账户 ÷ RPC唯一账户必须定义金额、日期、去重和成熟规则。

4）高低：高不一定好；若Kept下降，可能是低质量承诺。

5）七步案例：PTP 40%→57%，但Kept 68%→41%、Collection 31%→28%。Vendor B PTP=66%、Kept=28%。拆解激励/话术后做Challenger；改为Kept+Cash+Cure-Complaint绩效。

6）诊断：定义 → Vendor/Agent → 承诺金额/日期 → Kept/Collection。

7）动作：高PTP低Kept收紧有效承诺定义并改激励；低PTP高Cash不要误判。

8）误区：PTP越高越好；“会还”算PTP；承诺金额=现金；跨Bucket混比。

9）拆分：Vendor、Agent、DPD、Balance、Score、承诺金额比、承诺天数。

10）预警：PTP升但Kept降、投诉/Roll升为质量黄灯。

11）关系：RPC → PTP → Kept → Collection → Cure/Roll。

12）练习

500个RPC、300个有效PTP，PTP=60%。

PTP Kept Rate｜承诺兑现率

1）是什么：成熟PTP中按规则如期兑现的比例。

2）重要性：滞后质量指标，直接检验承诺是否真实。

3）公式：兑现的成熟PTP唯一账户 ÷ 已到承诺日且成熟的有效PTP唯一账户需定义部分支付、容忍日和多PTP处理。

4）高低：一般高好，但只向易还客索取PTP或承诺金额过低会虚高。

5）七步案例：Kept 68%→41%；Vendor B高余额低Score仅28%、Complaint 2.4%；调承诺模板和激励后以现金/Cure为最终结果。

6）诊断：成熟窗口 → 承诺金额/日期 → Agent/Vendor → Payment Success → Cash/Cure/Roll。

7）动作：高Fail调整现实承诺；支付问题先修支付；低Kept Vendor降量/质检。

8）误区：未成熟进分母；部分支付规则不一致；承诺金额过低；只看件数。

9）拆分：Vendor、DPD、Score、Balance、金额比、承诺天数、支付方式。

10）预警：Kept低于同Bucket历史稳定区间且Collection/Cure同步跌为红灯候选。

11）关系：PTP Quality → Kept → Cash → Cure → Roll/Recovery。

12）练习

300个成熟PTP、120个兑现，Kept=40%。

Collection Rate｜催收现金回收率

1）是什么：固定逾期/应收风险池中在固定窗口真正收回的现金比例。

2）重要性：贷后核心结果指标，连接催收动作和现金经营结果。

3）公式：Collection Rate@N = N天合格现金回收 ÷ 固定Due/Opening Eligible Balance分母、费用、展期、减免、冲正必须版本化。

4）高低：通常高好，但高额减免或高投诉换来的高回收未必是好经营结果。

5）七步案例：Due=15m，7日Collection 31%→28%；RPC/PTP升、Kept降、Roll升、Complaint升。拆Vendor发现B高触达低现金；按净回款和风险迁徙调整权重。

6）诊断：分母/入账 → RPC/PTP/Kept → Payment Success → Vendor/Segment → Cure/Roll/Cost。

7）动作：支付失败修通道；低RPC提可达；高RPC低Cash优化承诺；低ROI Vendor降量。

8）误区：分母漂移；承诺当现金；只报回款额；Gross忽略退款/冲正。

9）拆分：DPD、Vintage、MOB、Vendor、Treatment、Score、Balance、Payment Method。

10）预警：Collection下降且Roll上升、Cost/Collected变差为红灯候选。

11）关系：RPC/PTP/Kept → Collection → Cure/Roll → Bad/Charge-off → Margin。

12）练习

Due 15m、7天回款4.2m，Collection=28%。

Recovery Rate｜后段回收率

1）是什么：Default/Write-off等后段风险池中累计回收现金占原始暴露的比例。

2）重要性：滞后损失指标，是LGD关键输入。

3）公式：Recovery@MOB N = 累计Net Recovery Cash@N ÷ Default EAD固定Default定义、MOB和Gross/Net。

4）高低：通常高好，但不同Default Vintage/MOB不能直接比较。

5）七步案例：Default Pool约3m，MOB2 Recovery 18%→16%；Vendor B联系量高但高余额兑现差。调整高余额优先级、Vendor权重和混合催收后观察MOB2/MOB3 Recovery与LGD。

6）诊断：Default EAD/成熟期 → Gross/Net → Vendor/Balance/Fraud vs Credit → 处置 → LGD。

7）动作：低RPC提可达；高成本低净回收Vendor降量；高余额分层；Fraud/Credit分开策略。

8）误区：Gross=Net；不同MOB比较；分母漂移；核销后漏记回款。

9）拆分：Default Vintage、Recovery MOB、Vendor、Balance、Score、Region、Fraud/Credit。

10）预警：Recovery下降且Cost、LGD同步上升为红灯候选。

11）关系：Default EAD → Recovery → LGD → Actual Loss → Contribution Margin。

12）练习

Default EAD 5m，Gross回收1.2m、成本0.2m：Gross=24%，Net=20%。
