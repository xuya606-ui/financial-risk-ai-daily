主字典完整学习卡｜今日升级

RPC｜Right Party Contact Rate｜有效本人联系率

1. 是什么：真正联系到借款本人并形成有效沟通的比例；大白话是“催收有没有找到对的人”。

2. 为什么重要：贷后同步过程指标，是PTP/Cure上游；RPC高不等于催收价值高。

3. 精确定义：RPC = 成功与借款本人有效沟通的账户/案件 ÷ 进入可触达队列并完成规定尝试的账户/案件固定D+1/D+3窗口、有效沟通标准、账户/案件口径；不要用呼叫次数作账户级分母。

4. 如何看：高通常代表触达改善，但如果靠高频呼叫换来投诉上升、PTP Kept/Cure下降，则越高越差；下降也可能是号码质量、运营商拦截或系统故障。

5. 墨西哥案例七步法

背景：14天首贷，渠道C扩量，DPD1统一增加人工电话。
数据：8,000案件；RPC 46%→55%；PTP 28%→43%；PTP Kept 64%→42%；Cash Cure@D+7 39%→35%；投诉0.7%→1.9%；成本/账户MXN18→31。
现象：联系和承诺更多，但兑现、治愈和成本更差。
拆解：Channel×Score×Limit×Pay-history显示，高Score历史按时客多数可数字自愈，低Score高Limit更需要人工。
根因：统一人工策略与效率下降相关，但渠道结构也变化，因果需Challenger验证。
决策：稳定客群数字自助；高风险低触达客保留人工；KPI不再只考核RPC。
结果：观察2-4周PTP Kept、Cash Cure、Forward Roll、投诉、成本。

6. 诊断：号码/系统 → Channel/时段/运营商 → Contact Attempts/RPC → PTP/PTP Kept → Cure/Roll/Complaint。

7. 动作：清洗号码、调整触达时段、多渠道合规触达；RPC高但兑现低时改话术和KPI；高投诉时降低频次并强化自助。

8. 误区：接通=RPC；用Attempt次数作分母；RPC越高越好；忽略投诉/成本。

9. 拆分：DPD、Channel、Score、Limit、Region、Carrier、Time Slot、Collector/Vendor、Strategy Version。

10. 预警：同DPD/同产品/同策略最近稳定历史做基线；示例黄灯为RPC上升但PTP Kept/Cure连续下降，红灯再叠加投诉/成本恶化。

11. 关系：Contactability → RPC → PTP → PTP Kept → Cure → Roll → DPD30+

12. 小练习

A组RPC60%、PTP Kept35%、Cure29%；B组RPC48%、PTP Kept68%、Cure41%。如果成本接近，哪组更好？答案：B。

PTP Rate｜Promise to Pay Rate｜承诺还款率

1. 是什么：有效联系后形成明确“日期+金额”还款承诺的比例。

2. 为什么重要：贷后同步指标，位于RPC与PTP Kept之间；高PTP只有在兑现质量高时才有价值。

3. 精确定义：PTP Rate = 规定窗口内形成合格PTP的RPC账户 ÷ RPC账户明确承诺日期和金额；模糊“尽快还”不能算；账户级去重，重复承诺另行统计。

4. 如何看：适度提升通常有利，但若坐席为KPI制造低质量承诺，PTP会升而PTP Kept下降；用户直接付款增多时PTP下降也可能是好事。

5. 墨西哥案例七步法

背景：催收商把KPI改成PTP数量。
数据：RPC52%→58%；PTP31%→48%；PTP Kept63%→39%；平均承诺MXN820→570；Collection18%→18.4%；投诉1.0%→1.8%。
现象：承诺大幅增加，真实回款几乎没改善。
拆解：少数坐席大量创建小额短日期PTP，历史低兑现用户重复承诺。
根因：KPI激励与低质量PTP相关，仍需对照组验证因果。
决策：KPI改为PTP Kept + Cash Collected + Complaint；重复失约转更合适策略。
结果：观察PTP Kept、Cure、Collection、承诺金额、成本和投诉。

6. 诊断：PTP定义 → 承诺金额/日期 → Collector/Vendor → PTP Kept → Collection/Cure。

7. 动作：高PTP低兑现时提高合格PTP标准、改激励；低风险客数字自助；高风险重复失约升级策略。

8. 误区：PTP越多越好；模糊承诺算PTP；重复承诺重复计数；只看件数不看金额。

9. 拆分：DPD、Collector、Score、Limit、Cycle、Promise Amount/Date、历史PTP Kept、Strategy Version。

10. 预警：PTP Rate、PTP Kept、Average Promise Amount、Cash Cure联合预警；阈值由内部成熟历史确定。

11. 关系：RPC → PTP → PTP Kept → Cash Collection / Cure → Roll → Recovery

12. 小练习

A团队PTP50%、Kept38%；B团队PTP32%、Kept72%。哪个承诺质量更好？答案：B，仍需看Collection/Cure。

Cure Rate｜治愈率

1. 是什么：进入某逾期Bucket后，在规定窗口恢复到正常/满足Cure标准的比例。

2. 为什么重要：贷后核心同步/滞后指标，早期Cure影响DPD30+、Recovery和LGD。

3. 精确定义：Cure = 观察期达到规定Cure标准的期初逾期账户/余额 ÷ 期初该逾期Bucket账户/余额固定D+7/D+30、件数/余额、Full/Partial、Extension/Restructure；建议Cash Cure单列。

4. 如何看：通常越高越好，但展期/重组或小额支付可能制造“技术性治愈”；件数Cure也可能掩盖大额未治愈。

5. 墨西哥案例七步法

背景：上线展期功能。
数据：总Cure42%→56%；Cash Cure39%→37%；Extension6%→24%；MOB2 DPD30+12%→13%；投诉1.1%→1.5%。
现象：表面Cure好转，真实现金治愈和中期风险没改善。
拆解：低Score高Limit重复展期用户后续Roll更差。
根因：总Cure被展期口径美化；中期因果需同Vintage验证。
决策：拆Cash/Extension Cure、限制重复展期、高风险用户优先真实还款安排。
结果：观察同Vintage MOB1/2 DPD30+、Recovery、投诉和LTV。

6. 诊断：Cure定义 → Cash vs Extension → 件数vs金额 → DPD/Score/Limit → Roll/Vintage。

7. 动作：Cash Cure低修支付/触达；Extension Cure高拆口径并限重复展期；高余额低Cure提高人工优先级。

8. 误区：Partial Payment算Cure；Extension和Cash Cure混用；观察窗口不一致；只看件数。

9. 拆分：DPD、Score、Limit、Term、Cycle、Channel、Collection Strategy、Extension Count、Balance Band。

10. 预警：同DPD/同Vintage/同策略比较Cash Cure；示例黄灯为连续两个成熟Cohort低于内部稳定区间且Forward Roll上升。

11. 关系：RPC / Payment UX → Cash Cure → Forward Roll ↓ → DPD30+ ↓ → Recovery / LGD → EL

12. 小练习

总Cure45%→58%，Cash Cure40%→34%，Extension5%→25%。能否说催收改善？答案：不能。

Roll Rate｜迁徙率 / 滚动率

1. 是什么：某DPD Bucket里的账户/余额在固定窗口迁移到另一个Bucket的比例。

2. 为什么重要：贷后资产质量和催收核心迁徙指标，通常早于最终Bad/Recovery发现风险。

3. 精确定义：Forward Roll A→B = 期初Bucket A中期末进入Bucket B的账户/余额 ÷ 期初Bucket A账户/余额固定Bucket、快照、窗口、件数/金额。Backward Roll/Cure分开。

4. 如何看：Forward Roll通常越低越好，但展期/重组可能造成假改善；不同产品/期限/成熟度不能直接横比。

5. 墨西哥案例七步法

背景：渠道C首贷扩量并提额。
数据：DPD1-7余额MXN18m；1-7→8-30金额Roll29%→38%；8-30→31-60 41%→47%；Cash Cure40%→34%；Limit1,450→1,850；总体DPD30+仅11.8%→12.0%。
现象：总体DPD30+几乎不动，但早期迁徙明显恶化。
拆解：渠道C最低两档Score、Limit≥2,000的1-7→8-30 Roll达52%。
根因：客群/额度变化与Roll恶化相关；新资产增加稀释总体DPD30+。
决策：低Score高Limit收紧；高Roll段提高早催；稳定客群保持低摩擦。
结果：观察同Vintage MOB1/2 DPD30+、Cash Cure、EL、Contribution Margin。

6. 诊断：快照/口径 → 资产成熟度 → Bucket迁徙 → Channel/Score/Limit → Cure/Extension → Vintage/EL。

7. 动作：早期Roll高加强分层催收；高风险段收准入/额度；支付事故先修技术；展期导致假改善则拆Cash Cure。

8. 误区：Bucket定义不一致；件数/金额混用；总DPD稳定就忽略Roll；展期假改善；新旧Vintage混用。

9. 拆分：Vintage、MOB、DPD、Channel、Score、Limit、Term、Cycle、Region、Payment Method、Strategy Version。

10. 预警：同Vintage同MOB、同Bucket建立基线；示例黄灯为连续两个成熟Cohort Forward Roll超出内部稳定区间且Cash Cure下降，红灯叠加DPD30+/EL恶化。

11. 关系：FPD / DPD Entry → Roll ↔ Cure → DPD30+ / Bad → Recovery / LGD → EL / Margin

12. 小练习

总DPD30+几乎不变，1-7→8-30 Roll从28%升40%，新放款余额占比也上升。风险稳定吗？答案：不能，应看同Vintage同MOB。

常用指标字典｜口径提醒

指标核心定义/提醒
RPC / PTP / PTP Kept触达→承诺→兑现；只追RPC/PTP会制造低质量承诺。
Cure / RollCash Cure与Extension Cure分开；Roll固定Bucket/窗口，并优先同Vintage同MOB。
Approval / Credit Approval总Approval固定漏斗分母；Credit Approval只看真正进入信用决策的申请。
Policy/Fraud DeclineFinal Decline与Rule Hit分开；和FPR、Confirmed Fraud、Fraud Loss联动。
Approval-to-Disbursement批准后成功到账；与Take-up、Payment/Disbursement Failure分开。
Fraud Alert / Alert-to-Case / TTD / TTCAlert数量不等于价值；Unique Entity、Case容量、发现/控制速度与Net Loss一起看。
KS / AUC / PSI / O-E区分度、漂移和Calibration职责不同；不能用单一指标替代EL/利润。
CAC / LTV / Contribution Margin低CAC不等于好渠道；LTV和Margin必须包含风险与Funding成本。
PD / LGD / EAD / ELEL=PD×LGD×EAD为业务简化口径；时间窗口必须兼容。
FPD / DPD30+ / Vintage / MOB总体DPD可能被新资产稀释；同Vintage同MOB优先。
Payment Failure / Auto-debit支付技术风险和信用风险分开归因；Error Code、Provider、Retry可追踪。
ATO / Fraud Loss / Step-up账户接管件数与金额双看；Step-up联动Pass、Abandon、Complaint。
Limit Utilization / Ticket / DTI / PTI额度、实际EAD和偿付能力联合；一次性与循环额度口径不同。
APR / CAT / Funding Cost / ROI价格、资金与收益跨期限统一；高价格不能自动覆盖高风险。
