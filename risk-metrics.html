KYC Completion Rate｜KYC 完成率

1）是什么：进入KYC的Eligible用户中真正走完全流程并产生可决策结果的比例。

2）重要性：贷前同步指标，是Identity Pass、Approval与CAC转化上游，首先回答“系统/用户有没有走完”，避免技术问题被误当风险。

3）公式：完成全部必需KYC并产生最终可决策结果的唯一申请 ÷ 实际进入KYC的Eligible唯一申请固定入口定义、观察窗口、重试去重和主动退出口径。

4）高低：通常高更好，但过度简化KYC也可能降低身份保证；下降可能来自Fraud，也可能来自SDK、网络、OCR、设备兼容或UX。

5）七步案例：背景：首贷更换活体SDK并扩大Channel B；数据：申请50k，Completion78%→70%、Liveness Fail5%→11%、Identity Pass91%→87%、Step-up68%→44%、Approval32%→27%、Identity Fraud2.8%→3.0%；现象：漏斗明显恶化；拆解：旧Android×Channel B×新SDK最差；根因：技术与流量结构共同变化；决策：技术Fallback、风险冲突再Step-up；结果：48-72小时看Error/Completion，成熟Cohort看Fraud/FPR/Margin。

6）诊断：Eligible/Start → Step Drop-off → Vendor/Error → Device/App Version/Channel → Fraud/Approval。

7）动作：超时修SDK/Fallback；OCR差优化拍摄；异常渠道降量；真实Identity Conflict再加强Step-up。

8）误区：未完成=Fraud；全申请作分母；多次重试重复计；不同KYC路径横比。

9）拆分：Channel、Vendor、Document、Device、OS/App Version、Region、Network、新老客、Strategy。

10）预警：同版本稳定历史+最小样本；Completion跌出内部区间且Technical Error同步升为技术黄灯。

11）关系：KYC Start → Completion → Identity Pass → Step-up → Approval → Fraud/FPR → Margin。

12）练习

40k进入、30k完成，Completion=75%。若降至65%且SDK Timeout翻倍，先查SDK/网络。

Identity Verification Pass Rate｜身份核验通过率

1）是什么：已完成且可判定的身份申请中最终通过证件/身份一致性的比例。

2）重要性：贷前同步指标，连接身份风险与审批漏斗。

3）公式：最终Identity Pass唯一申请 ÷ 已完成且具备可判定身份结果的唯一申请Technical No-result单列。

4）高低：高不必然好，可能阈值过松；下降也可能来自Vendor变化或证件质量。

5）七步案例：背景：Channel B低价流量扩量；数据：Completed35k，Pass91%→87%、Document Mismatch2%→5%、High-risk Device6%→9%、Fraud2.8%→3.6%、Approval31%→28%；现象：Pass下降且Fraud升；拆解：Channel B×新设备×低清晰度；根因：真实风险与拍摄质量同时变化；决策：高风险Step-up，低清晰度先重拍；结果：看Fraud Capture/FPR/Completion。

6）诊断：可判定分母 → Reason Code → Vendor/Version → Channel/Device → Fraud/FPR。

7）动作：Mismatch高强化真实性；图像差重拍；高风险Device叠加身份冲突Step-up/Hard Fail；Vendor漂移Fallback。

8）误区：Technical Fail算Identity Fail；Pass越高越好；未成熟用户当Good；不同Vendor阈值直接比。

9）拆分：Channel、Document、Vendor、Reason、Device、Score、Region、App Version、Strategy。

10）预警：同Vendor/阈值版本比较，并与Identity Fraud、FPR、Technical Fail联看。

11）关系：Identity Evidence → Identity Pass → KYC Pass → Approval → Identity Fraud Loss。

12）练习

20k可判定、17.6k通过，Pass=88%。若下降4pp而Fraud不变、Technical Fail大升，先查技术链。

Liveness Failure Rate｜活体失败率

1）是什么：得到有效活体结果的申请中Fail比例；不等于Fraud Rate。

2）重要性：身份/欺诈同步指标，同时高度受设备、相机、网络、SDK和阈值影响。

3）公式：有效Liveness Result中Fail唯一申请 ÷ 得到有效Liveness Result唯一申请Timeout/Technical Error单列。

4）高低：高可能攻击多，也可能技术差；低可能阈值过松。

5）七步案例：背景：新SDK；数据：Fail5%→11%、Technical Error3%→9%、Step-up Pass68%→44%、Identity Fraud2.1%→2.3%、旧Android Fail18%、iOS4%；现象：Fail翻倍但Fraud增量有限；拆解：旧Android+弱网；根因：兼容性是强候选因素；决策：旧设备Fallback、优化提示；结果：小时级看技术，成熟后看Fraud/FPR。

6）诊断：Technical vs Business Fail → Device/OS → Network/Camera → Vendor/Threshold → Fraud Outcome。

7）动作：旧设备Fallback；光线姿态做UX引导；攻击升高强化动态动作/设备信号；误杀高用Challenger调阈值。

8）误区：Liveness Fail=Fraud；Timeout也算Fail；只看整体；低Fail=安全。

9）拆分：OS、Device、Camera、Network、Vendor、Threshold、Channel、Region、App Version。

10）预警：技术预警小时级；风险预警等成熟Fraud；两类告警分开。

11）关系：Device/Attack → Liveness → Step-up/KYC Pass → Fraud Capture/FPR → Approval。

12）练习

10k有效结果、1.1k Fail=11%；另900笔技术错误不应加到Fail分子。

KYC Step-up Conversion Rate｜KYC 加强验证转化率

1）是什么：被要求追加身份验证的成熟用户中，最终完成且通过的比例。

2）重要性：贷前同步指标，是Allow和Hard Decline之间的缓冲层，决定误杀、Fraud Capture、体验与成本。

3）公式：规定窗口内完成且通过Step-up的唯一申请 ÷ 被正式要求Step-up且窗口成熟的唯一申请固定类型、有效期、重试和Technical Fail口径。

4）高低：高通常代表可恢复，但过高可能验证太弱；低也可能流程太难或技术故障。

5）七步案例：背景：新设备+Bank Change进入Face+Bank Match；数据：Step-up 6k、Conversion68%→44%、Technical Fail7%→19%、Fraud Capture+0.4pp、Complaint0.6%→1.4%、Approval-4pp、旧Android Conversion31%；现象：转化恶化；拆解：技术失败集中旧Android，真实高风险集中New Device+Password Reset+Bank Change；根因：技术与风险并存；决策：技术Fallback，三联高风险保留强Step-up；结果：成熟Fraud看Net Loss与Lost Good Margin。

6）诊断：Trigger → Start → Technical Fail → Pass/Fail Reason → Fraud/FPR/Approval。

7）动作：技术Fail高修SDK；低风险流程过重降摩擦；高风险高Pass但Fraud升则加强验证；投诉高减少重复Step-up。

8）误区：未开始不拆原因；窗口未成熟；不同Step-up类型混合；Conversion越高越好；只看转化不看Fraud。

9）拆分：Trigger、Step-up Type、Channel、Device、Score、Limit、新老客、Bank Change、Vendor、App Version。

10）预警：同Trigger/流程版本比较；Conversion↓+Technical Fail/Complaint↑为技术黄灯；Conversion高但Fraud Loss↑为验证不足红灯候选。

11）关系：Risk Signal → Step-up → Conversion → KYC Pass/Decline → Fraud/FPR → Approval/Margin。

12）练习

5k成熟Step-up、3k通过，Conversion=60%。另1k因SDK错误无法开始，应单独报告技术失败。
