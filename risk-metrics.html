今日联合判断框架

Alert Rate → Alert-to-Case → Case-to-Report → Case Aging / Backlog → QA / Missed Risk

单独看Alert数量没有意义。若 Alert Rate上升、Alert-to-Case和Case-to-Report下降、P90 Aging和Backlog同时恶化，更像低质量扩量；若Alert和后续Yield同时上升且高风险Case时效稳定，才更像真实风险上升。

AML Alert Rate｜反洗钱警报率

1）是什么：被监控交易/客户中产生Alert的密度。

2）重要性：同步/领先运营指标，用于识别规则、流量、交易行为和数据变化；它衡量“监控有多敏感”，不是“洗钱风险有多高”。

3）公式：交易口径 = 唯一Alert数 ÷ 被监控交易数；客户口径 = 产生Alert的唯一客户 ÷ 被监控客户固定Rule Version、去重、时间窗口；后续Yield需等Case Outcome成熟。

4）高低：高可能真实风险上升，也可能阈值变严/重复Alert；低可能风险下降，也可能规则失效/数据缺失。

5）七步案例：Rule V3上线后，月120k交易，Alert Rate 2.8%→5.1%，Alert-to-Case 42%→29%，Case-to-Report 8%→6%，P90 Aging 36h→82h，Backlog 420→1,150；噪声集中稳定老客固定第三方低额代还，高风险集中新设备+新付款人+资金循环+Bank Change；决策是低风险降优先级、高风险Fast Lane，观察2-4周Yield和QA。

6）诊断：Rule/Data Version → Segment → Alert-to-Case/Report Yield → Aging/Backlog → High-risk Coverage。

7）动作：数据问题先修数据；低Yield高量Rule调阈值/合并重复Alert；高Yield高风险Rule提高优先级。

8）误区：Alert=可疑交易；Alert越低越好；Rule Hit重复计数；不同版本直接比较。

9）拆分：Rule、Customer Risk、Channel、Region、Payer/Beneficiary、Device、Amount、Velocity、Version。

10）预警：同版本历史带+最小样本量；Alert超历史P90且后续Yield下降、Backlog升可设内部黄灯，仅为示例。

11）关系：Risk Signal → Alert → Case → Report → Investigation Cost / Regulatory Risk。

12）练习

120,000笔交易、6,000 Alert，Alert Rate=5%。若Alert-to-Case同时由40%降至25%，先查规则噪声，不直接认定风险更高。

Alert-to-Case Escalation Rate｜警报升级案件率

1）是什么：完成初筛的成熟Alert中，最终升级正式调查Case的比例。

2）重要性：衡量Alert的调查价值和人工产能是否被噪声占用。

3）公式：升级正式Case的成熟唯一Alert ÷ 已完成Triage的成熟唯一Alert必须处理多Alert合并一Case。

4）高低：过低可能规则噪声高；过高可能入口过窄。应与Case-to-Report、QA、Missed Risk联看。

5）七步案例：5,900个完成Triage的Alert，1,711升级Case，约29%；旧版42%。Rule A稳定第三方低额代还仅12%，Rule B新设备+新付款人+Bank Change达68%；A降为批量低优先级，B进入Fast Lane。

6）诊断：Triage成熟度 → 去重 → Rule/Segment → Case Outcome → Report Yield/QA。

7）动作：低Escalation高量Rule调阈值；高Escalation高风险RuleFast Lane；高Escalation但低Report Yield则检查Case定义。

8）误区：未完成Triage进分母；重复Alert重复计数；高Escalation=高质量。

9）拆分：Rule、Risk、Channel、Amount、Velocity、Device、Analyst、New/Repeat。

10）预警：低于自身稳定历史同时Backlog升可设噪声治理黄灯；非行业统一阈值。

11）关系：Alert Volume × Escalation → Case Volume → Aging/Backlog → Report Yield。

12）练习

5,900 Alert中1,711升级Case，Escalation≈29%。

Case-to-SAR / STR / ROIU Conversion Rate｜案件转法定可疑报告率

1）是什么：成熟并完成调查的Case中，最终提交法定可疑报告的比例。

2）重要性：滞后质量/产出指标，连接规则、调查和法定义务；不同司法辖区标准不同。

3）公式：最终提交报告的成熟Case ÷ 已完成调查并可作最终处置的成熟CaseOpen Case排除；处理多Case合并一份报告。

4）高低：不是越高越好。低可能Case噪声高；极高也可能入口过窄而漏弱信号。

5）七步案例：成熟关闭1,600 Case、报告96，比例6%，旧版8%；低风险代还场景约1.5%，新设备+新付款人+资金循环约21%；低Yield场景调Rule/Triage，高Yield场景Fast Lane，同时用QA确认没有少报。

6）诊断：成熟度 → Jurisdiction/标准 → Rule/Segment Yield → QA → Retrospective Miss。

7）动作：低Yield规则优化；高Yield高风险加优先级；报告率下降且漏报/QA变差才强升级。

8）误区：Open Case进分母；跨司法辖区比较；把报告率当越高越好的KPI。

9）拆分：Rule、Risk Rating、Channel、Customer Type、Region、Amount、Network、Analyst。

10）预警：报告率下降同时Retrospective Miss升，才是强红灯候选。

11）关系：Alert Quality → Case Yield → Report Yield → Regulatory Reporting Quality。

12）练习

1,800个成熟Case中120份报告，Case-to-Report≈6.7%。

AML Case Aging / Investigation TAT｜案件账龄与调查时效

1）是什么：从Case创建到观察时点/最终处置的时间。

2）重要性：同步运营与控制有效性指标，高风险Case处理过慢可能带来持续交易、漏报和监管风险。

3）公式：Case Age = Observation Time − Case Created；TAT = Final Disposition − Case Created至少报告P50/P90/P95，Open/Closed分开。

4）高低：一般越短越好，但过短可能是机械批量关闭，必须与QA/Report Yield联看。

5）七步案例：P50 18h→31h、P90 36h→82h、Backlog 420→1,150，高风险Case超内部48h SLA从9%→27%，QA Error 3%→5%；根因是低质量Alert扩量+Priority不足，决策为高风险Fast Lane、低风险批量Triage、重复Alert合并并同步Rule Tuning。

6）诊断：Timestamp → Backlog → Severity/Priority → Rule Mix → Capacity → QA/Outcome。

7）动作：高风险加权；低风险自动化+抽样QA；持续SLA breach且漏报升时升级P0。

8）误区：只看平均TAT；忽略Open Case；不同Severity混合；追求速度牺牲质量。

9）拆分：Severity、Rule、Risk、Team、Shift、Channel、Region、Amount、Outcome。

10）预警：使用内部SLA和历史P50/P90；高风险超SLA比例持续上升且QA变差可设红灯，小时数不是行业标准。

11）关系：Alert → Case Volume → Backlog → Aging → Delayed Action/Reporting Risk。

12）练习

10/12/14/20/90小时的5个Case，仅看平均29.2小时会掩盖90小时长尾，应同时看P50/P90。
