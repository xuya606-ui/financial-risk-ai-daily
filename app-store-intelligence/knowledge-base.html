01｜开发者账户与安全治理

账户是 APP 的法律主体、品牌资产和发布权限载体。

Google Play

账号类型与验证

受监管金融业务应优先使用与真实服务主体匹配的组织账号。台账记录法律实体、注册地址、D‑U‑N‑S、官网、域名邮箱、验证状态、付款资料和管理员。

Apple

Account Holder 与角色

Account Holder 掌握协议、会员和核心权限。按 Account Holder、Admin、App Manager、Developer 分工，禁止多人共用主账号。

账号资产台账

账号关联公司主体、APP、package name/Bundle ID、证书、API Key、双重认证设备、恢复方式、Owner 和离职交接记录。

账户安全 SOP
  • 双重认证，不共享验证码和主密码。
  • 按最小权限分配角色；离职当天撤销权限、API Key、证书和设备。
  • 主体名称、地址、官网、D‑U‑N‑S 变化时触发商店影响评估。
  • 保存账号验证、协议签署、付款和重大审核事件时间线。
  • Google Play 包名注册和 Android developer verification 状态纳入账号台账。

Google Play target API 长期门禁

规则基线：自 2026-08-31 起，Google Play 新的移动应用和应用更新必须 target Android 16 / API 36 或更高；现有移动应用至少 target Android 15 / API 35，才能继续面向运行高于应用 target API 的新用户保持可用。官方允许符合条件的开发者申请延期到 2026-11-01。

落地：每个 APP 台账固定记录 current targetSdk、next release targetSdk、compileSdk、关键 SDK 兼容状态、延期状态。发版门禁不得只检查“能否编译”，还要跑登录、KYC、相机/文件选择、推送、深链、WebView、支付/还款等回归。

Apple 年龄分级/社交媒体能力门禁

Apple 2026-07-09 已把“社交媒体能力”加入年龄分级问卷；从 2026 年 9 月开始，提交新 App 或更新时需要回答。普通现金贷产品通常不存在公开内容传播能力，但若 APP 包含社区、公开评论、UGC feed、内容转发/互动等，应由产品和合规共同判定，并与 App Information 中答案一致。

每次发版最低检查集
  • 版本号、package name/Bundle ID、签名、环境、API 地址正确。
  • Google target API / Apple SDK 最低要求已满足。
  • 截图、商店文案、隐私政策、客服与当前产品一致。
  • 审核账号可登录，OTP/风控不阻断审核。
  • 新增 SDK、权限、采集字段同步更新隐私声明。
  • 金融参数变化同步复核 APR、期限、费用、代表性示例。
  • 灰度发布定义监控指标、回滚阈值和负责人。

03｜隐私、权限、数据生命周期与 SDK

数据生命周期

按采集→传输→使用→共享→保存→删除建立数据地图，每个字段记录用途、合法性/同意、保存期和第三方接收方。

权限最小化

区分必需、可选、高风险权限；真正需要时再申请，并提供用户可理解的用途说明。

SDK 治理

维护广告、归因、风控、推送、客服、分析 SDK 的版本、采集字段、权限、域名、数据去向和 Owner。

Data safety / App Privacy 四方对账

同时核对真实代码与网络行为、Google Data safety、Apple App Privacy、隐私政策。第三方 SDK 或 AI 集成也属于开发者责任范围。

账户与数据删除

删除入口应可发现、流程可完成、后端真正执行，并说明依法保留的数据；网页删除入口和商店声明持续有效。

04｜金融 / 贷款披露、声明与发布材料

商店文案不是营销孤岛：APR、期限、费用、还款示例、主体名称和资质信息必须与 APP、合同、客服和实际配置一致。

统一贷款披露

维护利率/APR、期限、费用、代表性总成本、还款计划的单一数据源，产品参数变化自动触发商店复核。

贷款数据红线

把联系人、照片/媒体、电话、精确定位等纳入高风险权限扫描，并检查 SDK 是否间接引入。

Financial features declaration

声明与真实业务模式保持一致；直接放贷、撮合、信用相关服务分别维护业务说明和证明材料。

金融 APP 发布材料包
  • 公司注册/主体证明及其与开发者账号的关系。
  • 适用许可、注册或合作机构证明/业务模式说明。
  • 费率、期限、费用参数表及代表性示例。
  • 隐私政策、用户协议、合同样本、客服渠道。
  • 审核测试账号和完整借款测试路径。
  • 品牌、运营方、资金/放贷方不同则准备关系说明。

05｜🇲🇽 墨西哥主体、本地化与审核证据

主体

七类主体关系

区分开发者账号、APP 品牌、实际运营、合同、资金/放贷、隐私责任、客服主体，并保存法律/商业关系证明。

登记

SIPRES / RECA / SOFOM 台账

SIPRES用于核验金融机构身份和状态；RECA用于查询金融机构标准合同。对 SOFOM E.N.R. 还应把 SIPRES、RECA、RECO、UNE 等运营义务纳入内部台账。

品牌安全

防冒名证据包

CONDUSEF 2026 年持续通报金融机构名称、Logo、网站和移动 APP 被冒用。建议每月保存官方登记、官网、商店页、开发者名、客服联系方式与品牌素材截图。

墨西哥品牌防冒名 SOP
  • 固定“官方 APP 清单”：包名/Bundle ID、商店链接、开发者主体、品牌名、官网域名。
  • 每月留档 SIPRES/相关登记与商店页面截图，形成时间证据。
  • 监测同名/近似名 APP、近似 Logo、非官方 WhatsApp/网站及提前收费话术。
  • 发现仿冒后同步准备商店投诉、品牌/主体证明、官方登记证明和用户风险公告。
  • 内部所有营销落地页、客服号码与商店页保持一致，降低用户和审核员识别成本。

06｜审核、拒审、申诉案例与模板

拒审类型优先排查动作
贷款政策APR、期限、费用、披露、金融声明先修产品/文案，再回复政策点
权限/隐私Manifest、SDK、运行时权限、声明删除非必要权限并给版本证据
主体/资质开发者、合同、牌照/合作关系提供主体关系和证明
无法审核登录、OTP、地区、风控、测试账号稳定 Demo account + Review Notes
技术要求target API、SDK、构建配置升级并完成关键链路回归
标准申诉结构

①确认政策问题；②说明根因；③列出已完成修改；④提供版本号、页面路径、截图/证明等验证方法；⑤请求基于新版本重新审核。若问题属于明确的技术提交门槛（如 target API），优先完成整改而不是争论规则。

07｜长期运营治理、政策雷达与指标复盘

政策雷达

记录发布日期、生效日、平台、影响 APP、风险级别、Owner、截止日、完成和验证状态。

发布门禁

高风险项未关闭不得发布；产品、研发、法务、运营共同确认 Checklist。

证据留档

保存每版商店文案、截图、声明、隐私政策、审核消息、官方登记和申诉，形成可追溯版本库。

建议月度复盘指标
  • 一次审核通过率、平均审核时长、拒审次数。
  • 技术门槛、元数据、权限、主体、金融政策导致的拒审占比。
  • 政策变更按期完成率、高风险待办逾期数。
  • 账号管理员、SDK、target API 和主体登记台账完整率。
  • 商店声明与真实产品抽检一致率。

08｜术语与学习地图

构建与发布

targetSdkVersion：应用声明适配的 Android API 级别；compileSdk：编译使用的 SDK。Bundle ID / package name：应用唯一标识。

隐私与数据

Data safety：Google Play 数据声明。App Privacy：Apple 隐私标签。SDK：嵌入 APP 的第三方软件组件。

墨西哥金融

SIPRES：金融服务提供者登记查询；RECA：标准合同登记查询；APR/CAT/期限/费用需在产品、合同与商店披露之间建立可核对关系。

推荐学习顺序

账号与标识 → 构建/target API → 上架与审核 → 隐私/权限/SDK → 金融专项 → 墨西哥主体与登记 → 拒审申诉 → 审核监控和长期治理。
