为什么要建立官方 APP 身份证据包

Google Play 自 2026-09-30 起要求 Play package 完成注册并完成开发者身份验证；Apple 组织会员的法律实体名称会作为 App Store seller 显示，组织注册还依赖 D‑U‑N‑S、工作邮箱与公开官网。CONDUSEF 在 2026-09-08 的安全提醒中，直接建议用户只从 Google Play / App Store 等官方商店下载，并在安装前核验是否为金融机构官方 APP。因此，商店账号、包名/Bundle ID、签名、官网、金融主体和品牌授权应形成同一套长期证据。

二、发布门禁

P0

八项一致性

每次生产提审前验证：entity_match / store_seller_match / package_bundle_match / signing_identity_match / official_domain_match / regulatory_evidence_fresh / impersonation_scan_status / takedown_owner。

任一主体漂移、签名异常、package 注册异常或高风险冒用未处置时，状态进入 IDENTITY_EVIDENCE_BLOCKED，禁止继续提审或放量。

变更触发器

哪些变化必须重做证据包

开发者账号迁移、App Transfer、公司更名、签名 key 轮换、Bundle/package 调整、官网域名切换、品牌授权主体变化、金融牌照/登记变化、Store seller/developer name 变化，都要触发完整 Diff。

三、反冒用扫描

至少每周一次，以品牌名、Logo、近似拼写、贷款关键词、公司名、package/Bundle 近似串，在 Google Play、App Store、Web 与主要社媒渠道做搜索。记录 discovered_url / store / developer_name / package_or_bundle / icon_hash / screenshot_hash / first_seen_at / evidence_capture / risk_level / takedown_ticket / status。

风险分级：P0 = 使用相同品牌/Logo 且提供贷款或索取敏感数据；P1 = 高度近似品牌或误导性名称；P2 = 内容引用但不构成 APP 冒用。P0 应立即取证、投诉和用户告警。
CONDUSEF：只从官方商店下载并核验官方 APP ↗

四、🇲🇽 墨西哥映射

主体一致性

SIPRES × Store seller × 合同主体

建立三方映射：监管登记名称、Google/Apple 商店展示主体、借款合同/Carátula 主体。名称不完全一致时必须保留集团关系、商标授权、运营授权或服务关系说明。

SIPRES 官方入口 ↗RECA 官方入口 ↗
用户安全

官网增加“官方 APP 核验页”

建议公开展示 Google Play / App Store 正式链接、开发者/卖家名称、package/Bundle ID（可选展示技术标识）、官方客服与防诈骗声明，便于用户和客服核验。不要通过短信、WhatsApp 或社媒发送可执行安装包。

五、假 APP 处置 Runbook

  1. 立即保存商店 URL、开发者名、包名/Bundle、图标、截图、描述、下载量/评分（如可见）和 UTC 时间戳。
  2. 与 OFFICIAL_APP_IDENTITY_PACK 做差异对比，形成机器可读 Diff。
  3. 提交 Google Play / Apple 的品牌、冒用或安全投诉，并记录 ticket / case ID。
  4. 如涉及墨西哥金融机构身份冒用，同步法务、合规、客服和当地监管沟通流程。
  5. 对受影响用户发布官方渠道核验指引，强调只从官方商店和官网入口下载。
  6. 关闭事件后保存 first_seen → reported → platform_ack → removed → postmortem 时间线，并复盘检测遗漏。
