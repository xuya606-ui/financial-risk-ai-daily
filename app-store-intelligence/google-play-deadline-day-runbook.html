Google Play 截止日发布战情室 Runbook

把 Target API、Play Billing、package registration 等“硬截止日”转成可重复执行的跨部门发布机制。目标不是当天临时救火，而是留下完整的版本、控制台和整改证据。

情报首页长期知识库合规工作台执行流程台账字段异常分流
适用

硬门槛

Target API、Play Billing Library、Play package registration、账号验证、技术质量执行日、受限制权限强制日期等。

输出

最小证据包

版本号/Build、政策原文、Play Console 状态、提交时间、测试结果、延期状态、失败截图、Owner、回滚版本、最终审核结果。

01｜截止日当天 7 步流程

1

冻结发布范围

列出今天必须提审、可延期、无需更新的全部 APP/package；停止非必要需求合并，避免最后时刻引入新 SDK、权限或配置。

2

逐包资产盘点

记录 package_name / versionCode / targetSdk / compileSdk / signing_cert / billing_version / release_track，并与 Play Console 当前线上版本对账。

3

核心合规回归

现金贷 APP 至少覆盖登录/OTP、KYC/OCR、相机/文件、额度、APR/费用、借款确认、合同、还款、Push/Deep Link/WebView，以及第三方风控/归因 SDK。

4

提审或延期

满足门槛则提交；无法满足时，在 Play Console 存在官方 extension form 的情况下立即完成延期，并保存表单提交证据。

5

保存 Console 证据

截图/导出 Policy status、App bundle explorer、Target API、Billing warning、package registration、review status、extension 状态，统一绑定 submission/release ID。

6

异常即时分流

构建失败、政策阻断、审核账号失败、SDK 不兼容、敏感权限命中、控制台状态异常分别进入对应 Owner，不允许只有一条“发布失败”大工单。

7

24h / 72h 发布后检查

确认审核结果、可发现性、崩溃/ANR、登录/KYC成功率、关键漏斗、商店页信息与权限声明，必要时启动回滚或热修。

03｜Target API 截止日专用检查

2026-08-31

Android 16 / API 36

新移动 APP 和更新需 target API 36+；现有移动 APP至少 target API 35 才能继续面向更高 Android 版本的新用户保持可发现性。符合条件的开发者可申请延期至 2026-11-01。

Google 官方原文 ↗
现金贷额外回归
  • OTP / 短信自动读取替代方案是否正常。
  • KYC/OCR/相机/文件选择权限与 Android 16 行为变化是否兼容。
  • 通知、后台任务、Deep Link、WebView 是否正常。
  • APR/费用/期限/合同页面与商店披露是否一致。
  • 风控/归因/设备 SDK 是否崩溃、误采敏感数据或改变 Manifest。

04｜Play Billing 条件性门禁

只有实际使用 Google Play Billing 的 APP 才适用。PBL 7 的新 APP/更新截止为 2026-08-31，扩展截止为 2026-11-01。现金贷 APP 如果没有数字商品/IAP，一般不应机械引入 Billing 依赖。

异常优先 Owner第一动作
targetSdk 不达标Android冻结非必要改动；完成目标 API 构建或申请官方延期
Billing version 过期Android / 支付确认是否实际需要 Billing；需要则升级，否则清理无效依赖

审核账号无法登录后端 / QA / 发布立即恢复稳定 demo account，避免 OTP/风控阻断
Console extension 未提交发布 Owner在截止日前完成表单并保存截图/确认信息
发布后崩溃或漏斗异常Android / 后端 / 风控启动回滚阈值判断并对关键链路做分层诊断

06｜截止日之后的复盘

复盘不是看“有没有过审”就结束。应统计：按时完成率、临时延期率、首次提审通过率、因 SDK/权限导致的阻断、审核账号失败、回归缺陷、发布后事故、证据完整率，以及下一次门槛提前多少天进入黄色/红色状态。
