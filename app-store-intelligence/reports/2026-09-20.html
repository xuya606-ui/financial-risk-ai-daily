产品 / 研发影响

把“提交版本”从一个 Build 号升级成完整 Evidence Manifest

建议 release pipeline 在 RC 产出时自动生成 canonical JSON，至少包括：platform / package_or_bundle / version / build / git_commit / artifact_sha256 / signing_cert / merged_manifest_hash / entitlements_hash / privacy_manifest_hash / sdk_inventory_hash / store_listing_hash / data_safety_hash / app_privacy_hash / financial_declaration_hash / loan_config_hash / regulatory_evidence_hash。然后生成唯一 submission_evidence_sha256。

如果任何 SDK、权限、Store listing、资金方、合同主体、APR/期限/费用、Data safety 或 App Privacy 发生变化，就必须重新生成 Evidence Manifest，旧指纹不能继续用于新版本申诉。
