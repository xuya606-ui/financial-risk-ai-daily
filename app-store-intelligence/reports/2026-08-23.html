今日新增｜Apple App Review Information 门禁

Apple · 2026-08-19提审可用性

审核联系电话改为国际格式校验

Apple App Store Connect Release Notes 在 8 月 19 日新增说明：App Review 联系电话必须采用国际格式，例如“+852…”，字段不接受仅数字输入。平台版本信息页同步给出同一规则。

墨西哥 APP 建议：审核联系人号码统一使用 +52 国家代码的完整可接通号码，并建立发版前自动/人工校验。不要只改格式，还应确保审核窗口内有人能接听或及时响应邮件。

长期知识

Demo account 不得过期

Apple 明确要求：如果 APP 需要登录，必须提供审核用用户名和密码；该 demo account 用于 App Review，不能过期。若使用 SSO，也应提供对应 demo 登录信息。

信贷 APP 落地：审核账号不要依赖一次性 OTP、短时白名单或容易被风控锁死的状态；应能稳定进入实名、额度、借款、费用、合同等核心路径。

Apple App Review Information ↗
长期知识

Review Notes 变成“审核导航”

Apple 允许在 Notes 中补充帮助审核的说明。对现金贷 APP，建议固定写清测试账号、目标国家、贷款模式、主体关系、KYC 测试路径、APR/费用展示位置、合同路径，以及任何特殊测试开关。

内部字段：review_contact_name、review_email、review_phone_e164、demo_user、demo_expiry、review_path、special_settings、last_verified_at。

Google Play 高风险节点

P0 · 2026-08-26Google Play

Geofencing 从获批 foreground service 场景移除

Google 的 Play 政策时间轴显示，2026-08-26 起 geofencing 不再属于获批的 foreground service 使用场景，开发者可使用 Geofence API。

现金贷特别判断：个人贷款/贷款导流/信用辅助类 APP 当前 Financial Services policy 已明确禁止 ACCESS_FINE_LOCATION。因此正确顺序不是“把 FGS 换成 Geofence API”，而是先确认该贷款业务是否应该采集精确位置；多数核心现金贷流程应优先删除不必要的位置能力。
Android / Google Play Policies 时间轴 ↗ Google Financial Services Policy ↗
P0 · 2026-08-31Google Play

Target API 36：距截止约 8 天

Google 继续要求从 2026-08-31 起，新移动 APP 和更新 target Android 16 / API 36+；现有移动 APP 至少 target API 35 才能继续向运行更高 Android 版本的新用户保持可发现性。

建议：未完成的包必须明确 Owner、提审日期、是否申请延期、回滚计划，并完成 OTP/KYC/相机/文件、通知、Deep Link、WebView、后台任务和关键 SDK 的 API 36 回归。

2026-09-30Android verification

区域执行不直接包含墨西哥，但 package 治理不要延后

Android developer verification 的 2026-09-30 区域节点先覆盖巴西、印度尼西亚、新加坡和泰国的参与商店；2027 年及以后再向全球认证 Android 设备扩展。Google 同时表示 Play 已自动注册约 99% 的应用，仍应检查剩余 package。

墨西哥产品：无需把 9/30 误写成“墨西哥强制生效日”，但现在仍应完成 package name、开发者身份、当前/历史 signing key、自动/手动注册状态台账。
