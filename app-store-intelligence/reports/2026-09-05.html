今日新增

Pre-review checks ≠ Formal review

Google 官方说明，Pre-review checks 会在 Play Console 中自动运行，用于在正式提交审核前发现潜在问题；这些检查通常在 15 分钟内完成，而且“全部通过”并不保证正式 App Review 一定通过。正式审核是之后的独立流程，部分开发者账号可能需要最多 7 天或更久。

审核监控影响：Dashboard 应新增 review_phase：PRE_REVIEW_RUNNING / PRE_REVIEW_CLEAR / SENT_FOR_REVIEW / FORMAL_REVIEW / RESULT。只有进入 FORMAL_REVIEW 后才对审核账号行为做 machine_score / human_score，避免把自动预检误判为“机器审核”。

今日新增长期知识｜Google 审核监控 V2

审核监控

把审核链路拆成 5 个阶段

推荐统一状态机：PRE_REVIEW_RUNNING → PRE_REVIEW_CLEAR/BLOCKED → SENT_FOR_REVIEW → FORMAL_REVIEW_IN_PROGRESS → APPROVED/REJECTED。Google 已明确 Pre-review checks 是自动运行、发生在正式审核前的独立机制，因此不能把预检事件、快速 API 探测或 Console issue 直接解释为“Google 机器审核已开始”。

Session 识别原则：以专用审核账号 + 服务端 session + 页面/API 事件为主；IP/ASN/地区/设备只能作为辅助。机器/人工只输出概率标签，不输出确定结论。正式审核可能最长 7 天或更久，故应同时记录 sent_for_review_at、first_review_session_at、result_at，并计算 review_latency。
Pre-review checks ↗Publishing status / Review time ↗App access / Sign-in details ↗进入 Google 审核监控 →
边界：该模型用于内部运营诊断和审核可达性提升，不能声称识别了 Google 内部员工、内部 IP 或真实审核系统，也不应尝试规避或欺骗审核。
