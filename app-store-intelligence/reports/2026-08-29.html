Target API 36：进入最后 2 天

从 2026-08-31 起，Google Play 新的移动 APP 和 APP 更新必须 target Android 16 / API 36+；现有移动 APP 至少 target API 35，才能继续面向运行高于其 target API 的新用户保持可发现性。符合条件的开发者可申请延期至 2026-11-01。

产品/研发影响：现金贷 APP 必须同步回归登录/OTP、KYC、OCR/相机、文件选择、通知、Deep Link、WebView、后台任务及风控/归因/推送 SDK，不应只看 targetSdk 数字。

Google Play今日长期知识

第三方 SDK 违规，责任仍由 APP 开发者承担

Google Play 当前 SDK Requirements 明确：APP 引入 SDK 后，开发者要确保第三方代码及其数据实践不会导致 APP 违反 Play 政策；Data safety 也必须包含第三方库/SDK 的数据收集、使用和共享。Google 的 SDK 安全最佳实践还建议使用 Play SDK Index 查看常见 SDK 的权限、注册状态及相关信息。

落地：发版前新增 SDK Diff：新增/升级/删除了什么 SDK？权限是否变化？数据字段/域名是否变化？是否存在 Play SDK Index/供应商警告？Data safety 是否同步更新？

AppleSDK 供应链

Privacy Manifest + SDK Signature 必须进入 iOS 发版门禁

Apple 明确要求开发者对第三方 SDK 中的代码和数据实践负责；对于 Apple 列出的常用第三方 SDK，在适用的新 APP 或新增 SDK 的更新提交中需要包含隐私清单，二进制依赖还需要签名。Xcode 会聚合 SDK 隐私清单，帮助生成更准确的 App Privacy 信息。

落地：iOS 发布前固定检查 xcprivacy、SDK Signature、Required Reason API、App Privacy 对账；任何 SDK 升级都视为“供应链变更”，需要保存版本、来源、签名和回滚版本。
