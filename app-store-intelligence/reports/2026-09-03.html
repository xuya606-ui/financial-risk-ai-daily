Google Play

P0 · 已执行Target API

API 36：继续检查执行后实际影响

自 2026-08-31 起，新移动 APP 和 APP 更新必须 target Android 16 / API 36+；现有移动 APP至少 target API 35，才能继续面向运行高于其 target API 的新用户保持可发现性。受影响 APP 可以在 Play Console 的 Policy status 中申请延期到 2026-11-01。

研发/发布影响：逐包确认 Play Console policy status、extension 状态、Android 16+ 可发现性，并完成登录/OTP、KYC、OCR/相机、文件选择、Push、Deep Link、WebView、后台任务和关键 SDK 的 24h/72h 稳定性复盘。

2026-09-30Package Registration

所有 Play package 必须完成注册

Google 当前明确要求：2026-09-30 起所有 Play package names 必须完成注册以满足 Android developer verification 要求；未注册的 APP 将依据 Play Console Requirements 从 Google Play 移除。Google 会自动注册大多数 APP，但历史换签、转移、多 key 或低安装量包仍可能需要手动处理。

建议字段：package_name、developer_account、identity_verified、registration_status、current_cert_sha256、historical_keys、manual_request、owner、deadline。

9/30 生效版本Play Console Requirements

金融 APP 同时复核 Organization、D-U-N-S 与审核账号

当前 Play Console Requirements 的 9 月 30 日更新版本明确：金融产品/服务开发者应使用 Organization 账号；组织资料需与 D-U-N-S 等信息保持一致；提交 APP 前要准确维护 metadata、隐私政策、Data safety，并提供有效 demo account / sign-in details 供审核使用。

产品/运营影响：不要把 9 月 30 日只理解为“package 注册日”。现金贷团队应同步检查开发者主体、D-U-N-S、官网/联系方式、Data safety、审核账号和业务主体证明。

数据边界

Apple Analytics 不应被当成用户级精确归因

Apple 明确说明，部分 usage/quality 数据只来自选择分享诊断与使用数据的用户，同时存在隐私阈值；Analytics Reports API 也会对低量数据进行阈值处理并加入隐私保护措施。因此跨系统分析应按周期、地区、版本、来源等聚合维度做趋势/断点诊断，缺失数据不能直接解释为 0。

社交媒体能力年龄分级继续作为 iOS 提审门禁
