01｜现金贷 APP 常见 AI / SDK 类型

身份

KYC / OCR / 人脸

证件影像、姓名、身份证号、生物特征、活体视频。通常属于高敏感数据，应单独记录用途、保留期与删除机制。

风险

反欺诈 / 信用评分

设备、行为、身份、交易、征信和模型特征。需要确认供应商是否将数据复用于模型训练或其他客户。

运营

客服 / 催收 / LLM

聊天文本、通话摘要、合同和借款信息可能进入生成式 AI 服务，需要额外关注提示词日志、模型训练、跨境和保留期。

02｜必须建立的数据台账

字段要回答的问题
vendor / sdk_name / version供应商和实际嵌入版本是什么？
data_fields具体发送哪些字段，不接受“用户数据”这种笼统描述。
purposeKYC、反欺诈、评分、分析、客服还是营销？
collection_trigger启动即采集、登录后、用户授权后、还是某页面触发？
storage_region数据存储在哪个国家/区域？是否跨境？
retention供应商和自身各保留多久？
model_training是否用于供应商模型训练、产品改进或二次用途？
deletion用户删除账号后，供应商侧如何同步删除？
privacy_disclosure在隐私政策、Data safety、App Privacy 的哪个位置披露？
owner内部谁对该接入负责？

04｜发布门禁

新增/升级 SDK 前
  • 完成字段级数据清单。
  • 核对 SDK 默认开启的权限和自动采集。
  • 确认训练用途、二次用途、跨境和保留期。
  • 完成隐私/法务评审。
打包前
  • 扫描 Manifest / entitlements / 网络域名。
  • 验证 SDK 实际启动时机和运行时权限。
  • 对比供应商文档与抓包/日志实际行为。
提审前
  • 更新 Google Data safety。
  • 更新 Apple App Privacy。
  • 更新隐私政策与用户授权文案。
  • 对金融 APP 再检查是否触碰 Google 明确禁止的敏感权限。

05｜账户验证权限迁移

截止：2027-01-27

READ_CALL_LOG 不再用于电话账户验证

Google 已公布：届时 READ_CALL_LOG 不再允许用于通过电话呼叫验证账户。推荐提前迁移到 SMS Retriever API、Digital Credentials API 或不需要敏感权限的验证方案。
