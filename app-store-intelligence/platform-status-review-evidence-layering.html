平台状态 × 审核证据分层

长期知识库专题｜适用：Google Play、Apple App Store、金融/信贷 APP、墨西哥发布治理

目标

避免把“平台无事故”“Build 已处理”“正在审核”“业务证据一致”混为一个状态。任何结论都必须绑定对应层级的官方或内部证据。

第 1 层：平台状态

记录官方 Status Dashboard 的状态、覆盖产品、最后更新时间和官方 incident URL。Google Play Dashboard 明确是部分产品试点，No incidents 不代表全部 Play Console 或审核队列正常。

官方原文：Google Play Status Dashboard

第 2 层：上传 / 处理状态

Google 侧看 Publishing API 等；Apple 侧区分 Processing、Failed、Complete。Apple 官方说明 Build 处于 Processing 超过 24 小时可能存在问题，应通过 Feedback Assistant 或联系 Apple。

官方原文：Build upload statuses

第 3 层：审核生命周期

Apple 至少区分 Waiting for Review、In Review、Unresolved Issues 等。Google 侧应保留 submission_id、审核状态、最后变更时间、重复提交时间与支持单号；不要用审核账号 Session 或单一时间线猜测“机器审核/人工审核”。

官方原文：App and submission statuses

第 4 层：业务与合规证据

将 Financial features declaration、Data safety、App Privacy、merged Manifest、SDK inventory、贷款披露、资金方/合同主体、墨西哥 SIPRES/PUR/RECA、官网与客服证据绑定到具体 Build。

官方原文：Financial features declaration · 官方原文：CONDUSEF RECA

推荐字段

platform_status affected_product incident_url status_checked_at build_status submission_status evidence_hash declaration_snapshot_id last_verified_at

发布门禁

  1. 平台状态异常只影响对应覆盖产品，不自动阻断全部提审。
  2. Build/Submission 状态未完成，不得用平台 No incidents 解释为“可上线”。
  3. 金融声明、权限、SDK、隐私或墨西哥主体证据发生漂移时，直接进入 EVIDENCE_DRIFT_BLOCKED。
  4. 正式发布必须同时满足四层证据可追溯。
