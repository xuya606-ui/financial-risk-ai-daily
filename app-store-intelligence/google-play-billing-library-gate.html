GOOGLE PLAY RELEASE GATE

Google Play Billing Library 版本门禁

把 Billing Library 版本作为 Android 发版前的条件性技术门禁：只有使用 Google Play Billing 的 APP 才适用；不使用 Billing 的现金贷 APP 可以明确标记 N/A。

情报首页长期知识库合规工作台
2026-08-31

当前关键截止

Google 官方弃用表显示，Play Billing Library 7 的新 APP / 更新截止日为 2026-08-31，延期截止为 2026-11-01。PBL 8 的对应截止是 2027-08-31；因此在没有延期的情况下，2026-08-31 之后提交的新 APP / 更新不应继续依赖 PBL 7。

01｜先判断是否适用

检查项判断
Manifest 是否包含 com.android.vending.BILLING有 → 进入 Billing 门禁；无 → 继续检查依赖树

03｜推荐升级目标

Google 当前集成文档示例使用 Billing Library 9.1.0；9.1.0 于 2026-06-18 发布。实际升级应结合现有代码改造成本决定，但不建议为了“最低过线”而忽略已经被删除或变更的 API。

Billing Library Release Notes ↗官方集成文档 ↗
升级回归重点
  • 购买流程成功/取消/失败状态。
  • 订阅续期、暂停、宽限期、账单重试。
  • 服务断开后的自动重连。
  • 产品详情加载、不可获取商品状态。
  • 服务器端 purchase token / entitlement 状态同步。
  • 老版本用户升级后的购买恢复。

04｜发版门禁规则

建议：在 CI/CD 中自动扫描 Billing permission 和 Gradle 依赖版本。若检测到 PBL 7 且无有效延期，则直接阻止生产提审；若完全不使用 Billing，则输出明确的 N/A 证据，而不是“不知道有没有”。
状态门禁
不使用 BillingPASS / N.A.
PBL 8+PASS，继续功能回归
PBL 7 + 有有效延期临时 PASS，记录延期截止
PBL 7 + 无延期BLOCK
无法确认版本BLOCK，先完成依赖审计

05｜与 Target API 双门禁联动

2026-08-31 同时是 Google Play Target API 36 的关键节点。建议把 Android 发版检查合并为一个“双门禁”：Target API 合规 + Billing Library 合规。任何一项失败都不进入正式提审。
