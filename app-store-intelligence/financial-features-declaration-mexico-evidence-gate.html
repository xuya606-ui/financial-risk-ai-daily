一、官方规则基线

1. 所有已发布到 Google Play 的 App 都要完成 Financial features declaration

Google 明确要求：App 只要已发布到 Google Play，closed testing、open testing、production 都需要完成 Financial features declaration；即使没有任何金融功能，也要声明“没有金融功能”。

Google Financial features declaration 官方原文 ↗

2. 金融功能要按真实能力声明，不按公司内部命名声明

Google 当前声明类别包含 Personal loan direct lender、Loan facilitator、Payday loans、Banking、Line of credit、Earned wage advances、Microfinance banking、Payments、Credit monitoring、Financial advice 等。选择逻辑应依据 App 实际用户流程、资金提供方、合同主体、放款/还款链路和用户可见功能，而不是内部把产品称为“平台”“导流”“技术服务”就自动决定声明类别。

声明类别官方原文 ↗

3. 个人贷款相关功能需要进一步提交贷款机构与业务关系信息

若 App 声明 Personal loan direct lender 或 Loan facilitator 等个人贷款相关能力，Google 要求进一步提供文档。对所有国家/地区，都需要说明所合作贷款机构及其与开发者业务的关系；对于政策列明的部分国家，还需要上传当地主管机构颁发的有效许可证明。

贷款相关补充材料官方原文 ↗

4. Developer account 与资质材料必须可建立关系

Google Financial Services 政策明确表示：开发者账号与任何用于证明金融产品经营能力的许可证/文件之间必须能够建立可验证联系；Google 还可能要求补充信息或文件，以确认符合当地法律和监管要求。

三、发布门禁状态机

正常

DECLARATION_MATCHED

真实业务能力、Play Console 声明、Store listing、合同与后台产品配置一致，可继续发版流程。

阻断

DECLARATION_DRIFT

功能、资金方、合作模式或用户流程已变化，但 Financial features declaration 仍是旧值。禁止提审/放量，先完成声明对账。

阻断

LENDER_RELATION_MISSING

无法证明开发者账号、App、贷款机构/资金方、合同主体之间的业务关系。先补授权、合作协议、主体映射与监管证据。

阻断

LOCAL_EVIDENCE_STALE

Mexico 本地证据过期或主体信息与商店/合同不一致。必须刷新 SIPRES/RECA/PUR 等可用证据及公司材料。

放行

READY_FOR_REVIEW

Declaration Diff、Lender Relation Check、Store/Contract/Backend 一致性与 Evidence Freshness 均通过。

四、🇲🇽 Mexico 专项判断

重要口径

Mexico 当前不在 Google 页面列出的 8 个额外国家级贷款要求示例中

截至 2026-09-18，Google Financial Services 当前页面列出的个人贷款“额外国家要求”包括美国、印度、印度尼西亚、菲律宾、尼日利亚、肯尼亚、巴基斯坦和泰国；页面未把 Mexico 列入该 8 国示例名单。

这绝不能解释为“墨西哥无需资质或主体证据”。Google 同一政策仍要求所有金融 App 遵守目标国家/地区的当地法律，并要求开发者账号与提交的许可证/证明材料之间能够建立可验证联系；Google 还可要求补充材料。Financial features declaration 页面也要求个人贷款相关 App 对所有国家/地区说明所合作贷款机构及业务关系。

五、Declaration Diff 触发条件

以下任一变化都应自动触发 Financial features declaration 重新对账，而不是等到被拒审后再处理：

  • 新增或删除贷款、额度、信用辅助、钱包、支付、保险、投资等功能；
  • Direct lender ↔ Facilitator / Lead generator 的商业模式变化；
  • 新增/替换资金方、贷款机构、合同主体或收款主体；
  • Store listing 对业务性质、贷款期限、APR/费用的描述变化；
  • APP 内用户链路新增直接报价、撮合、合同签署、资金发放或自动扣款；
  • 后台产品配置导致实际贷款产品与声明时不同；
  • 目标国家/地区新增或删除；
  • 当地监管资质、合作协议或主体证据发生变化。

六、发版 Runbook

  1. Freeze capability：冻结本次 Release Candidate 的真实金融能力清单。
  2. Generate diff：比较 RC 与线上版本的 Financial Capability Matrix。
  3. Check declaration：对照 Play Console 当前 Financial features declaration。
  4. Check lender relation：确认资金方/贷款机构/合同主体/开发者账号关系可证明。
  5. Check Mexico evidence：刷新本地主体、合同、商店页和后台参数证据。
  6. Check permissions：扫描 merged Manifest 与 SDK，确认贷款权限红线未漂移。
  7. Sign-off：产品 + 合规 + 发布 Owner 共同签字后进入 READY_FOR_REVIEW。
  8. Post-review snapshot：通过审核后保存 Console 声明、Policy status、Store listing 和上线 Build 证据。

七、与 Apple 的联动

Apple 没有与 Google Financial features declaration 完全同构的表单，但同一产品仍应复用 Financial Capability Matrix，用于核对个人贷款 APR/期限规则、App Review Information、App Privacy、第三方 SDK 数据行为和主体/合同一致性。Google 与 Apple eligibility 必须分别判断，不能把一端通过视为另一端自动合规。
