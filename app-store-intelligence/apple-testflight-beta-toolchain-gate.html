02｜工具链状态机与台账字段

BETA_TESTFLIGHT_ONLY

Beta Xcode/SDK 仅有官方 TestFlight 支持证据，不允许内部自动继承为生产可提审。

RC_APPSTORE_ACCEPTED

RC 工具链已被 Apple 明确接受用于 App Store 和 TestFlight；每个目标 Build 仍需实际上传验证。

STABLE_RELEASE

稳定版 Xcode/SDK 已发布并完成团队 CI、签名、关键 SDK 和生产回归。

MANDATORY_SDK

进入 Apple 公布的强制日期后，旧 SDK 构建直接视为发布阻断。

FALLBACK_READY

保留上一个已验证稳定工具链、release branch、证书与 CI runner，可快速构建 hotfix。

CONSOLE_OVERRIDE

若公开文档与当前 App Store Connect 实际提示不一致，保存 Console 截图并按更严格状态处理。

04｜发布 SOP

Step 1：先读官方状态，不凭经验推断

每次 Xcode/SDK 版本变化先核对 App Store Connect Release Notes、Apple Developer News 与 Upcoming Requirements；记录官方 URL 和核验时间。

Step 2：目标 Build 双通道验证

分别记录 TestFlight internal/external、App Store upload、build processing、version selectable、App Review submission 五个状态，任何一个失败都不能写成“工具链已全面支持”。

Step 3：金融核心链路回归

登录/OTP、KYC、相机/OCR、Face/Liveness、Push、Deep Link、WebView、银行卡/还款、合同 PDF、隐私、账号删除、风控/归因/客服 SDK 全量回归。

Step 4：未来门槛提前 90–180 天治理

2027-04 SDK 27 强制门槛应在 2026 Q4 建立兼容矩阵，2027 Q1 完成关键 SDK 升级和 CI runner 切换，避免临近截止日集中升级。

门禁原则：TestFlight 成功 ≠ Production 可提审；RC 官方可提审 ≠ 每个 Build 自动安全；新机型素材规格存在 ≠ 当前 App Store Connect 已开放对应素材上传。
