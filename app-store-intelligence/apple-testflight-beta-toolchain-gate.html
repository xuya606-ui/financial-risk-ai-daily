Apple TestFlight beta 工具链门禁

把“能上传到 TestFlight”和“可以提交正式 App Review / 客户分发”拆成两套工具链状态，避免 beta Xcode / beta SDK 的测试支持被误读为生产发布支持。

01｜为什么要拆成两条发布通道

2026-08-25 官方更新

Xcode 27 beta 6 已支持 TestFlight 内外部测试

Apple App Store Connect Release Notes 明确写明：使用 Xcode 27 beta 6 和 iOS/iPadOS/macOS/tvOS/visionOS/watchOS 27 beta 6 SDK 构建的 APP，可以提交用于 TestFlight internal / external testing。

不要过度推断：这条更新的适用范围是 TestFlight 测试。它并没有在同一条公告中说明 beta 工具链已经可用于正式 App Store 客户分发。发布团队必须分别确认测试通道和生产通道的当前支持状态。
Apple Release Notes 官方原文 ↗

Beta Testing

关注能否上传、处理、进入内部/外部 TestFlight 测试，以及外部测试是否需要 Beta App Review。

Production Review

关注该 Build 是否能够被选择进正式版本、提交 App Review，并用于面向客户的 App Store 分发。

Fallback

保留稳定 Xcode / SDK 和生产分支，beta 工具链出现兼容或审核问题时可快速回退。

03｜发布 SOP

提测前

研发选择 beta Xcode / SDK 前，先确认 Apple Release Notes 明确支持对应 TestFlight 版本；记录 Build、Xcode、SDK、上传时间和官方原文。

外部 TestFlight

把外部测试状态单独记录，避免“内部组可安装”被误认为“外部测试也已经通过”。同时保存 Beta App Review 结果和测试组范围。

正式提审前

重新核验当前 Apple App Store Connect 的上传/提交要求，确认目标 Build 可用于正式 App Review。不要直接继承 beta 测试阶段的 supported=true。

推荐门禁：如果 app_review_ok != true，生产发布任务不得仅凭 TestFlight 成功状态进入“可提审”。

04｜现金贷 APP 额外回归

使用新 beta SDK 提测时，优先回归登录/OTP、KYC、相机/OCR、Face/Liveness SDK、文件选择、Push、Deep Link、WebView、银行卡/支付、合同 PDF、隐私入口、账号删除，以及风控/归因/客服 SDK。任何系统权限或网络栈行为变化都可能影响商店审核与真实借款漏斗。
