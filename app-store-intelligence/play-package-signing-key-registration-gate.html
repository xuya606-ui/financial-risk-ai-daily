为什么这是 P0 门禁

Google Play 明确要求：自 2026-09-30 起，所有 Play package 必须完成注册以满足 Android developer verification；未注册的 APP 将依据 Play Console Requirements 从 Google Play 移除。虽然 Google 表示约 99% Play APP 已自动注册，但剩余包仍需要开发者在 Play Console Home / Android developer verification 页面逐包处理。

自动注册资格：按 signing key 的“已知安装量”判断

场景Google 自动/可注册规则内部判断
Majority key holder某 key 占总已知安装量超过 50%，该 key 优先注册 package。known_installs_share > 50% → majority_key=true
无单一 key > 50%安装量达到 50 的 key 都具备注册资格；低于 50 的其他开发者需提交请求。known_installs >= 50 → eligible=true
所有 key 都低于 50 安装任何 key 可按先到先得注册；首个完成后，其他开发者需要提交 package 使用请求。必须提前确定 package ownership 与历史 key 证据

最容易出问题的资产

历史换签、Play App Signing 迁移、APP 转移、OEM/预装版本、多渠道同包名、旧测试 key、低安装量 package、并购后账号迁移。只看当前 production signing certificate 不够，必须保存 historical_keys 与 install evidence。

手动注册 Runbook

步骤操作证据
1在 Play Console Android developer verification 页面确认 package 未成功自动注册。Console 截图、app_id、package_name、timestamp
2选择 Add key，从 eligible keys 中选择 APP public certificate。certificate SHA-256、key label、历史用途
3点击 Get started，获取 Play Console 提供的 snippet。snippet hash、request_id
4把 snippet 放入 APK asset folder，使用对应 signing key 签名并上传。verification APK hash、signing certificate
5等待成功邮件/Console 状态切换为 registered。approval email、final status screenshot

Google 特别说明：这一步不需要上传真实生产 APK；验证用 APK 只用于证明你持有相应 signing key。

发布门禁与告警规则

条件动作
registration_status != registered 且距截止 < 14 天P0 阻断非必要发版；Owner 每日跟进
current_cert_sha256 与 Play Console 记录不一致停止发版，先核对签名链/APP 转移记录
historical key 不明 / package ownership disputed立即整理公司主体、旧账号、APP 转移、签名证据并提交 support request
开发者身份尚未验证先完成 identity verification；未完成身份验证时可能看不到 package 注册通知
APP 在 Play 外也使用同一 package在 Play Console 同步注册 Play 外分发场景，保留渠道和 key 映射

与 2026-09-30 区域安装层执行的区别

Play package 注册是 Google Play 自身的全球要求；Android developer verification 的首批“用户安装层”执行则针对巴西、印度尼西亚、新加坡、泰国的参与商店与认证 Android 设备。墨西哥不在首批四国，但 Play 上架资产仍必须完成 package 注册。2027 年及以后 Android developer verification 将继续全球扩展。
