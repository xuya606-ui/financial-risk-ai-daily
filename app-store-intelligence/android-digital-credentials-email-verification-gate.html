适用于使用 Android Digital Credentials 邮箱验证流程的 APP。2026 年 8 月起响应 JSON 已切换为更严格的 W3C 结构，既有集成需要在迁移期兼容新旧格式；新接入应直接使用新格式，并把完整密码学验证放在服务端。

01｜发生了什么

2026-08 起

响应 JSON 结构变化

Android 官方文档说明，从 2026 年 8 月开始，Digital Credentials 邮箱验证响应 JSON 严格匹配 W3C 标准：外层包含 data 与 protocol，OpenID4VP 的 vp_token 位于 data 内。旧实现中 vp_token 可能直接位于外层。

迁移期内，既有集成需要同时兼容新旧结构；2026 年 8 月后才开始接入的 APP，应使用新结构。

02｜为什么现金贷 / 金融 APP 要关注

注册/KYC 中断风险

如果客户端或服务端仍只从外层读取 vp_token，新响应可能导致邮箱验证失败、注册漏斗下降或误判为认证失败。

身份与风控数据一致性

邮箱可作为账户联系属性或辅助身份信号，但不应因为解析兼容问题导致重复账户、异常拦截或将未验证邮箱误写入用户主档。

安全验证必须在服务端

Android 官方明确指出，客户端解析只适合立即更新 UI；完整密码学验证应在服务端完成，不能把客户端解析结果当作最终可信认证结论。

发布回归要覆盖迁移期

版本回归应同时覆盖新结构和仍可能出现的旧结构，直到后端确认旧实现完全退场。

03｜建议兼容逻辑

response JSON ├─ if data.vp_token exists → parse NEW format ├─ else if vp_token exists → parse LEGACY format (migration only) └─ else → fail closed + observability event client: parse for UI only server: cryptographic validation → verified claims → identity/account decision
原则：解析兼容可以“双读”，安全验证不能“双标准”。最终信任链应统一落在服务端验证结果。

05｜建议埋点字段

credential_flow、response_format（new/legacy/unknown）、protocol、client_parse_result、server_verify_result、verify_error_code、app_version、android_version、kyc_stage、fallback_used。

建议监控：邮箱验证成功率、unknown format 占比、服务端验证失败率、升级前后注册/KYC 转化差异。

06｜适用边界

这是 Android Digital Credentials 邮箱验证流程的技术兼容要求，不是所有现金贷 APP 都必须接入该 API。如果当前 APP 未使用这一能力，可把本页作为未来身份验证方案选型和 SDK/接口变更台账的一部分，无需立即开发。
