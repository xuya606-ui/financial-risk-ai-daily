01｜平台官方要求

Google Play

受限功能必须可供审核访问

Google 的 App content / Sign-in details 用于提供受登录、会员、位置、OTP/MFA 或其他认证限制功能的审核访问说明。官方允许维护最多 5 组访问说明，并要求开发者定期保持信息准确。

Google Play

提审前提供 demo account 与必要资源

Play Console Requirements 明确要求在提审前提供 active demo account、登录信息，以及审核需要的其他资源，例如 QR code；金融产品和服务开发者还必须使用 Organization developer account。

Apple

App Review 需要完整访问

Apple 要求 App Review 能完整访问 APP；登录型 APP 应提供有效 demo account，或在法律/安全约束下经 Apple 认可的完整 demo mode，并保持后台服务在审核期间可用。非显而易见功能和新产品变化需在 Notes for Review 具体说明。

App Review Guidelines 官方原文 ↗
原则：平台审核访问是正式发版资产，不是“临时账号”。它应该有 Owner、健康检查、版本兼容、合成测试数据、失效告警和拒审回溯。

02｜现金贷 APP 的审核访问证据包

模块建议内容常见失败
账号专用 reviewer account；主账号 + 2 个备用；账号长期有效，不与员工个人手机号绑定。密码过期、账号冻结、多人共享后被风控锁定。
认证可重复认证方式；明确 OTP/MFA/PIN/二维码步骤；审核说明与 Build 实际一致。OTP 只能发到内部手机号、一次性码过期、设备绑定阻断。
地区/设备审核账号不依赖特定办公 IP、SIM、GPS 或员工设备；若功能确有合法地区限制，在说明中写清替代审核路径。Reviewer 在境外或新设备登录时被地域/设备策略拒绝。
KYC合成身份、测试证件/人脸或安全 demo 路径；不得让审核人员使用真实个人敏感信息完成贷款流程。KYC SDK 只支持真实证件、测试数据被清理、第三方沙箱过期。
贷款披露能稳定进入额度、金额、期限、APR、费用、还款计划、合同预览和客服/投诉入口。审核账号被直接判定无额度，核心披露页面无法到达。
隐私隐私政策、Data safety/App Privacy 对应功能、账户删除、权限解释都可从审核路径进入。网页 404、地区跳转错误、删除入口隐藏。
服务端审核期间保持 API、KYC/风控沙箱、合同服务、短信/通知替代路径可用；记录 reviewer session。灰度环境关闭、依赖夜间任务、供应商限流。
安全边界：不要为了审核而普遍关闭生产安全控制。推荐使用受控的 reviewer/demo 标记、合成数据和审核专用策略，只在审核账号范围内提供可复现路径；不要创建真实债务、真实扣款或使用真实客户 PII。

03｜提审前自动门禁

P0

登录健康检查

从外部网络执行一次自动/人工冒烟：安装目标 Build → 登录 → OTP/MFA → 首页。失败即阻断提审。

P0

核心路径健康检查

至少覆盖 KYC → 额度/报价 → APR/费用 → 还款计划 → 合同预览 → 隐私/删除；记录截图或服务端事件证据。

P1

说明一致性检查

Google Sign-in details、Apple Notes for Review、版本号、账号、测试数据和实际界面逐项对账，禁止复制上一版说明后直接提交。

推荐阻断条件
  • 主审核账号或全部备用账号无法登录。
  • OTP/MFA/PIN/二维码步骤无法重复完成。
  • 审核账号受到不可解释的地区、设备或风控封禁。
  • 贷款核心披露页不可达，或 APR/费用/期限与商店材料不一致。
  • 隐私政策、账户删除、客服/投诉入口失效。
  • 第三方 KYC/风控/合同服务在审核时段不可用。
  • Review Notes / Sign-in details 与目标 Build 不一致。

05｜Reviewer Session 与审核监控联动

审核账号在服务端应有稳定的 account_type=STORE_REVIEW 或等价标记，用于将正式送审后的 reviewer session 与普通用户流量区分。它可以帮助定位“审核有没有真正登录、停在哪一页、哪个 API 失败”，但不应根据 IP/ASN/国家单独宣称识别 Google/Apple 员工。

06｜“无法访问 APP”拒审回溯模板

  1. 冻结当前 reviewer account、Build、说明版本与服务端日志，避免证据被覆盖。
  2. 确认是否发生登录请求：没有请求 → 优先检查说明/账号/入口；有请求但失败 → 定位认证、地区、设备、第三方服务或风控。
  3. 用与审核相同 Build 从外部网络复现完整路径，并生成截图/事件序列。
  4. 只修正实际阻断点；不要为了“试试看”连续重复送审。
  5. 更新 Google Sign-in details 或 Apple Review Notes，并明确“变更了什么、如何复现、预期看到什么”。
  6. 将拒审原因写回知识库：版本、路径、根因、修复、复现证据、是否需要申诉。
Google：更新访问说明后重新送审 ↗Apple：与 App Review 沟通/申诉 ↗

07｜推荐运行节奏

  • 每日：自动检查主审核账号登录、核心网页/接口、第三方沙箱健康。
  • 每次提审前：针对目标 Build 做完整 reviewer path 冒烟并冻结说明版本。
  • 每周：检查账号/OTP/MFA、地区/设备策略、KYC 测试数据、供应商沙箱有效期。
  • 每次拒审后：把根因归入“访问失败 / 政策问题 / 元数据问题 / 权限隐私 / 金融披露 / 技术质量”，更新模板和门禁。
