核心结论：Apple 工具链接受能力不能通过“版本号大小”推断。2026-09-16 Apple 已先明确 Xcode 27.2 beta + 27.2 beta SDK 可用于 TestFlight；2026-09-18 又单独明确 Xcode 27.1 beta + iOS/iPadOS 27.1 beta 可用于 TestFlight。这说明平台支持应被建模为官方显式许可集合：Xcode × SDK × Platform × Destination。未被官方当前原文明示支持的组合，默认 NOT_CONFIRMED。

1. 为什么必须用显式 Allowlist

禁止推断 01

版本号更高 ≠ 所有更低版本自动可用

9/16 先出现 27.2 beta，9/18 再出现 27.1 beta，本身就证明不能用简单的 sdk_version >= min_version 规则判断 App Store Connect 接受能力。

Apple Release Notes 官方原文 ↗
禁止推断 02

TestFlight 可用 ≠ Production 可提审

Apple Release Notes 会明确区分 TestFlight 与 App Store 正式提交。只写“internal and external testing”的条目，不能自动转义成 production submission 许可。

Apple Release Notes 官方原文 ↗
禁止推断 03

iOS/iPadOS 可用 ≠ 其他平台同步可用

9/18 条目只点名 iOS 27.1 beta 与 iPadOS 27.1 beta；因此 macOS、tvOS、visionOS、watchOS 27.1 beta 应继续标记为未确认，除非后续官方原文另行明确。

Apple Release Notes 官方原文 ↗
内部治理

官方 Accepted ≠ 内部 Validated

Apple 接受上传只代表平台层入口开放。生产 CI 仍需经过签名、KYC/OCR/活体、支付、Push、Deep Link、WebView/PDF、合同、崩溃率与正式提交流程验证，才能进入内部生产可用状态。

2. 推荐数据模型

建议将每一个工具链组合保存为一条独立记录，至少包含：

字段含义
xcode_versionXcode 精确版本，例如 27.1 beta、27.2 beta、27 stable
sdk_familyiOS / iPadOS / macOS / tvOS / visionOS / watchOS
sdk_versionSDK 精确版本
destinationTESTFLIGHT_INTERNAL / TESTFLIGHT_EXTERNAL / APP_STORE_SUBMISSION
official_support_dateApple 官方首次明确支持日期
support_state平台层支持状态
production_allowed是否允许进入生产 CI lane；应由内部门禁决定，不等同 Apple 官方状态
source_url / source_hash官方原文地址及证据哈希
last_verified_at最后核验时间
owner发布工程/客户端责任人

推荐状态枚举

EXPLICITLY_ALLOWED_TESTFLIGHT：官方明确允许 TestFlight；EXPLICITLY_ALLOWED_APPSTORE：官方明确允许正式 App Store submission；NOT_CONFIRMED：当前未找到精确组合官方支持证据；BLOCKED_PRODUCTION：只允许测试或内部验证，禁止生产提审；STALE_EVIDENCE：官方证据超过内部 Freshness SLA；内部可再叠加 INTERNAL_VALIDATED 与 PRODUCTION_VALIDATED。

4. CI / CD 门禁逻辑

Exact-key match，而不是区间判断

构建进入上传前，CI 使用精确主键 (xcode_version, sdk_family, sdk_version, destination) 查询 Allowlist。只有精确匹配到当前 EXPLICITLY_ALLOWED_* 且证据仍在 Freshness SLA 内的组合，才继续上传。未命中、证据过期或目的地不匹配时，一律 fail closed。

推荐伪逻辑：exact_match == false → NOT_CONFIRMED → block；destination=APP_STORE_SUBMISSION && only_testflight_allowed → BLOCKED_PRODUCTION；evidence_stale → STALE_EVIDENCE → recheck official source。

Apple Release Notes 官方原文 ↗

贷款 App 还需叠加业务回归

即使工具链组合被 Apple 接受，墨西哥信贷 App 仍建议对登录、OTP、KYC、OCR、相机、人脸活体、Push、Deep Link、WebView/PDF、合同签署、支付/还款回跳、Session 连续性和关键第三方 SDK 完成回归后，才将内部状态升级为 PRODUCTION_VALIDATED。

5. Runbook

  1. 每日读取 Apple App Store Connect Release Notes，识别新增 Xcode/SDK/平台/目的地组合。
  2. 按原文逐组合写入 Allowlist，并保存 source_url/source_hash/official_support_date。
  3. 不得把未点名的平台、低版本、高版本或 production 权限通过版本号规则自动继承。
  4. TestFlight 新工具链先进入独立实验 CI；验证签名、上传、processing、build selectable 与关键业务回归。
  5. 只有 Apple 明确允许正式提交，且内部生产回归通过后，才开放 production lane。
  6. 每次官方 Release Notes 变化触发 Diff，并重新计算受影响构建队列与 fallback runner。
