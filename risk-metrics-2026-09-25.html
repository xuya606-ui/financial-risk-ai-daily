Agentic AML/KYC 指标完整学习卡

以下阈值均为内部示例，不代表行业统一标准；模拟案例用于训练分析逻辑。

1. Agent Automation Rate

指标是什么：AI Agent自动完成的Case占Eligible Case的比例，直观看“有多少案件不用人工处理”。

为什么重要：领先/同步运营指标，适用于KYC、AML、Fraud Case自动化，但必须和质量指标一起看。

公式：Automation Rate = Auto-completed mature cases ÷ Eligible cases

如何看高低：高表示效率提升，但如果False Negative、投诉或Override同步上升，不能视为正面。

案例：100,000个Case中自动处理率68%→79%，人工复核32%→21%，高风险False Negative 1.1%→1.8%；按Risk Tier拆分后低风险改善、高风险恶化。决策是低风险放量、高风险保留人工Review。

诊断：先查Eligible/成熟度，再看Risk Tier、False Negative、Override、SLA。

策略动作：高风险Case设置人工门槛；低风险自动化需抽样QA；异常时回滚工具写权限。

常见误区：自动化率越高越好；把未成熟Case算成功；不区分只读与写入Agent。

拆分：Risk Tier、Use Case、Model Version、Tool、Channel、Region。

预警：Automation↑且False Negative↑为内部黄灯；Scope Violation>0且涉及外部写入为红灯候选。

关系：Automation→SLA/Cost→False Negative/Complaint→Net Loss。

练习：100,000个Case自动完成79,000个，Automation Rate=79%。

2. High-risk False Negative Rate

指标是什么：事后确认高风险、但当时未拦截或未升级的Case占成熟高风险Case比例。

为什么重要：滞后质量指标，直接反映Agent在高风险场景是否漏掉了关键风险。

公式：FN Rate = Confirmed high-risk cases missed by Agent ÷ Mature confirmed high-risk cases

如何看高低：通常越低越好；过低也可能是标签不足或人工过度介入造成。

案例：高风险成熟Case 10,000个，其中1800个未升级，FN Rate=18%；Low-risk仅0.6%。应先检查标签、Review覆盖和Case抽样。

诊断：确认标签→成熟窗口→分层→Agent建议→人工Override→事后Case。

策略动作：提高高风险规则召回、增加人工Review、限制Agent写入，不能只调低阈值。

常见误区：把False Positive当False Negative；用未成熟Case；只看总体不看高风险Segment。

拆分：Risk Tier、Rule/Prompt Version、Device/Bank Change、Channel、Case Type。

预警：连续两个成熟窗口超过内部基线并伴随Fraud/AML损失上升才升级。

关系：Agent Decision→FN→Fraud/AML Loss→Complaint/Regulatory Risk。

练习：1800/10000=18%。

3. Tool Scope Violation Rate

指标是什么：Agent调用超出授权工具范围的动作占全部工具调用比例。

为什么重要：领先安全指标，适用于任何能访问客户、支付、KYC、AML或外部系统的Agent。

公式：Scope Breach Rate = Unauthorized tool calls ÷ Total tool calls

如何看高低：理想状态接近0；任何涉及外部写入、支付、账户变更的越权都应高优先级处理。

案例：1,000,000次Tool Call中发现120次越权，整体0.012%，但其中8次涉及CLABE修改，风险不可用总体平均掩盖。

诊断：权限清单→调用日志→外部写入→受影响客户→撤销/回滚。

策略动作：立即吊销凭证、关闭写权限、修复Scope定义、回溯客户影响。

常见误区：越权但未造成损失就忽略；只看比例不看绝对事件；把Prompt承诺当权限控制。

拆分：Agent、Tool、Environment、Write/Read、Vendor、Version。

预警：任何高风险写入越权直接进入红灯候选。

关系：Identity→Scope→Tool Call→External Write→Incident。

练习：120/1,000,000=0.012%。

4. Human Override Rate

指标是什么：人工复核覆盖的Case中，人工改变Agent建议的比例。

为什么重要：同步治理指标，帮助发现Agent与人工判断差异和规则盲区。

公式：Override Rate = Human decisions different from Agent recommendation ÷ Human-reviewed cases

如何看高低：高不一定坏；如果高且理由集中，可能是Agent规则偏差；低也不一定好，可能是人工机械接受。

案例：人工Review 20,000个Case，2,400个被改变，Override=12%；其中9%集中在New Device+Bank Change组合。应进入Prompt/Rule Challenger。

诊断：人工Review覆盖→Override理由→Segment→后续Outcome→QA。

策略动作：按理由分类回流模型/规则；高风险组合增加人工；低风险组合减少无价值Review。

常见误区：把高Override直接视为人工更好；忽略人工自身错误；不保存理由。

拆分：Analyst、Case Type、Risk Tier、Agent Version、Reason Code。

预警：Override↑且后续Outcome明显改善，说明Agent存在盲区；Override↑但QA下降，先查人工质量。

关系：Agent Recommendation→Human Override→QA/Outcome→Model/Rule Update。

练习：2,400/20,000=12%。
