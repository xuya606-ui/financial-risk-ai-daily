第三部分｜海外风控知识学习

今日知识：Risk-Based Pricing｜风险定价与逆向选择

概念：风险定价不是“风险越高价格越高”这么简单，而是在合规约束下，把风险成本、资金成本、获客成本、用户价格敏感度和Take-up一起纳入报价。最终目标是最大化风险调整后的可持续利润，而不是最大化APR。

Contribution Margin ≈ Interest + Fees − Funding Cost − CAC − Expected Loss − Variable Ops/Payment/Collection CostPrice Elasticity（内部分析示例） = %ΔTake-up ÷ %ΔPrice

为什么重要：提价会增加单笔收入，但也可能让低风险、价格敏感客户更快退出，导致剩余借款人风险更高，这就是典型的Adverse Selection。降价也不一定值得，如果新增Take-up来自高风险客群或补贴超过边际利润，整体利润仍可能下降。

墨西哥现金贷模拟案例｜提价后收入提高，但客群变差

背景：首贷30天产品在Score B/C两档分别提高费用，目标是覆盖资金成本上升。
数据：样本20,000；平均总成本对应价格指标上调约8%；Take-up 51%→43%；平均收入/借款人 MXN265→301；FPD7件数14.8%→17.2%；低风险Score B占放款从52%降至41%；Contribution Margin/借款人 MXN78→71。
现象：单借款人收入提高，但Take-up和利润反而下降，早期风险变差。
拆解：按Score×Channel×Limit×Term后发现，优质Score B客户对价格更敏感，退出更多；边缘Score C仍有强提款需求，导致放款结构恶化。
根因：当前可以确认价格变化与客群结构变化高度相关，但渠道素材和额度也同期调整，因此需要Champion/Challenger或随机报价实验确认因果。
决策：不做全量统一提价；采用Score/Limit/Term分层报价，在监管和平台上限内控制价格，优质客群保留更有竞争力的总成本；边缘客群优先通过额度/期限而不是无限提价覆盖风险。
观察结果：至少等待FPD7成熟，并继续追MOB1 DPD30+、Take-up、Average Ticket、EL、Contribution Margin和LTV。

判断方法：Funding Cost → Offer Price → Take-up → Score Mix → EAD → FPD/Vintage → EL → Contribution Margin。

常见误区：APR提高=利润提高；只看借款人收入不看流失；把高风险定价当成无限加价；不同期限直接比APR/利润；忽视平台/监管价格限制。

小练习与答案

某价格方案让单笔收入+15%，Take-up -20%，低风险客户占比下降10个百分点，FPD7从13%升到17%。是否可以只因为“单笔收入更高”而上线？

答案：不能。应计算新增收入能否覆盖Take-up损失、客群恶化带来的EL和LTV下降，并用受控实验验证价格是否导致逆向选择。

第四部分｜风控指标集合学习

今天复习/升级四个高频经营与风险指标：CAC、LTV、Contribution Margin、Break-even Bad Rate。完整12段学习卡已同步到指标字典。

1. CAC｜Customer Acquisition Cost｜获客成本

是什么：获得一个符合固定定义的新客户/借款人实际花多少钱。

为什么重要：它是增长与利润的上游指标；CAC低不代表渠道好，必须与Take-up、FPD、EL、LTV一起看。

首贷CAC = 可归因获客营销成本 ÷ 成功首贷借款人数

口径：必须固定是注册CAC、申请CAC、Approved CAC还是First-disbursement CAC；媒体费、代理费、优惠补贴和归因窗口需统一。

高低：通常越低越好，但极低CAC可能来自低质量流量；高CAC如果带来高LTV客群仍可接受。

案例七步法：渠道A CAC=MXN260、FPD7=19%、LTV=MXN410；渠道B CAC=MXN330、FPD7=10%、LTV=MXN720。A虽然便宜，但风险和后续复借差，风险调整利润更低。

诊断：归因/样本 → Channel/Campaign → KYC/Approval/Take-up → FPD/EL → LTV。

动作：低CAC高风险渠道降量/改素材；高CAC高LTV渠道优化竞价而非直接停投。

误区：注册用户作分母；自然量与付费量混用；忽略优惠券/补贴；不同归因窗口比较。

拆分：Channel、Campaign、Creative、Region、OS、Score、First/Repeat。

预警：按成熟Cohort做CAC+FPD+LTV联合黄红灯；阈值来自内部历史。

关系：CAC → First-loan Contribution Margin → Repeat → LTV/ROI。

练习：CAC下降20%，但FPD金额率+6pp、LTV-25%，是否值得扩量？答案：不能只看CAC。

2. LTV｜Lifetime Value｜客户生命周期价值

是什么：一个客户在完整生命周期里预计能带来的净经济价值。

为什么重要：它把首贷亏损、复借、风险、资金成本和留存连接起来，是决定CAC上限和增长预算的关键滞后/预测指标。

简化LTV = 生命周期收入 − Funding Cost − Expected/Credit Loss − 支付/运营/催收成本 − 激励成本

口径：必须固定观察窗口、折现、客户/账户口径、是否含CAC；预测LTV与成熟实际LTV分开。

高低：高通常更好，但高复借不一定高LTV，如果Debt Cycling导致EL和催收成本上升，LTV会恶化。

案例七步法：复借率42%→58%，收入/用户+22%，但MOB2 DPD30+ 11%→16%、Recovery下降、Funding Cost上升，12个月LTV从MXN680降到590。

诊断：Retention/Repeat → Revenue → EAD/Vintage → Recovery/LGD → Funding/Ops → LTV。

动作：提高优质复借留存；对高Redraw/高多头客群降额；用LTV/CAC而非Repeat Rate单独驱动营销。

误区：把收入当LTV；未成熟Vintage外推过度乐观；忽略资金成本和催收；跨产品窗口不同。

拆分：Channel、Score、New/Repeat、Cycle、Limit、Term、Region。

预警：预测LTV vs 实际成熟LTV偏差、LTV/CAC和分渠道Vintage联合。

关系：CAC → First-loan Margin → Repeat/Redraw → Vintage/EL → LTV → ROI。

练习：复借率提升但LTV下降，首先看什么？答案：EAD/Vintage、Funding Cost和催收/Recovery。

3. Contribution Margin｜贡献利润

是什么：每个借款人/贷款在扣除与业务直接相关的变动成本和风险损失后，还剩多少利润贡献。

为什么重要：它是连接通过率、额度、定价、CAC、EL的核心经营指标。

Contribution Margin = Revenue − Funding Cost − CAC − EL − Variable Payment/Ops/Collection Cost

口径：明确按Loan/User/Vintage，收入确认时点，EL使用成熟/预测口径，固定成本是否排除。

高低：越高通常越好，但短期高利润可能牺牲长期LTV或投诉/合规风险。

案例七步法：策略V8 Approval 30%→35%、件均1,500→1,750、收入/借款人+18%，但EL/Loan +40%、资金成本+8%，Contribution Margin从MXN96降到72。拆解发现边缘Score+高Limit贡献负利润。

诊断：Revenue → CAC → Funding → PD/LGD/EAD/EL → Payment/Collection → Margin。

动作：收入低处理价格/产品；CAC高调投放；PD高收准入；EAD高控额度；LGD高优化催收。

误区：收入增长=利润增长；不计EL；固定成本/变动成本混用；未成熟样本直接算最终利润。

拆分：Channel、Score、Limit、Term、Cycle、Pricing、Strategy Version。

预警：成熟Cohort Margin、EL/Loan、CAC、Funding Cost联合预警。

关系：Price/CAC/Funding + PD×LGD×EAD → Contribution Margin → LTV/ROI。

练习：收入+20%，EL+45%，Funding+10%，是否一定更赚钱？答案：不一定，直接计算Margin。

4. Break-even Bad Rate｜盈亏平衡坏账率

是什么：在当前价格、资金成本、CAC、额度和回收假设下，坏账率最多到多少仍能做到边际不亏。

为什么重要：它把“我们能承受多少风险”转成业务可解释阈值，适合定价、渠道、额度和策略评审。

简化思想：Break-even Credit Loss = Revenue − Funding Cost − CAC − 其他变动成本；再结合Average EAD/LGD换算成可承受Bad Rate

口径：不是行业统一公式。必须明确Bad定义、LGD、收入、EAD、税费/运营成本和期限；件数Bad与金额Bad不可混用。

高低：可承受Bad Rate高不代表产品更好，可能只是价格更高；还要看用户保护、平台政策、Take-up和LTV。

案例七步法：渠道A贡献前收入/成本净空间可承受信用损失约MXN180/Loan，Average EAD=1,500、LGD=80%，简化Break-even PD约15%；实际成熟Bad 18%，该渠道边际亏损。渠道B CAC更高但Break-even约14%、实际Bad 9%，反而更赚钱。

诊断：Revenue/Price → Funding → CAC → Ops → LGD/EAD → Actual Bad。

动作：实际Bad高于Break-even：先区分PD/EAD/LGD根因，再决定收紧、降额、改渠道或调整合法价格。

误区：把Break-even当监管阈值；忽略LGD/Recovery；用未成熟Bad；用高价格掩盖不可持续风险。

拆分：Channel、Score、Limit、Term、Pricing、Funding Source。

预警：Actual Mature Bad vs Break-even差值、Margin和LTV联合；阈值只能做内部管理。

关系：Revenue/Cost → Break-even Loss → Actual PD/LGD/EAD → Margin。

练习：可承受信用损失180、EAD1500、LGD80%，简化Break-even PD≈15%。如果实际成熟Bad 18%，策略应进入复盘。

第五部分｜海外风控实操

今日实操：Score × Price × Term 风险调整利润矩阵

所需字段：application_id、channel、score_band、offer_price/apr_or_cat、term、approved_limit、takeup_flag、disbursed_amount、fpd7、dpd30、bad_flag、revenue、funding_cost、cac、expected_loss、payment_cost、collection_cost、strategy_version。

操作步骤：1）固定Price/Term版本；2）按Score×Price×Term分层；3）算Take-up和Average Ticket；4）等待FPD7/DPD30成熟；5）计算EL/Loan和Contribution Margin；6）识别“提价后优质客退出、边缘客占比上升”的Adverse Selection；7）设计Champion/Challenger验证。

Segment Margin = Avg Revenue − Avg Funding − Avg CAC − Avg EL − Avg Variable Cost

SQL思路：

SELECT score_band, price_band, term,
       COUNT(*) AS n,
       AVG(takeup_flag) AS takeup,
       AVG(disbursed_amount) AS avg_ticket,
       AVG(fpd7_flag) AS fpd7,
       AVG(revenue - funding_cost - cac - expected_loss - variable_cost) AS contrib_margin
FROM matured_pricing_test
GROUP BY score_band, price_band, term;

阈值判断：不套行业统一价格/Bad阈值。若同Score段价格上调后连续两个成熟Cohort出现Take-up下降、低风险客占比下降、FPD/EL上升且Margin下降，应进入黄/红灯并回滚或重新分层。

输出模板：Score｜Price｜Term｜样本｜Take-up｜Ticket｜FPD7｜DPD30+｜EL｜CAC｜Funding｜Margin｜LTV｜Action。

第二天复盘：只看流量分配、报价曝光、Take-up、技术错误和客群结构；信用标签未成熟前不要根据一天FPD全量改价。

第六部分｜业务与产品

风控 × 业务：为什么提高价格，利润反而可能下降？

提价对现金贷有三条同时发生的链路：Revenue↑、Take-up↓、Customer Mix变化。如果优质、价格敏感用户退出更快，而高风险、资金需求更强的用户仍愿意借款，就可能形成Adverse Selection，最终PD/EL上升。

经营看板建议固定串联：Price → Take-up → Score Mix → Average Ticket/EAD → FPD/Vintage → EL → Contribution Margin → LTV。价格评审不能只看APR/CAT或单笔收入。

风控 × 产品：报价页需要同时满足“透明成本 + 分层报价 + 可解释变化”

产品页建议直接展示用户当前真实可获得的金额、期限、总成本和到期日；优惠券/降费应明确显示“优惠前/优惠后总成本”，不要用模糊月费或局部利率隐藏总成本。

当用户因风险变化导致额度、期限或价格变化时，前端可以给稳定、合规的原因类别，例如“基于最新可验证信息，本次可用额度/方案已更新”，而不是暴露内部Score阈值或“你属于高风险”。

职责：产品负责成本展示和方案比较；风控负责Price/Limit/Term映射及Guardrail；数据负责Price→Take-up→Risk→Margin；研发负责报价版本、有效期和回滚；运营只能在已批准报价范围内发优惠。
