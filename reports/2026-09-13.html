第三部分｜海外风控知识学习

今日主题：Repeat-loan Selection & Risk-adjusted LTV｜复借选择与风险调整LTV

概念：复借用户拥有更多真实还款行为，因此通常能比首贷使用更丰富的风险信号；但“首贷已经还清”本身会造成幸存者选择，且提额、缩短冷静期、优惠券、自动预授信都会重新改变风险。复借策略的目标不是最大化Repeat Rate，而是最大化成熟风险调整后的累计客户价值。

为什么重要：首贷可能只是获客入口，真正利润来自后续Cycle；但如果复借提额过快，件数Bad可能稳定，金额Bad/EL却恶化。只看单笔利润也会忽略后续复借、催收、营销和资金成本。

Risk-adjusted LTV_N = Σ(Revenue − Funding − EL − Variable/Servicing/Collection Cost − Incremental Incentive)_cycle

上式是内部学习口径，不是行业唯一标准；是否折现、是否在LTV中扣初始CAC，必须由内部数据字典统一。

墨西哥现金贷七步案例

背景：30天首贷，首期结清后自动进入复借候选，并对部分客群提额。
数据：首贷放款10,000人，Avg Ticket MXN1,500、FPD7 15%、单笔风险调整贡献MXN80；5,500人达到复借资格，3,850人实际复借；Cycle2 Avg Ticket 2,100、FPD7 12%、单笔贡献135；Cycle3有2,100人放款，Avg Ticket 2,700、FPD7 13%、金额FPD18%、单笔贡献120。初始CAC约MXN90/首贷用户。
现象：复借件数风险低于首贷，但Cycle3金额风险重新上升；“复借客更安全”并不足以支持持续自动提额。
拆解：Channel C × 首贷低Score × Cycle3 Limit≥MXN3,000 的金额FPD和MOB1 DPD30+最差；稳定高Score用户仍保持高Margin。
根因：还款历史提供了增量信息，但Limit/EAD、复借间隔和客群选择同时变化；不能把风险变化仅归因于“第几借”。
决策：复借资格由首贷行为+最新征信/多头+收入/支付+设备/ATO共同决定；低Score/短间隔/高提额设置Guardrail，中高质量用户保留Challenger。
结果：同首贷Vintage、同Cycle成熟度观察Repeat Bad@MOB、金额FPD、EL、Contribution Margin和累计LTV；至少跨2个成熟复借Cohort再确认策略。

判断方法：首贷Vintage固定 → Eligibility → Offer Exposure → Repeat Application/Approval → Limit/EAD → FPD/Bad同Cycle成熟 → Cycle Contribution → Cumulative LTV/CAC。

常见误区：把“有资格复借”当全部首贷用户；只看Repeat Rate不看Offer Exposure；首贷结清=低风险；复借提额后仍用件数Bad判断；未成熟Cycle直接算LTV；CAC在Contribution和LTV里重复扣除。

小练习与参考答案

首贷10,000人；Cycle1总贡献800k，Cycle2贡献519.75k，Cycle3贡献252k。若这些贡献均未扣初始CAC，则前三个Cycle每个首贷用户累计风险调整贡献约多少？若初始CAC=90，LTV/CAC约多少？

答案：累计贡献1,571,750 / 10,000 ≈ MXN157.2/用户；LTV/CAC≈1.75。实际生产还需处理成熟度、未来Cycle删失、折现及增量复借营销成本。

第四部分｜风控指标集合学习

今日4张指标学习卡：Repeat Rate / Repeat Approval / Repeat Bad@MOB / Risk-adjusted LTV

完整12段卡同步到今日指标页；主字典也已把今天指标加入历史索引。

1. Repeat Rate｜复借率

1）是什么：成熟首贷客群或复借Eligible客群中，真正再次放款/借款的比例。2）重要：生命周期增长同步指标，是LTV上游，但高并不等于好。3）定义：必须同时维护 Repeat Borrower / Mature First-loan Cohort 与 Repeat Take-up / Eligible Offer Exposed 两个口径，不能混用；固定N天窗口、唯一用户和Cycle。4）高低：高可能是产品粘性，也可能是高风险客户资金饥渴、优惠刺激或冷静期过短。

5）七步案例：首贷10k→Eligible5.5k→Repeat3.85k；原始Cohort复借率38.5%，Eligible Take-up70%；Channel C低Score复借率75%但Cycle2 FPD7 18%；现象是高复借集中高风险；拆解Score×Limit×Days-since-payoff；根因是需求与提额共同影响；决策对短间隔/低Score降低Offer；结果看Repeat Bad/EL/LTV。6）诊断：Eligibility → Exposure → Apply → Approval → Disbursement → FPD/Bad → LTV。7）动作：技术曝光低修触达；高风险高Repeat降额/延长冷静期；优质低Repeat优化Offer。8）误区：分母错、未成熟、同一用户多笔重复、只看高低。9）拆分：Channel、Campaign、首贷Score、Cycle、Limit、Term、Days-since-payoff、新老客、Region。10）预警：同首贷Vintage+同观察窗；Repeat↑且Cycle Bad/EL同步恶化可做内部黄灯。11）关系：First-loan Cure → Eligibility → Repeat → EAD → Repeat Bad → LTV。12）练习：Eligible4,000、Offer Exposure3,600、Repeat2,520：Eligible Repeat=63%，Exposed Take-up=70%，不要混成一个指标。

2. Repeat Approval Rate｜复借审批通过率

1）是什么：真正进入复借重新决策的申请中，被批准的比例。2）重要：反映复借风险偏好和重评强度。3）公式：Approved Repeat Applications / Repeat Applications Actually Re-underwritten；自动预授信、资格展示和最终审批必须分开。4）高低：高可能来自好客户沉淀，也可能是策略过度依赖历史还款。

5）案例：Approval 88%→94%，Avg Limit +45%，Cycle2 FPD7 9%→13%、金额FPD 11%→17%；差异集中低Score+近期多头；相关性明确但需Challenger确认因果；决策恢复征信/多头重评并限制提额；观察两个成熟Cycle。6）诊断：Re-underwrite分母 → Score/最新征信 → Prior DPD → Limit → FPD/Bad。7）动作：高Approval+高Bad收紧；技术/数据缺失走Fallback；优质客可自动化。8）误区：Eligibility=Approval、预授信=最终批、只看首贷表现。9）拆分：Cycle、Prior DPD、Score、Inquiry、Limit Increase、Days-since-payoff、Strategy。10）预警：同Cycle同成熟度；Approval上升但EL/Margin恶化为内部黄灯。11）关系：Eligibility → Re-underwrite → Approval → Limit/EAD → Repeat Bad → LTV。12）练习：复借审批94%但金额Bad显著升，不能因为件数Bad稳定就判断策略成功。

3. Repeat Bad Rate@MOB / Cycle Bad Rate｜复借周期坏账率

1）是什么：同一复借Cycle、同一MOB/成熟窗口达到统一Bad定义的比例。2）重要：避免把Cycle2和Cycle5、MOB1和MOB3直接混比。3）公式：Mature Bad Accounts(or Amount) in Cycle c at MOB m / Mature Accounts(or Exposure) in same Cycle c at MOB m；固定Bad、件数/金额、重组/展期。

4）高低：通常低更好，但幸存者选择会让后续Cycle天然看起来更优；提额会让金额Bad先恶化。5）案例：Cycle2件数Bad10%/金额12%，Cycle3件数11%/金额18%，Avg EAD 2.1k→2.7k；拆解发现低Score高提额组金额Bad25%；决策按Cycle×EAD Guardrail；结果看EL/Margin。6）诊断：成熟度 → Cycle/Vintage → 件数vs金额 → Score/Limit → Cure/Roll → EL。7）动作：EAD驱动则降额；PD驱动则重评准入；支付/技术先修流程。8）误区：不同MOB横比、只看件数、忽略幸存者偏差、把首贷Bad定义和复借定义混用。9）拆分：First Vintage、Cycle、MOB、Score、Limit、Term、Prior DPD、Channel。10）预警：同Cycle同MOB、最小样本量；金额Bad和EL同步恶化再升红灯。11）关系：Repeat Approval/Limit → EAD + Bad@MOB → EL → LTV。12）练习：Cycle3件数Bad不变、金额Bad+6pp且EAD+30%，不能判断风险稳定。

4. Risk-adjusted LTV / LTV:CAC｜风险调整客户终身价值

1）是什么：把客户各Cycle收入扣除Funding、EL、服务/催收、激励等成本后的累计价值；LTV:CAC看生命周期价值是否覆盖获客成本。2）重要：是经营/利润类滞后指标，把首贷亏损、复借盈利和风险统一。3）示例公式：RALTV_N = Σ Cycle Contribution；LTV:CAC = RALTV / Initial Acquisition CAC。是否折现、是否扣初始CAC必须固定，不能重复扣。

4）高低：通常高更好，但未成熟未来Cycle会高估或低估；高LTV也可能来自高风险高价格且尾部损失尚未出现。5）案例：10k首贷 cohort：Cycle贡献800k+519.75k+252k=1.57175m，约157.2/首贷用户；CAC90→LTV/CAC≈1.75；拆分后Channel C低Score高Limit未来Bad更差，需下调预期LTV；决策把成熟EL/Recovery并入。6）诊断：Cohort删失 → Revenue → Funding/CAC → EL/Recovery → Cycle Retention → Cum LTV。7）动作：低LTV高CAC渠道降量；高Repeat低LTV收优惠/额度；高LTV稳定客提高复借体验。8）误区：Gross Revenue=LTV、未来未成熟当0损失、CAC重复扣、忽略复借营销/催收成本和幸存者偏差。9）拆分：Acquisition Channel、Campaign、First Score、Cycle、Limit、Term、Region、Strategy。10）预警：按同首贷Vintage、同生命周期窗口和最低成熟样本；成熟LTV/CAC持续跌破内部盈亏线才升级。11）关系：CAC → First Loan → Repeat/Cycle Margin → Recovery → RALTV → Portfolio Allocation。12）练习：RALTV=180、CAC=120，则LTV/CAC=1.5；是否足够好仍取决于资本、固定成本和内部目标。

第五部分｜海外风控实操

Cycle Cohort LTV Matrix｜复借周期队列价值矩阵

所需字段：user_id、acquisition_channel、first_vintage、cycle_no、eligibility_date、offer_exposed、repeat_apply、repeat_approved、disbursement_date、amount、score_at_cycle、prior_dpd、days_since_last_payoff、approved_limit、term、revenue、funding_cost、el、cac_initial、incremental_marketing_cost、variable_cost、collection_cost、fpd7、dpd30、bad_flag、maturity_flag、strategy_version。

步骤：固定首贷Vintage与Cycle → 定义Eligibility/Offer Exposure → 计算Repeat/Approval → 按Channel×First Score×Cycle×Limit拆EAD → 成熟后计算FPD7/Bad@MOB/EL → 计算Cycle Contribution与累计LTV → 对边际Cycle做Challenger。

SELECT first_vintage, acquisition_channel, first_score_band, cycle_no,
       COUNT(DISTINCT user_id) AS n,
       AVG(repeat_flag) AS repeat_rate,
       AVG(repeat_approved_flag) AS repeat_approval_rate,
       AVG(disbursed_amount) AS avg_ticket,
       AVG(CASE WHEN fpd7_matured=1 THEN fpd7_flag END) AS fpd7,
       AVG(CASE WHEN bad_matured=1 THEN bad_flag END) AS bad_rate,
       AVG(revenue-funding_cost-el-variable_cost-collection_cost-incremental_marketing_cost) AS cycle_contribution
FROM cycle_cohort
GROUP BY first_vintage, acquisition_channel, first_score_band, cycle_no;

阈值逻辑：不用行业统一Repeat/LTV阈值。内部黄灯示例：Repeat率上升但连续两个成熟Cycle的Amount Bad/EL恶化、Cycle Contribution下降；红灯候选：边际Cycle Contribution转负且累计LTV持续被下修。

输出模板：Cohort｜Channel｜First Score｜Cycle｜N｜Eligible｜Repeat｜Repeat Rate｜Approval｜Avg EAD｜FPD7｜Bad@MOB｜Cycle Margin｜Cum LTV｜LTV:CAC｜Action。

第二天复盘：先查Eligibility/Offer曝光口径、技术失败、策略版本和Cohort删失；深度Bad未成熟前，不用一天数据全量取消复借或大幅提额。

第六部分｜业务与产品

风控 × 业务｜不要最大化“第二借”，要最大化成熟生命周期贡献

经营链建议固定成：CAC → 首贷Margin → Eligibility → Repeat Rate → Cycle2/3 EAD与Bad → Recovery → Cumulative LTV → LTV:CAC。如果一个渠道首贷亏损较多但复借健康且长期LTV高，可以保留；反之首贷赚钱但复借提额后EL爆发，也可能是坏生意。增长会议应同时看首贷Vintage、Cycle、金额风险与累计价值。

风控 × 产品｜一次按时还款，不应自动触发最大提额

复借页建议先判断：首贷是否真实结清、是否发生技术性延期/展期、最新Inquiry/多头、收入/Payroll、Device/ATO、距上次结清天数，再决定额度和期限。产品负责复借入口、额度/期限展示和解释；风控定义Eligibility、Re-underwrite和Limit Guardrail；数据维护Cycle Cohort/LTV；研发维护Strategy Version、灰度和回滚；运营只能在批准额度/优惠范围内触达，不能人工越过高风险Guardrail。
