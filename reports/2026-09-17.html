第三部分｜海外风控知识学习

今日主题：Delinquency Flow & Net Flow Forecasting｜逾期迁徙与净流量预测

概念：单看 DPD30+ 存量，只能知道“现在有多少逾期”；Flow / Roll / Cure 则回答“资产正在向哪个方向移动”。建议统一建立：

Current → 1-7 → 8-29 → 30-59 → 60-89 → 90+ / Write-off

每个 Bucket 同时记录 进入（Inflow）、向更差桶迁徙（Roll）、治愈/回流（Cure）、净流量（Net Flow）。这比单一月底 DPD 更适合做早期风险预警和催收资源配置。

为什么重要：一个 Portfolio 的 Current DPD30+ 可能暂时稳定，但如果 1-29 → 30+ Roll 快速上升、30+ Cure 同时下降，未来 DPD30+/Bad 会恶化；反之，存量高但 Cure 改善，风险可能正在修复。

墨西哥现金贷七步案例

背景：30天复借产品，Channel B 扩量，同时 Collection Strategy C 下调人工触达比例。
数据：观察12,000个到期账户；1-29→30+ Roll 由28%升至39%；30+ Cure 由31%降至22%；30+期初余额 MXN8.0m；本期新流入30+ MXN3.6m；从30+ Cure/回收流出 MXN1.7m；Net Flow +MXN1.9m；MOB1 DPD30+ 由12.5%升至16.8%。
现象：月底30+余额快速积累，早期催收的“进入更差桶”速度超过“治愈/回收”速度。
拆解：Channel B × Low Score × Limit≥MXN2,000 的 1-29→30+ Roll 达52%；同渠道低Limit约34%；其他渠道约27%-31%。
根因：能够确认 Roll/Cure 共同恶化且集中在特定 Segment；但渠道扩量、额度、触达策略同时变化，因此不能把催收策略或渠道单独写成已验证因果。
决策：高Roll Segment降额/降量；恢复高风险早期人工触达；低风险稳定客保留Digital First；建立 Champion/Challenger 验证 Collection Strategy C。
结果：观察2-4周的 1-29→30+ Roll、30+ Cure、Net Flow、MOB1 DPD30+、Bad/Charge-off 与 Collection Cost；净流入持续下降且成本可控才认为有效。

判断方法：统一Bucket和Snapshot → 先看Roll/Cure → 再看Net Flow → 按Channel×Score×Limit×Term×Strategy拆解 → 等MOB/Bad/Charge-off成熟验证。

常见误区：用不同月龄资产直接比较 Current DPD；把部分还款当完全 Cure；只看件数不看余额；当期核销导致DPD下降就误判改善；用期末存量反推因果。

小练习与答案

期初30+余额8.0m，本期从1-29流入30+ 3.6m，Cure/回收/结清流出1.7m。若不考虑核销和其他调整，30+净流入多少？

答案：+1.9m；期末理论余额约9.9m。方向明显恶化，需要继续看 Roll/Cure 来源而不是只看期末余额。

第四部分｜风控指标集合学习

指标卡1｜Ever 30+ Rate｜曾经进入30+逾期比例

1）是什么：一个固定放款 Cohort 在观察窗口内，曾经至少一次达到 DPD30+ 的账户/金额比例。

2）为什么重要：属于成熟信用表现指标，比单一快照 Current DPD 更少受“后来 Cure”掩盖；适合策略、渠道、Vintage复盘。

3）定义与公式：Ever30+ = 窗口内任一时点达到DPD≥30的成熟账户 ÷ 同Cohort成熟账户；件数和金额分开，固定窗口（如MOB2/MOB3）与成熟条件。

4）如何看：通常越低越好；但更长观察窗口天然更高，不能跨窗口直接比较。

5）七步案例：背景：Channel B提额；数据：N10k、Avg EAD 1,600→2,050、Ever30+@MOB2 14%→19%、Current30+ 11%→12%、FPD7 15%→18%；现象：Current变化不大但Ever显著恶化；拆解：Low Score×High Limit最高25%；根因：风险与额度/流量相关但未证因果；决策：高风险组合降额；结果：看下两个Vintage的Ever30+@同MOB和EL。

6）诊断：窗口/成熟度 → Current vs Ever → Channel/Score/Limit → Cure/Roll → Bad/EL。

7）动作：特定Segment异常先局部降额/降量；全局恶化再收准入。

8）误区：MOB2和MOB4直接比；Current=Ever；件数金额混用；核销后忽略历史逾期。

9）拆分：Vintage、MOB、Channel、Score、Limit、Term、Strategy、新老客。

10）预警：同MOB历史基线 + 最小样本量；连续两个成熟Vintage超稳定区间可设内部黄灯。

11）关系：FPD/Roll → Ever30+ → Bad → Recovery/LGD → EL。

12）练习

成熟10,000单，1,800单曾进入30+，后来600单已Cure。Ever30+=18%，不能用期末12%替代。

指标卡2｜Early-to-30 Roll Rate｜1-29天滚入30+率

1）是什么：期初处于1-29DPD的账户/余额中，有多少在固定窗口滚入30+。

2）为什么重要：贷后早期同步/领先指标，常在Bad完全成熟前发现催收、支付或信用恶化。

3）公式：Roll 1-29→30+ = 期初1-29且期末/窗口内进入30+ ÷ 期初Eligible 1-29；固定快照频率、件数/金额口径和重组/展期规则。

4）如何看：一般越低越好；但若大量账户被展期、重组或技术性延期，表面Roll可被人为压低。

5）七步案例：12k到期账户，Roll 28%→39%，Channel B×Low Score×High Limit=52%；同时Cure下降、MOB1 DPD30+升；动作是该Segment降额+恢复早期触达；结果看2-4周Net Flow和MOB1。

6）诊断：Bucket/快照 → Payment Failure → Channel/Score/Limit → Contact/RPC → Cure → DPD30+/Bad。

7）动作：支付技术问题先修支付；联系率下降改催收；信用风险集中则降额/收准入。

8）误区：把新增放款混入分母；展期不单列；只看件数；不同观察周期横比。

9）拆分：Channel、Score、Limit、Term、Payment Method、RPC、Strategy、Region。

10）预警：同账龄/同产品历史带，Roll上升且Cure下降为组合黄灯；最终阈值使用内部基线。

11）关系：Payment/RPC → 1-29 Roll → 30+ Balance → Bad/Charge-off。

12）练习

期初1-29有2,000单，780单进入30+，Roll=39%。

指标卡3｜Net Flow to 30+｜30+余额净流入率

1）是什么：一个期间内流入30+的余额减去从30+治愈/回收/结清流出的余额，衡量30+风险池净增长。

2）为什么重要：贷后同步指标，把Roll和Cure合并到同一方向判断，比单独看某一个比率更接近“坏账池是在扩大还是收缩”。

3）示例公式：Net Flow Rate = (Inflow to 30+ − Cure/Recovery/Settlement Outflow) ÷ Opening 30+ Balance；核销、出售、重组应独立列出，避免把核销当改善。

4）如何看：长期正值通常表示30+池扩张；负值通常表示收缩，但若来自大额核销也不能理解成风险改善。

5）七步案例：Opening 8.0m，Inflow 3.6m，真实Cure/回收流出1.7m，Net +1.9m，Net Flow Rate=23.75%；若另有1.0m核销，应单列而非并入Cure；决策优先处理高Roll Segment并提升Cure。

6）诊断：Opening Balance → Inflow来源 → Cure/Recovery → Write-off/Restructure → Segment → Bad/EL。

7）动作：Inflow驱动则做准入/额度/早催；Cure下降则做支付/RPC/Collection；核销异常单独查政策。

8）误区：核销当Cure；期初/期末口径不一致；金额和件数混用；净流量下降就直接说信用变好。

9）拆分：Vintage、MOB、Channel、Score、Limit、Collection Strategy、Vendor、Region。

10）预警：连续多期正净流入 + MOB1 DPD30+/EL同步恶化可作为红灯候选。

11）关系：Roll In − Cure Out → Net Flow → DPD30+ Stock → Bad/Charge-off → Recovery/LGD。

12）练习

3.6m流入−1.7m流出=1.9m；除以8.0m期初余额，Net Flow Rate=23.75%。

指标卡4｜Charge-off / Write-off Rate｜核销率

1）是什么：达到内部核销政策条件并从账面冲销的账户/余额比例。

2）为什么重要：是滞后损失确认指标，连接Bad、Recovery、LGD和财务损失，但不等于“债务不存在”或“风险已经消失”。

3）公式：常见为 期间核销本金 ÷ 平均/期初贷款余额 或 Cohort累计核销 ÷ 原始放款本金；必须固定 gross/net write-off、Recovery-after-write-off、窗口和币种。

4）如何看：通常越低越好；但核销政策变严/变松会改变指标，不能跨政策直接比较。

5）七步案例：某Vintage放款MXN20m，MOB4累计核销1.8m=9%；上一Vintage8%，但Recovery-after-write-off 1.5%→2.5%，净损失差异小于gross核销差异；拆解发现高Limit Segment占增量多数；动作降额并优化后段催收；结果看Net Charge-off、Recovery、LGD、Margin。

6）诊断：Write-off Policy → Gross vs Net → Vintage/MOB → Score/Limit → Recovery → LGD/EL。

7）动作：信用驱动收准入/降额；Recovery低改催收/法律策略；政策变化先做可比口径重算。

8）误区：核销=债务免除；Gross=Net；不同核销天数政策直接比；期末余额作错误分母。

9）拆分：Vintage、MOB、Score、Limit、Channel、Term、Collection Vendor、Fraud/Credit。

10）预警：同政策、同MOB比较；Gross Charge-off 与 Recovery/LGD/Net Loss 联动，不设行业统一绝对阈值。

11）关系：DPD90+/Bad → Charge-off → Recovery-after-write-off → LGD → Actual Loss/Margin。

12）练习

原始本金20m，累计Gross核销1.8m，Gross Charge-off=9%；若后续回收0.4m，净损失比例约7%。

第六部分｜业务与产品

风控 × 业务：经营周报从“DPD30+存量”升级到“风险流量”

建议固定链路：FPD → 1-29 Roll → 30+ Inflow → 30+ Cure/Recovery → Net Flow → DPD30+ Stock → Bad/Charge-off → Recovery/LGD → Margin。只有这样才能区分“风险正在恶化”还是“历史坏账仍高但新流入正在改善”。

风控负责Bucket/策略和异常判断；业务负责量/利润目标；数据负责Snapshot与迁徙；催收负责RPC/PTP/Cure；财务负责核销/回收口径。

风控 × 产品：还款页和催收触达应按风险迁徙阶段设计

1-7 DPD：支付失败恢复、Bank/CLABE校验、轻提醒；8-29 DPD：强化提醒、分层渠道、明确金额与截止日期；即将30+：高风险用户增加人工触达/可执行还款路径；30+：根据RPC/PTP、余额、历史行为和合规要求分层。

产品负责还款路径与状态解释；风控定义Bucket/Treatment；数据监控Roll/Cure；研发保证支付幂等/入账及时；运营/催收不得通过人工操作改变DPD口径。
