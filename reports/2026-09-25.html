第三部分｜海外风控知识学习：Agentic AML/KYC Governance

概念：当AI Agent参与KYC、AML、Fraud Case或支付流程时，风控对象不再只是模型，而是Model/Prompt/Tool/Permission/Identity/Network/Data/External Write的组合。

为什么重要：Agent的错误可能直接影响客户身份、账户、支付、拒绝和报告，不同于只生成一段文本。

核心链路：Use Case → Risk Tier → Agent Identity → Tool Scope → Human Review → Monitoring → Incident → Rollback

墨西哥现金贷模拟案例：月度KYC/AML Agent处理100,000个Case；自动化处理率68%→79%，人工复核率32%→21%，但高风险Case的False Negative从1.1%升至1.8%，New Device+Bank Change+Shared Payer组合最差。当前可确认的是自动化扩展和漏检同步上升；不能把相关性直接写成因果，需Holdout与人工复核验证。决策：高风险组合保持人工Review，低风险Case采用自动化，所有Agent动作保留证据链。

常见误区：自动化率越高越好；模型输出有理由就等于可审计；把Agent权限与用户权限混为一谈。

小练习：100,000个Case中自动处理79,000个，自动化率是多少？高风险误漏检为1,800个，误漏检率是多少？答案：79%；1.8%。

第五部分｜海外风控实操

Agentic AML/KYC Control Matrix

数据：agent_id、model_version、prompt_version、tool_name、tool_scope、customer_risk、case_outcome、human_review、override_reason、incident_flag、false_negative_flag。

步骤：登记Agent→固定风险等级→设置工具白名单→区分只读/写入→高风险组合强制人工Review→记录每次Tool Call→每日监控Automation/False Negative/Override/Scope Violation。

SELECT risk_tier, AVG(auto_completed) AS automation_rate, AVG(false_negative_flag) AS fnr, AVG(scope_violation_flag) AS scope_breach, AVG(human_override_flag) AS override_rate FROM agent_case_monitoring GROUP BY risk_tier;

阈值逻辑：Automation↑且False Negative↑→黄灯；Scope Violation>0且涉及外部写入→红灯候选；Automation↑、SLA改善、False Negative稳定→可局部放量。

第二天复盘：先看标签成熟、Case抽样、工具调用日志和权限变更，再看是否调整Agent权限或回滚。
