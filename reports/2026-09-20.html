影响：这对金融风控的启示是：技术投资高增长与家庭现金流改善并不必然同步。企业信用、地方融资和消费金融可能出现完全不同的风险方向。

行动建议：宏观风险映射不要只使用GDP/工业增加值；增加 Household Income、Consumption、Corporate Inventory/Capacity、Local-government Stress，并把“企业AI受益”与“个人偿债能力”拆成两条链。

第三部分【海外风控知识学习】

今日主题：Collection Funnel & Promise-to-Pay Governance｜催收漏斗与承诺还款治理

概念：催收的目标不是“联系越多人越好”或“拿到越多PTP越好”，而是把触达转化成真实现金回收，同时控制投诉、成本和后续Roll。

Deliverability → RPC → PTP → PTP Kept → Cash Collected → Cure / Roll → Recovery / Net Loss

为什么重要：如果团队把原始PTP数量当核心KPI，催收员可能诱导用户做不现实的承诺，PTP率看起来上升，但PTP Kept、Collection Rate和Cure反而下降，形成Goodhart效应。

墨西哥现金贷七步案例（模拟）

背景：30天复借产品，Collection Strategy V4加入WhatsApp自动触达，并把部分Agent激励从现金回收改为PTP数量。
数据：到期/逾期账户10,000；应收金额MXN15m；RPC 36%→52%；RPC后的PTP 40%→57%；PTP Kept 68%→41%；7日Collection Rate 31%→28%；30+ Roll 34%→39%；投诉0.8%→1.6%；后段Recovery 18%→16%。
现象：触达和承诺明显增加，但真实回款、承诺兑现和迁徙结果反而变差。
拆解：Vendor B × Low Score × High Balance 的RPC 61%、PTP 66%，但PTP Kept仅28%、投诉2.4%；Vendor A同类客群RPC约45%、Kept约63%。
根因：激励变化、客群结构和Vendor话术与低质量承诺高度相关，但不能未经对照实验就断言“PTP激励”是唯一因果。
决策：Agent KPI从Raw PTP改为Kept PTP + Cash + Cure + Complaint；High Balance/High Roll优先人工；低风险稳定用户Digital-first；Vendor B进行Challenger与话术审计。
结果：连续2-4周观察RPC、PTP、Kept、Cash Collection、Cure、Roll、Recovery、Cost/Collected、投诉。只有现金和风险结果改善且投诉可控，才判定策略有效。

常见误区：RPC越高越好；PTP越多越好；把“承诺金额”当现金回收；不同逾期Bucket直接比较；不区分件数和金额；忽略投诉和合规成本。

判断方法：先看可触达率与RPC → 再看PTP质量 → 再看Kept与现金 → 最后看Cure/Roll/Recovery和投诉成本。

小练习与答案

1,000个逾期账户中500个RPC，300个给出PTP，其中120个按时兑现。RPC、PTP、PTP Kept分别是多少？

答案：RPC=50%；PTP=300/500=60%；PTP Kept=120/300=40%。如果Kept持续下降，不能因为PTP高就认为催收更有效。

第四部分【风控指标集合学习】

今天升级5张完整学习卡

RPC Rate：真正联系到正确借款人的比例；需要与Deliverability、PTP、投诉和Cure联看。

PTP Rate：RPC后形成明确可执行还款承诺的比例；高不等于好，关键看Kept。

PTP Kept Rate：承诺在约定窗口按规则兑现的比例，是承诺质量核心指标。

Collection Rate：固定应收口径下实际现金回收比例；必须统一分母、时间窗口、件数/金额口径。

Recovery Rate：Default/Write-off等后段风险池中回收的净现金比例；必须固定Default EAD与Recovery MOB。

第五部分【海外风控实操】

今日实操：Collection Funnel × Vendor / Treatment Matrix

所需数据：loan_id、user_id、dpd_bucket、due_amount、outstanding_balance、channel、score_band、limit_band、collection_vendor、treatment、contact_attempt、deliverability、rpc_flag、ptp_flag、ptp_amount、ptp_due_time、ptp_kept_flag、cash_collected_7d、cure_flag、roll30_flag、recovery_cash、collection_cost、complaint_flag、strategy_version。

步骤：固定逾期Bucket与观察窗 → Deliverability/RPC → PTP → Kept → 现金回收 → Cure/Roll → Recovery/成本/投诉 → Vendor×Score×Balance×Treatment拆解。

SELECT
  collection_vendor,
  treatment,
  COUNT(DISTINCT loan_id) AS n,
  SUM(due_amount) AS due_amount,
  AVG(rpc_flag) AS rpc_rate,
  AVG(CASE WHEN rpc_flag=1 THEN ptp_flag END) AS ptp_rate,
  AVG(CASE WHEN ptp_flag=1 AND ptp_matured=1 THEN ptp_kept_flag END) AS ptp_kept_rate,
  SUM(cash_collected_7d) / NULLIF(SUM(due_amount),0) AS collection_rate,
  AVG(cure_flag) AS cure_rate,
  AVG(roll30_flag) AS roll30_rate
FROM collection_funnel
GROUP BY collection_vendor, treatment;

阈值逻辑：RPC↑、PTP↑但Kept↓且Collection/Cure恶化 = “低质量承诺”黄灯；Collection↓、Roll↑、Complaint↑连续两期 = 红灯候选。具体阈值只能用内部历史，不冒充行业标准。

输出模板：Vendor｜Treatment｜N｜Due｜RPC｜PTP｜Kept｜Collection｜Cure｜Roll｜Recovery｜Cost/Collected｜Complaint｜Action。

第二天复盘：先核对支付入账、承诺窗口、重复联系和数据延迟；再抽样监听Vendor话术，检查高PTP低Kept是否来自不现实承诺；最后才调整激励或Treatment。

第六部分【业务与产品】

风控 × 业务：优化“净现金与风险迁徙”，不是优化电话量或PTP量

建议固定经营链：Deliverability → RPC → PTP → Kept → Cash Collection → Cure / Roll → Recovery → Net Loss → Cost / Complaint。Vendor、Agent与策略评价至少同时看Kept、Cash、Cure、Roll、Cost/Collected和投诉，不再用Raw Call/Raw PTP作为主结果KPI。

风控 × 产品：PTP后的还款页面要帮助用户兑现，而不是制造第二次摩擦

用户已经承诺还款后，产品应明确展示承诺金额、日期、可用还款方式、失败重试和提醒；对符合合规条件的用户可提供保存支付方式或自动还款授权，但不得默认勾选或使用误导性Dark Pattern。产品负责还款路径和恢复，风控/催收定义Treatment与优先级，数据维护Funnel与Outcome，研发保障入账幂等和提醒事件，运营/Vendor不得人工篡改PTP兑现口径。
