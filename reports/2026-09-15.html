第三部分｜海外风控知识学习

今日主题：Model Monitoring Triangulation & Drift Governance｜模型监控三角法与漂移治理

概念：模型监控不能只看一个 PSI 或 AUC。真正需要同时回答三个问题：①输入/客群有没有变（PSI）；②模型排序能力有没有变（AUC/KS）；③预测概率是否仍与真实坏账率匹配（O/E）。

Population Drift → PSI ｜ Rank Performance → AUC / KS ｜ Calibration → O/E

为什么重要：PSI 高但 AUC/KS 稳定，可能只是客群结构变化而模型排序仍稳健；AUC/KS 下降但 PSI 稳定，可能是特征-标签关系变化、数据质量或策略选择效应；PSI 稳定而 O/E>1，则可能是基础坏账率上升或模型校准偏低；四者同时恶化才更像严重的全链路漂移。

墨西哥现金贷七步案例

背景：30天首贷 Model V6 上线后，Channel C 快速扩量，同时额度策略提高。
数据：成熟样本50,000；整体 PSI 0.06→0.24；AUC 0.73→0.72；KS 0.38→0.36；O/E 1.02→1.28；FPD7 14.8%→17.2%；Approval 32%→35%；Avg EAD MXN1,500→1,800。
现象：客群分布和坏账校准明显恶化，但排序能力只小幅下降。
拆解：Channel C PSI=0.37、O/E=1.55；其他渠道 PSI≈0.08、O/E≈1.05。Low Score × High Limit 的金额FPD最差。
根因：可确认 Channel Mix/额度变化与风险恶化相关，但不能仅凭相关性说“模型失效”。AUC/KS没有同步大幅坍塌，更像 Population Shift + Calibration Deterioration；仍需排除特征缺失/数据管道变化。
决策：先降低 Channel C 边缘流量、恢复低Score高Limit旧额度；校准层做 Segment Recalibration/Intercept 调整的 Challenger；不因一个 Cohort 就直接全量重训。
结果：继续观察两个成熟 Vintage 的 PSI、AUC、KS、O/E、FPD7、MOB1 DPD30+、EL/Loan 和 Contribution Margin；如果排序、校准与业务损失都持续恶化，再升级模型重训。

判断方法：数据质量/Feature Missing → Population/Channel/Strategy Mix → PSI → AUC/KS → O/E → FPD/Vintage → EL/Margin。

常见误区：PSI一高就重训；AUC稳定就认为模型没问题；未成熟Bad直接算AUC/KS/O-E；不同评分方向计算KS/AUC；O/E分子分母使用不同Default窗口；把 Approval 策略改变造成的 Selection Bias 当模型漂移。

小练习与答案

某模型 PSI 从0.07升到0.28，但 AUC 0.74→0.73、KS 0.40→0.39、O/E 1.03→1.04。应先重训吗？

参考答案：不应仅凭 PSI 直接重训。先拆 Channel/Feature/Strategy Mix，确认是否只是 Population Shift；排序与校准仍较稳定时，可以先做流量/数据治理并继续观察成熟 Cohort。

第四部分｜风控指标集合学习

今天高级复习四个模型监控核心指标：PSI、AUC、KS、O/E。下面均采用统一12段学习卡；任何阈值数字仅作为内部示例，不是行业统一标准。

指标卡1｜PSI｜Population Stability Index｜群体稳定性指数

1）是什么：衡量当前样本分布和基准样本分布“变了多少”。大白话：今天来的客群/分数/特征，还是不是模型开发时那批人。

2）为什么重要：模型监控的领先/同步指标，可在坏账标签成熟前发现流量、渠道、特征或策略漂移，适用于贷前与贷中。

3）精确定义与公式：PSI = Σ (Actual_i − Expected_i) × ln(Actual_i / Expected_i)必须固定基准期、固定分箱、样本口径和缺失值处理；分母是各箱基准占比，当前占比是比较对象。零占比需要按内部规则平滑，不能临时换箱。

4）如何看高低：升高代表分布更不同，但不等于风险一定更高；渠道扩量、营销活动、季节性都可能推高PSI。低PSI也不代表模型校准一定正常。

5）七步案例：背景：Channel C扩量；数据：整体PSI0.06→0.24，C渠道0.37，O/E1.55，FPD7 14.8%→17.2%，Avg EAD1,500→1,800；现象：分布明显漂移；拆解：C渠道Low Score/High Limit集中；根因：流量与额度变化是强候选，模型排序仅小幅下降；决策：C渠道降量、边缘额度回滚并持续监控；结果：两个成熟Vintage看PSI/O-E/FPD/EL是否回归。

6）诊断：数据管道/缺失 → Channel/Campaign Mix → Score/Feature PSI → Strategy Version → AUC/KS/O-E。

7）策略动作：Feature Missing突增先修数据；单渠道PSI高先降量/拆模；稳定业务季节性漂移可调整基线；PSI+O/E持续恶化再考虑Recalibration/重训。

8）常见误区：PSI高=模型失效；每次重分箱；只看总PSI不看Segment；忽略样本量和季节性。

9）推荐拆分：Channel、Campaign、Score、关键Feature、Region、Device、Product、新老客、Strategy/Model Version。

10）预警：优先用自身历史稳定分布和最小样本量。内部示例可以将“明显超出历史P90且连续两个周期持续”设黄灯；如叠加O/E/FPD恶化升级红灯。不要把0.1/0.25等经验数值冒充统一行业标准。

11）关系：Traffic/Data → PSI → Score Distribution → AUC/KS/O-E → FPD/Vintage → EL/Margin。

12）小练习

PSI高、AUC/KS/O-E都稳定，第一动作？答：先拆流量/数据/渠道变化，不直接宣布模型失效。

指标卡2｜AUC｜Area Under ROC Curve｜ROC曲线下面积

1）是什么：模型把真实坏客户排在好客户前面的整体排序能力。大白话：随机抽一好一坏，模型有多大概率把坏的判得更风险。

2）为什么重要：滞后模型表现指标，必须等标签成熟；用于验证评分排序能力是否随时间、渠道或策略变化。

3）精确定义与公式：AUC 来自 ROC 曲线下的面积，可理解为好/坏随机配对的正确排序概率。必须固定 Bad Definition、预测窗口、成熟期、评分方向和样本选择；件数为主，不应把未成熟样本当Good。

4）如何看高低：高通常排序更强，但AUC高不等于PD校准准确，也不等于利润更高；AUC稳定时 O/E 仍可能明显恶化。

5）七步案例：背景：Model V6 + Channel C扩量；数据：AUC0.73→0.72、PSI0.24、O/E1.28、FPD7+2.4pp、Approval+3pp；现象：业务风险恶化但AUC仅小幅降；拆解：C渠道AUC0.69，其他渠道0.73；根因：局部客群排序变弱、总体更明显是分布与校准变化；决策：C渠道单独Challenger/特征检查，不马上全量重训；结果：成熟Vintage看AUC置信区间、O/E与Margin。

6）诊断：标签成熟/定义 → Score方向/样本 → Channel/Score Band → Feature Missing → PSI/O-E → FPD/EL。

7）策略动作：单Segment下降做分群模型/特征修复；全局持续下降再重训；AUC稳定但O/E差优先Recalibration而非重训排序。

8）常见误区：AUC高=校准好；未成熟标签；不同坏账定义横比；只看总体掩盖渠道下降。

9）推荐拆分：Channel、Product、Vintage、MOB、Score、Region、Model Version、Strategy Version、Thin/Thick file。

10）预警：使用同成熟窗口、置信区间和最小Bad样本量；内部黄灯用相对Champion/历史基线的持续下降，而不是统一绝对阈值。

11）关系：Feature/Score → AUC ↔ KS → Rank Quality；AUC + O/E → Model Performance → Approval/EL/Margin。

12）小练习

AUC稳定但O/E从1.0升到1.4，能说模型正常吗？答：不能，排序可能正常但PD明显低估实际坏账。

指标卡3｜KS｜Kolmogorov–Smirnov Statistic｜好坏区分度

1）是什么：好客户与坏客户累计分布之间的最大距离。大白话：在某个分数切点上，好坏客户能被拉开多远。

2）为什么重要：滞后排序/区分指标，直观反映评分分离能力，也常用于Score Cutoff和Champion/Challenger比较。

3）精确定义与公式：KS = max_t |CDF_good(t) − CDF_bad(t)|固定标签、预测窗口、成熟期、评分方向、样本和分箱/排序方法；主要按账户/订单件数计算。

4）如何看高低：高通常区分更好，但KS集中在一个切点，不代表全区间都好；策略筛选和坏账基数变化也会影响。

5）七步案例：背景：C渠道扩量；数据：总体KS0.38→0.36，C渠道0.30，其他0.37；PSI C=0.37、O/E C=1.55、金额FPD明显升；现象：C渠道排序分离下降；拆解：Low Score/High Limit和新设备集中；根因：客群/特征质量可能改变，尚不能认定模型整体失效；决策：C渠道数据质量与特征覆盖审计、限量Challenger；结果：两个成熟Cohort看KS/AUC、O/E和净利润。

6）诊断：标签/Score方向 → KS Cut-point → Channel/Segment → Feature/PSI → AUC/O-E → Bad/EL。

7）策略动作：局部KS下降做分群阈值/特征治理；全局持续下降再重训；KS正常但O/E坏做校准。

8）常见误区：KS越高越赚钱；使用不同Bad窗口比较；把策略筛掉的Rejected样本忽略 Selection Bias；只看一个KS最大点。

9）推荐拆分：Channel、Score Band、Vintage、Product、Region、Device、Model/Strategy Version。

10）预警：同标签/成熟期基线 + 最小Bad样本。内部可用连续两个成熟Cohort低于历史稳定区间作为黄灯；叠加AUC/O-E/EL恶化升级红灯。

11）关系：Population/Feature → Score → KS/AUC → Cutoff/Approval → Bad/EL；KS不直接替代Calibration。

12）小练习

KS下降但PSI稳定，优先查什么？答：标签/特征-风险关系、数据质量、策略选择和Segment表现，而不是先归因流量变化。

指标卡4｜O/E｜Observed / Expected Ratio｜实际/预期坏账比

1）是什么：真实成熟坏账数量与模型预测坏账数量的比值。大白话：模型预测会坏100个，实际到底坏了多少。

2）为什么重要：滞后校准指标，回答PD是否系统性低估/高估风险；用于模型校准、EL、定价和额度。

3）精确定义与公式：O/E = Σ Observed Default_i ÷ Σ Predicted PD_i必须固定同一Default Definition、预测窗口、决策时点、成熟样本和账户口径。若做金额/损失O/E，应明确叫Loss O/E并用Expected Loss作分母，不能与Default O/E混用。

4）如何看高低：约1表示总体校准接近；>1通常表示实际坏账高于预测，<1表示模型偏保守。但短期/小样本波动很大，不能用一天数据判断。

5）七步案例：背景：Channel C扩量；数据：整体O/E1.02→1.28，C渠道1.55，其他1.05；AUC0.72、PSI0.24、Avg EAD+20%、FPD7+2.4pp；现象：校准明显低估新增风险；拆解：Low Score×High Limit最差；根因：客群Base Rate与额度结构变化，排序仍基本可用；决策：C渠道Segment Recalibration + 降额Challenger；结果：两个成熟Vintage看O/E回归、EL/Loan和Margin。

6）诊断：Default/成熟期 → PD版本 → Segment O/E → PSI → AUC/KS → EAD/LGD/EL。

7）策略动作：排序稳定、O/E高可先Recalibrate；单Segment高做Segment PD/价格/额度；O/E和AUC/KS都恶化再重训。

8）常见误区：未成熟Bad算Observed；不同预测窗口混用；Default O/E与Loss O/E混用；O/E>1就说模型一定“坏掉”。

9）推荐拆分：Channel、Score Band、Vintage、MOB、Product、Term、Limit/EAD、Region、Model/Strategy Version。

10）预警：用成熟Cohort、置信区间/最小Observed事件数。内部黄灯可设计为连续两个成熟Cohort显著偏离1并超自身稳定区间；若EL/Margin同步恶化升级红灯。

11）关系：PD → Expected Defaults → O/E → Recalibration → EL/Price/Limit → Margin；与PSI/AUC/KS组成监控三角。

12）小练习

10,000笔成熟贷款，ΣPD=1,200，实际Default=1,500，则O/E=1.25。含义：实际坏账比模型预期高25%，需拆Segment/成熟期并判断校准问题。

第五部分｜海外风控实操

今日实操：Model Monitoring Dashboard × Drift Root-cause Drill-down

所需数据：application_id、decision_date、channel、campaign、model_version、strategy_version、score、predicted_pd、关键feature及missing flag、approval、limit、disbursement/eAD、fpd7、bad_label、bad_maturity、actual_loss。

操作步骤：①锁定Reference Cohort/固定分箱；②做数据质量与Missing监控；③按Channel/Feature/Score算PSI；④成熟标签后算AUC/KS；⑤同窗口算O/E；⑥拆Channel×Score×Limit×Strategy；⑦桥接FPD/Vintage/EL/Margin；⑧提出Recalibration / Traffic / Limit / Retrain的分层动作。

SELECT
  model_version, channel, strategy_version,
  COUNT(*) AS n,
  AVG(predicted_pd) AS avg_pd,
  AVG(CASE WHEN bad_matured=1 THEN bad_flag END) AS observed_bad_rate,
  SUM(CASE WHEN bad_matured=1 THEN bad_flag ELSE 0 END)
    / NULLIF(SUM(CASE WHEN bad_matured=1 THEN predicted_pd ELSE 0 END),0) AS oe_ratio,
  AVG(CASE WHEN fpd7_matured=1 THEN fpd7_flag END) AS fpd7
FROM model_monitoring
GROUP BY model_version, channel, strategy_version;

Python/Excel思路：PSI使用固定Reference bins；AUC/KS只在成熟标签样本中计算；Excel可用Pivot做Channel×Score×Limit矩阵，Python可用 sklearn.metrics.roc_auc_score 计算AUC，并按Score排序计算Good/Bad累计占比的最大差得到KS。

阈值逻辑：不使用统一行业阈值。优先采用自身稳定历史、置信区间和最小样本量。示例：PSI异常但AUC/KS/O-E稳定→流量/结构黄灯；O/E连续偏高+EL/Margin恶化→校准红灯候选；AUC/KS/O-E同时持续恶化→重训/策略回滚红灯候选。

输出模板：日期｜Model｜Strategy｜Channel｜N｜Missing｜PSI｜AUC｜KS｜O/E｜Approval｜FPD7｜MOB1 DPD30+｜EL/Loan｜Margin｜Root Cause｜Action。

第二天复盘：先看Data Freshness、Feature Missing、流量与PSI；AUC/KS/O-E必须等标签成熟，不因一天未成熟波动全量重训。

第六部分｜业务与产品

风控 × 业务：模型“漂移”先区分流量、排序、校准，再决定是改渠道、改额度还是重训

业务会议以后不建议只展示一个PSI或AUC。统一经营链建议为：Traffic/Channel → PSI → AUC/KS → O/E → Approval/Limit/EAD → FPD/Vintage → EL → Contribution Margin。

典型动作映射：PSI高、排序/校准稳→先治理流量；AUC/KS跌→查特征/关系漂移，必要时重训；O/E高而排序稳→优先Recalibration/Price/Limit；三者同时恶化且Margin转负→回滚策略、降量并启动重训。

风控 × 产品：模型监控告警要能直接落到灰度、限额和回滚开关

产品与研发应把 Model Version、Strategy Version、Channel、Limit Guardrail 和Feature Flag打通。当单一渠道/Segment进入红灯，可只限制对应流量/额度，而不是全量关闭产品。

职责：产品负责灰度/页面/Offer与恢复路径；风控负责模型与策略告警和阈值动作；数据负责PSI/AUC/KS/O-E与业务结果口径；研发负责Feature/Model/Strategy版本、回滚和审计日志；运营不得用人工审批绕过红灯Segment。
