第三部分｜海外风控知识学习

今日知识：多头借贷（Multiple Borrowing / Loan Stacking）

概念：同一借款人在短时间内同时向多家机构申请或持有多笔未结清消费信贷。它既可能反映正常的信用需求，也可能代表流动性恶化、过度负债、欺诈性套现或“以贷养贷”。

为什么重要：多头常常是FPD和深度逾期的领先信号，尤其对thin-file或短期现金贷用户；但“多头数”不能直接等同坏客户，需要结合申请时间密度、未结清余额、还款历史、收入和设备/身份一致性。

核心指标：多头率 = 在定义观察窗内命中≥N家信贷机构/产品的申请用户数 ÷ 有效申请用户数申请密度 = 最近7/30天新增信贷查询次数；负债压力 = 未偿信贷月还款额 ÷ 可验证月收入

墨西哥现金贷案例（模拟）：5,000名首贷申请人中，900人最近30天有≥3家机构查询；该组FPD7为27%，其余用户FPD7为12%。但进一步拆解后发现，真正高风险集中在“≥3家查询 + 最近7天新增2家以上 + 额度使用率>80%”人群，单纯“历史上多头”并不足以全拒。

判断方法：先区分存量多头与短期新增多头，再叠加收入、设备、银行卡、还款历史和申请时间密度；建议把多头用于分层额度/准入而不是单变量一刀切。

常见误区：1）把征信查询次数直接当真实借款笔数；2）不同征信源时间戳/机构覆盖不一致；3）不区分首贷和复借；4）未验证因果就把渠道风险全部归因于多头。

今日练习

若A组用户最近30天有≥3家查询，FPD7=24%；B组无多头，FPD7=13%。但A组的平均额度比B组高60%。你下一步应该先做什么？答案：先按Score×Limit×查询密度拆解，判断是多头本身、额度暴露还是二者叠加导致金额风险恶化。

第四部分｜风控指标集合学习

今日新增/复习5个指标：FPD1、FPD3、FPD30、Ever DPD30+、Current Rate

FPD1：首期到期后第1天仍逾期的成熟订单占比。大白话：最早看“第一次还款马上就掉链子”的比例。它对支付失败、欺诈和极高风险客群特别敏感。

FPD3：首期到期后第3天仍逾期的成熟订单占比。相较FPD1，能过滤一部分短暂技术失败，更适合做渠道/策略早期预警。

FPD30：首期到期后第30天仍逾期的成熟订单占比。更接近实质信用风险，但成熟慢，不能用于刚上线策略的即时判断。

Ever DPD30+：观察期内“曾经达到过DPD30+”的账户/余额占比。与Current DPD30+不同，客户后来即使治愈，Ever标签仍然保留。

Current Rate：观察日处于正常状态的账户/余额占比。大白话：当前资产里有多少还在正常还款。它会受到新放款占比和成熟度影响，不能孤立用于判断资产质量。

统一案例（模拟）：策略V4上线后FPD1从21%升至28%，FPD3从18%升至20%，FPD30预计仍未成熟。支付监控发现到期日自动扣款失败率从4%升至11%。这时不能马上判定信用恶化；先修支付链路，再看FPD3/7是否回落。如果FPD1高、FPD3快速回落，更多像支付/提醒问题；若FPD1/3/7持续同步恶化，则更可能是客群质量问题。

指标关系：FPD1 → FPD3 → FPD7 → FPD30 → Ever DPD30+ → Bad Rate / Vintage。

第五部分｜海外风控实操

今日实操：多头借贷 × FPD早期预警矩阵

目标：识别“渠道风险恶化究竟来自多头、额度、支付问题还是策略放宽”。

所需字段：user_id、application_time、channel、campaign、score_band、approved_limit、disbursed_amount、bureau_inquiries_7d/30d、active_loans、monthly_debt_payment、verified_income、due_date、dpd1/dpd3/dpd7、payment_fail_flag、device_risk、strategy_version。

步骤：① 定义多头分层：0-1、2、3+；② 再拆最近7天新增查询；③ 计算FPD1/3/7件数和金额；④ 叠加Score×Limit；⑤ 把技术支付失败单独剔出或单列；⑥ 输出渠道×多头×额度矩阵。

SQL思路：

SELECT channel, multihead_band, limit_band,
 COUNT(*) matured,
 AVG(CASE WHEN dpd1>0 THEN 1.0 ELSE 0 END) fpd1,
 AVG(CASE WHEN dpd3>0 THEN 1.0 ELSE 0 END) fpd3,
 AVG(CASE WHEN dpd7>0 THEN 1.0 ELSE 0 END) fpd7,
 AVG(payment_fail_flag) payment_fail
FROM matured_first_due
GROUP BY channel, multihead_band, limit_band;

判断逻辑：如果FPD1高但FPD3/7回落，先查支付/提醒；如果多头3+人群FPD1/3/7持续同步高，且高额度档更差，再考虑准入或额度收紧。

预警：使用最近8周同渠道、同产品历史中位数做基线；黄灯/红灯阈值按内部波动和样本量设定，不使用“行业统一值”。

第二天复盘：看新增申请多头结构、支付失败率和最新FPD1；策略效果至少等FPD3/7成熟后再作更强结论。

第六部分｜业务与产品

风控 × 业务：为什么某渠道放款高，但FPD更差？

常见误判是直接把原因归到“渠道差”。实际需要拆四层：流量结构 → 多头/欺诈 → Score → Limit/Term。例如渠道X审批率高、首贷CAC低，但新增用户最近7天信贷查询密度更高，同时低Score用户拿到更大额度，最终会出现“放款量和件均都好看，金额FPD恶化”的组合。

经营判断：渠道是否值得保留应看风险调整后贡献利润，而不是CPI/CAC单指标。建议用：收入 - 资金成本 - CAC - EL - 支付/运营/催收成本。

风控 × 产品：放款前增加“实时轻量复核”

对于申请→审批→提款存在时间差的产品，建议在“确认提款/放款”前执行一次轻量复核：近期多头变化、设备/手机号/银行卡变化、账户状态、黑名单、额度有效期。

页面/交互：用户点击“确认借款”后，若风险不变直接放款；若风险轻度上升可降额或缩短额度有效期；若出现重大身份/设备异常则触发二次验证。不要把后台复核做成不可解释的随机失败。

职责：产品负责状态与解释；风控定义触发规则；数据监控复核命中→提款→FPD→EL；研发实现额度版本/幂等/回退；运营只触达当前仍有有效额度的用户。
