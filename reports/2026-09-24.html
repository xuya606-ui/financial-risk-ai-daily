三、海外风控知识学习｜AML Network & Mule Account Detection

概念：钱骡账户、设备、付款人、收款人、手机号和交易之间形成网络；单规则命中往往不如多跳关系和时间速度有效。

Customer → Device → Phone → Payer/Beneficiary → Transaction Velocity → Case → Report / Close

为什么重要：AI和自动化诈骗让账户开立、收款、转账、提现和还款网络更快形成；对现金贷，要把Fraud、AML、ATO和支付账户变更联动。

墨西哥现金贷七步案例

背景：APP发现部分新用户在放款后48小时内更换设备、修改还款账户，并由多个用户使用相同付款人代还。

数据：月度放款50,000笔；New Device 6%；Bank/CLABE Change 2.8%；共享付款人网络0.9%；共享设备网络0.4%；相关组合的确认欺诈率0.15%→0.62%；FPD7 12.8%→18.4%。

现象：单项指标都不算极端，但组合风险快速上升。

拆解：New Device×Password Reset×Bank Change×Shared Payer是最高风险组合。

根因：组合信号与欺诈结果高度相关，但需要Holdout和人工Case验证，不能仅凭图谱关联断言因果。

决策：高风险组合进入Step-up/人工复核；低风险固定设备和长期稳定付款人保留低摩擦；付款人/设备/账户建立网络特征。

结果：观察14—30天确认欺诈、FPD7、Roll30、Case Yield、投诉、误伤率和净损失。

常见误区：共享付款人=欺诈；图谱关联=因果；只看用户不看设备和付款人；过早扩大规则导致误杀。

小练习：50,000笔放款中450笔处于共享付款人网络，另有80笔确认欺诈。共享付款人网络占比是多少？确认欺诈率是多少？答案：0.9%；17.8%。

四、风控指标集合学习

指标统一学习卡摘要
Mule Network Hit Rate命中钱骡网络特征的成熟账户÷监控账户；用于贷前/贷中/贷后网络风险识别。高不一定坏，可能是规则太宽；必须联看Confirmed Fraud、FPD、误伤率和Case Yield。关系链：Device/Payer/Beneficiary→Network Hit→Step-up→Fraud/FPD。
Shared Payer Rate由共享付款人代还或入账的账户占比；件数和金额要分开，按固定观察窗口去重。高可能是家庭/共同经营，也可能是团伙或代收集资金，应按设备、地址、银行账户、金额速度拆分。
Account Network Velocity固定时间内一个设备/手机号/付款人/收款账户关联的新增账户或交易数量。领先指标；上升可能意味着团伙扩张，但也可能来自营销活动或批量企业客户。
Case Yield成熟Alert中升级为可确认风险Case的比例。它是AML/Fraud规则质量和调查资源利用率指标，不应以“越高越好”简单判断。需与P90 Aging、Backlog、Report Yield一起看。

五、海外风控实操｜Money Mule Network Detection

所需数据：customer_id、device_id、phone、payer_account、beneficiary_account、bank_account、loan_id、disbursement_time、repayment_time、password_reset、bank_change、fraud_label、fpd7、case_id。

步骤：实体标准化→构建二部/多部图→生成共享设备/付款人/收款人特征→按速度与金额分层→Step-up/人工复核→回流Case结果。

High-risk candidate = New Device + Password Reset + Bank Change + Shared Payer + High Velocity

SQL思路：按device_id、payer_account、beneficiary_account计算关联账户数、24h新增数、金额和节点度；Excel做Network Segment透视；Python可用图聚类/连通分量做团伙候选。

第二天复盘：检查高风险节点的真实Case Yield、误伤率和FPD，避免把正常家庭/商户网络全量封禁。
