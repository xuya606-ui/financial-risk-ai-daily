2026-08-29征信 / 多头 / 申请速度

今日风控指标完整学习卡

今天新增四个高频贷前指标：Bureau Hit Rate、Recent Inquiry Rate、Multi-Borrowing Rate、Application Velocity。核心学习目标是：征信“查不到”不等于低风险，查询次数多也不应一刀切拒绝；必须把征信覆盖、近期查询、活跃贷款、申请速度与Score、Limit、收入和设备风险组合判断。案例数字均为模拟训练数据，不代表行业统一阈值。

今日指标关系链

Bureau Query → Bureau Hit → Recent Inquiry / Active Lenders → DTI/PTI → Approval / Limit → FPD / Vintage → EL / Contribution Margin

反欺诈侧还需要叠加：User / Device / Phone / IP Application Velocity → Identity/Graph Risk → Step-up / Reject。

1. Bureau Hit Rate｜征信命中率

贷前数据质量领先指标

1）指标是什么

中文可称征信命中率/征信可用率。大白话：真正发起征信查询的人里，有多少拿到了可用于风控判断的有效征信结果。

2）为什么重要

它同时反映征信覆盖、身份匹配、供应商稳定性和客群Thin-file/No-file结构。属于贷前领先/同步指标。Hit下降既可能是客群更“薄”，也可能只是Vendor超时、CURP/姓名映射或接口故障。

3）精确定义与公式

Bureau Hit Rate = 返回可用征信结果的有效申请数 ÷ 实际完成征信查询的有效申请数

分子：返回满足内部“可用”定义的报告/变量。分母：真正发起并完成查询尝试的申请。技术超时、身份不匹配、No-file、数据为空建议分别打原因码，不要全部混为No-hit。按申请/用户口径需固定；重复申请去重规则也需固定。

4）如何看高低

通常稳定较好，但越高不一定代表风险更低。Hit突然下降时先排技术；Hit升高也可能只是供应商覆盖改善，使过去不可见的高负债用户被识别出来。

5）墨西哥现金贷案例七步法（模拟）

背景：首贷产品切换征信接口版本。
数据：申请20,000；Bureau Hit 78%→64%；Vendor Timeout 4%→18%；No-file占比基本稳定；Approval 31%→30%；成熟FPD7 15.0%→15.3%。
现象：Hit下降14个百分点，但信用表现几乎没变。
拆解：按Vendor Error、CURP匹配、Channel、App Version拆解，新增No-hit主要集中接口超时，而不是No-file增加。
根因：更强候选原因是技术可用性下降；不能把No-hit增加直接解释成客群恶化。
决策：恢复备用路由；技术No-hit与真实No-file分流；新客技术No-hit不直接放宽额度，稳定复借客可用内部历史做有限Fallback。
观察结果：未来24小时看Hit/Timeout恢复，风险端继续等FPD7和MOB1成熟。

6）诊断逻辑

① Vendor/接口错误码 → ② 身份字段匹配 → ③ No-file/Thin-file结构 → ④ Channel/地区 → ⑤ FPD/Bad表现。

7）策略动作

技术型No-hit：切备用Vendor/重试；真实No-file：结合收入、设备、内部历史和低额度策略；身份不匹配：进入KYC二验；不要把所有No-hit统一拒绝或统一放行。

8）常见误区

误区1：把技术超时当No-file。误区2：用“查不到征信=低负债”做提额依据。误区3：申请级与用户级重复查询混算。

9）推荐拆分维度

Vendor、Error Code、Channel、Region、CURP/姓名匹配、New/Repeat、App Version、Device、Strategy Version。

10）预警方式

数据可用性适合小时/日级监控；使用自身稳定7/30天基线和最小样本量。Hit跳变时先做技术黄灯，只有客群结构和成熟风险同步变化才升级信用风险预警。

11）与其他指标关系

Bureau Hit → Inquiry / Active Loans / DTI → Approval/Limit → FPD → EL。

12）小练习与参考答案

Hit从80%降到65%，Timeout从3%升到17%，No-file占比不变。首先应该收紧准入吗？

答案：不应。优先修复征信数据链路，并把技术No-hit和真实No-file分开。

2. Recent Inquiry Rate｜近期征信查询率 / 查询密度

信用压力贷前领先指标

1）指标是什么

大白话：用户最近7/30天是不是在密集找钱。 可用“高查询用户占比”或“人均查询次数”两种口径，但必须固定。

2）为什么重要

近期查询密度常用于捕捉短期资金压力、Loan Shopping和潜在Loan Stacking。它比历史账户总数更敏感，但不能单独证明用户一定会坏。

3）精确定义与公式

High Inquiry Rate = 近N天有效Hard Inquiry达到内部阈值的Bureau-hit用户数 ÷ Bureau-hit用户数
Inquiry Density = 近N天有效Hard Inquiry总次数 ÷ Bureau-hit用户数

时间窗（7/30/90天）、Hard/Soft Inquiry、同一机构短时间重复查询去重方式必须固定。阈值只能使用内部成熟历史校准。

4）如何看高低

通常越高表示短期信用需求越强，但正规比价也会提高查询。低查询也不代表低风险：征信覆盖不足或地下借贷可能不可见。

5）案例七步法（模拟）

背景：墨西哥首贷渠道C扩量。
数据：12,000个Bureau-hit用户；30天查询0-1次组FPD7=11%；2-3次=17%；4次及以上=27%；高查询用户占比12%→20%；渠道C高查询占比31%。
现象：整体Approval基本不变，但FPD7升高。
拆解：高查询风险进一步集中于低Score + Limit≥MXN1,800；中高Score低额度用户风险增幅有限。
根因：近期查询与风险恶化高度相关，但不能直接证明查询本身造成坏账；渠道和额度结构是共同变化因素。
决策：不做“查询≥4直接拒绝”；采用Inquiry × Score × Limit × DTI分层，边缘组降额或二验。
观察结果：看FPD3/7、金额FPD、Approval、EL和Contribution Margin。

6）诊断逻辑

① 查询类型/去重 → ② 7d vs 30d变化 → ③ Score/DTI → ④ Active Loans/Limit → ⑤ Channel和成熟FPD。

7）策略动作

高查询+低Score+高Limit：降额/拒绝/二验；高查询但高Score且收入稳定：可限额测试；渠道高查询占比跳升：渠道降量或素材/媒体位排查。

8）常见误区

误区1：把所有查询都当Hard Inquiry。误区2：不同机构的重复查询不去重。误区3：查询多直接等于欺诈或坏账。

9）拆分维度

7d/30d、Channel、Score、Limit、DTI/PTI、New/Repeat、Region、Bureau Provider。

10）预警方式

监控高查询用户占比和人均查询数的周/月变化，并与FPD和Approval联动。任何“≥N次”阈值都标注为内部示例，不冒充行业标准。

11）指标关系

Recent Inquiry → Multi-Borrowing / DTI → Limit → FPD/Vintage → EL。

12）小练习与答案

用户A有4个历史账户但仅1个活跃、30天无新查询；用户B只有2个活跃账户但7天5次查询。哪个更值得优先二验？

答案：B。短期查询密度比历史账户总数更能反映近期资金压力。

3. Multi-Borrowing Rate｜多头借贷率

信用风险偿付能力贷前

1）指标是什么

大白话：申请人里，有多少正在同时向多家机构背债。

2）为什么重要

多头会提高现金流压力和借新还旧风险，是信用风险的重要领先指标；但“历史曾有多家机构”与“当前同时多头”不是一回事。

3）精确定义与公式

Multi-Borrowing Rate = 当前活跃贷款机构数达到内部阈值的Bureau-hit用户数 ÷ Bureau-hit用户数

必须固定：Active定义、机构去重、信用卡/分期/现金贷是否纳入、观察日、数据时滞。件数口径为主，建议同步看活跃贷款余额和月度债务偿付。

4）如何看高低

通常越高信用压力越大，但稳定复借用户可能同时持有低风险正规账户；反之“No-hit”用户的外部负债可能不可见。

5）案例七步法（模拟）

背景：首贷产品准备把多头作为新准入规则。
数据：活跃Lender 0-1家FPD7=10%；2家=15%；3家及以上=24%；但3+中“收入可验证+Limit≤1,200”FPD7=16%，而“30天查询≥4+Limit≥2,000”FPD7=33%。
现象：多头整体风险更高，但内部差异很大。
拆解：Active Lender × Recent Inquiry × Score × Limit × Income Verification。
根因：高风险更集中在“近期新增多头+高额度+低Score”，而不是所有多头用户。
决策：3+不直接一刀切；低额度稳定收入用户可Challenger，高查询/高额度组合收紧。
观察结果：追FPD7、MOB1 DPD30+、EL和复借表现。

6）诊断逻辑

① Active vs Historical → ② Lender数量与余额 → ③ Recent Inquiry → ④ DTI/PTI/收入 → ⑤ Score/Limit和成熟风险。

7）策略动作

近期新增多头：降额/缩短额度有效期；高DTI多头：拒绝或降额；历史多头但当前稳定：差异化处理；数据不完整：避免“假低多头”。

8）常见误区

误区1：历史关闭账户也算活跃多头。误区2：只看机构数不看余额/偿付额。误区3：数据时滞造成多头低估。

9）拆分维度

Active Lenders、Outstanding Balance、Inquiry、DTI/PTI、Score、Limit、Channel、New/Repeat。

10）预警方式

监控3+等内部高多头档占比、平均活跃Lender数及其FPD；阈值按成熟历史和产品期限校准。

11）指标关系

Inquiry → Active Lenders → DTI/PTI → Approval/Limit → FPD/Bad → EL。

12）小练习与答案

两个用户都是3家活跃Lender，一个DTI 25%、收入稳定；另一个DTI 55%且7天新增2家。风险相同吗？

答案：不同。应优先收紧第二个用户，不能仅按Lender数量做同一动作。

4. Application Velocity｜申请速度 / 短期申请密度

欺诈信用压力实时指标

1）指标是什么

大白话：同一用户、设备、手机号或IP在很短时间里提交了多少次申请。

2）为什么重要

高速度可能代表紧急资金需求、重复尝试、机器人/团伙攻击或多账号欺诈。它既是反欺诈领先指标，也是短期信用压力辅助指标。

3）精确定义与公式

Application Velocity = 滚动窗口内申请次数 ÷ 观察实体（User/Device/Phone/IP）
High Velocity Rate = 达到内部次数阈值的实体数 ÷ 有效实体数

窗口可用30分钟/24小时/7天。必须区分同一用户重复提交和多个用户共享设备/IP；技术重试/重复上报应去重。

4）如何看高低

越高通常风险更值得关注，但网络不稳定造成重复提交、家庭共享设备/公共IP会产生假阳性。低速度也不能排除有组织的一人一机欺诈。

5）案例七步法（模拟）

背景：渠道D某小时申请量暴增。
数据：30分钟≥3次申请的Device占比1.2%→4.8%；该组Fraud Rate 14%、全量3.5%；若同时“同CLABE≥2用户”，Fraud Rate升至26%，FPD7=32%。
现象：高速申请和欺诈同时上升。
拆解：User vs Device vs IP，叠加CLABE、Phone、Channel和时间段。
根因：多信号组合与团伙风险高度相关；单纯IP高速可能受运营商NAT影响。
决策：单一Velocity只二验/限频；Velocity+共享CLABE/设备图谱高风险进入人工或硬拒。
观察结果：看Fraud Capture、FPR、Approval、投诉和最终Fraud Loss。

6）诊断逻辑

① 去除技术重复 → ② User/Device/IP分开 → ③ Shared Bank/Phone图谱 → ④ Channel/时段 → ⑤ 成熟Fraud/FPD。

7）策略动作

用户重复申请：冷静期/限频；设备多用户高速：Step-up/图谱审核；IP高速：结合Device/Phone避免NAT误杀；明显机器人：Rate Limit + Device/Session控制。

8）常见误区

误区1：同IP多申请直接等于团伙。误区2：系统重试重复计数。误区3：只看申请次数不看不同身份数。

9）拆分维度

User、Device、Phone、IP、CLABE、Channel、Minute/Hour、OS、App Version、Strategy。

10）预警方式

实时分钟/小时基线最合适；关注P95/P99速度和高Velocity实体占比。阈值必须按自身流量和网络环境校准。

11）指标关系

Application Velocity + Graph Risk → Step-up/Reject → Fraud Capture → Fraud Loss / FPD。

12）小练习与答案

同一IP 30分钟出现20个申请，但Device都不同；另一个Device 20分钟出现3个不同身份且共享同一CLABE。哪个更优先风控？

答案：第二个组合通常信息更强；第一个需要先排查运营商NAT/公共网络。

今日共同结论

征信策略不要只做“查到/查不到”和“查询次数≥N就拒绝”。更有效的结构是：

Bureau可用性 → 近期查询 → 活跃Lender/余额 → DTI/PTI → Score → Limit → 申请速度/设备图谱 → FPD/EL

任何数值阈值均应来自墨西哥实际产品、期限、成熟样本和成本函数；模拟案例只用于学习分析逻辑。
