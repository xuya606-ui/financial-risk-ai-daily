风控指标学习卡｜ATO / Fraud Loss / Step-up Challenge / Override

以下指标统一采用12段结构：是什么、为什么重要、精确口径、怎么看高低、墨西哥案例七步法、诊断、动作、误区、拆分、预警、关系、小练习。案例数字为模拟训练数据，不代表行业统一阈值。

ATO Rate｜Account Takeover Rate｜账户接管率

贷中/贷后欺诈领先+滞后结合

1）指标是什么

已经存在的真实账户里，有多少在观察期内被确认或高度可信地发生了“非本人控制账户并执行关键动作”。大白话：不是假用户来申请，而是真用户的账户被别人拿走了。

2）为什么重要

ATO常发生在复借、提款、换卡、账户修改阶段。复借客户通常额度更高、流程更短，因此ATO虽然件数不一定高，但金额损失和投诉影响可能很大。它是账户安全的核心风险指标。

3）精确定义与公式

ATO Rate（用户口径） = 观察期内确认ATO的独立账户数 ÷ 同期可观察活跃账户数
ATO per 10k = ATO账户数 ÷ 活跃账户数 × 10,000

必须固定：什么算“确认ATO”、观察窗口、活跃账户定义、同一用户多次事件是否去重。建议同时报用户口径和金额损失口径。

4）如何看高低

通常越低越好。但如果新增更强的ATO识别模型，短期“确认ATO率”反而可能上升，因为以前未识别的事件被识别出来。所以需要区分 Detected ATO 和 Estimated/Confirmed Loss。

5）墨西哥现金贷案例七步法（模拟）

背景：复借用户平均额度MXN3,000，过去两周用户投诉“不是本人提款”增加。
数据：活跃复借账户120,000；ATO确认账户由420升至984；ATO Rate 0.35%→0.82%；新设备+密码重置组ATO率3.6%；银行卡变更后30分钟提款组ATO率5.2%；平均ATO损失MXN2,450。
现象：Approval和信用FPD基本稳定，但Fraud Loss明显恶化。
拆解：按Device Change × Password Reset × Bank Change × Time-to-Drawdown × Limit后，损失高度集中在多信号组合。
根因：多信号组合和ATO高度相关；单一换设备不是充分因果证据，需要排除正常换机和旅行场景。
决策：高风险组合Step-up；银行卡刚变更时设置短冷静期；高额度提款要求更强认证。
观察结果：至少观察ATO事件成熟和投诉结案；同时看Fraud Loss、Step-up Pass、Take-up和Contribution Margin。

6）诊断逻辑

①确认标签与投诉证据 → ②看设备/认证变化 → ③看银行卡/手机号修改 → ④看关键动作时间差和额度 → ⑤看Step-up是否有效。

7）策略动作

单一新设备：低摩擦二验；多信号高风险：强二验或冷静期；高额提款：提高认证强度；重复ATO组件：设备/IP/银行卡图谱封控。

8）常见误区

误区1：新设备=ATO。误区2：只看件数，不看金额损失。误区3：把用户遗忘密码造成的重置当欺诈。误区4：不区分“已检测ATO”和“真实ATO基率”。

9）推荐拆分维度

新老客、复借次数、Device Change、Password Reset、Phone Change、Bank Change、IP/Geo、Limit、Time-to-Drawdown、Strategy Version。

10）预警方式

建议用最近稳定8周同产品/同版本基线，并至少设置每万活跃账户ATO事件、ATO金额损失、用户投诉三个联动信号。黄/红灯阈值按内部损失容忍度和样本量设定。

11）与其他指标关系

Account Change Risk → Step-up Challenge → ATO Rate → Fraud Loss Rate → Recovery → Contribution Margin。

12）小练习

某周ATO Rate从0.4%升至0.7%，但同时新模型上线使ATO识别覆盖提升一倍。能否直接认定攻击变严重？

参考答案：不能。要同时看确认损失、投诉、金额Fraud Loss及历史回溯识别率，区分检测能力提升和真实事件增长。

Fraud Loss Rate｜欺诈损失率

欺诈金额风险滞后指标

1）指标是什么

放款或风险暴露中，最终确认因为欺诈而损失掉的金额比例。大白话：不是抓了多少欺诈，而是真正损失了多少钱。

2）为什么重要

Fraud Rate件数不变时，如果欺诈集中在高额度账户，Fraud Loss Rate可能大幅恶化。它比单纯欺诈件数率更直接连接利润和资本损失。

3）精确定义与公式

Fraud Loss Rate = 确认欺诈净损失金额 ÷ 同期放款本金或风险暴露金额

分子建议明确是否扣回收；可以同时报告Gross Fraud Loss和Net Fraud Loss。分母要固定用Disbursed Principal还是EAD，不同产品不可混用。

4）如何看高低

通常越低越好。但Fraud Loss下降可能只是额度收缩或业务量下降，因此要和Approval、Take-up、Average Ticket、Recovery一起看。

5）墨西哥案例七步法（模拟）

背景：复借信用策略未调整，Fraud Rate件数0.9%→1.0%。
数据：件均MXN1,900→2,250；Fraud Loss Rate 1.1%→1.9%；ATO占欺诈损失从28%升至49%；Recovery 8%→9%。
现象：件数欺诈只微升，但金额损失明显恶化。
拆解：高Limit复借 + 新CLABE + 新设备贡献大部分增量。
根因：金额暴露结构变化比欺诈事件数量变化更关键。
决策：对高Limit提款加强ATO二验，不必全量收紧信用Approval。
观察：Fraud Loss、ATO、Take-up、Average Ticket、Net Recovery和Contribution Margin。

6）诊断逻辑

①件数vs金额 → ②Fraud Type → ③Limit/Ticket → ④Recovery → ⑤渠道/设备/账户变化。

7）策略动作

高额欺诈：限额/二验；设备团伙：图谱规则；支付欺诈：银行卡/收款账户策略；首方欺诈：信用与身份联合策略。

8）常见误区

Fraud Rate与Fraud Loss Rate混用；Gross/Net口径不一致；尚未成熟事件提前算最终损失；只按件数评估模型。

9）拆分维度

Fraud Type、Channel、Score、Limit、New/Repeat、Device Risk、Bank Change、Strategy Version。

10）预警方式

建议金额口径设置周/月滚动基线，并用“Fraud Loss偏离 + 高额度欺诈占比 + ATO占比”联合预警。

11）指标关系

Fraud Signals → Fraud Capture / ATO → Fraud Loss → Recovery → Net Loss → Contribution Margin。

12）小练习

Fraud Rate从1.2%降到1.0%，但Fraud Loss Rate从1.5%升到2.1%，说明什么？

答案：优先检查高额度欺诈、Average Ticket和Fraud Type结构，不能只看件数认为风险改善。

Step-up Challenge Rate｜二次验证触发率

账户安全产品摩擦同步指标

1）指标是什么

关键会话或高风险操作中，有多少被要求额外完成活体、OTP、银行卡同名、人工审核等验证。

2）为什么重要

它衡量“风控增加了多少摩擦”。触发太低可能漏风险；触发太高可能造成大量放弃、客服投诉和转化损失。

3）精确定义与公式

Step-up Challenge Rate = 触发二次验证的eligible关键操作数 ÷ eligible关键操作总数

分母必须定义“eligible”：登录、换卡、提款、额度使用等场景不要混成一个总体数字，建议分场景报告。

4）如何看高低

不是越高越好。理想状态是高风险段高触发、低风险段低摩擦。

5）墨西哥案例七步法（模拟）

背景：ATO策略上线，对复借提款增加Step-up。
数据：Challenge Rate 3%→11%；Pass Rate 76%；提款放弃率5%→8%；Fraud Loss下降26%；低风险Score段也被触发7%。
现象：风险下降，但产品摩擦明显增加。
拆解：低风险用户主要因单一“新设备”触发，而高风险组合的Fraud Capture显著更高。
根因：触发规则过宽，把低风险换机用户也纳入强验证。
决策：单一新设备降级为轻验证；新设备+密码/银行卡变化才强Step-up。
观察：Challenge、Pass、Abandonment、Fraud Loss、投诉和Take-up。

6）诊断逻辑

①按触发原因拆分 → ②看Risk Band → ③看Pass/Abandonment → ④看Fraud Capture/Loss → ⑤看投诉。

7）策略动作

低风险高触发：降低敏感度；高风险低触发：加强规则；Pass低但Fraud也低：检查验证技术问题；Pass高且Fraud高：验证强度不足。

8）常见误区

分母用全部登录而不是eligible操作；把系统故障触发也算风险Step-up；只优化Fraud Loss不看转化。

9）拆分维度

Trigger Reason、Risk Band、Device Change、Bank Change、Limit、New/Repeat、OS、Strategy Version。

10）预警方式

按场景设置内部稳定基线，联合监控Challenge Rate、Pass Rate、Abandonment和Fraud Loss，不建议单独给统一行业阈值。

11）指标关系

Risk Signal → Step-up Challenge → Step-up Pass/Abandon → ATO/Fraud Loss → Take-up/Profit。

12）小练习

Challenge从5%升到15%，Fraud Loss下降10%，但Take-up下降12%。是否直接继续加码？

答案：不能。需要按风险段算Fraud Loss Saved与转化利润损失，找到边际最优触发范围。

Override Rate｜人工改写率

模型治理策略治理同步指标

1）指标是什么

模型或规则给出原始决策后，有多少被人工最终改写。应至少拆成Approve Override（原拒绝改通过）和Decline Override（原通过改拒绝）。

2）为什么重要

Override既可能代表人工补充了模型无法捕捉的信息，也可能代表策略执行不一致、运营干预或模型/规则失配。持续高Override是模型治理的重要信号。

3）精确定义与公式

Override Rate = 被人工改变最终结果的决策数 ÷ 可被人工Override的决策数

必须保存Original Decision、Final Decision、Override Reason、Operator、Time、Strategy Version，并对Override样本单独做成熟表现。

4）如何看高低

低不一定好，如果团队根本不允许必要的人工作业；高也不一定坏，如果处于新市场模型冷启动。但持续高且集中在某Score段通常需要检查模型或规则。

5）墨西哥案例七步法（模拟）

背景：首贷模型V6上线，人工审核团队仍可改写结果。
数据：Override 4%→13%；其中Approve Override占72%；Override通过组FPD7=24%，模型直接通过组=14%；多数Override集中在边缘Score且来自同一运营班组。
现象：人工改写明显增多，并把风险较高的边缘客重新放行。
拆解：按Operator、Reason、Score、Channel后发现“业务保量”是主要原因。
根因：这不是简单模型失效，更可能是治理问题；需要检查激励目标、权限和审批链。
决策：限制无证据的Approve Override；高风险Override需二级审批；把“补充材料后通过”与“纯业务保量”分开。
观察：Override样本的FPD/Vintage、净利润、操作人员分布和申诉结果。

6）诊断逻辑

①Approve/Decline拆分 → ②Reason → ③Operator/Team → ④Score/Rule → ⑤成熟Bad/Profit。

7）策略动作

高Approve Override+高Bad：收权限；高Decline Override+低Bad：检查是否过度人工保守；集中某Score段：调整模型/策略；集中某班组：治理/培训。

8）常见误区

把人工Review但未改结果也算Override；不保存原始模型结果；只看总体Override不拆方向；未成熟样本直接判断人工优劣。

9）拆分维度

Override Direction、Reason、Operator、Channel、Score、Rule、Limit、Strategy Version。

10）预警方式

按团队/策略版本设置历史基线；如果Override上升同时Override Bad Rate显著高于模型直接通过组，应升级治理审查。

11）指标关系

Model/Rule Decision → Override → Final Approval → FPD/Vintage → EL → Model Governance。

12）小练习

Override从5%升到12%，但全部发生在“补充收入证明后通过”，且成熟Bad低于模型直接通过组。是否一定是坏事？

答案：不一定。这可能说明人工获得了有价值的新增信息，应评估是否把该信息结构化并纳入模型/规则，而不是简单禁止Override。
