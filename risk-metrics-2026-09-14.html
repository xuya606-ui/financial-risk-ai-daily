2026-09-14｜KYC / Identity 四张完整指标学习卡

今日指标：KYC Completion Rate、Identity Verification Pass Rate、Liveness Failure Rate、KYC Step-up Conversion Rate。所有阈值仅作内部示例，不能冒充行业统一标准。

1. KYC Completion Rate｜KYC 完成率

1）指标是什么：进入 KYC 流程的 Eligible 用户里，有多少真正完成全部必需 KYC 步骤并产生可供决策的结果。大白话：不是看“过没过”，而是先看“有没有走完”。

2）为什么重要：属于贷前/身份阶段的同步指标，解决技术、产品体验与风险结果混淆的问题，是 Identity Pass、Approval 和 CAC 转化的上游。

3）精确定义与公式：KYC Completion Rate = 完成全部必需KYC步骤并产生最终可决策结果的唯一申请 ÷ 实际进入KYC流程的Eligible唯一申请必须固定进入KYC定义、重复申请去重、观察窗口和是否把主动退出/超时算未完成。建议按申请/订单口径；用户口径另报。

4）如何看高低：一般较高更好，但并非越高越好；过度简化 KYC 可能提高 Completion 却降低身份保证强度。下降既可能来自攻击增加，也可能来自 SDK、网络、OCR、设备兼容或页面摩擦。

5）墨西哥七步案例：背景：首贷APP更换活体SDK并扩大Channel B。数据：申请50k；Completion 78%→70%；Liveness Failure 5%→11%；Identity Pass 91%→87%；Step-up Conversion 68%→44%；Approval32%→27%；成熟Identity Fraud2.8%→3.0%。现象：Completion大降但Fraud只小幅升。拆解：Android旧版本×Channel B×新SDK错误率最高。根因：技术问题与流量结构共同变化，不能把全部下降归因于Fraud。决策：提供重试/Fallback，风险冲突再Step-up。结果：48-72小时看Error/Completion，两个成熟Fraud Cohort看FPR/Approval/Margin。

6）诊断逻辑：①Eligible/Start分母；②Step-level Drop-off；③Vendor/Error Code/Network；④Device/App Version/Channel；⑤Identity Fraud/Approval。

7）策略动作：技术超时→修SDK/Fallback；OCR模糊→改善拍摄引导；特定渠道异常→降量并核验流量；真实身份冲突上升→加强Step-up或Hard Fail。

8）常见误区：未完成=Fraud；Start分母和全申请混用；多次重试重复计数；不同KYC路径横比；只看总Completion不看错误码。

9）推荐拆分维度：Channel、Campaign、KYC Vendor、Document Type、Device、OS/App Version、Region、Network、New/Repeat、Strategy Version。

10）预警方式：以同KYC版本稳定历史和样本门槛为基线。内部示例黄灯：Completion连续2个批次低于历史P10且Technical Error同步升高；若Fraud/Identity Conflict同步升高，再升红灯候选。

11）与其他指标关系：KYC Start → Completion → Identity Pass → Step-up → Final KYC Pass → Approval → Fraud/FPR → Margin。

12）小练习

40,000个Eligible进入KYC，30,000个走完并获得最终结果。Completion=75%。如果次日降到65%且SDK Timeout翻倍，第一动作应是查SDK/网络，而非直接收紧信用。

2. Identity Verification Pass Rate｜身份核验通过率

1）指标是什么：完成身份核验且证据足够可判断的申请中，有多少最终通过证件、身份一致性和基础身份规则。大白话：走完KYC的人里，身份本身有多少被认可。

2）为什么重要：贷前同步指标，决定后续审批漏斗和身份欺诈暴露；需要把技术No-result从业务Fail中分离。

3）精确定义与公式：Identity Verification Pass Rate = 最终Identity Pass唯一申请 ÷ 已完成且具备可判定身份结果的唯一申请分母不应混入SDK超时、图片上传失败等Technical No-result；需固定证件类型、Vendor、阈值、人工复核是否计入最终结果。

4）如何看高低：通常高代表更多身份有效，但过高可能阈值过松；下降可能是客群变差，也可能是Vendor策略/阈值或证件识别问题。

5）墨西哥七步案例：背景：Channel B引入新的低价流量。数据：Completed KYC35k；Identity Pass91%→87%；Document Mismatch2%→5%；Device High Risk6%→9%；Confirmed Identity Fraud2.8%→3.6%；Approval31%→28%。现象：Pass下降且Fraud上升。拆解：Channel B×新设备×身份证件低清晰度最差。根因：存在真实客群风险恶化证据，但证件拍摄质量也变差。决策：高风险组合加强Step-up；低清晰度优先重拍而非Hard Fail。结果：看Fraud Capture、FPR、Completion和投诉。

6）诊断：①可判定分母；②Document/Face/Identity Reason；③Vendor/Version；④Channel/Device；⑤成熟Fraud/FPR。

7）策略动作：Document Mismatch高→加强证件真实性/姓名一致；低质量图像→重拍；高风险Device叠加身份冲突→Step-up/Hard Fail；Vendor漂移→Fallback或重新校准。

8）常见误区：把Technical Fail算Identity Fail；Pass越高越好；未成熟用户都当Good；不同Vendor阈值直接横比。

9）拆分：Channel、Document Type、Vendor、Reason Code、Device Risk、Score、Region、App Version、Strategy。

10）预警：同Vendor/阈值版本比较；Pass下降必须同时看Identity Fraud Capture、FPR与Technical Fail。单一比例不作为红灯。

11）关系：Document/Face Evidence → Identity Pass → KYC Final Pass → Approval → Identity Fraud Loss。

12）小练习

20,000个可判定身份申请，17,600通过，Identity Pass=88%。若Pass降4pp而Fraud Capture不变、Technical Fail大升，应先查Vendor技术链。

3. Liveness Failure Rate｜活体失败率

1）指标是什么：实际进入活体检测并得到有效结果的申请中，有多少未通过活体检测。大白话：活体环节拦下了多少，但它不等于“有多少欺诈”。

2）为什么重要：贷前身份/欺诈同步指标，既反映攻击，也高度受光线、摄像头、设备、SDK、网络和阈值影响，是最容易被误判的KYC指标之一。

3）公式：Liveness Failure Rate = 有效Liveness Result中Fail的唯一申请 ÷ 得到有效Liveness Result的唯一申请Technical Error、Timeout建议单列，不进入业务Fail；需固定Vendor、SDK和阈值版本。

4）高低：高可能代表攻击增加，也可能代表技术体验恶化；低也可能阈值过松。不能用“越低越好”简单判断。

5）墨西哥七步案例：背景：新Liveness SDK上线。数据：Failure5%→11%；Technical Error3%→9%；Step-up Pass68%→44%；Confirmed Face/Identity Fraud2.1%→2.3%；Android 10及以下Fail18%；iOS Fail4%。现象：Fail几乎翻倍但Fraud增量有限。拆解：主要集中旧Android与弱网。根因：强烈支持技术兼容性是主要因素之一，但需回滚/AB验证。决策：旧设备Fallback、增加拍摄引导；强身份冲突才Hard Fail。结果：小时级看Error/Fail，成熟后看Fraud/FPR。

6）诊断：①Technical vs Business Fail；②Device/OS；③Network/Camera；④Vendor/Threshold；⑤Fraud Outcome。

7）策略动作：旧设备异常→Fallback；光线/姿态问题→UX提示；攻击模式升高→强化动态动作/设备信号；误杀高→调整阈值并Challenger。

8）常见误区：Liveness Fail=Fraud；Timeout也算Fail；只看整体不看设备；低Fail率=安全；不同阈值版本横比。

9）拆分：OS、Device Model、Camera、Network、Vendor、Threshold、Channel、Region、App Version、Fraud Type。

10）预警：技术预警可小时级；风险预警必须等成熟Fraud。示例黄灯：Fail↑且Technical Error↑、Fraud不升；另一类红灯候选是Fail↑且Confirmed Face Fraud/Device Risk同步升。

11）关系：Device/Camera/Attack → Liveness Result → Step-up/KYC Pass → Fraud Capture/FPR → Approval。

12）小练习

10,000个有效活体结果，1,100 Fail，Failure=11%。若其中技术错误另有900笔未进入有效结果，不应把900加进11%的分子。

4. KYC Step-up Conversion Rate｜KYC 加强验证转化率

1）指标是什么：被要求追加验证的用户中，有多少最终完成并通过加强验证。大白话：灰区用户被要求“再证明一次”后，有多少能顺利回来。

2）为什么重要：贷前同步指标，是 Hard Decline 和 Allow 之间的重要缓冲层，决定误杀、Fraud Capture、体验与审核成本。

3）公式：KYC Step-up Conversion Rate = 在规定窗口内完成且通过Step-up的唯一申请 ÷ 被正式要求Step-up且窗口成熟的唯一申请必须固定Step-up类型、有效期、是否允许多次重试、用户/订单口径；Technical Fail单列。

4）高低：高通常意味着灰区用户可恢复，但过高可能说明Step-up太弱；低可能是真高风险，也可能流程过难、供应商故障或通知不到位。

5）墨西哥七步案例：背景：V8将新设备+银行卡变更用户导入Face+Bank Match Step-up。数据：Step-up用户6k；Conversion68%→44%；Technical Fail7%→19%；Fraud Capture+0.4pp；Complaint0.6%→1.4%；Approval -4pp；其中Android旧版Conversion31%。现象：风险捕获小幅提升但转化和体验恶化。拆解：技术失败集中旧Android，真正高风险集中New Device+Password Reset+Bank Change。根因：技术与风险同时存在。决策：技术失败Fallback；三联高风险保留强Step-up；低风险新设备采用轻量验证。结果：两个成熟Fraud Cohort看Net Fraud Loss和Lost Good Margin。

6）诊断：①Step-up Trigger；②通知/开始率；③Technical Fail；④Pass/Fail Reason；⑤Fraud/FPR/Approval。

7）策略动作：技术Fail高→修SDK/Fallback；低风险灰区流程过重→降摩擦；高风险高Pass但Fraud仍高→加强验证；高投诉→减少重复Step-up。

8）常见误区：未开始Step-up直接算Fail但不拆原因；窗口未成熟；所有Step-up类型混合；Conversion越高越好；只看转化不看Fraud。

9）拆分：Trigger Reason、Step-up Type、Channel、Device、Score、Limit、New/Repeat、Bank Change、Vendor、App Version。

10）预警：同Trigger/同流程版本比较。示例黄灯：Conversion下降且Technical Fail/Complaint上升；若Conversion高但Fraud Loss同步升，则属于验证强度不足红灯候选。

11）关系：Risk Signal → Step-up Required → Step-up Conversion → KYC Pass/Decline → Fraud/FPR → Approval/Margin。

12）小练习

5,000个成熟Step-up用户，3,000完成且通过，Conversion=60%。其中1,000因SDK报错无法开始，应单独报告Technical Failure，而不是只用一个60%解释风险。

本页案例为模拟业务数据，用于学习诊断方法，不构成行业基准或个案决策建议。
