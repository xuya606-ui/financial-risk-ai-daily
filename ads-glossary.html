Ads广告/广告体系广告业务的泛称；Google Ads 也可指平台名称。泛概念Mexico consumer loan ads。泛指广告投放。把 Ads 当成固定账户层级。应与 Ad、Campaign 区分。
Ad Account广告账户承载账单、权限、事件源和 Campaign 的账户容器。账户层Mexico TikTok Ads Account。权限、资产、账单管理。与 Business Center/Manager Account 混同。上接 Business Center，下接 Campaign。
Campaign广告系列围绕 Objective、Budget、Bid Strategy 组织投放的高层容器。账户下MX_iOS_NewUser。按目标/产品/实验拆分。无限拆分导致信号过碎。下接 Ad Set/Ad Group。
Ad Set广告组（Meta）Meta 常用层级，用于 Audience、Placement、Budget、Optimization 等设置。Campaign 下MX Broad iOS。人群/版位/预算实验。与 Google/TikTok Ad Group 直接等同。Meta 专有命名。
Ad Group广告组Google/TikTok 常用层级，承载 Audience、Bid、Keyword、Placement、Creative 等。Campaign 下MX Lead Higher Intent。出价/定向/表单设置。跨平台字段完全照搬。下接 Ad/Creative。
Ad具体广告实际审核并展示给用户的广告单元。广告层贷款费用透明型视频广告。素材测试。只看 Campaign 不看单 Ad。关联 Creative、CTA、URL/Form/Store。
Creative广告素材/创意视频、图片、文案、Hook、CTA、UGC 等构成的素材资产。素材层Mexico 信任型素材。CTR/CVR/质量测试。CTR 高就判定优质。应连接 Store、Qualified Lead、CAC、FPD/LTV。
Placement版位广告展示的位置或流量环境。Ad Set/Ad Group 配置TikTok Feed、Search、Ad Network。流量结构拆分。与 Publisher 混为一谈。Network 下还可拆 Publisher。
Publisher媒体发布者Ad Network 中真正承载广告的具体 App/网站。Network 下游第三方 App Publisher。反作弊/质量治理。只按 CPI 拉黑。Placement → Network → Publisher。
Audience受众平台用于定向或探索潜在用户的集合。定向层Mexico 18+ broad users。Prospecting/Retargeting。把 Audience 当信用风险标签。Broad、Retargeting。
Broad宽泛定向/广泛匹配给算法更大探索空间；Search 中也可指 Broad Match。受众/关键词策略Mexico Broad Audience。拓量。Broad=完全不受控制。仍受 Event、Budget、Policy Guardrail 约束。
Retargeting再营销再次触达曾访问、安装或互动但未完成目标的人群。受众策略KYC 未完成用户召回。漏斗召回。与催收/风险营销混用。Deep Link、Audience、Attribution。
Conversion转化被定义为营销或业务目标的动作。事件层Register、Apply、Disburse。优化/衡量。只写 Conversion 不写事件名。CPA、Optimization Event。
Optimization Event优化事件平台算法重点寻找的目标行为。算法目标从 Install 升级到 Valid Apply。深层优化。越深越好，不看事件量和延迟。Learning Phase、Signal Density。
Learning Phase学习期平台积累信号并探索受众、素材和出价的阶段。算法状态新 Mexico Lead Campaign 初始学习。新建/大改后。频繁修改导致学习波动。Budget、Bid、Event。
Journey-aware Bidding旅程感知出价Google 当前处于 beta 的 Search Smart Bidding 能力：在完整追踪 Lead→Sales Journey 时，Target CPA Search Campaign 可以从 biddable 与 non-biddable conversion goals 的完整旅程中学习，以更好预测哪些早期行为最终有价值。Google Smart Bidding / Lead GenMexico Search 以 Valid Apply 为主要目标，同时让系统学习后续 KYC/Approve/Disburse 旅程。销售/转化周期较长、上游事件与最终业务结果存在延迟的场景。认为所有账户已开放；或把“学习深层旅程”理解为可以上传信用评分、逾期等敏感字段。Google 官方；与 tCPA、Primary/Secondary、Conversion Lag 相关。
Lead Intent Scoring线索意图评分Google 在 2026-09-18 Ads Decoded 中披露的 lead intent scoring pilot，用于帮助优先识别更高潜的 Lead；公开信息目前仍以 pilot 为主，具体账户资格与评分逻辑不应自行假设。Google Lead Gen Pilot优先识别更可能继续完成 KYC/Valid Apply 的营销线索，而不是把信用风险分当 Lead Intent。Lead 量大、质量差异明显时。把它等同信用评分、授信评分或认为所有账户都已开放。Google 官方（2026-09-18）；与 Journey-aware Bidding、Data Manager 相关。
Primary Conversion Action主要转化动作Google Ads 中在 Campaign 使用其所属 Goal 进行优化时，会进入 Conversions 列并用于出价的 Conversion Action。Google Conversion Setting把经过定义和去重的 Valid Apply 设为 Primary。Smart Bidding 优化目标设计。认为设成 Primary 就必然被所有 Campaign 使用；仍取决于 Campaign 是否使用对应 Goal。Google 官方；与 Secondary、Conversion Goal 配套。
Secondary Conversion Action次要转化动作Google Ads 中通常用于观察、进入 All conversions、不会直接用于出价的 Conversion Action；但若加入 Custom Goal 且 Campaign 使用该 Custom Goal，则仍会参与出价。Google Conversion Setting先把 Disburse 或 KYC 作为 Secondary 观察事件，验证信号质量与延迟。深层事件尚未准备好直接优化时。“Secondary 永远不影响出价”；Custom Goal 是重要例外。Google 官方 ｜ Custom Goal 官方说明
Biddable Conversion Goal可出价转化目标在实际 Campaign Goal 配置下会影响 Smart Bidding 的转化目标/动作集合；是否可出价不能只看事件深度，还要看 Primary/Secondary 与 Custom Goal 配置。Google Bidding / GoalMexico Search 用 Valid Apply 作为直接优化目标。需要明确算法到底在学什么时。越深的事件越适合作为可出价目标。与 Primary Conversion Action、Campaign-specific Goal、Journey-aware Bidding 相关。
Non-biddable Conversion Goal非直接出价转化目标被跟踪但不作为当前直接出价目标的 Conversion Goal/信号；Google 对 Journey-aware Bidding beta 的描述指出，完整旅程中的 non-biddable goals 也可帮助模型理解后续结果。Google Journey Signal当前以 Valid Apply 出价，同时追踪更晚的 Disburse 结果。延迟长、量级较少的深层业务结果。非直接出价信号“完全没价值”。Google 官方；与 Journey-aware Bidding 配套。
Conversion Goal Architecture转化目标架构围绕 Event Journey 统一设计事件业务定义、Primary/Secondary、Campaign Goal、出价资格、Conversion Lag、去重、数据边界和版本管理的治理框架。Cross-team Measurement GovernanceMX Search：Register→KYC→Valid Apply→Approve→Disburse，并记录 goal_version。多事件深漏斗投放、Goal 迭代、跨团队对账。只在 Google Ads UI 勾选 Primary/Secondary 就算完成架构。与 Goal Architecture Contract、Journey Registry、Marketing-safe 数据边界相关。
Conversion Lag转化延迟从广告互动或上游事件发生，到后续指定 Conversion 实际发生/回传之间的时间。Measurement / OptimizationApply 当日发生，但 Disburse 可能 D1-D3、FPD/Vintage 更晚成熟。判断深层事件能否及时用于优化与复盘。把所有事件按同一日对比；或忽视 P50/P90 延迟差异。与 Attribution Window、Deep-event Lag、Journey-aware Bidding 相关。
Google Data ManagerGoogle 第一方数据管理/接入能力Google 用于集中连接和管理第一方数据工作流的能力；Google 2026 年持续扩展其连接与 API，以支持测量和 AI 优化的数据基础。Measurement Infrastructure将经合规审核的 Lead/CRM 业务事件接入 Google Ads 测量体系。第一方数据接入、Enhanced Conversions/Lead 数据流程。Data Manager 意味着可以上传全部 CRM/风控数据。Google 官方（2026-09-10）；需同时遵守 Customer Data Policy。
Marketing-safe Journey Registry营销安全事件旅程登记表内部长期维护每个事件的业务定义、来源、平台去向、Primary/Secondary、允许/禁止字段、延迟、去重键、Schema Version 和 Owner 的登记表。Data/Product Governance允许回传 KYC Complete/Valid Apply 等审核后的事件，明确禁止 credit score、debt load、delinquency 等敏感字段。金融广告深层事件建设。只登记 event_name，不登记字段级数据边界。与 Customer Data Policy、Risk Truth Layer、Goal Architecture Contract 配套。
Risk Truth Layer内部风险真实层内部保存 Approve、Fraud、FPD、Vintage、LTV 及用户级风险判断的经营/风险数据层；用于渠道质量评估，但不等同可发送给广告平台的营销信号。Internal Risk/Data Architecture按 Campaign Cohort 评估 FPD/Vintage，而不把个人信用分或逾期状态直接上传平台。投放与风控协同、渠道质量评估。为了“算法学得更深”就直接把风险标签回传媒体。与 Marketing-safe Journey Layer 分层；Google Customer Data Policy 对负面金融状态有敏感类别限制。
Goal Architecture Contract目标架构契约跨产品、投放、数据、风控、研发约定每个 Campaign 的 conversion_goal、optimization_event、goal_version、tCPA、attribution_window、product_version、effective_from 与 Owner。Cross-team ContractMX Google Search 每次从 Apply Goal 改为新的 Goal 配置都生成独立 goal_version。Goal 变更审计、实验与回滚。只记当前配置，不保留历史版本。与 Conversion Goal Architecture、Marketing-safe Journey Registry 配套。
Custom Product Page (CPP)自定义产品页Apple App Store 中为特定受众/营销主题创建的额外产品页版本，可配置不同 Screenshot、App Preview、Promotional Text 和唯一 URL；Apple 当前允许每个 App 最多 70 个。App Store Acquisitiones-MX “费用透明”CPP 与“申请流程简单”CPP 分别承接对应素材。Campaign-specific Store Routing、Apple Ads、外部 iOS 投放。把 CPP 当普通网页落地页；创建后不做业务质量追踪。Apple 官方；关联 Campaign Link、Deep Link、PPO。
Asset LibraryApp Store 素材资产库Apple 预告在 App Store Connect 中集中管理图片、视频、App Preview、Screenshot 等素材，并允许资产独立于 App 版本提交、提前审核，供产品页和 Apple Ads 复用。App Store Creative Ops把 es-MX 合规审核过的贷款截图/视频做成可复用资产。多 CPP、多 Campaign 素材版本治理。把“Coming this fall”理解成所有账户今天已上线。Apple 官方；与 Product Page Preview、CPP 相关。
Product Page Optimization (PPO)产品页优化测试Apple App Store 的产品页实验能力，可测试不同 App Icon、Screenshot、App Preview 等页面资产，以比较转化表现。App Store Experiment测试 Mexico Default Product Page 的费用透明截图 vs 流程截图。默认产品页资产实验。与 CPP 完全相同；CPP 是按受众/链接路由，PPO 更偏实验。Apple 官方；关联 CPP、Store Conversion。
Campaign LinkApp Store 营销活动链接App Store Connect Analytics 的 URL-based Campaign 参数，用于将外部营销活动与 Product Page Views、Downloads、Usage 等表现关联。App Store MeasurementMeta iOS Trust Campaign 使用独立 campaign token。广告、社媒、邮件等外部流量追踪。把它等同 MMP Deep Link；它首先用于 App Store Connect Campaign Analytics。Apple 官方；关联 CPP、MMP、Deep Link。
App Store Connect AnalyticsApp Store Connect 分析Apple 提供的 App Store Acquisition/Engagement 等分析能力，可按 Source Type、Territory、Device、Campaign 等维度观察 Impressions、Product Page Views、Downloads 等。App Store Analytics按 Mexico、CPP Campaign 对比 First-Time Download 与 Redownload。iOS Store 漏斗与 Campaign 诊断。把 App Store Analytics 当成用户级 MMP。Apple 官方；与 Campaign Link、MMP 互补。
First-Time Download首次下载用户第一次下载该 App 的下载事件，用于与 Redownload 区分新增与再次下载。App Store Acquisition Metric评估 Mexico iOS Campaign 真正新增下载占比。拉新评估。把所有 Total Downloads 都当新用户。Apple 官方；与 Redownload、Total Downloads 相关。
Redownload再次下载曾经下载过该 App 的用户再次下载；App Store Analytics 中应与 First-Time Download 分开看。App Store Acquisition Metric老用户换机/卸载后重新下载现金贷 App。新客 vs 召回拆分。把 Redownload 计入纯新客 CAC。Apple 官方；与 First-Time Download、Retargeting 相关。
Message Match信息承诺一致性广告承诺、Store Page 证据和 App 内真实产品事实在核心利益点、费用/期限/流程与信任表达上保持一致的治理方法。Growth/Product Governance广告讲“费用透明”，CPP 和 App 也展示与当前 Product Version 一致的费用/期限信息。Ad→Store→App 承接优化。只要视觉风格一致就算 Message Match。Ad Promise → Store Evidence → Product Reality；关联 disclosure_version。
Storefront Routing Registry商店页路由登记表记录 Platform/Campaign/Creative Angle 与 CPP、Campaign Token、Locale、Deep Link、Product/Disclosure Version 的长期治理表。Product/Data GovernanceMX TikTok Trust Creative → cpp_trust_esmx_v3。多平台 iOS Store 路由管理。只记录 URL，不记录产品/披露版本。与 Creative-to-Store Contract、Campaign Link 配套。

Upgraded Smart+TikTok 升级版 Smart+把 Manual 与 Smart+ 统一到同一创建流程，可按模块采用 full automation、partial automation 或 fully manual；支持 Traffic、Sales、Lead Generation、App Promotion。TikTok Campaign 体系Mexico Lead Campaign 让 Audience 自动探索，但锁定 Destination 与 Disclosure。需要兼顾算法扩量和控制时。Smart+=必须全自动。TikTok 官方

Web-to-App网页到 App 链路用户先进入 Web/LP，再通过 Deep Link/App Store 进入 App。增长产品链路Google Search → LP → App KYC。搜索/内容承接。只看 Web Conversion。LPV、Deep Link、MMP。
AEO / App Event Optimization应用事件优化以特定 In-app Event 作为优化目标。App Optimization优化 Completed KYC。安装后深层事件。事件越深越好。与 MAI、VBO、Event Volume 相关。
VBO / Value-Based Optimization价值优化用 Conversion Value 让算法优化更高价值转化。Optimization只能使用合规、非敏感的业务价值信号。有稳定 Value 体系时。把用户级信用风险直接上传平台。与 tROAS、Value Schema 相关。
MAI / Mobile App Install移动应用安装以 App Install 为主要目标的投放/优化方式。App UAMexico 新用户安装。冷启动、量级不足。安装成本低就代表业务好。CPI、AEO、Disburse。
SKAN / SKAdNetworkApple 隐私归因框架（旧称）Apple 的隐私保护移动广告归因框架；目前演进到 AdAttributionKit 体系。iOS AttributioniOS Campaign 使用匿名 Postback 衡量安装/事件。iOS 隐私归因。SKAN Postback 可以用户级匹配。Apple 官方
Attribution Window归因窗口广告互动与 Conversion 之间允许被归因的最大时间范围。AttributionClick 7d、View 1d 等。跨平台对账。不同平台窗口不一致仍直接比较 CPA。与 Conversion Lag、Reporting Gap 相关。
Postback回传平台、MMP 或归因框架把归因/转化信息发送给广告主或服务器的数据消息。MeasurementSKAN/AdAttributionKit Postback。归因与事件回传。Postback=实时且用户级。S2S、Dedup、Delay。
S2S / Server-to-Server服务器到服务器回传后端直接向平台或测量系统发送事件。Measurement InfrastructureBackend Valid Apply 回传。提高事件稳定性。无需 event_id/去重。Events API、MMP、Dedup。

AdAttributionKitApple 广告归因框架Apple 提供的隐私保护跨广告网络归因框架；在已注册网络中采用相应归因逻辑并限制可返回的数据粒度。Apple Attribution对比 Apple Ads 与其他已注册 App 广告网络。iOS 跨渠道测量。与 AdServices 完全相同。Apple 官方
tCPA / Target CPA目标转化成本告诉平台希望围绕某个优化事件达到的平均目标成本。BiddingApply tCPA=200 MXN。稳定事件量下的自动出价。tCPA=首贷 CAC。Business-derived Target、Actual CPA。
tROAS / Target ROAS目标广告支出回报让算法围绕目标 Conversion Value/Spend 优化。Bidding用合规 Value Schema 优化高价值事件。有稳定 Value 信号时。把放款本金直接等同利润价值。VBO、ROAS。
