Ads广告/广告体系付费广告业务泛称，不是固定账户层级。泛概念Mexico consumer-loan ads。描述付费获客。把 Ads 当具体 Ad。与 Campaign、Ad、Creative 区分。
Ad Account广告账户承载账单、权限、事件源和 Campaign 的账户容器。账户层MX TikTok Ads Account。资产/权限治理。与 Business Center 混同。下一层通常是 Campaign。
Campaign广告系列围绕 Objective、Budget、Bid Strategy 组织投放的高层容器。账户下MX_iOS_NewUser。按目标/产品/实验拆分。拆太细导致学习不足。下接 Ad Set/Ad Group。
Ad Set广告组（Meta）Meta 常用层级，承载 Audience、Placement、Budget、Optimization 等。Campaign 下MX Broad iOS。受众/版位实验。与 Google/TikTok Ad Group 完全等同。Meta 专有命名。
Ad Group广告组Google/TikTok 常用层级，承载 Bid、Audience、Keyword、Placement 等。Campaign 下MX Lead Higher Intent。出价/定向实验。跨平台字段照搬。下接 Ad/Creative。
Ad具体广告实际审核并展示给用户的广告单元。广告层费用透明型贷款视频。素材/目的地测试。只看 Campaign 不看单 Ad。关联 Creative、CTA、URL/Form/Store。
Creative广告素材/创意视频、图片、文案、Hook、CTA、UGC 等素材资产。素材层es-MX 信任型短视频。CTR/CVR/质量测试。CTR 高=业务质量高。需连接 Store/LP、CAC、FPD/LTV。
Placement版位广告展示位置或流量环境。投放配置TikTok Feed/Search。流量结构拆分。与 Publisher 混同。Placement 下可能继续拆 Publisher。
Publisher媒体发布者第三方网络中真正承载广告的具体 App/网站。Network 下游某第三方 App 流量。反作弊/质量治理。只按 CPI 拉黑。应看 Disburse/FPD/LTV。
Audience受众平台用于定向或自动探索潜在用户的集合。定向层Mexico 18+ broad users。Prospecting/Retargeting。把受众标签当信用评分。受 Policy 和算法 Guardrail 约束。
Broad宽泛定向/广泛匹配给算法更大探索空间；Search 中也可指 Broad Match。定向/关键词MX Broad Audience。拓量。Broad=无边界。仍受 Policy、Event、Budget 限制。
Retargeting再营销再次触达访问、安装或互动但未完成目标的用户。受众策略KYC 未完成召回。漏斗召回。与催收名单混用。Deep Link、Attribution、Consent。
Conversion转化被定义为营销或业务目标的动作。事件层Register、Valid Apply、Disburse。测量/优化。只写 Conversion 不写事件名。CPA、Goal、Optimization Event。
Optimization Event优化事件平台算法重点寻找的目标行为。算法目标从 Install 升级到 Valid Apply。深层优化。事件越深越好。需看 Signal Volume、Lag、Policy。
Learning Phase学习期平台积累信号并探索受众/素材/出价的阶段。算法状态新 MX Campaign 初始学习。新建/大改后。频繁修改配置。Budget、Bid、Event 都会影响。
Smart+TikTok Smart+ 自动化投放TikTok 的 AI 自动化投放方案，可按 Audience、Budget、Placement、Creative 等模块使用自动化。TikTok 产品MX Smart+ Lead Generation。App/Lead/Sales 扩量。自动化=无需合规 Guardrail。TikTok 官方。
Performance Max / PMaxGoogle 效果最大化广告Google 跨库存自动化 Campaign 类型，使用自动出价、素材和信号优化目标。Google 产品Google PMax 获客。跨网络效果投放。认为 PMax 报表中的浅层转化就是业务增量。Google 官方。
Demand GenGoogle Demand GenGoogle 面向视觉化、发现式场景的需求生成 Campaign 类型。Google 产品YouTube/Discover 触达贷款潜在人群。上中漏斗。与 Search Intent 等同。需结合深层事件评估。
UAC / App CampaignGoogle 应用广告系列Google 自动化 App 获客/互动 Campaign，历史常称 UAC。Google 产品Mexico Android/iOS 安装与事件优化。App Acquisition。只优化 Install。应连接 MMP 与深层事件。
AEOApp Event Optimization以安装后的指定 App Event 作为优化目标。App 优化优化 KYC/Apply。深层 App 获客。把 AEO 当平台通用同名功能。不同平台命名/实现可能不同。
VBOValue-Based Optimization根据转化价值而非单一事件数量优化。价值优化按合规的代理价值优化用户。LTV/ROAS 场景。直接上传敏感信用结论。必须遵守平台数据政策。
MAIMobile App Install移动应用安装目标的常见简称。App Acquisition以 Install 为目标。冷启动/量级积累。Install=首贷。下游需看 First Open/KYC/Disburse。
MMP移动归因平台跨渠道衡量 App Install、Re-engagement 和 Post-install Event 的第三方测量系统。Measurement把 TikTok/Google/Apple Ads 归因接入统一报表。移动归因。MMP 是唯一真相源。需与平台/Backend/Apple 口径对账。
Deep Link深度链接把用户直接带到 App 内指定页面的链接机制。Product/Attribution广告点击直达 KYC 或优惠券页。Web-to-App/召回。只验证链接能打开 App。还需验证正确路由、Fallback、Deferred Deep Link。
Web-to-App网页到 App 转化链广告先落 Web，再引导下载/打开 App 并延续归因和业务状态。JourneyLead LP→App KYC。多步获客。UTM 到 App 后自然可追踪。需 Deep Link/MMP/ID Join。
S2S / Server-to-Server服务端回传由广告主服务器直接把事件发送给平台/测量系统。MeasurementBackend Valid Apply 回传。深层事件/稳定回传。发送越多越好。需 Dedup、Allowlist、Data Policy。
SKAN / SKAdNetworkApple 旧代隐私归因框架Apple 的隐私保护广告归因框架；AdAttributionKit 在其能力上继续扩展。Apple MeasurementiOS App Install/Conversion 测量。隐私归因。与 MMP 一对一等价。Apple 官方。
Attribution Window归因窗口广告交互与转化之间允许被归因的最大时间范围。AttributionClick 7d vs 30d 对 Apply 数影响。平台/MMP 对账。跨平台直接比总 Conversion。Window 必须显式登记。
Postback归因回传消息设备/平台向广告网络或开发者发送的隐私保护归因结果。AttributioniOS 安装后收到 Apple Postback。App 归因。收到即直接计数。AdAttributionKit 要验证签名与去重。
Invalid Traffic / Invalid Click无效流量/点击不代表真实用户兴趣的广告交互，例如自动化点击或人为制造流量。Media Integrity机器人点击贷款广告。计费/异常诊断。平台 IVT 低=无假 Lead。Google 官方。
Invalid Lead无效线索到达表单但虚假、错误、重复或低可用的线索。Lead Integrity假邮箱、无效 MX 手机号。CRM/表单治理。所有 Invalid Lead 都等于媒体 Invalid Click。Google 官方。
Fraud Lead欺诈线索内部基于明确规则/证据判定存在身份冒用、批量注册等欺诈的线索。Internal Fraud批量身份异常注册。反欺诈。单一异常就判 Fraud。与 Invalid Lead、Credit Risk 分开。
reCAPTCHA人机验证帮助识别真人与自动化提交的 Google 技术服务。Form SecurityWeb Lead Form 防机器人。表单防刷。通过后就是优质借款人。Google 官方。
Server-side Validation服务器端校验在服务端验证邮箱、手机号、重复/高频提交等，避免前端校验被绕过。Backend验证 MX 电话格式。Lead Integrity。前端 JS 校验已足够。与 Rate Limit/Dedup 配套。
Primary Conversion Action主要转化动作在 Campaign 使用对应 Goal 时通常进入 Conversions 并参与出价。Google GoalValid Apply 作为 Primary。Goal Architecture。Primary 越深越好。需看量级、延迟和数据边界。
Secondary Conversion Action次要转化动作通常用于观察并进入 All conversions；若被纳入 Campaign 使用的 Custom Goal，也可能参与出价。Google GoalDisburse 先 Secondary。深层观察。Secondary 永不用于出价。与 Custom Goal 配置相关。
Journey-aware Bidding旅程感知出价Google Lead Gen beta，尝试利用完整 Lead→Sales Journey 中更多可用信号学习高价值用户。Google betaApply 之外参考更深 Lead Journey。长转化周期。等于把所有深层事件都设 Primary。Google 官方。
CPP / Custom Product Page自定义产品页Apple App Store 可为不同营销场景配置的自定义产品页。App StoreTrust Creative 对应 es-MX 信任型 CPP。Message Match。只优化 Download。Apple 官方。
Message Match广告-商店-产品信息一致性广告 Claim、Store Evidence 与 App 真实产品事实保持一致。Creative/Product广告说费用透明，CPP/App 也展示真实期限与费用。提升高质量转化。三层视觉必须完全一样。核心是事实一致而非样式一致。
AdAttributionKitApple 隐私保护广告归因框架Apple 提供的隐私保护归因方案，用签名信号衡量 App 安装/再互动并支持 Postback。Apple MeasurementiOS 27 Mexico 获客安装归因。跨广告网络 App 归因。需要 ATT 授权后才能调用。Apple 官方；Apple 明确说明使用该归因 API 本身不需要 ATT 授权。
JWS SignatureJSON Web Signature 签名Apple 对 AdAttributionKit Postback 使用的加密签名，用于验证消息确由 Apple 生成。Attribution IntegrityBackend 收到 Postback 后先验签再计数。防伪/数据完整性。只解析 payload 不验签。Apple 官方。
postback-identifierPostback 唯一标识AdAttributionKit Postback 中用于识别唯一消息的 ID；重复 ID 应去重。Attribution Integrity同一 ID 第二次到达不重复计数。防重复回传。按时间戳去重即可。Apple 官方。
did-win是否赢得归因AdAttributionKit Postback 字段，用于判断该广告网络的 Postback 是否为 winning attribution。Attribution只把符合口径的 winning attribution 计入渠道结果。多网络归因。收到 Postback 就算赢。Apple 官方。
Redownload重新下载用户曾下载过 App 后再次下载；Apple Ads 会单独报告并计入相关安装统计。App Acquisition老用户重新下载现金贷 App。新客/回流拆分。把所有 Download 当首装新客。Apple Ads 官方。
OS Version Cohort操作系统版本队列按用户首次触达/安装/首开时的 OS Version 划分的 Cohort。Version AnalyticsiOS 26 vs iOS 27 首贷 CAC。系统升级期。只按日期做 Before/After。与 App Version Cohort、Release ID 联合。
App Version / Build Version应用版本/构建版本用于识别产品代码与发布批次的版本字段；Build 应比市场显示版本更细。Release6.8.0 build 60803。发版影响分析。只记录 App Store 展示版本。与 SDK/Schema/Release ID 关联。
SDK VersionSDK 版本MMP、Analytics、KYC、Push 等第三方/内部 SDK 的版本标识。Technical VersionKYC SDK 5.2→5.3 后完成率变化。兼容性/归因 QA。认为 App Version 已足够解释所有技术变化。应随 Release Registry 记录。
Release Confounding版本混杂OS/App/SDK/产品/风控等在同一时间变化，使总报表无法单独识别媒体真实效果。AnalysisiOS 27 上线同时 KYC SDK 升级，CAC 变化无法直接归因给广告。发版期投放分析。所有 9/14 后变化都算 iOS 27 影响。需要 Version Cohort、Release ID、Control/Matched Baseline。
Version-aware CAC版本感知获客成本在相同 OS/App/Build/SDK Cohort 内计算并比较 CAC。Business AnalyticsiOS 27 + App 6.8.0 首贷 CAC。版本迁移期预算判断。用 Blended CAC 代替。与 Blended CAC 同时展示。
Deep Link Regression深链回归/退化新 OS/App/Router 版本导致 Deep Link 打开失败、Fallback 错误或路由到错误页面。Product QA广告应到 KYC，却回首页。系统/发版回归。App 能打开就算成功。对应 Deep Link Success Rate。
Release Performance Contract发版-投放性能契约跨产品/投放/数据/风控/研发记录 release_id、版本、灰度、事件与业务影响的治理约定。GovernanceiOS 27 Build 上线前完成投放链路 QA。发版与预算联动。只由研发维护。连接 Release Registry、Attribution QA、CAC/FPD。
