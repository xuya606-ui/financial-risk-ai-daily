一、账户结构与素材

Ads

英文/中文：Ads｜广告/广告体系泛称。

解释：Google Ads 是平台名；Ad 是具体广告；Ads 本身不是一个固定账户层级。

现金贷例子：“Google Ads CAC 上涨”指渠道，“这条 Ad 的 CTR 高”指单条广告。

误区：把 Ads、Ad、Campaign 混为一谈。

Campaign

中文：广告系列/广告活动。

层级：通常位于 Ad Account 下、Ad Set/Ad Group 之上，承载目标、预算/出价与核心投放逻辑。

现金贷例子：Mexico_NewUser_Disburse_Search。

误区：Campaign 拆得越细不一定越好，过细会导致事件量不足与学习不稳定。

Ad Set

中文：广告组（Meta 常用）。

常设置受众、版位、排期、优化事件等；概念接近 Ad Group，但平台字段不完全等同。

Ad Group

中文：广告组（Google/TikTok 常用）。

用于组织 Keyword、Audience、Bid、Creative 与 URL。

Ad

具体广告，由视频/图片、标题、正文、CTA 与目标链接组成。

Creative

广告创意/素材，包括视频、图片、文案、Hook、CTA、UGC 脚本等。

现金贷评估不能只看 CTR，要接 Apply/Approve/Disburse/FPD。

Placement

广告版位，例如 Feed、Stories、Reels、Search、Pangle、Audience Network。

Publisher

实际提供流量的网站、App、媒体或联盟子渠道。现金贷应按 Publisher 看 Fraud、Approve、Disburse、FPD。

Audience

受众，包含年龄、地区、兴趣、自定义受众、相似受众、再营销等。

Broad

宽泛定向/广泛匹配的泛称，具体含义依平台和场景而定。Search 中 Broad Match 是关键词匹配方式；Audience 中 Broad 可能指减少人工限制。

Retargeting

再营销/重定向，例如安装未注册、注册未申请、审批未提款用户。

Hook

素材开头吸引注意力的钩子。金融广告不能靠夸大“保证放款/秒批”换 CTR。

UGC

User-Generated Content 或 UGC 风格内容。

CTA

Call To Action，行动号召，如 Apply Now / Learn More。

二、出价、自动化与 TikTok Smart+

Bid Strategy

出价策略，决定平台更偏拿量、控 CPA 还是控价值/ROAS。

Cost Cap

围绕设定 CPA 目标控制长期/平均成本，不是每笔转化硬上限。

Maximum Delivery

以预算为主要约束，尽量获取更多结果。

Learning Phase

平台积累转化信号、探索人群/素材/版位/Bid 组合的阶段。

CBO

Campaign Budget Optimization，Campaign 级预算优化/分配。

Smart+

TikTok 自动化投放体系，可自动化受众、预算、版位、素材等模块。

TikTok 官方

Smart+ Bid Protection

TikTok 限时激励：符合资格的 Smart+ Campaign 在实际成本/ROAS 相对 Bid 明显失控时，可能获得部分 Ad Credit。

现金贷：只能缓冲媒体试错成本，不保护 Approve、Disburse、FPD、LTV。

TikTok 官方

Full Cycle / Full Lifecycle

Bid Protection 从早期仅覆盖学习期/前几天，扩展到 Campaign 运行全周期的保护框架。

Ad Credit

广告金/广告抵用额。不能提现、不能跨账户转移，内部不应当现金收入。

Protection Status

Bid Protection 是否 Active / Ineligible 等状态。

Negative Operations

可能导致当日保护失效的暂停/删除、素材全拒、余额不足、风控/封禁、特定预算下调等操作或状态。

Incentive-aware Scale Guardrail

内部产品设计：把平台补贴状态与业务扩量状态分开，Gross CAC/FPD/LTV 仍是主要闸门。

三、Google Search、AI Max 与查询路由

Performance Max / PMax

Google 跨 Search、YouTube、Display、Discover、Gmail、Maps 等资源的自动化 Campaign 类型。Search Theme 可参与账户级 Search 优先级。

AI Max for Search

中文：Google Search AI 增强套件。

核心：Search Term Matching + Asset Optimization（Text Customization / Final URL Expansion 等）。不等于 PMax。

现金贷：需要把 Query、Ad、Final URL、Disclosure 与后端用户质量一起治理。

Google 官方

AI Max Auto Upgrade

Google 从 2026 年 9 月开始把仍使用 ACA/Text Customization 或 Campaign-level Broad Match Setting 的符合条件 Search Campaign 自动升级至 AI Max；DSA 自动升级已延后到 2027 年 2 月。

Google 官方

Campaign-level Broad Match Setting

Search Campaign 级 Broad Match 设置；历史上除了要求 Broad + Smart Bidding，还改变账户级 Keyword Prioritization。

Keyword Prioritization

当一个 Search Term 可以匹配多个 Keyword/Search Theme 时，Google 用匹配身份、AI relevance 与 Ad Rank 决定谁进入竞价。

Exact Match Priority

与 Search Term 完全相同的 Exact Keyword 在标准优先级中位于第一层；同层候选再比较 Ad Rank。

Identical Search Term

与 Keyword 文本完全相同的 Search Term，是 Keyword Prioritization 的关键条件。

Ad Rank

同等优先级候选之间用于决定谁进入竞价/展示机会的广告评级。

Query Routing

内部治理术语：同一 Search Term 最终被哪个 Campaign / Ad Group / Keyword / URL 承接。

Search Terms Match Type

Search Terms 报告用于观察实际搜索流量在 Exact/Phrase/Broad 相关匹配层级上的结构。

Brand Inclusions

让自动化 Search 围绕指定品牌意图扩展的控制。

Brand Exclusions

阻止指定品牌意图进入某些 Campaign，减少 Brand/Non-brand 混流。

Search Term Matching

AI Max 中用于扩大可触达搜索意图的能力。

Text Customization / ACA

根据网站、广告和关键词自动创建/调整 Search 文案；现金贷需限制 AI 改写金融承诺。

Final URL Expansion / FUE

Google 根据搜索意图把用户送到同域名更相关页面。现金贷需维护可投 URL 白名单/排除表。

AI Max Experiment

在同一 Search Campaign 内分 Control/Trial 流量测试 AI Max。

四、Google Demand Gen / App 与深层转化

Demand Gen

Google 视觉化中下漏斗 Campaign，可覆盖 YouTube、Discover、Gmail、Maps 与 GDN 等库存。

GDN in Demand Gen

Demand Gen 中的 Google Display Network 库存。

Channel Reporting

拆分 Demand Gen 不同库存/渠道表现的报告能力。

UAC / App Campaign

Google 应用广告系列。行业仍常说 UAC，Google 当前通常称 App Campaign。

AEO

App Event Optimization，按应用内事件优化。

VBO

Value-Based Optimization，按事件价值优化。

MAI

Mobile App Install，移动 App 安装优化。

Multimodal Video Creation

Google Asset Studio 的 AI 创意能力，可制作不同方向/比例的视频。

Messaging-app Conversation Entry

Demand Gen 测试能力：让部分 YouTube 高意向用户直接在消息应用中与品牌开启对话。

五、Lead Quality 与深层转化

Lead Journey Mapping

线索旅程映射：把广告互动后的 Raw Lead、Qualified Lead、Converted Lead 与最终业务结果串成一个可优化漏斗。

Raw Lead

刚产生的表单、消息对话、注册或申请，尚未经过业务资格验证。

Qualified Lead

已通过最低业务资格验证、值得继续审批/跟进的 Lead。

Converted Lead

比 Qualified Lead 更接近最终结果的深层 Lead，可按公司定义为 Approve 或 Disburse。

Enhanced Conversions for Leads

Google 使用经过哈希处理的客户数据，把网站 Lead 与后续离线业务结果更可靠地匹配回 Ads。

Offline Conversion Import

把 CRM/后台的 Qualified Lead、Approve、Converted Lead 等导回广告平台。

Lead Verification

通过 reCAPTCHA、double opt-in、server-side validation、backend application_id 等确认 Lead 真实有效。

六、搜索广告基础术语

Keyword

广告主设置、希望购买的搜索意图。

Search Term / Query

用户实际输入的搜索内容。与 Keyword 不同。

Match Type

Keyword 与 Search Term 允许差多远的匹配规则，常见 Broad / Phrase / Exact。

Negative Keyword

否定关键词，用于排除不需要的搜索意图。

Keyword Planner

研究搜索量、竞争度和关键词机会的工具。

七、归因、事件与数据连接

MMP

Mobile Measurement Partner。连接广告触达与 Install、Register、Apply、Disburse 等 App 事件。MMP 是归因层，不等于业务真相。

Pixel

浏览器侧事件采集器。

Events API

TikTok 服务器侧营销事件回传接口。

Conversions API / CAPI

Meta 服务器侧数据连接接口。

S2S / Server-to-Server

服务器到服务器事件或归因数据连接。

Postback

归因或事件结果由设备/MMP/平台回传给广告网络或开发者的数据通知。

Event Deduplication

Browser + Server 同时上报同一事件时，利用 event_id 等避免重复计数。

Deep Link

点击广告、Push、短信后直接打开 App 指定页面。

Web-to-App

广告 → Web Landing Page → App Store/App → App 内转化。

Attribution Window

广告接触后多长时间内的转化仍有资格算给该广告。

Attribution Model

多个触点都合格时，决定转化信用如何分配。

Conversion Lag

从广告互动到转化发生/被记录的时间延迟。

Incrementality

回答“如果没有广告，这个用户是否仍会转化”。通常需要 Holdout/Lift/Geo Experiment。

八、移动归因反作弊

Protect360

AppsFlyer 反欺诈套件，包含实时阻断、归因后欺诈识别、Raw Data、Validation Rules 等。

Advanced Security

Protect360 Android 高级安全模块，在首次启动后、归因前评估可疑流量。

SDK Spoofing

攻击者模拟真实 App SDK 网络请求，制造假的 Install/In-app Event。

Attribution Spoofing

使 MMP 把原本不属于某渠道的转化归给它。

Install Hijacking

真实用户确实安装 App，但欺诈方伪造最后触点抢走归因。

Device Farm

批量真机、云设备或模拟器制造 Install/Event。

Emulator

模拟器。并非所有模拟器都是欺诈，但大规模营销流量中需单独识别。

Validation Rules

AppsFlyer 自定义校验规则，可针对错误 Geo、OS、Media Source、可疑 Install/Event 做阻断或重归因。

Real-time Blocking

在归因写入或事件计入前识别并阻断欺诈。

Post-attribution Fraud

安装已归因后，通过后续统计/异常检测才识别出的 Fraud。

Attribution Trust Layer

内部归因可信层：结合 MMP fraud flags、backend verification、设备/网络异常、Publisher 历史与事件时序，输出 Trusted / Review / Blocked。

九、金融广告准入与墨西哥政策

Restricted Vertical

受限行业/垂类。金融、博彩、医药等通常存在额外准入与内容要求。

Advertiser Eligibility

广告主是否有资格在目标国家推广某一金融产品。

Platform Permission

某些受限产品需要平台额外批准。不要扩大成“所有金融广告都必须白名单”。

Ad Review

针对具体 Ad/Creative、文案、Landing Page/URL 的审核；通过不等于所有上层准入永久满足。

TikTok Financial Services Policy

Mexico 当前普通金融服务/贷款核心要求：当地/区域许可、必要披露、18+；may-be-allowed 示例包含 mortgage、consumer finance、P2P、BNPL。

当前禁止示例：APR ≥50% High APR Loan、Payday Loan、≤90 天 Short-term Loan 等。Crypto/NFT 等特定类别另有 Sales Representative application permission。

TikTok 官方

Google Personal Loans

Google 只允许需要 61 天或以上才能全部还清的 personal loan，并要求在 LP/App 显著披露最短/最长期限、最高 APR/当地等效口径和代表性总成本。

Google 官方

十、iOS 隐私归因｜2026-09-02 新增

2026-09-02

AdAttributionKit

中文：Apple 广告归因框架。

类别：iOS 隐私归因。

准确解释：Apple 提供的隐私保护广告归因 API，让广告网络、Publisher App 与被推广 App 在不依赖跨 App 个体追踪的前提下获得安装、再互动和转化 Postback。

现金贷例子：Mexico iOS 新客 Campaign 可利用聚合 Postback 判断 Install/Register/Apply 阶段信号，但最终首贷、FPD、LTV 仍以 Backend Cohort 为准。

适用：iOS App 获客、SKAN 迁移、MMP 对账。

常见误区：认为它等于 MMP，或认为使用 AdAttributionKit 就能拿到用户级跨 App 追踪。

关系：与 SKAdNetwork 互操作，包含 Conversion Value、Postback、Privacy Tier、Reengagement 等概念。

Apple 官方

SKAdNetwork / SKAN

中文：Apple 隐私广告归因网络框架。

类别：iOS 归因基础设施。

解释：在保护用户隐私的情况下提供 App 安装和转化归因；AdAttributionKit 在其能力基础上继续扩展。

现金贷例子：iOS Campaign 不应只按用户级 IDFA 归因思路设计报表，而要接受聚合、延迟和数据粒度受限。

误区：把 SKAN 数据缺失直接等同于 Fraud 或投放失败。

Apple Ad Attribution

Fine Conversion Value

中文：细粒度转化值。

类别：Postback 转化信号。

解释：开发者定义的整数值，用于表达更细的用户价值/漏斗阶段；Apple 的 App AdAttributionKit 支持最多 64 个用户价值信号。

现金贷例子：可把 First Launch、Register、KYC、Submit Application 等早期阶段映射成不同值。

误区：Fine Value 缺失就认为 SDK 坏了；Apple 可能因隐私阈值不返回细粒度值。

关系：与 Coarse Conversion Value、Postback Data Tier、Privacy Threshold 联动。

Coarse Conversion Value

中文：粗粒度转化值。

取值：low / medium / high。

解释：当隐私条件不足以返回更细信息时，用较粗的相对价值层级表达转化质量。

现金贷例子：可内部定义 low=注册、medium=申请、high=更深业务阶段，但必须结合真实窗口和隐私审查。

误区：认为 high 等同高信用质量；它只是开发者/广告网络定义的归因信号。

Postback Data Tier / Crowd Anonymity

中文：Postback 数据层级 / 群体匿名性。

解释：Apple 根据隐私条件决定 Postback 可携带的数据粒度，流量规模和匿名性不足时可能减少细粒度字段。

现金贷用途：解释“Fine Value Availability 下降但 Backend 业务稳定”的情况。

误区：把数据层级变化当成用户质量变化。

Apple 官方

JWS-signed Postback

中文：Apple 加密签名 Postback。

类别：数据完整性。

解释：Apple 使用 JWS 签名 Postback；生产环境应验证签名，只统计验证通过的数据。

现金贷用途：避免把伪造/损坏 Postback 纳入正式 iOS 归因。

误区：仅凭收到 HTTP 请求就计 Conversion。

Apple 验签官方文档

postback-identifier

中文：Postback 唯一标识。

作用：Apple 建议用它保证只统计唯一消息，重复 identifier 的 Postback 应丢弃。

关系：与 JWS 验签共同组成“先验证、再去重、再计数”的基础流程。

AttributionCopyEndpoint

中文：开发者 Postback 副本接收端点。

解释：被推广 App 可以配置 Server Endpoint，接收 winning postback 的副本。

现金贷用途：自建 Apple Postback 数据层，与 MMP/平台报表做聚合对账。

误区：以为开发者副本天然包含所有细粒度字段；仍受 Apple 隐私层级控制。

lockPostback / lockWindow

中文：提前锁定 Postback 窗口。

解释：开发者可要求系统更早锁定并发送信号，从而缩短等待时间，但会减少后续继续更新 Conversion Value 的空间。

现金贷例子：若 Apply 通常发生较晚，过早锁窗口可能让 Apply 永远无法进入该 Postback。

误区：为了更快数据无脑开启。

did-win

中文：是否赢得归因。

解释：Postback 中用于表示该广告网络是否赢得最终归因的字段；安装场景下部分未获胜但满足资格的网络也可能收到 nonwinning postback。

业务意义：归因参与与最终赢得归因要分开理解。

Reengagement

中文：再互动 / 重新激活。

解释：已经安装 App 的用户再次通过可归因广告回到 App 并发生互动。

现金贷例子：注册未申请、审批未提款、沉默老客召回都可能涉及再互动测量。

误区：把 Reengagement 与新安装混在同一 CAC 分母。
