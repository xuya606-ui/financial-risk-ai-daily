2026-09-20｜催收漏斗与回收质量完整指标学习卡

今日复习并升级5个高频贷后指标：RPC、PTP、PTP Kept、Collection Rate、Recovery Rate。所有数值阈值仅是内部示例；模拟案例用于训练诊断逻辑，不代表行业统一标准。

Deliverability → RPC → PTP → PTP Kept → Cash Collection → Cure / Roll → Recovery / Net Loss

1. RPC Rate｜Right Party Contact Rate｜本人有效联系率

1）指标是什么：在可进入催收触达的逾期账户中，真正联系到正确借款人并完成有效身份确认的比例。大白话：不是“电话接通了多少”，而是“真正跟该借款人说上话多少”。

2）为什么重要：贷后同步/领先指标，是PTP、现金回收和Cure的上游；用于判断联系数据质量、渠道可达性、Vendor执行与客户逃避联系程度。

3）精确定义与公式：RPC Rate = 在观察窗内至少1次Right-party Contact的唯一账户 ÷ Eligible Collection AccountsEligible需固定DPD Bucket、观察窗口、是否排除已结清/法务/争议账户；按账户去重。另可报金额口径：RPC账户期初余额÷Eligible期初余额。

4）如何看高低：通常提高有助于后续回款，但“越高越好”不成立：如果靠过度频繁联系、宽松身份确认或骚扰换来高RPC，投诉与合规风险会增加；高RPC但PTP Kept/Collection不升，说明触达质量有限。

5）墨西哥七步案例：

背景：30天复借产品，V4增加WhatsApp自动触达和新外呼Vendor。
数据：N=10,000；Due=MXN15m；RPC 36%→52%；PTP 40%→57%；Kept 68%→41%；7日Collection 31%→28%；Complaint 0.8%→1.6%。
现象：RPC显著提升，但真实现金和承诺兑现变差。
拆解：Vendor B×Low Score×High Balance RPC=61%，Kept仅28%；Vendor A同类RPC≈45%，Kept≈63%。
根因：可以确认高RPC与低Kept同时出现，但还需排查号码质量、话术、客群与联系频率；不能直接把Vendor作为唯一因果。
决策：限制重复触达；身份确认标准化；Vendor KPI加入Kept/Cash/Complaint；高余额高Roll继续人工优先。
结果：观察2-4周RPC、Kept、Cash、Cure、投诉与Cost/Collected；仅当下游同步改善才认为RPC提升有价值。

6）诊断逻辑：①号码/渠道Deliverability → ②RPC按Vendor/时段/DPD拆 → ③PTP/Kept → ④Cash/Cure/Complaint。

7）策略动作：Deliverability差先修号码/渠道；特定时段低RPC优化拨打窗口；高RPC低Kept调整话术/激励；高投诉降低频率并加强合规质检。

8）常见误区：把接通率当RPC；重复接通重复计数；不同DPD Bucket直接比较；RPC高就认为催收强。

9）推荐拆分：DPD、Vendor、Treatment、Channel、Score、Balance、Region、时段、号码来源、新老客。

10）预警方式：使用同Bucket/同Treatment历史稳定带和最低样本量；RPC突降同时Deliverability/号码失败上升是技术/数据黄灯；RPC升但Kept/Cash降且投诉升是质量红灯候选。

11）与其他指标关系：Deliverability → RPC → PTP → Kept → Collection/Cure → Roll/Bad。

12）小练习

1,000个Eligible账户中500个完成RPC，RPC=50%。如果电话接通700个但只有500个确认本人，不能用70%作为RPC。

2. PTP Rate｜Promise-to-Pay Rate｜承诺还款率

1）指标是什么：已经RPC的账户中，有多少形成了明确金额与日期的可执行还款承诺。

2）为什么重要：同步指标，用于评估沟通后客户支付意愿与催收员协商能力，是PTP Kept和现金回收的上游。

3）精确定义与公式：PTP Rate = 成熟观察窗内形成有效PTP的唯一账户 ÷ RPC唯一账户有效PTP必须有金额、承诺日期、记录来源；同一账户同窗口多次承诺要按规则去重，不能把“愿意还”自由文本直接算PTP。

4）如何看高低：高可能意味着协商有效，也可能是催收员为完成KPI制造不现实承诺；只有与Kept、Cash、投诉联看才有意义。

5）七步案例：背景同V4；RPC后PTP 40%→57%，但Kept 68%→41%、Collection 31%→28%。Vendor B PTP=66%但Kept=28%。现象是“承诺更多、兑现更少”。拆解发现激励偏向PTP数量。根因仍需Challenger确认。决策把Agent KPI改为Kept+Cash+Cure-Complaint。结果连续2-4周看承诺质量与现金。

6）诊断逻辑：①PTP定义/记录完整性 → ②Vendor/Agent/DPD → ③PTP金额和日期合理性 → ④Kept/Collection/Cure。

7）策略动作：高PTP低Kept收紧“有效承诺”定义、改激励；低PTP但高Cash可能是用户直接支付，不宜误判；高风险高余额可允许分期承诺但需明确规则。

8）常见误区：越高越好；口头“会还”算PTP；承诺金额和应收金额不区分；跨Bucket直接比。

9）拆分：Vendor、Agent、DPD、Balance、Score、Channel、Treatment、PTP金额档、承诺天数。

10）预警：PTP连续上升但Kept下降、投诉或Roll上升应触发质量黄灯；不要设置行业统一PTP目标。

11）关系：RPC → PTP → PTP Kept → Cash Collection → Cure/Roll。

12）小练习

500个RPC账户中300个形成有效PTP，PTP Rate=60%。

3. PTP Kept Rate｜承诺兑现率

1）指标是什么：已经到达承诺日期且成熟的PTP中，按内部规则如期足额/合格支付的比例。大白话：用户答应的事，有多少真的做到。

2）为什么重要：滞后但非常关键的质量指标，直接检验PTP是不是“真实承诺”，也能识别不合理话术和激励。

3）精确定义与公式：PTP Kept = 满足兑现规则的成熟PTP唯一账户 ÷ 已到承诺日且观察窗成熟的有效PTP唯一账户需定义足额/部分支付、容忍天数、同账户多PTP处理。未到承诺日不能进分母。

4）如何看高低：通常越高越好，但过高也可能来自只向最容易还款用户索取PTP、或承诺金额设置过低，因此需和Cash Collected、Coverage及Cure联看。

5）七步案例：V4 Kept 68%→41%；Vendor B×Low Score×High Balance仅28%，同时投诉2.4%；Vendor A约63%。现象表明Raw PTP被放大但质量下降。拆解Agent/话术后发现B的短承诺日期和高承诺金额更多。决策调整承诺模板、激励和Challenger。结果看Kept、现金、Cure、投诉。

6）诊断逻辑：①成熟窗口 → ②承诺金额/日期 → ③Agent/Vendor → ④Payment Success/技术失败 → ⑤Cash/Cure/Roll。

7）策略动作：高违约PTP客群改为更现实金额/日期；支付链失败先修支付；特定Vendor低Kept做质检/停量；Kept低且投诉高时暂停激进话术。

8）常见误区：未成熟PTP进分母；部分支付一律算Kept或一律算Fail但未定义；承诺金额过低导致虚高；只看件数不看金额。

9）拆分：Vendor、Agent、DPD、Score、Balance、承诺金额/应收比、承诺天数、支付方式、Treatment。

10）预警：Kept低于同Bucket历史稳定区间且Collection/Cure同步下降为红灯候选；具体比例是内部阈值。

11）关系：PTP Quality → Kept → Cash Collection → Cure → Roll/Recovery。

12）小练习

300个已成熟PTP中120个按规则兑现，Kept=40%。

4. Collection Rate｜催收现金回收率

1）指标是什么：固定观察窗口内，从指定逾期/应收风险池中实际收回的现金占应收基准的比例。

2）为什么重要：贷后核心结果指标，连接催收活动与真实现金；相比RPC/PTP更接近经营结果。

3）精确定义与公式：Collection Rate@N = N天内合格现金回收 ÷ 固定应收/期初Eligible Balance分母可用Due Amount、Opening Delinquent Balance等，但必须固定且版本化；展期、减免、费用、冲销是否计入需明确。件数Collection另报，不能和金额混用。

4）如何看高低：通常高更好，但若通过高额减免、过度催收或只挑易收客群实现，也可能损害LTV/合规；需与Cure、Roll、Cost/Collected、Complaint联看。

5）七步案例：Due=15m，7日Collection 31%→28%，同时RPC/PTP上升、Kept下降、Roll 34%→39%、投诉0.8%→1.6%。拆解发现Vendor B高触达但现金弱。根因尚需控制客群。决策按净回款和迁徙重设Vendor权重。结果观察2-4周。

6）诊断逻辑：①分母/入账完整性 → ②RPC/PTP/Kept → ③支付成功率 → ④Vendor/Segment → ⑤Cure/Roll/Cost。

7）策略动作：支付失败修通道；低RPC提升可达性；高RPC低Cash优化承诺质量；高Balance高风险提高人工优先级；低ROI Vendor降量。

8）常见误区：每期分母漂移；承诺金额当现金；只报回款额不除风险池；Gross Cash忽略退款/冲正；不同DPD混比。

9）拆分：DPD、Vintage、MOB、Vendor、Treatment、Score、Balance、Channel、Payment Method、Region。

10）预警：同Bucket/同观察窗同比、环比和同Vintage比较；Collection下降且Roll上升、Cost/Collected变差可进入红灯候选。

11）关系：RPC/PTP/Kept → Collection → Cure/Roll → Bad/Charge-off → Margin。

12）小练习

固定Due MXN15m，7天实际合格回款MXN4.2m，则Collection Rate=28%。

5. Recovery Rate｜后段回收率

1）指标是什么：Default、Write-off或指定后段风险池中，经过催收/处置后回收的现金占原始风险暴露的比例。

2）为什么重要：滞后损失指标，是LGD的重要输入，评价后段催收、外包、法务或资产处置价值。

3）精确定义与公式：Recovery Rate@MOB N = 累计Net Recovery Cash@N ÷ Default EAD需固定Default定义、Default EAD、Recovery MOB、Gross/Net（是否扣Vendor/法务成本）。也可另报Gross Recovery与Cost。

4）如何看高低：通常越高越好，但短MOB的高回收可能来自提前回收客群结构；不同Default Vintage和观察期不能直接比较。

5）七步案例：V4后Default Pool 约MXN3m，MOB2 Recovery 18%→16%；Vendor B虽然联系量高，但高余额账户兑现差且投诉升。拆解发现高余额低Score后段效果弱。决策提高高余额优先级、按净回收调整Vendor、尝试数字+人工混合。结果看同Default Vintage的MOB2/MOB3 Recovery和LGD。

6）诊断逻辑：①Default EAD/成熟期 → ②Gross vs Net → ③Vendor/Balance/Fraud vs Credit → ④支付/法务/处置 → ⑤LGD。

7）策略动作：低RPC先提升可达；高成本低净回收Vendor降量；高余额账户分层；Fraud资产与Credit资产采用不同回收策略；必要时评估出售/外包。

8）常见误区：Gross=Net；不同Recovery MOB比较；用当月回款除当月余额导致分母漂移；核销后忘记后续回款。

9）拆分：Default Vintage、Recovery MOB、Vendor、Balance、Score、Region、Product、Fraud/Credit、法律状态。

10）预警：同Default Vintage、同MOB、最小EAD样本；Recovery下降且Cost升、LGD升为红灯候选。

11）关系：Default EAD → Collection/Recovery → LGD → Actual Loss → Contribution Margin。

12）小练习

Default EAD=MXN5m，MOB3累计Gross Recovery=1.2m，回收成本0.2m，则Gross Recovery=24%，Net Recovery=20%。
