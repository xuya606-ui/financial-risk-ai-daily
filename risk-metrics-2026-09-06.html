2026-09-06｜催收与迁徙四张完整指标学习卡

今日升级：RPC、PTP Rate、Cure Rate、Roll Rate。所有数值均为教学模拟，不代表行业统一标准；预警阈值应来自自身同产品、同DPD、同策略版本的成熟历史。

指标组合先记住

Contactability → RPC → PTP → PTP Kept → Cash Cure → Forward Roll → DPD30+ → Recovery / LGD → Contribution Margin

1. RPC｜Right Party Contact Rate｜有效本人联系率

1）指标是什么：中文名“有效本人联系率”，英文 Right Party Contact Rate，缩写 RPC。大白话：催收尝试里，有多少真正联系到了借款本人，而不是空号、关机、第三方或无人接听。

2）为什么重要：它解决“催收是否真正触达到可沟通对象”的问题，是贷后早期同步指标。适用于DPD1开始后的电话、WhatsApp、短信转人工等催收流程。RPC是PTP、Cure和Collection的上游，但RPC高并不等于催收有效。

3）精确定义与公式：

RPC Rate = 成功与借款本人有效沟通的账户/案件数 ÷ 进入可触达催收队列并完成规定触达尝试的账户/案件数

必须固定观察窗口（如D+1至D+3）、“有效沟通”的最短标准、账户/订单口径和去重逻辑。按电话尝试次数做分母会把多次呼叫的用户重复计算；更推荐账户/案件级RPC，同时单独报Attempt-level Answer Rate。

4）如何看高低：通常RPC升高意味着触达能力变好，但不一定“越高越好”。如果通过增加呼叫频次把RPC做高，却导致投诉、拒接和PTP Kept/Cure下降，策略可能更差。RPC下降也可能来自号码质量、运营商拦截、时段变化或系统故障，而不是客户风险恶化。

5）墨西哥现金贷案例｜七步法

背景：14天首贷，渠道C扩量；DPD1案件8,000笔，新增人工电话轮次。
数据：RPC 46%→55%；PTP 28%→43%；PTP Kept 64%→42%；Cash Cure@D+7 39%→35%；投诉0.7%→1.9%；单账户催收成本MXN18→31。
现象：有效联系率提高，但兑现、治愈和成本表现反而变差。
拆解：Channel×Score×Limit×Pay-history发现，高Score历史按时客虽然RPC不高，但APP/WhatsApp自助Cure好；低Score高额度客才更依赖人工触达。
根因：增加人工触达与成本/投诉上升存在相关性，但渠道结构也变差，不能直接写成因果。
决策：稳定客群降低人工触达频率、强化自助还款；高风险低触达客保留人工和多渠道策略。
结果：观察2-4周RPC、PTP Kept、Cash Cure、Forward Roll、投诉和成本；若Cure提升且投诉下降，才认为分层策略有效。

6）诊断逻辑：先看号码/触达系统可用性 → 再看Channel/时段/运营商 → 再看Contact Attempts与RPC → 再看PTP/PTP Kept → 最后看Cure/Roll/Complaint。关联指标必须一起看：Answer Rate、PTP、PTP Kept、Cash Cure、Complaint、Collection Cost。

7）策略动作：号码质量差：清洗/验证手机号；运营商/时段问题：调整发送/呼叫窗口；RPC高但PTP Kept低：优化话术与承诺质量；高RPC高投诉：降低频次、增加数字自助；高风险低RPC：增加备用联系方式/合法合规的多渠道触达。

8）常见误区：把接通电话当RPC；用Attempt次数作分母造成重复；RPC越高越好；忽略投诉和成本；不同DPD阶段直接横比。

9）推荐拆分维度：DPD Bucket、Channel、Campaign/来源、Score、Limit、Term、新老客、Region、Phone Carrier、Time Slot、Collector/Vendor、Strategy Version。

10）预警方式：按同DPD、同产品、同触达策略建立最近8周稳定基线。示例黄灯：RPC环比明显升高但PTP Kept和Cure连续两周下降；红灯：同时出现投诉/成本显著上升。数值阈值仅可作为内部示例。

11）与其他指标关系：

Contactability → RPC → PTP → PTP Kept → Cure → Roll → DPD30+ → Recovery / LGD
12）小练习与答案

A组RPC 60%、PTP Kept 35%、Cure 29%；B组RPC 48%、PTP Kept 68%、Cure 41%。如果成本接近，哪组更值得保留？

参考答案：B。RPC只是上游过程指标，真实治愈与承诺质量更重要。

2. PTP Rate｜Promise to Pay Rate｜承诺还款率

1）指标是什么：借款人被有效联系后，有多少形成了明确的还款承诺。大白话：真正聊到本人后，有多少人说清楚“什么时候、还多少钱”。

2）为什么重要：它衡量催收沟通是否推动用户进入明确行动计划，是RPC和PTP Kept之间的同步指标，主要用于贷后催收。PTP高本身不等于回款高，必须看PTP Kept。

3）精确定义与公式：

PTP Rate = 在规定窗口内形成合格PTP的RPC账户数 ÷ RPC账户数

合格PTP必须至少包含承诺日期、承诺金额和责任人/渠道。只说“尽快还”不能算合格PTP。分母应是RPC账户，不应是全部DPD账户。多个PTP按账户去重或单独维护最新有效PTP。

4）如何看高低：通常适度提升有利，但如果坐席为KPI制造大量低质量承诺，PTP会升高、PTP Kept反而下降。PTP下降也可能是用户更倾向直接付款、自助还款提高，并不一定是坏事。

5）墨西哥现金贷案例｜七步法

背景：催收商改KPI，从回款改为“PTP数量”。
数据：RPC 52%→58%；PTP Rate 31%→48%；PTP Kept 63%→39%；平均PTP金额MXN820→570；Collection Rate 18%→18.4%；投诉1.0%→1.8%。
现象：承诺数量大幅增加，但兑现和真实回款几乎没有改善。
拆解：Collector×Score×DPD发现少数坐席大量创建“小金额、短日期”承诺，历史低兑现用户重复PTP。
根因：KPI激励与低质量PTP高度相关；是否全部由激励导致需对比其他团队/时期验证。
决策：KPI改为PTP Kept + Cash Collected + Complaint；重复失约用户减少无意义PTP，转分期/自助/高级催收策略。
结果：观察PTP Kept、Collection、Cure、Promise Amount、成本和投诉至少2周。

6）诊断逻辑：先检查PTP定义 → 再看承诺金额/日期 → 再看坐席/供应商 → 再看PTP Kept → 再看Collection/Cure。必须联动PTP Kept、Promise Amount、Collection Rate、Cash Cure、Complaint。

7）策略动作：PTP高但兑现低：收紧合格PTP定义、改KPI；PTP低但直接还款高：不强求PTP；高风险重复失约：改为更严格还款安排/人工升级；低风险稳定客：数字自助和提醒优先。

8）常见误区：PTP越多越好；把模糊口头承诺算PTP；多次PTP重复计数；不看承诺金额；只考核坐席PTP数量。

9）推荐拆分维度：DPD、Collector/Vendor、Score、Limit、Cycle、Channel、Promise Amount Band、Promise Date、历史PTP Kept、Strategy Version。

10）预警方式：同时看PTP Rate、PTP Kept、Average Promise Amount、Cash Cure。示例黄灯：PTP升>内部稳定波动区间，但PTP Kept连续下降；红灯：Collection/Cure同步恶化且投诉上升。

11）与其他指标关系：

RPC → PTP → PTP Kept → Cash Collection / Cure → Roll → Recovery
12）小练习与答案

团队A PTP 50%、PTP Kept 38%；团队B PTP 32%、PTP Kept 72%。如果RPC相同，哪个团队更可能产生高质量承诺？

参考答案：B，仍需再看实际Collection和Cure。

3. Cure Rate｜治愈率

1）指标是什么：进入某逾期Bucket的账户中，有多少在规定观察期内恢复到“正常/满足Cure定义”的状态。大白话：已经逾期的人里，有多少真正恢复正常。

2）为什么重要：它是贷后迁徙和催收质量的核心同步/滞后指标。早期Cure会影响后续DPD30+、Recovery和LGD。

3）精确定义与公式：

Cure Rate = 在观察期内达到规定Cure标准的期初逾期账户/余额 ÷ 期初该逾期Bucket账户/余额

必须明确：账户还是余额口径；观察期D+7/D+30；Full Cure还是Partial；是否允许展期/重组。建议分别报Cash Cure与Extension/Restructure Cure。

4）如何看高低：通常越高越好，但如果通过大量展期、重组或极小额支付把账户“技术性转正常”，表面Cure可能变好而中期Vintage不改善。件数Cure高也可能掩盖大额账户未治愈。

5）墨西哥现金贷案例｜七步法

背景：团队推出展期功能，希望提高DPD1-7的Cure。
数据：总Cure 42%→56%；Cash Cure 39%→37%；Extension Rate 6%→24%；DPD30+@MOB2 12%→13%；Average Extension Fee收入提高；投诉1.1%→1.5%。
现象：表面Cure显著变好，但现金治愈和中期资产质量没有改善。
拆解：按Score×Limit×Extension次数发现，低Score高Limit重复展期用户后续Roll明显更差。
根因：总Cure被展期口径“美化”；是否导致中期风险还需同Vintage对照确认。
决策：管理看板拆Cash Cure/Extension Cure；限制重复展期；高风险用户优先真实还款安排而非循环延后。
结果：观察同Vintage MOB1/MOB2 DPD30+、Net Recovery、投诉和LTV。

6）诊断逻辑：先看Cure定义 → Cash vs Extension → 件数vs金额 → DPD Bucket/Score/Limit → 后续Roll/Vintage。关联指标：Roll Rate、Extension Rate、Collection Rate、Recovery、DPD30+。

7）策略动作：Cash Cure下降：优化支付和触达；Extension Cure高：拆分口径并控制重复展期；高余额低Cure：提高人工优先级；低风险高自愈：增加自助路径。

8）常见误区：Partial Payment直接算Cure；展期和现金还清混用；观察期不一致；只看件数不看余额；总体Cure跨Vintage比较。

9）推荐拆分维度：DPD Bucket、Score、Limit、Term、Cycle、新老客、Channel、Collection Strategy、Extension Count、Payment Method、Balance Band。

10）预警方式：同DPD/同Vintage/同策略比较Cash Cure；样本量不足不触发强阈值。示例黄灯：Cash Cure连续两个成熟Cohort低于内部基线且Forward Roll上升。

11）与其他指标关系：

RPC / Payment UX → Cash Cure → Forward Roll ↓ → DPD30+ ↓ → Recovery / LGD → EL
12）小练习与答案

总Cure从45%升到58%，但Cash Cure从40%降到34%、Extension从5%升到25%。能否直接说催收改善？

参考答案：不能，先看Cash Cure、Forward Roll和同Vintage中期风险。

4. Roll Rate｜迁徙率 / 滚动率

1）指标是什么：一个DPD Bucket里的账户/余额，在规定窗口内迁移到另一个更坏或更好的Bucket的比例。大白话：逾期资产正在往更坏方向走多快。

2）为什么重要：它是贷后资产质量、催收和现金流压力的核心迁徙指标，可提前于最终Bad/Recovery发现风险变化。

3）精确定义与公式：

Forward Roll A→B = 期初Bucket A中在期末进入Bucket B的账户/余额 ÷ 期初Bucket A账户/余额

必须固定起点Bucket、终点Bucket、快照日期、窗口和件数/金额口径。常见如DPD1-7→8-30、8-30→31-60。也可计算Backward Roll/Cure，但不要混在一个值里。

4）如何看高低：Forward Roll通常越低越好，但“降低”可能因为展期/重组把账户移出原Bucket而非真实改善。不同产品期限、催收政策或资产成熟度之间不能直接横比。

5）墨西哥现金贷案例｜七步法

背景：渠道C首贷扩量并提高Limit。
数据：DPD1-7样本余额MXN18m；1-7→8-30金额Roll 29%→38%；8-30→31-60 Roll 41%→47%；Cash Cure 40%→34%；平均Limit 1,450→1,850；总体DPD30+仅11.8%→12.0%。
现象：总体DPD30+变化很小，但早期迁徙明显恶化。
拆解：Channel×Score×Limit发现渠道C最低两档Score、Limit≥2,000的1-7→8-30 Roll达到52%。
根因：客群/额度变化与迁徙恶化相关；总体DPD30+被新资产占比上升部分稀释。
决策：低Score高Limit收紧；DPD1-7高Roll人群提高早催优先级；稳定客群保持低摩擦自助。
结果：至少观察同Vintage MOB1/MOB2 DPD30+、Cash Cure、EL和Contribution Margin。

6）诊断逻辑：快照/口径 → 资产成熟度 → DPD Bucket迁徙 → Channel/Score/Limit → Cure/Extension → Vintage/DPD30+/EL。关联指标：Cure、Flow Rate、Vintage、MOB、DPD30+。

7）策略动作：早期Roll高：加强DPD1-7分层催收/支付修复；高风险段Roll高：收紧准入/额度；Roll因技术支付事故高：先修支付；Roll因展期口径下降：拆真实Cash Cure。

8）常见误区：不同Bucket定义横比；件数和金额混用；总体DPD30+稳定就忽视Roll；展期造成“假改善”；新旧Vintage混在一起。

9）推荐拆分维度：Vintage、MOB、DPD Bucket、Channel、Score、Limit、Term、Cycle、Region、Payment Method、Collection Strategy、Strategy Version。

10）预警方式：首选同Vintage同MOB、同Bucket基线；样本量/余额达到内部门槛后再触发。示例黄灯：Forward Roll连续两个成熟Cohort高于内部稳定区间且Cash Cure下降；红灯：同时MOB1/2 DPD30+与EL恶化。

11）与其他指标关系：

FPD / DPD Entry → Roll Rate ↔ Cure → DPD30+ / Bad → Recovery / LGD → EL / Margin
12）小练习与答案

总体DPD30+几乎不变，但1-7→8-30 Roll从28%升到40%，新放款余额占比同时上升。应该判断风险稳定吗？

参考答案：不能。新资产可能稀释总体DPD30+，应优先看同Vintage同MOB和后续迁徙。

今日诊断树

如果RPC高、PTP高，但Cure差：先看PTP Kept和承诺质量；再看支付故障；再看高风险客群结构。

如果Cure上升但Roll/Vintage没改善：拆Cash Cure vs Extension/Restructure Cure。

如果Roll恶化但总DPD30+稳定：检查新资产稀释、Vintage/MOB和额度结构。

如果RPC下降同时投诉下降、Cure上升：可能数字自助/分层策略更有效，不要机械追求高RPC。
