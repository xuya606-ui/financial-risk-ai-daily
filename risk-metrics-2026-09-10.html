规则引擎与 Override 治理｜4 张完整指标学习卡

今日指标：Rule Hit Rate、Unique Reject Rate、Manual Review Rate、Override Rate。统一采用12段学习卡；示例数字用于训练分析方法，不是行业统一阈值。

Rule Hit Rate｜规则命中率

1）指标是什么：中文名“规则命中率”，英文 Rule Hit Rate。大白话：在真正被这条规则评估的申请里，有多少触发了它。

2）为什么重要：它是贷前/欺诈策略的领先或同步过程指标，用于发现流量结构、设备/征信数据或规则阈值变化；但命中不等于最终拒绝，也不等于抓到真实风险。

3）精确定义与公式：Rule Hit Rate = 触发该规则的唯一Application/用户数 ÷ 实际进入该规则评估的唯一Application/用户数必须固定规则版本、观察窗口、是否按订单/用户、重复尝试去重规则。若规则未对全部申请执行，分母不能用总申请量。

4）如何看高低：突然升高可能是攻击增加、渠道结构变差、Vendor字段变化或阈值变严；下降可能是流量改善，也可能是规则失效/字段缺失。不存在“越高越好”。

5）墨西哥现金贷七步案例：背景：首贷V7新增设备+手机号规则；数据：30,000申请，Hit 22%→35%，Unique Reject 8%→14%，Manual Review 12%→24%，Override 2%→9%，Confirmed Fraud 3.8%→4.1%；现象：Hit大升但真实Fraud只小升；拆解：Channel C × 新设备贡献大部分新增Hit，三条规则Overlap>45%；根因：可以确认重复命中和客群结构变化，但不能仅凭Hit断言攻击翻倍；决策：高Overlap规则降为Review/Step-up，保留强图谱硬拒；结果：观察2个成熟Fraud/FPD7 Cohort及投诉、Approval和Net Fraud Loss。

6）诊断逻辑：①规则版本/分母 → ②字段Missing/Vendor → ③Channel/Device/Score → ④Overlap/Unique Reject → ⑤Confirmed Fraud/FPR。

7）策略动作：技术字段异常先修Vendor；渠道异常降量；高Hit低增量改Step-up；高Hit高Fraud Capture且低FPR可保留硬拒；禁止只因Hit高就直接收紧全部阈值。

8）常见误区：Hit=Reject；多次申请重复计数；分母用全量但规则只覆盖部分申请；把Hit增长直接当欺诈增长。

9）推荐拆分：Rule ID/Version、Channel、Campaign、Device、Score、Limit、Region、新老客、KYC/Bureau Vendor、Strategy Version。

10）预警方式：用同Rule Version稳定期建立基线；示例黄灯可设“Hit超历史P90且样本达到门槛”，但必须叠加Missing、Overlap、Fraud Outcome判断；数值阈值仅内部使用。

11）与其他指标关系：Signal/Data → Rule Hit → Overlap → Unique Reject/Review → Approval → Fraud Capture/FPR → Net Loss。

12）小练习

Rule A Hit从10%升到20%，但字段Missing也从1%升到18%，Fraud Capture不变。第一步是收紧阈值吗？

参考答案：不是，先查数据/Vendor异常和分母完整性。

Unique Reject Rate｜唯一拒绝率 / 增量拒绝率

1）指标是什么：大白话：去掉规则重叠以后，这条规则或规则组真正新增拒掉了多少申请。

2）为什么重要：贷前/欺诈同步指标，用于衡量规则的真实业务影响，避免多条高度重叠规则各自“邀功”。

3）精确定义与公式：Unique Reject Rate = 因目标规则/规则组形成唯一最终Decline的Eligible Applications ÷ Eligible Applications生产中还可定义Incremental Reject：删除该规则后本应通过/进入Review、但现状被其拒绝的申请比例。必须固定Final Action和First-hit/Decision Priority。

4）如何看高低：高意味着规则对Approval影响大，但不代表价值高；若高Unique Reject伴随高Fraud Capture/低FPR可能合理，若伴随高Override/投诉、Fraud Loss不降则可能过严。

5）墨西哥现金贷七步案例：背景：设备、手机号、CLABE规则同时上线；数据：Hit总和折算42%，但去重后Unique Reject仅14%，Rule A单看Hit18%、单独Unique Reject2.6%，Override 38%，Fraud Capture增量仅0.15pp，Approval降4pp；现象：Rule A看起来“抓很多”，实际新增拒绝很少且误杀明显；拆解：多数命中同时被Rule B/C覆盖；根因：高度Overlap是已确认事实，但是否下线仍需看若删除A是否影响Net Fraud Loss；决策：A降为Step-up并做Challenger；结果：若Approval恢复、Fraud Loss无显著恶化、投诉下降，则确认优化有效。

6）诊断：①Final Action → ②Overlap Matrix → ③First-hit/Decision Priority → ④Override/FPR → ⑤Fraud Loss/FPD/Margin。

7）动作：高Overlap低Unique Reject合并/降级；高Unique Reject低价值规则收窄；高Unique Reject高风险捕获保留；用Challenger验证删除/降级效果。

8）误区：把所有Hit都算拒绝；忽略多规则Overlap；把Final Reject归因给最后一个命中规则；不看策略优先级。

9）拆分：Rule Family、Channel、Score、Device、Limit、Fraud Type、Strategy Version。

10）预警：Unique Reject周环比突然上升且Approval下降应报警；若Fraud Capture没有同步提升，升级黄灯；若投诉/误拒和Margin也恶化可升级红灯。

11）关系：Rule Hit → Overlap/Dedup → Unique Reject → Approval → Take-up → Fraud/FPD → Margin。

12）小练习

三条规则Hit分别10%、8%、7%，总申请10,000，但最终去重只拒绝1,100人。能否说“规则总拒绝25%”？

参考答案：不能；去重Final Reject约11%，需进一步算每条规则的独立增量。

Manual Review Rate｜人工审核率

1）指标是什么：进入决策漏斗的申请中，有多少被送入人工审核。大白话：自动化策略有多少工作量转移给了人。

2）为什么重要：贷前/欺诈同步运营指标，决定审核产能、SLA、申请时长与成本，也能暴露模型/规则不确定性。

3）精确定义与公式：Manual Review Rate = 进入人工Case并满足有效Case定义的唯一申请 ÷ Eligible Applications需明确重复复审、二审、KYC补件是否计入；建议另报Case/Reviewer、Median/P90 TAT和Cost/Case。

4）如何看高低：过低可能漏风险，过高可能说明规则过宽或自动化不足。高Review只有在增量Fraud Capture/审批价值覆盖审核成本和延迟时才合理。

5）墨西哥现金贷七步案例：背景：V7把多条边缘设备规则从Allow改Review；数据：Review 12%→24%，P90 TAT 18→52分钟，Approval 34%→28%，Review后Override-to-Approve 31%，Confirmed Fraud增量仅0.3pp，Cost/Application 7→13 MXN；现象：审核量翻倍但增量价值有限；拆解：Review集中Channel C与新设备低风险Score；根因：规则边界过宽是强候选，但需要控制渠道结构后验证；决策：低风险段回自动Allow/Step-up，高风险图谱继续Review；结果：目标是Review回落、TAT和成本下降且Fraud Loss不恶化。

6）诊断：①Case定义/重复Case → ②Rule/Reason来源 → ③TAT/Capacity → ④Outcome/Override → ⑤Fraud Capture/Approval/Complaint。

7）动作：Review高且价值低则缩规则；Case Backlog高则调整优先级/班次；高风险高余额提高人工优先级；低风险重复Case自动化。

8）误区：Review越多越安全；重复Case多次计数；只看Review Rate不看TAT；审核通过都算误报。

9）拆分：Rule/Reason、Channel、Score、Limit、Device、Reviewer/Vendor、Time Slot、Strategy Version。

10）预警：Review Rate、P90 TAT、Backlog、Cost/Case、Override与Fraud Capture联合；示例红灯为Review和TAT同时大升且Fraud Loss无改善。

11）关系：Rule/Model Uncertainty → Manual Review → Outcome/Override → Approval → Fraud Loss / Cost / CX。

12）小练习

Review从10%升到20%，但Fraud Capture只升0.2pp、P90 TAT翻倍。可以判断审核策略更好吗？

参考答案：不能，必须计算增量损失避免与审核/流失成本。

Override Rate｜人工改判率

1）指标是什么：系统/规则给出初始决策后，被授权人工或上层策略改成不同最终动作的比例。大白话：机器判断有多少被人“改了”。

2）为什么重要：模型与策略治理核心指标，可发现规则过严/过松、人工权限滥用、运营绕规则和决策一致性问题。

3）精确定义与公式：Override Rate = 被合法改写初始Decision的唯一Decision数 ÷ 允许进入Override流程的唯一Decision数必须区分Decline→Approve、Approve→Decline、Limit Override、KYC Override；每次Override需Owner、Reason、Evidence、权限和版本。

4）如何看高低：高可能意味着策略需要修正，也可能是业务滥用人工权限；低也不一定好，可能是审核员不敢纠正错误。关键看方向、Reason和后续Outcome。

5）墨西哥现金贷七步案例：背景：V7上线后人工可对部分设备风险进行改判；数据：Override 2%→9%，其中Decline→Approve占78%，这些账户FPD7为17% vs 自动Approve组14%，但Fraud确认率仅略高；Review成本上升、运营团队A的Override达到16%；现象：Override集中某团队和某规则；拆解：Team × Rule × Score × Limit发现大量“营销重点用户”Reason自由文本；根因：权限与Reason治理不足是确认问题，但不能仅凭更高FPD证明所有Override错误；决策：标准化Reason、额度上限、双人审批高风险Override、营销不得直接覆盖硬风险；结果：观察Override cohort的Fraud/FPD/Margin和团队间差异。

6）诊断：①Override方向/权限 → ②Reason/Evidence → ③Team/Rule/Segment → ④后续Fraud/FPD → ⑤Margin/Complaint/Audit。

7）动作：高风险Hard Rule禁止Override；边缘信用可设置限额Override；异常团队收权限并审计；持续高Override规则进入再设计/Challenger。

8）误区：Override越低越好；人工Approve就说明规则错；自由文本Reason即可；营销/客服可以无审计改判。

9）拆分：Direction、Reason、Reviewer/Team、Rule、Score、Limit、Channel、新老客、Strategy Version。

10）预警：按Team/Reason设内部稳定区间；Override激增、硬规则被覆盖、后续Fraud/FPD恶化任一出现都需升级；阈值来自内部治理，不是行业统一标准。

11）关系：Initial Decision → Manual Review → Override → Final Decision → Approval/Limit → Fraud/FPD → Margin/Audit。

12）小练习

某运营团队Override率为15%，其他团队3%，且Reason大量为空。第一动作是什么？

参考答案：先冻结/收紧异常权限并审计Reason与样本，随后再判断策略本身是否需修改。
